# 写作规范

本文规定作者怎样书写世界书：文本的措辞，条目、档案与事件的写法，状态的分工，作者资料的维护，以及改动与建立世界书的步骤。机制的含义见第一至第六章，字段与取值的清单见参考各表。本文的规则中，能由程序检查的，检查器报错或提示，其余由作者与审阅判断。

## 原则

世界书中的文本有两类读者：程序读取结构字段，叙事模型阅读文本字段。模型每轮读到的文本，既是它了解世界的依据，也是它模仿的样本。状态则由事件与命令写入本局，在每轮的上下文中单独给出。文本因此只写稳定的事实与行为方式，状态只走事件与命令，两者不相混。

- 模型可见的文本用世界之内的直接叙述介绍事物，不以外部作品、作者的判断或未启用的版本说明静态的事实。本卡禁用的来源用语，例如“原作中”，在第五层声明。
- 不在正文中断言本局的状态。关系、婚姻、家系、职位、资产、持有物、伤势、当前穿着、能力的取得与丧失，只来自事件的变化。所在与当前地点由写场景写入。把这些状态改写成句子，或换个字段名放进文本，同样越界。
- 版本之间的差别，只在角色组、档案与事件的门槛中体现。其它正文不描述未启用的版本，也不对照版本。
- 同一信息只写在职责最贴切的一处，换一种说法复述也算重复。
- 第二层的种类与取值只在 `设定/` 中声明一次。正文、说明文件与作者资料都不复述这些清单。模型需要的清单，打包时由声明生成。
- 第五层只能收紧或补充第四层，不能放宽。能机器检查的部分写在 `设定/文本规范.yaml`。叙述人称、对白比例、文风偏好与本卡的写入约束，例如“只有双方明确表白后才写恋人”，写进扮演准则。扮演准则的视角约定默认兼容自建玩家与扮演任意角色组（以玩家当前在场视角叙述），不把视角锁死在单一角色身上，除非本卡刻意限定单主角。

## 文本

文本字段的每一句都占用上下文，也都可能被模型模仿，所以写得越少而准，模型越不容易出错。本节的规则约束一切文本字段。

- 全文用简体中文，不用繁体字或日文汉字。
- 关键的名称写明，不用“某城市”“某组织”这类占位的说法。不确定时向作者确认，不编造。
- 用列表与键值，不写成段落散文。每条独立可读，不写“详见某条”“与某条配套”这类引用，需要的关键句写进本条。
- 每句话过四问：删去它，模型会不会出错；它是信息还是装饰；能否改成列表；不看原文能否读懂。只写会让模型出错的差异信息，不写模型已知的常识与主观评价。
- 用行为与画面代替标签。一句一意，写完一个判断就停，不补述同一件事。
- 模型可见的 ID 是世界之内有意义的短语，不用编码样式，宜短，因为记账结果或关闭记账时的正文命令要把它原样写回。

| 不写 | 写 |
|---|---|
| 性格温柔善良 | 遇到受伤的小动物会带回家照顾 |
| 他们关系很好 | 有记忆起就在一起 |
| 她很独立 | 搬进新宿舍那晚，她没让任何人帮忙搬箱子 |

以下写法不用：

| 类型 | 例子 | 改法 |
|---|---|---|
| 主观评价、堆砌形容词 | 非常善良、精美绝伦的门 | 删去，或只留必要的特征，如“雕花木门” |
| 模糊词 | 似乎、几乎、仿佛、如同、宛如 | 纯属虚指的删去，不确定的认知改为以行为呈现 |
| 陈旧的比喻 | 心湖泛起涟漪、像小兽、投石入湖 | 删去比喻，直陈事实 |
| 八股的微表情与语气描写 | 嘴角微微上扬、眼中闪过一丝、带着……的口吻 | 删去，或改为简洁的动作。让对白本身承担语气 |
| 极端的情绪词 | 陷入极大的恐惧、万念俱灰 | 改为具体的行为或状态 |
| 否定转折 | 她不是冷漠，只是不善表达 | 直接写表现：她话少，常被当成冷淡 |
| 空洞的数字 | 目光停留 1.5 秒 | 删去 |
| 假性主体 | 一个念头在她心里成形、一股烦躁涌了上来 | 写出实际的行为者，或改为行为 |
| 远距离叙事 | 她感到一阵悲伤、她并不知道这个决定将改变一切 | 改为行为或对白、删去预告 |
| 翻译腔 | 她是拘谨的、对这件事，她始终是回避的 | 她表现得拘谨、她一直回避这件事 |
| 元叙事 | 写作要点、戏剧用途、本卡独家 | 删去 |

- 破折号一律不用：删去后半段仍然成句的，删去；否则改为逗号、冒号或省略号。原作的原台词中的破折号按原文保留。
- “笑了”“皱眉”“攥拳”这类常见的动作词不算违规，不要矫正过度。
- 禁用词、系统视角的措辞与破折号，检查器报错，原台词中的破折号只提示。陈旧的写法按词提示。字数超出长度预算时提示。清单与预算见参考“世界书”的“措辞检查”。其余的写法由作者与审阅判断。

## 条目

条目与说明文件描述公共的对象：技能、装备、地点、势力等。它们按需进入上下文，模型据此了解对象本身，而不是了解某一局中它此刻的状况。

- 条目保持原子粒度，一物、一技、一地或一势力一文件，不设人为的总条目数上限，不把多件独立对象拼成一条合集条目。路由按本局引用、地点链与提及窗口按需展开（且提及按条目 ID 与名称逐字匹配），拆成单件原子条目既能让角色与开局自建表单精准单选，也能更准命中、更省单库预算。`技能/` 只收可习得或持有的具体技能，纯百科总纲归入常识类库、分类说明文件或世界概况；`装备/` 只收可独立持有的具体器物或不可分的成套随身装备，不收巨型固定设施。
- 条目只介绍对象本身：身份、作用、稳定的特征、自然的边界与必要的动态范围。会随时间、经历、地点或关系变化的内容，写成“会随……变化”这类世界之内的表达，不写当前的状况。
- 边界只写在它适用的最高一层，下层不重复上层或协议文本已有的边界。条目的边界只写本领域特有、模型容易犯错的部分，例如“聚军自乡里募勇而出，受州府节制而非经制官军”“两剑同式，成对携用”。各库中这类字段宜统一叫“边界”。
- 说明文件写得出本层特有的内容才写，不留空壳；同类原子条目拆分后，整类共性法则抽入库根或分类目录同名说明文件（展开同分类多条时只输出一次），具体条目只写自身差异。某个分类层写不出特有的内容时，考虑并入上级。说明文件不复述第二层声明的种类与取值，也不用系统视角的措辞。
- 跨越几个条目库的格局，例如世界的战力格局，写进世界概况，不写进某个库的说明文件。世界概况与扮演准则均按单一独立主题分文件，不为压缩文件数把多个独立主题硬拼成一篇（二者每轮全量进入上下文，拆细同时控制总篇幅）；世界概况写在整个可游玩时期都成立的内容，多世界线卡若某条世界线有独立背景，可另放 `世界概况/世界线/{世界线ID}/*.txt`，只在该世界线追加输出。

## 档案

在场者的当前档案每轮都进入上下文，是模型扮演这个人的依据。档案写“这个人会怎么做”，不写“现在是什么状态”。字段表与建议条数见参考“角色”。

- 档案只写本时期及以前已经确立的事实，不提及之后才出现的人物、身份或事件。档案不写年龄，当前年龄由出生年与当前时间计算。
- 称号只写本时期对外使用的称号或名号，没有就省略，不写“无”。职位由事件写入。出生年只有范围时省略，不编造。种族、出身各写一句，补充放括号。身份与经历交给事件。
- 稳定体貌写遮住名字也能认出的特征，只写偏离该种族与年龄默认印象的，不写“精致”“白皙”这类放在谁身上都成立的词。体型只写显著的特点。各时期之间体貌的变化，写进各自的档案。
- 穿着习惯写“在什么场合偏好穿什么、为什么”。偏好不等于当前的穿着。涉及专属装备时写成“持有并使用某物时……”，偏好某件装备不等于持有它。
- 能力特征的特征写天赋、体质、当期的施法限制这类个人差异，一句一项。技能补充写某个公共技能在此人身上的表现与限制。不写当前的能力、已学的技能名单、综合实力或公共技能的正文。写了技能补充，不等于已经掌握该技能。
- 核心身份每轮为角色定调，只放这一时期最稳定的身份感，写成“形容词加身份”，不放亲密倾向与一次性的处境。行为准则写可以执行的处事顺序，不写“善良”“冷静”这类评价。价值优先写成名词短语，从高到低排序，前面的在冲突时胜出。
- 表达规律只写与常规叙述口吻不同的部分，按自称与称呼、句式、语气变化、场合差异、内外差、口头特征归位，资料没有的省略。拿到一句台词，读者能据每一条判断它像不像这个角色。“温柔”“冷淡”“礼貌”不能单独成条，须落到具体的说法。自称与称呼、句式最能区分角色，资料中没有时在作者资料中列为待补，不编造。
- 完整的台词不写进档案，只放在事件角色位置的候选台词中。写进档案的台词每轮都会进入上下文，模型会反复套用。通用反应写“做什么”，语气变化只写“怎么说”。
- 通用反应的键写具体的情境，值写具体的做法。只属于某一次事件的反应，写进那个事件的角色位置。
- 关系表现的键写对象的类别或条件。针对具名的角色或亲密的关系时，键写第二层的关系阶段与场合，不用数值作条件。键只描述条件，不声明双方现在是什么关系。同一对象的行为与说话方式写在同一条，其它字段不重复。值写具体的触发与收起的情境，不写“偶尔”“有时”这类频率词。亲密场景写主动性、态度与节奏，保留成年与自愿的前提。
- 表现禁区每条以“不”开头，写模型最容易写歪的具体方向。适用于所有角色的规则写进角色通用约束，不在每份档案中重复。
- 核心身份、行为准则、价值优先或稳定体貌明显改变时，另开档案，例如流亡前后、婚后、身份公开前后。单纯的能力成长或装备变化不另开，由事件写入本局。每个版本通常 1 至 4 份档案，更多时在作者资料中说明理由。
- 共享档案改一处即对全部适用版本生效。只想改其中一个版本时，先把它拆成镜像档案。修改镜像档案的一份时，比对另一份的同一字段：原本相同的，考虑是否同步。原本不同的是版本差异，不动。
- 代表授职、受雇、取得身份或成婚的档案，生效条件只引用实际达成结果的分支，拒绝或暂缓的分支不能冒充取得身份。检查器不核对分支的含义，须由作者确认。

## 事件

事件是本局改变的单位，原作的走向、作者的改编与 if 线都写成事件。事件的结构决定 if 线能否成立，事件的文本决定模型怎样叙述它。字段表见参考“事件”。

- 事件ID与事件标题用世界之内中性的名称，按发生的行动、转折或结果命名，不带“原作·”这类来源的前缀，不以单一角色的视角命名。身份的转变，例如成为护卫、成为家庭教师，是分支的结果，写进变化表，不单独成为事件，也不写进事件ID。
- 静态的正文不写本局的确认状态。事件的出处写进作者资料的出处记录，不写进正文。
- 门槛只写真正的因果，即“没有它，这件事就不会发生”，不写“原作中它排在前面”。核心参与者只列缺了事件就不成立的角色组，世界事件通常没有核心参与者。世界事件与它对各人的后果分开写。关键的事件写出多个分支，后面的事件按实际所走的分支设门槛。
- 自由游玩中的多数预设外经历通过动态事件（附实际参与者与摘要）及角色知识作软记忆即可，无需强造硬门槛；但对幕后自动确认时容易穿帮的关键节点（如空间分流、核心人物重大状态、主线转折前提），门槛优先读取状态条件（所在、同处、角色状态、剧情标记、事件串状态），使动态事件改写的状态或提前结束的事件串自然接上预设事件树。
- 只想表达“在它之前”时，用条件“当前时间”或“事件串状态”，不用 none。none 表示终身的排斥。
- 封卷时求不出值的要求，例如事件须在某个场景中发生、须有某些人在场，写进叙事条件，或把事件改为仅作候选。
- 事件串进行中时，事件串ID与概述每轮都在上下文中。二者写这段过程是什么，不写它怎样结束。写出结局，模型会抢先把剧情推向结局。
- 各分支的分支条件须能相互区分，分支结果写这个分支实际的结果。自动确认的事件有带门槛的分支时，须有不带门槛的兜底分支。
- 修改条件文本，即叙事条件、分支条件、介入条件、触发情境与触发限制时，除措辞之外，还须核对它的适用范围没有因此改变。
- 角色位置不复制事件的正文与变化表，状态的变化只写在变化表中。角色知情与主观记忆须与所适用的分支一致，不把成功的记忆写进失败的分支。角色知道、猜测、希望或记得某事，不等于它在世界中已经成立。
- 候选台词只收本角色自己说的话，别人对他说的话写进他的角色知情或主观记忆。原作中此人在本事件或同类情境下的台词，逐字收录，排在作者撰写的台词之前。原作已有适用的台词时，不另写同义的台词。只有原作没有适用的台词时，例如本局新增的分支、原作未覆盖的情境、扩展的角色，才由作者撰写，并须符合当期档案的表达规律。
- 原台词的出处写进出处记录，正文不标注。台词不能单独确认事实，台词涉及的事实须已在事件的正文或已确认的结果中。
- 多世界线卡用 `历史/世界线/{世界线ID}.yaml` 承载跨整条时间轴生效的平行设定，预设开局方案标明所属 `世界线`（并可附 `开局地点`），与自由开局自然分层。
- `历史/开局选项.yaml` 的写法保持克制简练、客观自然：分岔处可直接省略 `问题`（界面回退事件标题或事件ID）或直接写事件名称，选项直接写简明的分支名称。例如：

```yaml
- 事件ID: 三张决意取天下
  选项:
    乘势取天下: 乘势举事取天下
    温和传教: 止于传教，不举兵
    未发生: 三张未起事
```

## 状态

本局的状态由事件与命令写入，每轮在上下文中单独给出。状态写在哪个字段，决定它在什么情形下进入上下文，所以按内容的性质选字段。以下针对采用默认声明中身份、职位与知识三个字段的卡。

| 内容 | 放到 |
|---|---|
| 与势力挂钩的职位 | 职位 |
| 与势力无关的社会身份，例如“船工”“外乡人” | 身份 |
| 会影响以后行为的长期事实 | 知识 |
| 剧情条件 | 剧情标记 |
| 经历与记忆 | 角色位置的主观记忆 |
| 只与这一次事件有关的细节 | 角色位置的角色知情 |

- 知识作为在场者的本局状态每轮进入上下文，不受经历预算的限制，因此只收会影响以后行为的长期事实，例如“救董卓反遭轻慢，董卓以无官职轻之，不为礼”。
- 已写进知识的事实，角色位置的角色知情不再重复。
- 身份的转变由事件的变化写入，不单独成为事件。

## 作者资料

作者资料不进入上下文，不参与运行，放在世界书之外的 `作者资料/`。世界树只规定工具要读写的部分，其余的格式与位置由项目自定。出处记录与暂存清单的字段见参考“世界书”。

- `通读/`：第 0 层的通读分卷坐标账本、活词表与全局总账，`init` 预建 `通读/分卷/`。
- `出处/`：事件级记录写事件的来源，例如原作的章节、“作者改编”或“作者原创”；台词记录写每句原台词的来源。
- `暂存/`：已经写好、待条件满足后接回世界书的内容，按它在世界书中的相对布局存放，并在暂存清单中逐项登记。接回之后删除清单中的对应项。
- `候选/`：尚未定下的内容，定下之后写入世界书，并从候选中删除。
- `生成/`：工具的输出，不手改。
- `归档/`：撤下的内容，保留它在世界书中的相对布局。
- `审阅器/`：`ygg view` 的缺省审阅存储目录，存批注、布局与保存备份，首次写入时创建。
- 创作规划与核定日志由项目自定，只写设计理由、创作意图、进度与待办，不抄写第二、五层的声明，也不重述本规范的条文，需要时引用。

## 编辑

改动的级别按所改的字段属于哪一层判断，不按文件判断。级别决定改动之前与之后要做哪些检查。

| 级 | 层 | 范围 | 检查 |
|---|---|---|---|
| 设定级 | 二 | `设定/` 中第二层的声明 | 全量检查。不再合法的第三层内容逐项列出，经作者同意后迁移，不静默丢弃 |
| 结构级 | 三 | 程序读取的字段：事件的时间、门槛、分支与变化，事件串，开局选项与方案，角色组的全部字段，档案的生效条件，条目的 ID、取值与引用 | 改动之前列出指向该对象的全部引用，逐项同步、结构检查与抽样 |
| 文本级 | 四、五 | 文本字段：档案的正文、事件的概要与叙事条件、角色位置、条目与说明文件、世界概况、扮演准则、`设定/文本规范.yaml` | 格式与措辞检查，条件文本另核对适用范围 |

第一层只能经修订世界树的规范改变，卡不能覆盖。

- 文本级的改动不授予本局的状态：不把“已成婚”“持有某物”“已任职”“已掌握某招”写进文本，也不换个字段名承载；不借改字改变条件文本的适用范围；不顺带改动结构、设定、测试或检查器。发现事实放错了位置时，清理越界的断言，保留行为方式，并指出缺口交给结构级的改动，不在文本修改中自行补写事件。
- 设定级与结构级的改动，之前先跑检查与测试，记下已有的失败。之后再跑同样的检查，只对新增的失败负责，交付时分开列出新增的失败与改动之前已有的失败。
- 结构级改动之前，在任意创作项目目录运行 `ygg trace <世界书目录> <对象键>`（例如 `ygg trace examples/三国演义/世界书 '事件:桃园结义'`），先列出指向该对象的全部引用，再逐项同步。
- 不为让检查通过而改测试或检查器。计数或快照因改动而合理变化时，报告具体的断言，经同意再改。
- 事件ID、档案ID等是存档中的引用键。改动 ID 之前，确认没有需要兼容的存档，或建立旧 ID 到新 ID 的迁移表。
- 没跑的检查不说通过。交付时说明改了什么、属于哪一级、跑了哪些检查与结果。
- YAML 的书写风格，例如列表写成块状还是行内、缩进与引号，不属于任何一层，检查器不为它报错。需要统一时运行 `ygg format <世界书目录>`：缺省只检查，有差异时列出文件并返回非零；`--write` 才写回确有差异的文件。真实项目先不带 `--write` 检查差异，确认符合预期后再 `--write`；仓库内置示例（`examples/`）只在副本试验。字段顺序、缩进与原子写入等格式化细节见[参考：命令](参考/命令.md#format)。

从原作或资料建立整套世界书时，按建卡第 0 至第 5 层顺序推进（每层步骤、三国示例与门禁见[作者指南](作者指南.md)，各层 skill 入口见 [`skills/README.md`](../skills/README.md)）：

1. **第 0 层·通读**：两遍读法第一遍，分批抽坐标账本并维护活词表，归并五份全局总账进 `作者资料/通读/`（原创世界经作者访谈产出同构总账）；名单、分期与体系取值经作者拍板后进入下一层。
2. **第 1 层·地基**：依据拍板总账建 `设定/` 声明、`世界概况/` 与 `扮演准则/`，通过静态检查。
3. **第 2 层·条目**：铺公共条目库，只写对象本身与领域特有的边界。
4. **第 3 层·骨架**：建全名单角色组与全书事件树、事件串、if 线分支与开局，正文字段先写简明占位；全量检查、`if` 与 `preview` 通过后请作者拍板骨架。
5. **第 4a/4b 层·档案与填景**：两遍读法第二遍，按坐标回查原文精写档案正文、补实事件正文与角色位置，逐字摘录原台词并记入 `作者资料/出处/`。
6. **第 5 层·打包**：定稿卡面并构建酒馆角色卡。

工具调用口径与按阶段/按级别的最小检查矩阵见 [`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)。
