# 协议

协议是内核中读写本局的部分。第二、三章说明了协议读取什么、写入什么：档案怎样解析，能力怎样读出，事件怎样成为候选、怎样确认。本章说明协议怎样执行这些规则：本局怎样存放，条件怎样求值，开局之前与窗口已过的事件怎样按时间先后补出，读取所依据的有效本局怎样算出，封卷怎样写下开局，写入怎样构造与提交，五种命令各自怎样执行，排斥检查怎样把关，检查器怎样以协议抽样，最后以示例《三国演义》的几次封卷与写入串联上述内容。本局骨架、命令、封卷与抽样的逐项清单，见参考“协议”。检查器的规则与协议的错误码，见参考“检查规则”。协议只读本局与世界书，不调用模型。读取不改变本局，写入不修改传入的本局，成功时返回新的本局，失败时报错，什么也不写。

## 本局

本局变量是本局的存储结构，分两部分：一层骨架由规范规定，所有卡相同；二层字段由卡在 `设定/本局变量.yaml` 声明。一层骨架有五个部分：

| 部分 | 内容 |
|---|---|
| 世界 | 当前时间；当前地点，由地标与场景组成；剧情标记，以标记ID为键 |
| 开局 | 开局设定：可选的世界线、开局时间、已封卷、历史选择、所用的方案，全部角色组的启用与版本，玩家模式及扮演角色组或自建档案（含双模式通用可选定制与扮演增量定制） |
| 角色 | 以角色组ID为键的角色变量：在场、所在、各能力维度、装备、能力移除记录、已初始化，以及二层的角色字段 |
| 事件 | 以事件ID为键的事件记录：状态、分支、实际时间、实际参与者，动态事件另有摘要与结束事件串 |
| 待定项 | 待定项的列表 |

开局设定在封卷时写入，此后只读。装备以装备ID（或动态写入时的本局自定义装备名称）为键，值为状态与位置。能力移除记录是相对字段路径的列表，例如 `技艺.{键}` 或单值等级的维度名。事件记录的状态为 1 表示确认，为 2 表示排除。没有记录的事件，既未确认，也未排除。首次登场初始化同样写成事件记录，事件ID为 `初次登场·{角色组ID}`。自建的玩家，其角色变量记在保留的角色组ID“玩家”之下。

二层的声明有四项：词表，即命名的取值表，第一个值是默认值，其中 `词表.装备状态` 必须声明，因为一层的装备记录引用它；角色，即角色变量中的二层字段；世界，即世界下的二层字段，可选；单次增减上限，即数值字段每次增加或减少的上限，可选，缺省为 100。字段按第一章“字段”的写法声明，其中数值与集合两种写法只用于本局变量。字段名不得与一层骨架重名，角色字段也不得与能力维度重名。世界树的默认声明推荐关系、好感度、身份、职位与知识五个角色字段，内核不特别对待它们。

角色变量在首次写入时创建，例如初始化、写场景或事件的变化写到这个角色组时，不为全部已启用的角色组预建。没有角色变量，与其中的字段都从未写过相同：读取时，有取值表的字段取第一个值，所在取初始所在，其余为未知。场景状态以外的持久字段，都能在事件记录中找到写入它的事件。本局变量本身不逐字段记录来源。

待定项记下叙事模型一时不能确定取值的字段，每项写字段路径、候选值、事件ID与说明，不覆盖字段的原值。剧情明确之后，叙事模型写入结果并移除待定项。待定项不产生事件记录，原样进入上下文中世界的当前状态。

本局只存放写下的状态。当前档案、当前能力、可用技能、事件有效状态与事件串状态，都在读取时计算，不写回本局。存档与回档由适配层实现，楼层记录与重放规则见第六章。

## 求值

门槛与生效条件读取本局记下的状态。协议从有效本局读取每个条件叶子的值，按第三章“门槛”的三值规则组合。封卷之前一律为未知。none 之内的叶子按取反后的极性求值，未知取反仍为未知。

求值时作为当前时间的时间，称为时间语境。读取时，时间语境就是本局的当前时间。历史求解为某个事件求值时，以这个事件的触发时间最晚为时间语境，条件“当前时间”与之比较，其余条件仍读取当时的状态。时间语境缺失时，条件“当前时间”为未知。

所在按以下顺序读取：视为在场、且当前地点已写入的，取当前地点的地标；否则取本局记下的所在；没有记下的，取 `角色组.yaml` 中的初始所在；都没有为未知。条件“角色状态”读取字段时，所在按此读取。其余字段取本局中该路径的值，从未写过时取取值表的第一个值，没有取值表的为未知。条件“同处”比较所列角色组按此读出的所在。

条件“在场实力人数”在当前地点缺失时为未知。否则，对视为在场者中已启用的角色组，以及自建模式下的“玩家”，除去参数“排除角色组”所列的角色组，读取综合实力维度的值。不低于最低实力的人数达到最少人数为成立，否则有人没有综合实力的值为未知，再否则不成立。本局中能力的值不在维度所用的等级之内时，协议报错，不作猜测。

## 求解

求值给出单个条件的结果，补出一组事件则要按时间逐个求值、逐个写入。封卷补入开局之前的历史，协议补登待登记事件，用的是同一个求解过程，称为历史求解。它从一组参加求解的事件中，按时间先后逐个写入能够发生的事件。参加求解的事件，封卷时是除去指定为“未发生”之外的开局前事件。补登时是本局没有记录、确认策略为自动确认、核心参与者都已启用、当前时间已过触发时间最晚的事件。

参加求解的事件按触发时间最晚的起点排序，同时刻按事件ID的码点顺序，即逐字比较字符的 Unicode 码点。每一轮按这个顺序，找第一个满足以下条件的事件：尚未写入；确认策略不是仅作候选；核心参与者都已启用；以触发时间最晚为时间语境，事件门槛成立，且按第三章“分支”的规则选得出分支。找到后写入记录，状态为 1，分支为所选分支，实际时间为触发时间最晚，实际参与者为核心参与者，并按分支的变化写入状态。然后回到这个顺序的开头重新寻找，因为刚写入的记录与状态可能使排在前面的事件成立。找不到时，求解结束。

求解中，条件“事件确认”只认已经写入的记录，其余条件读取草稿上当时的状态。事件之间的依赖因此按写入的先后生效：前一个事件写下的关系、所在或剧情标记，后面的事件读得到；后面的事件写下的，前面已经写入的事件不再重新判断。

找到的事件，若触发时间最晚的起点早于上一个写入事件的实际时间的起点，就是倒流：较晚事件的变化使较早的事件成立。封卷时，倒流报时间顺序冲突。补登时，这个事件不写入，因窗口已过而排除，求解继续。补登时“上一个写入事件的实际时间”的初值，取本局中状态为 1 的记录里最晚的实际时间。

## 有效本局

读取之前，协议以历史求解补出待登记事件，得到第二章已经引入的有效本局：本局已封卷、当前时间已写入时，在本局的副本上，对补登的事件做历史求解；求解后的副本即有效本局，求解中写入的事件依次构成待登记列表，各带所选的分支。封卷之前或当前时间缺失时，有效本局就是本局，待登记列表为空。

一切读取都在有效本局上进行：条件求值、档案解析、当前能力与可用技能、事件有效状态与事件串状态。本局本身不因读取而改变。每次写入开始时，也先在草稿上登记写入之前读到的待登记事件，事件与分支都与读到的相同。写场景推进当前时间之后，另行登记因此新到期的事件（见“命令”）。路由每轮只求解一次，各部分的读取共用同一份有效本局，档案、能力与事件状态的结果在这一轮中缓存。

事件有效状态按以下顺序，取第一个符合的：

| 状态 | 条件 |
|---|---|
| 已确认 | 本局有该事件状态为 1 的记录 |
| 已排除 | 本局有该事件状态为 2 的记录 |
| 待登记 | 在待登记列表中 |
| 未到 | 未封卷，或当前时间缺失 |
| 已排除 | 有核心参与者未启用 |
| 未到 | 当前时间的终点不晚于触发时间最早的起点 |
| 已排除 | 当前时间的起点不早于触发时间最晚的终点 |
| 候选 | 事件门槛成立，且至少一个分支的门槛成立 |
| 不适用 | 其余情况 |

候选与不适用的门槛在有效本局上求值，时间语境为当前时间。事件串状态同样在有效本局上推出：有结局的记录状态为 1，指定了分支时分支一致，或有状态为 1 的记录声明本串结束，为已结束；否则有起点的记录状态为 1，为进行中；其余为未开始。

## 封卷

封卷同样以历史求解补出开局之前的历史，它把开局的选择写成最初的本局。输入有世界线、开局时间、方案、角色组、玩家与历史选择六项，各项可选。没有方案时，开局时间必填。封卷依次执行以下各步：

1. 合并：世界书声明了世界线时，先确定世界线（显式传入优先，否则继承方案的世界线，再否则取默认世界线或码点第一条；同时传入且与方案冲突时报参数不合法）；未声明世界线的世界书不得传入世界线。角色组按角色组ID逐键合并，优先级为 `角色组.yaml` 默认值 < 世界线角色组 < 方案角色组 < 直接传入的角色组；历史选择以方案为底按事件ID合并。
2. 角色组：没有写的取默认启用与默认版本，只有一个版本的角色组，版本ID为角色组ID；版本ID须属于该组。开局设定中写入全部角色组。
3. 玩家：缺省为自建模式、档案为空，扮演模式的扮演角色组须已启用；双模式均支持可选 `自定义装备`、`自定义技能`、`额外技能`、`移除技能`；自建模式另支持 `初始能力`、`初始装备`，扮演模式另支持 `能力覆写`、`移除能力`、`额外装备`、`移除装备`。
4. 骨架：当前时间设为开局时间，剧情标记设为开局值，即声明中的第一个取值；写入开局设定（多世界线世界书写入 `开局.世界线`，单世界线世界书不写该键）；角色与事件初始为空，待定项为空列表。此后的求值都按封卷之后进行。
5. 开局前事件：触发时间最晚的终点不晚于开局时间的起点、确认策略不是仅作候选的事件。
6. 历史选择：每项的事件须是开局前事件，值须是该事件的分支ID或“未发生”，否则报历史选择错误；指定“未发生”的事件写下状态 2。
7. 求解：对其余开局前事件做历史求解，指定了分支的事件只能走该分支。
8. 指定了分支却没有写入的事件，报历史选择错误，不退回默认分支。其余没有写入的开局前事件，写下状态 2。
9. 排斥检查，对象是全部写入的预设事件。违反时报配置冲突。
10. 玩家开局定制落盘与唯一装备清理：若自建玩家带有 `初始能力`、`初始装备` 或 `自定义装备` 任一项，落盘 `角色.玩家` 并置 `已初始化` 为真；若扮演玩家带有 `能力覆写`、`移除能力`、`额外装备`、`移除装备` 或 `自定义装备` 任一项，须校验扮演角色组当前档案成立，合并其自动基线后按确定性顺序叠加定制并置 `已初始化` 为真（不写 `初次登场·` 记录）。最后，对玩家控制角色持有的每件 `唯一: true` 装备，自动从所有其他角色的 `装备` 映射中移除。

封卷不写当前地点与在场，也不初始化未做开局落盘定制的角色组，这些都在游玩中由命令写入。协议另提供只读的 `roleplayBaseline(state, groupID)`，在有效本局副本上返回指定已启用角色组的 `{结果, 档案ID, 能力, 可用技能, 装备, 所在}` 基线快照，不修改传入本局。历史选择只能使用开局选项中声明的事件与选项，这一点由检查器与开局前端把关，协议只按第 6 步校验。封卷的错误有四种：参数不合法、历史选择错误、时间顺序冲突与配置冲突。出现任何一种，封卷不产生本局。

## 写入

封卷之后，本局只经命令写入。五种命令都按同一过程写入。协议在传入本局的副本上，即草稿上构造修改，传入的本局本身不变。写入之前，先记下有效本局中已确认的预设事件，供排斥检查使用。然后依次：登记待登记事件，与本次写入同属一次提交；执行本次命令自身的写入；对出场自动的角色组完成初始化；做排斥检查。全部通过时，返回新的本局与已写入的列表，称为提交。列表依次是登记的待登记事件、本次命令的事件与初始化的记录。任何一步不通过即报错，什么也不写。

命令的目标事件已有记录，或目标角色组已经初始化时，这个对象不重复写入，对它而言结果为“未写入”。同一次提交中，待登记事件的登记与出场自动的初始化照常进行。没有任何内容写入时，已写入的列表为空。

每条变化先按第三章“变化”的规则校验，与检查器用同一套校验，再写入。等级维度的提升在本局没有值或新值更高时写入，设定直接写入，两者都清除该字段的能力移除记录。移除删去值，记入能力移除记录。集合的新增与移除不产生重复，移除不存在的成员不报错。映射的设定写入键，新增在键不存在时才写入，移除删去键；装备若声明了 `唯一: true`，预设事件 `新增` 在任一角色已持有时跳过，动态事件 `新增` 与显式 `设定` 写入时自动从其他持有者移除。数值的增加与减少在本局没有值时从 0 起算，结果截断在第二层声明的范围之内。单值以设定写入。路径与映射键中的角色组须已启用。“玩家”只在自建模式下可写。动态事件另允许对本局 `开局.玩家.自定义装备` 中声明的名称写入装备变化。角色变量在首次写到时创建。

初始化的执行按第二章“初始化”的填写规则：写入记录 `初次登场·{角色组ID}`，补入初始能力与初始装备，并把已初始化记为真。写入初始化不会再触发初始化。出场自动的初始化在每次提交之前进行，对象是已启用、尚未初始化、初始化方式为出场自动的角色组，且满足下列之一：是本次写入的事件的实际参与者，随之登记的待登记事件也计在内；或者写入之后视为在场。当前档案不成立时跳过。待初始化预览在有效本局上计算。

本局只经命令写入，任何模型都不直接改动本局变量。默认记账时，适配层把记账结果转换为命令；关闭记账时，命令由叙事模型写在正文中。只有经过协议，上述校验、登记、初始化与排斥检查才都得到执行。适配层绕过协议直接改动场景状态，可能使待登记事件的分支与窗口结束时的状态不一致。

## 命令

上述过程中，“执行本次命令自身的写入”这一步因命令而异。本局的写入共五种命令，每条命令对应一次写入：

| 命令 | 参数 |
|---|---|
| 确认事件 | 事件ID、分支ID，可另列实际参与者 |
| 动态事件 | 事件ID、摘要、变化，可另列实际参与者与结束的事件串 |
| 确认初始化 | 角色组ID |
| 写场景 | 当前时间、当前地点、在场、所在，各项可选 |
| 待定项 | 操作、字段路径，新增另需候选值、事件ID与说明 |

确认事件须已封卷，事件须是预设事件，分支须属于该事件。本局已有状态为确认、且分支与所选分支一致的记录时，结果为未写入。事件已有排除记录，或已确认的分支与所选分支不一致时，报 `协议.事件状态`。事件为待登记时，所选分支须与待登记的分支一致，随待登记一并登记。不一致时报错。否则，事件在有效本局上须为候选，所选分支的门槛须成立。实际参与者是核心参与者与另列的角色组的并集，核心参与者在前，都须已启用。记录的实际时间为当前时间，并按分支的变化写入。

动态事件的事件ID须符合第一层的 ID 规则，不与预设事件重复，不以“初次登场·”开头。摘要必填。变化可以为空列表，每条按写入变化的规则校验。另列的实际参与者都须已启用。声明结束的事件串，须存在且在有效本局上进行中。记录的分支为“完成”，实际时间为当前时间。

确认初始化要求角色组已启用、当前档案成立，否则报错。已经初始化的，结果为未写入。

写场景按当前时间、当前地点、在场、所在的顺序处理。当前时间须是合法的纪年，起点不早于原值的起点。写入之后，登记因此新到期的待登记事件，后面几步读到的是走动之前的状态。当前地点的地标须是地点ID，场景为文本。在场的键须是已启用的角色组，扮演角色组与“玩家”不能写。从未出场的角色组写为真时，初始化方式为显式确认的报错，须先确认初始化，出场自动的在本次提交中初始化。由真变假、而本次没有给它写所在时，把写入之前当前地点的地标存为它的所在。所在的键须是已启用的角色组，值须是地点ID。写入之后视为在场的角色组，不能写所在。在场的角色随当前地点移动，要让某人留在原地，同一次写入把他的在场写为假。时间推进先于走动处理，因为待登记事件的分支应按窗口结束时的状态选出。

待定项的字段路径按变化的路径写法，须写到已声明的字段格，规则同变化。在场与所在不能作为待定项。新增须有非空的候选值列表、本局中状态为 1 的事件ID与说明，同一字段路径已有待定项时替换它。移除删去该字段路径的待定项，没有时不报错。写入待定项之前，照常登记待登记事件。

一轮的命令按顺序逐条执行，每条是独立的一次写入：后一条读到前一条写入之后的本局；失败的那条不写入，记下序号、命令名、错误码与说明，接着执行后面的命令。一轮执行完毕，得到最后的本局、各条命令已写入的内容按执行顺序合成的已写入列表，以及失败的列表。默认记账时，记账调用返回记账 JSON，适配层把它转换为同样的命令列表后提交，正文不写命令。关闭记账时，仍使用正文末尾的 `<命令>` 标签，内为 YAML 列表，每项是以命令名为键的单键映射。适配层可以换用命令的承载方式，但不能改变命令语义，并须决定失败怎样反馈给玩家。

## 排斥

写入过程的最后一步是排斥检查。排斥是终身的（见第三章“门槛”），协议在每次提交之前以排斥检查把关。检查的对象，是写入之前有效本局中已确认的预设事件，包括随这次写入登记的待登记事件。封卷时，是封卷写入的全部预设事件。对每个对象，以写入之后的记录重新求值它的事件门槛与所走分支的门槛：条件“事件确认”按记录求值，计入极性；其余条件一律记为未知。结果为不成立，即排斥冲突，本次写入被拒绝。封卷时报配置冲突。

事件记录只增不删，确认时已经成立的正向引用，此后仍然成立。其余条件记为未知，也不会得出不成立。因此检查实际捕捉的，是对象以 none 排斥的事件在后来得到确认。对象的门槛在 any 之下另有成立的一项时，排斥的那一项不再决定结果，不构成冲突。

## 抽样

封卷与写入的规则，也供检查器在写卡时使用。检查器以协议试验世界书，称为抽样。静态检查没有错误时才抽样，否则提示未执行抽样。抽样年份取全部事件触发时间最早与最晚所在的年份，各取该年与下一年，另加最早年份的前一年，不小于 0。去重后升序排列，抽样时的开局时间写到年。抽样有四项。

档案互斥已在第二章“解析”说明：在只含所枚举记录的封卷后本局上直接解析档案，不经封卷，也不登记待登记事件；声明了世界线的世界书按每条世界线分别枚举，避免跨世界线档案误报冲突。

运行抽样在每个抽样年份（多世界线世界书覆盖每条世界线）封卷：默认开局一次；全部角色组启用、各取其第 i 个版本各一次，i 从 1 到各角色组版本数的最大值，版本不足的取默认版本。封卷须成功，每个启用的角色组档案解析不得冲突。解析异常只提示。

开局方案的抽样，对每个方案封卷一次：开局时间取方案所写的；方案没有写时，取所选事件中触发时间最晚的年份的下一年，没有所选事件时取最后一个抽样年份。封卷须成功。

开局选项的抽样，对每个选项的每个分支，包括“未发生”，在该事件触发时间最晚的年份的下一年，以默认开局加这一项历史选择封卷（多世界线世界书逐条世界线试验，只要在至少一条世界线下可选就不提示不可选）。历史选择错误只提示，因为默认的历史下这一项不可选，开局前端不会给出。其它失败报错。

抽样与游玩用的是同一个协议，抽样中封卷的失败，就是玩家以同样的选择开局时会遇到的失败。

## 实例

下面以示例《三国演义》说明协议的执行。《三国演义》的事件触发时间分布在 `中平000年` 至 `中平006年`，抽样年份因此是 `中平000年` 至 `中平007年` 共八年。

### 封卷

以 `中平000年` 开局，开局时间的起点是该年首日。最早的事件（如 `雷雹坏屋`、`青蛇惊驾`）均在 `中平000年01月01日`，没有事件的触发时间最晚的终点早于这一起点，开局前事件为零。封卷只写下骨架：当前时间为 `中平000年`；9 项剧情标记均取声明中的第一个开局值（例如 `黄巾之势` 为 `未起`，`董卓之命` 为 `悬而未决`）；全部 37 个角色组按默认启用与单版本写入开局设定，玩家为自建模式、档案为空；角色与事件记录都为空。

以开局方案 `榜前长叹`（`中平001年04月02日`）封卷，共有 44 个开局前事件（如 `雷雹坏屋`、`三张决意取天下`、`三路讨贼之诏`、`幽州出榜招军`、`榜行涿县引刘备` 等）按时间顺序补入：44 条确认、0 条排除。此时落在当日窗口内的 `榜前定交` 处于 `候选` 状态，`村店遇关羽` 因门槛依赖尚未确认的 `榜前定交` 而处于 `不适用` 状态（待 `榜前定交` 确认后才成为 `候选`）；`榜文聚义` 事件串处于 `进行中`；`刘备` 仅保留先前事件写入的 `关系.卢植: 师生` 与 `身份: [汉室宗亲（中山靖王刘胜之后）]`，尚未出场初始化，也不在场。

以 `中平007年`（时间轴末尾）封卷，全部 150 个事件均完成求解并确认：`刘备` 当前档案切期至 `刘备·平原县令期`，`董卓` 切期至 `董卓·入京专权期`。

### 登记与一轮命令

以 `榜前长叹`（`中平001年04月02日`）开局后，在游玩中提交以下一轮命令：

```yaml
- 写场景: {当前地点: {地标: 涿县, 场景: 张榜处}, 在场: {刘备: true, 张飞: true}}
- 确认事件: {事件ID: 榜前定交, 分支ID: 定交}
- 待定项: {操作: 新增, 字段路径: 角色.刘备.身份, 候选值: [义军首领, 中山靖王后裔], 事件ID: 榜前定交, 说明: 举事名号尚未正式定下}
- 确认事件: {事件ID: 榜前定交, 分支ID: 定交}
```

第一条写下当前地点与两人在场。`刘备` 与 `张飞` 均为 `出场自动`，写入之后视为在场，程序在同一次提交中自动写入 `初次登场·刘备` 与 `初次登场·张飞`，补上 `勇力: 骁勇`，而封卷写入的 `关系.卢植: 师生` 等原有记录保持不变。第二条确认 `榜前定交`：它在当日窗口内且门槛（`榜行涿县引刘备` 已确认）成立，写入 `刘备` 与 `张飞` 相互的 `关系: 相识`。第三条写入待定项，引用刚确认的 `榜前定交`。第四条再次确认 `榜前定交`，本局已有该事件记录，结果为未写入。

此后若直接以 `写场景` 把当前时间推进到 `中平001年04月03日`，窗口已过的 `村店遇关羽` 与 `庄上聚议` 按自动确认规则作为待登记事件在同一次提交中依次登记，并同时为新成为实际参与者的 `关羽` 自动完成首次登场初始化（写入 `初次登场·关羽`）。时间推进到 `中平001年04月04日` 时，`桃园结义` 也随之登记，刘备当即切期至 `刘备·结义起兵期`。时间不能倒退，把当前时间写回早于当前值的日期即报错；对仍视为在场的角色组写 `所在` 同样报错。

### 排斥

《三国演义》的 `董卓应诏起兵`（窗口 `中平006年06月05日`）门槛同时要求 `暗发密诏` 已确认且 `none(张飞怒欲杀卓:提刀杀卓)`。若在前序游玩中确认了 `张飞怒欲杀卓` 的 `提刀杀卓` 分支，排斥条件不再成立，后续进入 `中平006年` 时 `董卓应诏起兵` 不会成为候选而被排除；反过来，若某事件的门槛以 `none` 排斥另一个尚未发生的事件且该事件在后来的游玩中被确认，排斥检查会捕捉到门槛变为不成立的冲突并拒绝该次写入，在封卷时则直接报配置冲突。

### 抽样

《三国演义》在八个抽样年份（`中平000年` 至 `中平007年`）上的档案互斥枚举、运行抽样、两个开局方案（`榜前长叹`、`温明园盛宴`）与开局选项（`三张决意取天下` 三个分支）的封卷全部通过；全量检查下世界书错误数为 0（仅保留 10 条反映原作因果结构或孤立支线的非阻塞提示）。
