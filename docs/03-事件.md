# 事件

本局的改变以事件为单位。第一章已经说明，预设事件写明触发时间、门槛、核心参与者与各个分支，每个分支以变化表写入本局，确认策略决定事件由谁确认。本章依次说明这些规则：时间、门槛、分支、变化、确认与分类；再说明角色在事件中的个人视角，即角色位置；然后说明事件怎样由门槛连成事件树，事件树中的过程怎样命名为事件串，if 线怎样在事件树中写出，开局怎样选择开局之前的历史，作者怎样查看 if 线的后果；最后以示例“雾港”的几组事件串联上述内容。事件、条件、变化、角色位置、事件串与开局的字段表，见参考“事件”。

每个预设事件在 `历史/事件/{事件ID}/` 下有模型可见的 `事件.txt`，角色位置放在同目录的 `角色/` 下。事件文件的字段分三组。程序读取的结构字段有事件ID、触发时间、地点、确认策略、核心参与者、门槛、默认分支与分支，变化表写在各个分支之内。地点是地点ID的列表，只用于挑选与当前地点相关的事件，不是门槛。关联事件列出相关的事件ID，只供作者查阅。用于分类的字段有主类型、标签与事件结果，见“分类”。

供模型阅读的文本字段有事件标题、事件概要、影响范围、叙事条件、公开信息与隐秘信息。事件概要以一句话点明事件的内容。影响范围写事件波及的范围。叙事条件是条件文本，写门槛无法表达、须由叙事模型判断的要求。公开信息是众所周知的事实。隐秘信息属实，但只有知情者知道，事件为候选时不进入上下文。

事件ID与事件标题用世界之内中性的名称，按发生的行动、转折或结果命名，不以单一角色的视角命名。成为护卫、成为家庭教师这类身份的转变是分支的结果，写进变化表，不单独成为事件，也不写进事件ID。静态的正文不写本局的确认状态。

## 时间

触发时间按第二层的纪年书写，写到年或写到日，分最早与最晚，最晚不可省略。事件可以发生的时段称为窗口，从最早的起点到最晚的终点，最早与最晚当日（或当年）都在窗口之内。当前时间早于最早时，事件未到。当前时间在窗口之内时，事件可以成为候选。当前时间已过最晚而事件仍未确认时，自动确认的事件若门槛成立且选得出分支，即为待登记，其余事件排除。事件本身没有持续时间，持续的过程由事件串表达。

事件的门槛要求另一事件已经确认时，后者称为前者的前置事件。前置事件的触发时间最晚，不得晚于后续事件的触发时间最晚。门槛中的前置事件往往不止一条路径，例如几个事件任取其一即可（见“门槛”）。检查器逐条路径比较时间，所有路径上前置事件的最早都晚于后续事件的最晚时，后续事件无从发生，报前置超出窗口。所有路径上前置事件的最晚都晚于后续事件的最晚时，报前置倒流。这两项比较的都是起点，写到年的时间以该年第一天计。以雾港为例，夜间值守以拜师为前置，拜师的窗口是潮历071年01月10日这一日。夜间值守的最晚若写作潮历071年，起点071年01月01日早于拜师的最早，检查器报前置超出窗口，写作071年04月91日则不报。要把窗口放宽到年末，最晚应写到年末的那一日。检查器对事件门槛与各分支的门槛分别作这项检查。

较晚事件的变化不能使较早的事件成立，这种情形称为倒流。封卷按时间先后确认开局之前的事件，后面的事件读到前面事件写入后的状态。某个事件要靠时间更晚的事件写入的状态才成立时，封卷报时间顺序冲突。游玩中补登待登记事件时遇到倒流，该事件不写入，因窗口已过而排除。

## 门槛

门槛与档案的生效条件写法相同，称为条件。条件是单键映射，键为条件类型或组合词：all 要求全部成立，any 要求任一成立，none 要求全部不成立，组合词的列表不能为空。事件门槛写在事件的顶层，分支门槛写在分支之内，省略即恒成立。条件类型属于第一层，共十一种：

| 条件类型 | 参数 | 成立 |
|---|---|---|
| 角色启用 | 角色组ID | 本局启用了该角色组 |
| 角色版本 | 角色组ID、版本ID | 启用且选定了该版本 |
| 事件确认 | 事件ID，可附分支ID | 该事件已确认或待登记，附分支ID时所走的分支一致 |
| 事件串状态 | 事件串ID、状态 | 该事件串处于未开始、进行中或已结束（见“事件串”） |
| 当前时间 | 比较、值 | 比较为小于时，当前时间的终点不晚于值的起点，为大于等于时，当前时间的起点不早于值的起点 |
| 剧情标记 | 标记ID、比较、值 | 标记的本局值等于或不等于该值 |
| 角色状态 | 角色组ID、字段、属于 | 该字段的本局值在“属于”所列的值之中 |
| 同处 | 至少两个角色组ID | 所列角色组的所在相同 |
| 角色已出场 | 角色组ID | 该角色组已经出场（见第二章“初始化”） |
| 当前场景 | 地标、场景 | 当前地点的地标与场景都与之一致 |
| 在场实力人数 | 最低实力、最少人数，可附排除的角色组 | 视为在场者中，综合实力不低于最低实力的人数达到最少人数 |

求值的结果为成立、不成立、未知三者之一。封卷之前一律为未知。条件所读的状态缺失时为未知，例如当前地点尚未写入，或某个角色组的所在从未写过、也没有初始所在。组合时，all 有一项不成立即不成立，否则有一项未知即未知。any 有一项成立即成立，否则有一项未知即未知。none 是 any 的取反，未知取反仍为未知。门槛与生效条件为未知时，按不成立处理。同处的所列角色组有一个未启用即不成立，有一个所在未知即为未知。在场实力人数在人数不足、而有在场者没有综合实力的值时为未知。

角色状态让门槛读取本局记下的状态，使动态事件写出的结果也能接上预设事件。字段须是第二层声明了取值表的字段，例如以词表为值的关系，或者是所在。数值与自由文本的字段不能用，“属于”所列的值须在取值表中。字段为所在时，“属于”列地点ID，所在是其中某个地点或其下级地点即成立。所在的读取：视为在场且当前地点已写入的，取当前地点的地标；否则取本局记下的所在；再没有时取初始所在。其余字段从未写过时，取取值表的第一个值。角色状态只读由事件写入的取值，不读会自然涨落的数值。没有预设事件写出门槛所要求的值时，检查器只提示，因为动态事件也可能写出。依赖条目库或能力维度的条件，在卡没有声明所依赖的项时不可用，例如没有声明综合实力的卡不能用在场实力人数。

none 之下的事件确认表示排斥，不是前置，不参加前置的时间顺序检查。排斥是终身的：事件确认之后，后来的确认不得使它的门槛变为不成立。因此，事件甲的门槛须以 none 排斥乙才能成立时，甲一经确认，乙就不能再确认。甲的门槛为 any(none(乙), 丙) 而丙已确认时，甲的门槛不再依赖排斥乙，乙仍可确认。协议在每次提交之前以排斥检查把关，见第四章。只想表达“在它之前”时，用当前时间或事件串状态，不用 none。

条件中不处于否定之下的事件确认，称为正向引用，即不在 none 之内，或处于偶数层 none 之内。前置事件、事件串的起点与依赖，以及路由为候选选取它所依赖的已确认事件时，都只认正向引用。

封卷在幕后补出开局之前的历史，此时没有当前场景，也没有在场者，当前场景与在场实力人数两种条件求不出值，称为封卷不可求值的条件。其余九种在封卷时都能求值。哪些事件可以使用这两种条件，由确认策略决定，见“确认”。

## 分支

分支是事件可能的走向。每个分支有分支ID，在事件之内唯一。门槛可选，省略即恒成立。分支条件是条件文本，写这个分支在何种情形下发生，各分支之间须能区分。分支结果是文本，写这个分支的结果。变化表写这个分支写入本局的变化。

事件门槛决定事件能不能发生，分支门槛决定这个分支能不能走。游玩中，叙事模型只能在门槛成立的分支中选择，门槛未知的分支不能选。确认时，协议校验所选分支的门槛。事件成为候选时，只附上门槛成立的分支。事件门槛成立而没有一个分支的门槛成立，事件不成为候选。

程序替事件选择分支时，默认分支的门槛成立就选默认分支，否则按书写顺序，取第一个门槛成立的分支，都不成立则选不出分支。封卷补入开局之前的事件、协议补登待登记事件，都按这一规则选择，求值时以事件的触发时间最晚为当前时间。封卷时选不出分支的事件排除。

不带门槛的分支称为兜底分支。自动确认的事件只要有一个分支带门槛，就须有兜底分支，否则检查器报错：没有兜底分支，所有分支的门槛又都不成立时，事件即被排除，它应有的后果随之消失。检查器对每个分支分别检查前置的时间顺序。分支是否可达，见“事件树”。

## 变化

每条变化有路径、操作与值。路径有三种根：`世界.剧情标记.{标记ID}`、`世界.{第二层的世界字段}`、`角色.{角色组ID}.{字段}`。路径一律写到要改的那一格，操作由这一格的种类决定：

| 种类 | 路径 | 操作 |
|---|---|---|
| 集合，例如身份、知识与集合维度 | 写到集合，值是成员 | 新增、移除 |
| 映射，例如关系、职位与装备 | 写到键，例如 `关系.{角色组ID}` | 设定；新增，键不存在时才写入；移除，不带值 |
| 数值，以及值为数值的映射，例如好感度 | 写到键 | 增加、减少 |
| 等级 | 写到键，单值等级写到维度 | 提升、设定、移除，见第二章“能力” |
| 单值，例如所在、剧情标记与第二层的取值或文本字段 | 写到该字段 | 设定 |

集合不能以设定整体覆盖。增加与减少的值是正整数，单次不超过第二层声明的上限。本局没有值时从 0 起算，结果截断在值域之内。取值按第二层的声明校验，映射的键按声明解析，例如关系的键是角色组ID、职位的键是势力ID。装备的键是装备ID，这一条由第一层规定。所在属于场景状态，通常由写场景写入，也可以由事件的变化设定。

变化写到的角色组须保证已启用：某个分支的变化中，路径里与映射键里的角色组ID，须是核心参与者，或由事件门槛与这个分支的门槛共同保证已启用。检查器把这样的角色组视为未启用，凡涉及它的条件，即角色启用、角色版本、角色已出场、角色状态与同处，记为不成立，其余条件记为未知。求值的结果不是不成立，就报错。预设事件不写“玩家”：路径、映射键与引用角色组的值都不能是它（见第二章“玩家”）。能力移除记录与已初始化由协议维护，变化表不能写入。事件记录中已有某事件时，它的变化不再写入，同一事件的变化只写一次。

## 确认

确认策略规定事件在封卷与游玩中怎样被确认，有三种：

| 确认策略 | 封卷 | 游玩中 |
|---|---|---|
| 自动确认 | 按门槛补入开局之前的历史 | 可由叙事模型确认，窗口结束时仍未确认，而门槛成立且选得出分支，即为待登记，由协议登记 |
| 条件确认 | 按门槛补入开局之前的历史 | 须由叙事模型确认，窗口结束时仍未确认即排除 |
| 仅作候选 | 不参加封卷 | 须由叙事模型确认，窗口结束时仍未确认即排除 |

触发时间最晚早于开局时间、确认策略不是仅作候选的事件，称为开局前事件。封卷对开局前事件按门槛与默认分支补出历史，没有补入的记为排除。仅作候选的事件不参加封卷，只有它们可以使用封卷不可求值的条件。其余事件的门槛与各分支的门槛，包括 none 之内，都不得含这两种条件，否则开局时间晚于这些事件时，事件及其后续会被封卷悄悄排除，检查器为此报错。这类要求可以改为仅作候选，或者把对地点与在场的要求写进叙事条件，交给叙事模型判断。

核心参与者都已启用、当前时间在窗口之内、事件门槛成立且至少一个分支的门槛成立的事件，是候选。叙事模型以命令“确认事件”确认候选，给出事件ID、分支ID，可以另外列出参与的角色组。协议校验事件在有效本局上是候选、所选分支的门槛成立，然后写入事件记录：状态为确认，分支为所选分支，实际时间为当前时间，并按分支的变化写入本局。

核心参与者是缺了事件就不成立的角色组，其中有未启用者时，事件排除，因此只列真正不可缺少的角色组。事件记录中的参与者称为实际参与者：封卷补入与协议补登的事件，实际参与者就是核心参与者；叙事模型确认的事件，实际参与者是核心参与者与它另外列出的角色组的并集，这些角色组都须已启用。实际参与者决定角色是否已经出场，也决定事件此后作为谁的经历进入上下文。

待登记事件是确认策略为自动确认、窗口已过、门槛成立且选得出分支、本局尚无记录的事件。协议读取时，把它们按顺序写到有效本局上，因此它们在其它条件中视为已确认。下一次写入时，它们随之登记，与这次写入在同一次提交中。待登记事件的分支已经选定，叙事模型在此之前确认它时，所选分支须与之一致，否则报错。

事件排除之后不再能确认。排除有三种来源：有核心参与者未启用；窗口已过而事件未确认，也不是待登记；封卷时没有补入的开局前事件，以及开局时指定为“未发生”的事件（见“开局”）。封卷时的排除写下排除的记录。游玩中的排除在读取时计算，不写入本局。本局已有记录的事件，再确认时不重复写入它与它的变化，同一次提交中的待登记事件与出场自动初始化仍照常写入。没有记录而已排除的事件不是候选，确认即报错。当前时间在窗口之内、核心参与者都已启用，而事件门槛不成立，或没有一个分支的门槛成立时，事件不适用。不适用与排除不同，状态改变之后，它仍可能成为候选。事件在本局中的这些状态，即已确认、已排除、待登记、未到、候选与不适用，合称事件有效状态，每次读取时计算，判定的先后见第四章。

叙事模型也可以以命令“动态事件”登记世界书中没有预写的事件。动态事件没有门槛与分支，命令给出事件ID、摘要、实际参与者与变化。事件ID须符合第一层的规则，不与预设事件重复，不以“初次登场·”开头，摘要必填，变化可以为空，每条按变化的规则校验。动态事件的记录，分支为“完成”，实际时间为当前时间，并记下摘要。它还可以声明某个进行中的事件串到此结束（见“事件串”）。“玩家”的状态只能由动态事件写入。动态事件写出的状态，也能由角色状态这类条件读取，使预设事件接上游玩中的变化。

## 分类

主类型、标签与事件结果，取第二层在事件分类中声明的值（见第一章“设定”）。主类型单选。标签多选，至少一项。事件结果多选，至少一项，取所有分支实际写入的长期结果的并集。三者只用于检索与作者审阅，不参与门槛的求值，也不用来推出能力或结果。

事件分类为每项事件结果声明支撑它的本局变量字段，检查器据此在事件结果与变化表之间双向提示：变化表写了某个字段，事件结果中却没有它所支撑的一项；或者事件结果写了某一项，变化表中却没有支撑它的变化。只有出现在某项支撑清单中的字段才参加这项检查，例如在场不在任何清单中，写了它也不提示。没有声明支撑字段的事件结果不检查，由作者判断。支撑名“档案切期”表示本事件的某个分支被某份档案的生效条件引用。

事件分类声明了表示世界事件的主类型时，这类事件的门槛正向引用其它主类型的事件，检查器提示。世界事件到时间就发生，不应依赖个人的经历。没有声明时，不作这项检查。

## 角色位置

角色位置记录某个角色组在某个事件中的个人视角、知情、记忆与台词，位于 `历史/事件/{事件ID}/角色/{角色组ID}.txt`，模型可见。每个角色组在一个事件中至多有一份角色位置。它不复制事件的正文与变化表，状态的变化只写在变化表中。

角色位置的字段有：事件ID与角色组ID，分别等于目录名与文件名；角色概要，以一句话写此人在事件中的处境；角色定位，以短语列表写此人在事件中的身份；适用分支，列出它适用的分支ID，省略即适用于全部分支，组装时剥离；介入条件，是条件文本，写此人在何种情形下介入；角色知情，写此人知道的事；主观记忆，写此人记得的经过；以及按分支与事件触发语料。角色知情与主观记忆须与所适用的分支一致，不把成功的记忆写进失败的分支。角色知道、猜测、希望或记得某事，不等于它在世界中已经成立。

各分支的知情与记忆不同时，共用的部分写在外层，分支专属的写在“按分支”之下。按分支的键是分支ID，须在适用分支之内，值只含角色知情与主观记忆。进入上下文时，外层与本局所走分支的内容合并，分支ID在组装时剥离。

事件触发语料是供叙事模型取用的台词素材，每项写触发情境与候选台词，可选表达目的、情绪或语气与触发限制，都属于第四层。候选台词只收本角色自己说的话，别人对他说的话写进他的角色知情或主观记忆。原作中此人在本事件或同类情境下的台词，即原台词，逐字收录，排在作者撰写的台词之前。原作已有适用的台词时，不另写同义的台词。只有原作没有适用的台词时，才由作者撰写，并须符合当期档案的表达规律。原台词的出处写在作者资料中，正文不标注。台词不能单独确认事实，台词涉及的事实须已在事件的正文或已确认的结果中。

角色位置随事件进入上下文的方式，因事件的状态而不同。路由每轮从已确认的事件中，按是否在最近的消息中被提到、是否发生在当前地点、是否有在场者参与等理由选入若干，称为经历。经历中，在场者的角色位置适用于所走分支的，随之进入上下文，外层与该分支的内容合并。待登记事件已经选定分支，以与经历相同的完整形式单独列出，标为已经发生。事件为候选时，只取在场者的角色定位、介入条件与事件触发语料，且只取适用分支与门槛成立的分支有交集的角色位置。角色知情与主观记忆不进入上下文，以免叙事模型把尚未发生的事当作已经发生。经历与候选的选入理由、排序与预算，见第五章。

## 事件树

全部事件由门槛与分支门槛连成的整体，称为事件树：事件可以有几个分支，某个分支通向后面的事件；几条路径也可以在后面某个事件处汇合，即这个事件的门槛以 any 接受其中任一条。原作的走向、作者的改编与 if 线，在结构上没有区别，都是事件树中的路径。默认分支只表示封卷时没有其它因素决定时走哪一边。

事件树的结构只由门槛给出。后面的事件声明它需要什么，前面的事件不声明它之后接什么。某个事件之后能走向哪些事件，由作者工具，即供作者浏览与编辑世界书、不参与运行的工具，从门槛反查。检查器按乐观假设判断事件与分支是否可达：正向引用的事件或分支，本身可达、且在时间上可能早于引用它的事件时，视为可能成立；事件串状态在该事件串有可达的起点时，视为可能成立；其余条件都视为可能成立。按这样宽松的假设，事件的门槛仍不可能成立时，检查器提示事件不可达。分支的门槛连同事件门槛仍不可能成立时，提示分支不可达。事件以正向引用互为前置而成环，环中又没有一个事件可达时，这些事件都无从发生，检查器报错。

## 事件串

事件串是事件树中被命名的一段，表达有开头、有结局的过程，例如救援、师从。每个事件串对应文件 `历史/事件串/{事件串ID}.yaml`，是工具数据，写概述、事件与结局三项：概述以一句话写这个过程，事件串进行中时进入上下文；事件列出本串的事件ID，列表的顺序不表示先后；结局列出本串的终点，每项为一个事件ID，可附分支ID，该事件或该分支确认，即走到结局。

事件串不规定结构。串内的先后与分岔，仍然只由门槛给出。事件串只负责命名过程与声明结局，并由此推出过程是否在进行。每个事件至多属于一个事件串，不属于任何事件串的称为孤立事件，不必为它建串。事件串的边界由作者划定，不按门槛自动推算，跨串的依赖照样写在门槛中。起点不写：事件门槛中没有正向引用本串其它事件的事件，就是起点，每个事件串至少有一个起点。检查器提示不可达的结局，以及与本串其它事件既不依赖、也不被依赖的事件，这里的依赖指事件门槛或分支门槛的正向引用。

事件串的状态由已确认的事件推出，不写入本局，分三种：有结局确认，或有动态事件声明本串结束，为已结束；否则有起点确认，为进行中；其余为未开始。过程在预设的结局之外中止，例如中途辞职，由叙事模型登记动态事件，声明本串结束。门槛以条件“事件串状态”读取它。进行中的事件串作为世界的当前状态进入上下文，附概述与本串已确认的事件，不受经历预算的限制，本串的候选也优先选入。封卷时起点已确认、结局尚未确认的事件串，开局时就是进行中。

## if线

开局时不作任何选择，各事件按默认的规则补出，所得的路径称为默认路径。if 线是与默认路径不同的路径：开局时或游玩中，某件事没有发生，走了另一个分支，或某个角色组没有启用，后面的世界随之调整。if 线不是另一类事件，也不另建事件树，只是事件树中的另一条路径。实现 if 线是世界树的主要目的。

一条 if 线能否成立，取决于事件的写法，世界树为此定下四条原则。其一，门槛只写真正的因果，即“没有它，这件事就不会发生”，不写“原作中它排在前面”。按原作的先后把事件串成一条链，任何一处偏离都会使下游整串消失。其二，核心参与者只列缺了事件就不成立的角色组，世界事件通常没有核心参与者。其三，世界事件与个人后果分开写：世界事件到时间就发生，只写世界层面的变化；它对各人的后果各写成一个事件，称为个人后果，门槛是世界事件已确认，分支门槛读取当时的状态，例如所在、关系与能力。其四，关键的事件写出多个分支，后面的事件按实际所走的分支设门槛。

这四条原则依靠前文的几项机制落实。角色组的初始所在与本局的所在，使个人后果能按人在何处分流。场景状态由叙事模型以写场景直接写入，使所在在游玩中随剧情改变。条件“同处”与“角色状态”读取所在与其它状态。自动确认的事件以兜底分支保证后果总有着落。

## 开局

多数 if 线的分岔发生在开局之前。开局时，开局之前历史中的关键分支，由作者预设，或由玩家选择。

开局时可以选择哪些事件，在 `历史/开局选项.yaml` 中声明，称为开局选项。它是工具数据，每项写事件ID、问题与选项：选项的键是该事件的分支ID或“未发生”，值是展示给玩家的文字。仅作候选的事件不参加封卷，不能作为开局选项。只有开局前事件可以选择。各项按触发时间的先后排列，前面的选择使后面某个事件的门槛不成立时，这一项不出现，分支门槛不成立的分支也不能选，开局前端每选一项即以协议预演封卷。没有选择的事件，按默认的规则补出。开局选项的“自由组合”缺省为否，此时玩家只在默认的历史与开局方案之间选择，开局选项只供开局方案引用。为是时，玩家还可以在方案的基础上逐项修改。

开局方案是作者预设的开局组合，每个方案对应文件 `历史/开局方案/{方案ID}.yaml`，是工具数据，写概述，可写开局时间、角色组与历史选择。概述随方案展示给玩家。历史选择只能使用开局选项中声明的事件与选项。

开局时为开局前事件指定的分支或“未发生”，称为历史选择。封卷时，指定了分支的事件只能走该分支，它的事件门槛或分支门槛不成立时，封卷报历史选择错误，不退回默认分支。指定“未发生”的事件记为排除。其余事件按默认的规则补出。历史选择与所用的方案写入开局设定。检查器对每个开局方案各封卷一次，须能成功。抽样另对开局选项的每个分支各封卷一次，见第四章。

## 视图

if 线的后果由作者工具查看，这一工具尚未实现，以下是规定的做法。“如果”视图用于比较 if 线与默认路径：作者选定开局方案，或临时排除某个事件、改走某个分支、关闭某个角色组，工具以全部事件的窗口都已结束的时间为开局时间，即时间轴的末尾，封卷两次，一次用作者的选择，一次用默认的分支。对比列出四项：没发生的事件，即默认路径中发生、这条路径中没有发生的事件，这是 if 线的缺口，由作者判断是否补写；新发生的事件，即默认路径中没有发生、这条路径中发生的事件；分支不同的事件；停住的事件串，即已经开始、却没有任何结局可达的事件串。

影响面是“如果”视图附带的报告：对每个事件，假设只有它没有发生，统计下游随之不能发生的事件。推算时只看事件门槛中的事件确认：所引用的事件已缺失，正向引用即不成立，其余条件都不作限制。门槛因此必然不成立的事件计入影响面，并作为缺失的事件继续向下推算。影响面大的事件，提示后续的门槛可能写得过死。

## 实例

下面以示例“雾港”的事件说明上述规定。雾港有 13 个事件：主类型为世界的 1 个，即大雾之夜，关系 2 个，个人 10 个；确认策略为自动确认的 3 个，仅作候选的 2 个，其余 8 个为条件确认。事件串有两个，“学徒修习”含 6 个事件，“雾夜余波”含 2 个，其余 5 个事件是孤立事件。开局选项声明了两个事件，开局方案有两个。

### 雾夜余波

大雾之夜是世界事件，没有门槛，也没有核心参与者，窗口是潮历071年04月20日这一日，写入灯塔熄灭、雾季已至与起雾（见第一章“大雾之夜”）。以它为门槛的个人后果有三个：自动确认的“学徒守灯”“白棠在码头”，窗口同在这一日；条件确认的“港务署问责”，窗口是此后的十日，另要求灯塔不处于运转的状态。三者的主类型都是个人，门槛正向引用世界事件，检查器不提示。反过来，世界事件的门槛若正向引用它们，检查器提示。学徒守灯的分支如下，节选，略去分支条件与分支结果：

```yaml
事件ID: 学徒守灯
确认策略: 自动确认
核心参与者: [灯塔学徒]
门槛: {事件确认: {事件ID: 大雾之夜}}
默认分支: 重燃灯塔
分支:
  - 分支ID: 重燃灯塔
    门槛: {同处: {角色组ID: [灯塔学徒, 秦守]}}
    变化:
      - {路径: 世界.剧情标记.灯塔状态, 操作: 设定, 值: 重燃}
      - {路径: 角色.灯塔学徒.天赋, 操作: 新增, 值: 雾中视·辨影}
      - {路径: 角色.灯塔学徒.好感度.秦守, 操作: 增加, 值: 10}
      - {路径: 角色.秦守.好感度.灯塔学徒, 操作: 增加, 值: 5}
      - {路径: 角色.灯塔学徒.知识, 操作: 新增, 值: 秦守在雾夜守住了灯}
  - 分支ID: 独自守灯
    门槛: {角色状态: {角色组ID: 灯塔学徒, 字段: 所在, 属于: [灯塔]}}
    变化:
      - {路径: 世界.剧情标记.灯塔状态, 操作: 设定, 值: 重燃}
      - {路径: 角色.灯塔学徒.天赋, 操作: 新增, 值: 雾中视·辨影}
      - {路径: 角色.灯塔学徒.身体状态.健康, 操作: 设定, 值: 受伤}
  - 分支ID: 在镇上听闻
    变化:
      - {路径: 角色.灯塔学徒.知识, 操作: 新增, 值: 大雾那夜灯塔熄了半宿}
```

三个分支按学徒当时的处境分流：与秦守同处，走默认分支重燃灯塔；独自在灯塔，走独自守灯；在别处，走不带门槛的兜底分支在镇上听闻。学徒守灯是自动确认的事件，有带门槛的分支，兜底分支因此必不可少。在副本上删去它，检查器报两条错误：一条是缺少兜底分支，另一条是灯塔学徒的角色位置中，按分支的键“在镇上听闻”不在适用分支之内。重燃灯塔写入秦守的好感度，秦守不是核心参与者，但这个分支的门槛“同处”保证了他已启用。

以潮历072年开局时，三个个人后果都在封卷中决出。学徒的所在是“拜师”的“拜师”分支设定的灯塔，秦守从未写过所在，取初始所在灯塔，二者同处，学徒守灯走重燃灯塔，灯塔状态改为重燃。白棠的初始所在是上城，不在码头区，白棠在码头走兜底分支“在家等候”。港务署问责的核心参与者周岚默认不启用，事件排除。开局时启用周岚，它在窗口的最晚，即04月30日补入，此时灯塔状态是重燃而不是运转，秦守已启用，走默认分支“问责秦守”。

游玩中，同样的规则逐步生效。以潮历071年04月01日开局，封卷补入“拜师”“夜间值守”与“接手商会账目”。当前时间写到04月20日时，大雾之夜是候选，可走的分支为“发生”。学徒守灯与白棠在码头的门槛要求大雾之夜已确认，此时不成立，二者不适用。叙事模型确认大雾之夜之后，学徒守灯成为候选，学徒与秦守都在灯塔，三个分支的门槛都成立，一并附上。白棠在码头也成为候选，只有在家等候可走。叙事模型若不确认，当前时间写到04月21日时，三个事件的窗口都已结束，成为待登记，由这次写场景按顺序登记，大雾之夜在前，实际时间都记为04月20日，所选分支与开局时的封卷相同。若在此之前先把秦守的所在写为码头区，二者不再同处，学徒守灯登记为独自守灯，灯塔同样重燃，学徒受伤。

学徒守灯的两份角色位置，体现按分支与适用分支的两种写法。灯塔学徒的角色位置适用于全部分支，三个分支各在“按分支”下写有主观记忆。秦守的角色位置只适用于重燃灯塔，因为只有这个分支中他与学徒一起守灯。以潮历072年开局、当前地点写为灯塔之后，学徒与秦守都在场时，这段经历带出两人的角色位置，各附重燃灯塔的那条主观记忆。只有学徒在场时，只带出学徒的一份。

雾夜余波以大雾之夜为起点，以学徒守灯为结局。白棠在码头与港务署问责同样以大雾之夜为门槛，却不在这个事件串中，是孤立事件：事件串的边界由作者划定。

### 学徒修习

事件串“学徒修习”的文件如下：

```yaml
概述: 学徒拜秦守为师，在灯塔学艺。
事件: [拜师, 夜间值守, 学修船, 出师考核, 补考, 正式守灯]
结局:
  - {事件ID: 正式守灯}
  - {事件ID: 拜师, 分支ID: 未拜师}
```

拜师没有门槛，是唯一的起点。其余五个事件都正向引用本串的事件。夜间值守与学修船要求拜师以“拜师”分支确认，出师考核要求夜间值守已确认，补考要求出师考核以“未通过”确认，正式守灯的门槛以 any 接受出师考核或补考以“通过”确认，两条路径在这里汇合。结局有两个：正式守灯确认，学艺有成；拜师以“未拜师”确认，这段师从在起点就已结束。各个前置事件的触发时间最晚都不晚于后续事件，例如补考最晚为073年02月91日，正式守灯最晚为073年03月91日，检查器不报时间顺序的错误。出师考核与补考的“通过”分支另要求学徒对秦守的关系为师徒，这个关系可以由拜师写入，也可以由游玩中的动态事件写入，角色状态只读本局记下的值。

其余选择均取默认，学徒修习在潮历070年与071年开局时未开始，拜师尚未发生。072年与073年开局时进行中，拜师已经补入，正式守灯还没有。074年开局时，正式守灯已经补入，事件串已结束。开局方案“补考之年”以潮历073年开局，指定出师考核“未通过”：封卷后补考在窗口之内，是候选，可走“通过”与“再次未通过”两个分支，学徒修习进行中，林澜的当前档案是学徒期。以潮历072年开局而指定出师考核“未通过”，封卷报历史选择错误，因为出师考核的窗口在072年02月01日，不早于开局时间，不是开局前事件。

学修船与秦守讲旧事都是仅作候选，门槛中都有封卷不可求值的条件“当前场景”，前者要求在灯塔的工具间，后者要求在灯塔的值守室，另要求学徒修习进行中、秦守已出场。秦守讲旧事不是学徒修习的成员，它以事件串状态读取这段师从是否在进行。以潮历072年01月20日开局、当前地点尚未写入时，当前场景为未知，两个事件都不适用。当前地点写为灯塔的值守室之后，秦守讲旧事成为候选，只附分支“讲述”。同时写秦守在场，秦守出场自动初始化，名望为匠人，分支“讲述并示范”的门槛“在场实力人数”随之成立，两个分支一并附上。学修船的窗口最晚为072年01月91日，以072年03月02日开局时已经排除。仅作候选的事件不参加封卷，以074年开局时它没有记录，学徒的修船因此没有值（见第二章“初始化”）。

### 码头少年

雾港的开局选项声明了拜师与出师考核两项，“自由组合”为否，玩家只在默认的历史与两个开局方案之间选择。开局方案“码头少年”如下：

```yaml
概述: 少年没有拜师，在码头长大。
开局时间: 潮历072年
历史选择:
  拜师: 未拜师
```

封卷时，拜师只能走“未拜师”，学徒的身份记为码头帮工，所在没有改写，仍取初始所在码头区。夜间值守的门槛要求拜师以“拜师”分支确认，不成立，记为排除。大雾之夜那夜学徒不在灯塔，学徒守灯走兜底分支在镇上听闻，灯塔状态停在熄灭。学徒修习以“未拜师”走到结局，已结束。林澜的当前档案停在少年期。拜师选了“未拜师”之后，出师考核的门槛再也不能成立，开局前端不再出现这一项。以潮历073年开局、在这个方案上再指定出师考核“通过”，封卷报历史选择错误：所选的分支未能写入。

以潮历074年为开局时间，即时间轴的末尾，分别以码头少年与默认的历史封卷，对比如下：没发生的事件是夜间值守、出师考核与正式守灯；没有新发生的事件；分支不同的事件是拜师，由“拜师”变为“未拜师”，以及学徒守灯，由“重燃灯塔”变为“在镇上听闻”；没有停住的事件串，学徒修习在两条路径上都走到了结局。

拜师与否还影响别的角色组。选白棠的版本为“白棠·船长”时，默认的历史中，潮汐号首航在072年04月92日补入，白棠的当前档案是航海期。在码头少年的方案上，灯塔状态停在熄灭，潮汐号首航的门槛“灯塔状态不等于熄灭”不成立，事件排除，白棠停在少女期。两者之间没有门槛直接相连，联系它们的是剧情标记灯塔状态。

雾港各事件的影响面中，拜师最大，为 5 个：夜间值守、学修船、出师考核、补考与正式守灯。其次是夜间值守，为出师考核、补考与正式守灯 3 个；大雾之夜，为学徒守灯、白棠在码头与港务署问责 3 个；出师考核，为补考与正式守灯 2 个；其余事件都为 0。正式守灯以 any 接受两条路径，只缺补考时，它仍可经出师考核成立，补考的影响面因此为 0。缺出师考核时，两条路径都断，它才计入。潮汐号首航经剧情标记受拜师影响，秦守讲旧事经事件串状态受拜师影响，二者门槛中都没有对拜师的事件确认，不计入影响面。拜师下游的五个事件都以师从为因，影响面大是这段师从的实际结构，不是门槛写得过死。
