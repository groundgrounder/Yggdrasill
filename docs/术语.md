# 术语

本文收录世界树文档所用的术语，按领域分为九组，组内先列基础概念，再列由其派生的概念。每条给出定义，括注讲述它的章节或写作规范。与酒馆原义或相近术语易混的，另附辨析。字段名与枚举值并入所属对象的条目。各卡在第二层自行声明的字段不收，只在相关条目中以示例《三国演义》或通用机制说明。文末列出统一用语。

## 运行

**SillyTavern**：开源的大语言模型角色扮演前端，简称酒馆，是世界树卡的目标运行环境。酒馆以角色卡承载角色描述、开场白与世界书，以正则与脚本扩展其行为。世界树卡经适配层接入酒馆（见第六章）。

**角色卡**：导入酒馆的 PNG 或 JSON 文件，载有角色描述与开场白，可内嵌世界书、正则与脚本。以世界树为基底制作的角色卡由适配层打包生成，含三部分：作者书写的世界书；世界树提供的程序，即内核、适配层脚本与局部正则；卡名、头像、开场白与默认开局等卡面内容。三部分的输入、输出与版本关系由适配层规定（见第六章）。

**卡**：以世界树为基底制作的角色卡的简称。“本卡”指所讨论的卡，与“所有卡”相对，用以区分卡自行声明的内容与世界树统一规定的内容（见第一章）。

**世界树**：世界书的规范及其工具链，包括规范、内核、检查器、命令行工具 `ygg`、协议文本模板、作者工具与 skill。规范即 `docs/` 中的第一至第六章、参考、写作规范、作者指南与术语，规定世界书的组织、字段的写法、运行机制与酒馆适配；README 是入口索引。工具链依据规范读取、检查与运行世界书。

辨析：“世界树”指整个规范与工具链项目，不特指图形界面 `ygg view`；skill 名称中的“世界树·”只是前缀。事件树是世界书中全部事件连成的结构，不是世界树的组成部分。

**项目**：卡的工作目录，根下有世界书与作者资料，可选 `来源资料/` 与 `yggdrasill.yaml`。参与运行的是世界书与运行参数。角色卡所需的其余部分，例如卡面内容，由适配层规定（见第一、六章）。

**世界书**：作者书写的源文件目录，即项目中的 `世界书/`，载有卡的世界内容与声明，不含程序。根下分固定根、条目库与文本容器三类目录（见第一章）。

辨析：酒馆的世界书是一组按关键词触发、插入提示词的条目。世界树沿用其名指称源文件目录。模型每轮读到的内容由路由决定，不由关键词触发。

**作者**：制作卡的人。作者声明第二、五层，撰写第三层内容与受第四、五层约束的文本。第一、四层由世界树规定，作者不能更改（见第一章）。

**叙事模型**：扮演世界与角色、推进剧情的语言模型。叙事模型不直接读取世界书，只读取每轮由路由组装的上下文，并且不能直接改动本局。默认记账时它只写正文，由记账结果经适配层生成命令；关闭记账时它在正文末尾写命令（见第四至六章）。

**玩家**：与叙事模型对话、参与游戏的人，参与方式见“玩家模式”。“玩家”同时是保留字，不得用作任何 ID（见第一章）。

**内核**：世界树的程序库（`core/`）。内核读取声明与世界书，求值条件，校验变化，并包含协议与路由。检查器建立在内核之上，与协议共用同一套校验（见第四章）。

**检查器**：检查世界书的程序，以 `ygg check` 运行。检查器先做静态检查，没有错误时再做抽样。结果分错误与提示两级，错误须修正，提示供作者判断（见第四章）。

**`ygg`**：世界树的命令行工具，有 `check`、`trace`、`if`、`preview`、`context`、`tree`、`status`、`init`、`view`、`pack`、`format` 十一个子命令。`check` 运行检查器，`trace` 查询引用、出处与异常，`if` 比较默认路径与 if 路径，`preview` 只读封卷后输出首次登场将写入的档案、能力与装备，`context` 只读封卷并推演一局的路由上下文与预算占用，`tree` 导出 Markdown 事件树并统计候选台词，`status` 只读诊断项目所处第 0–5 层，`init` 生成新项目的分层骨架，`view` 启动本地作者视图，`pack` 打包酒馆角色卡，`format` 统一 YAML 排版与键顺序（见第一章、第三章与写作规范）。

**作者工具**：供作者检查、分析、排版与审阅世界书的工具，不参与运行。包括命令行工具 `ygg` 的十一个子命令、十个作者 skill（见[`skills/README.md`](../skills/README.md)）以及本地图形作者视图 `ygg view`（见[作者视图](../view/README.md)）。其中 `tree` 只做静态台词统计，原台词与来源原文的逐字一致由作者人工核对（见第一、三章与写作规范）。

**作者视图**：`ygg view` 启动的本地作者可视化工具，只监听 `127.0.0.1`，复用 `core/`、`checker/` 与 `if` 数据，提供事件树浏览、分析与事件/角色位置的图形化编辑；预览使用静态检查，保存后执行全量检查，批注与布局写入审阅状态，与事件正文分离。功能与编辑边界见[作者视图](../view/README.md)。

**审阅状态**：作者视图在 `<存储>/审阅状态.json` 保存的批注与布局，schema 为 `{notes:{key:{text,status}}, layout:{key:{x,y}}}`，与事件正文分离；写入使用 revision 冲突检查，令牌预览与备份见[作者视图](../view/README.md)。

**skill**：供编程代理遵循的写卡流程说明，按建卡分层与改动级别规定负责的范围与须跑的检查。现有十个作者 skill：[世界树·统筹](../skills/ygg-guide/SKILL.md)（只读诊断与流程编排）、[世界树·通读](../skills/ygg-read/SKILL.md)（第 0 层，两遍读法与坐标账本）、[世界树·迁移](../skills/ygg-migrate/SKILL.md)（第 0 层，既有酒馆角色卡/世界书拆包与同构总账映射）、[世界树·地基](../skills/ygg-foundation/SKILL.md)（第 1 层）、[世界树·条目](../skills/ygg-entries/SKILL.md)（第 2 层）、[世界树·骨架](../skills/ygg-skeleton/SKILL.md)（第 3 层）、[世界树·档案](../skills/ygg-profile/SKILL.md)（第 4a 层）、[世界树·填景](../skills/ygg-scenes/SKILL.md)（第 4b 层）、[世界树·打包](../skills/ygg-pack/SKILL.md)（第 5 层）与[世界树·修订](../skills/ygg-edit/SKILL.md)（建成后局部改动）；职责表见[`skills/README.md`](../skills/README.md)，工具调用与检查口径见[`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)，越界与条件文本五槽速查见[`skills/shared/写作红线.md`](../skills/shared/写作红线.md)（见[写作规范](写作规范.md)）。

**适配层**：把世界树卡接入具体运行环境的部分，负责打包、生成前路由与注入、叙事与记账调用的协作、命令转换与执行、楼层记录、重放、设置和升级门禁。包裹标签与命令的承载方式可由适配层替换，命令语义不能改变（见第四至六章）。

**记账**：把叙事正文转换为本局变化的适配步骤。记账开启时，适配层另发一次不写正文的模型调用，取得限定为 JSON 的正文变化，再由程序转换为命令。记账可选择与叙事同一模型、另设模型或关闭；关闭后回到正文 `<命令>` 的旧方式（见第六章）。

**记账调用**：记账开启时的一次独立生成请求及其校验、重试与转换过程。它不是叙事角色，不读酒馆对话历史，不调用路由，也不生成聊天正文。另设模型只改变这次请求所用的连接与模型（见第六章）。

**开局前端**：开局时供玩家选择世界线（多世界线卡）、预设或自由开局、开局时间与地点、玩家定制、四模式开场白，以及高级角色组与历史选择的界面，属于适配层。玩家每选一项，前端以协议预演封卷；最终提交重新封卷，预设模式原子应用开场命令，动态开场白模式落初始地点并经叙事/记账写入第 0 楼。适配层已实现并验证六类选择、预演、原子封卷与失败不写半份本局；跨记录格式大版本的旧存档迁移暂不在当前版本范围内，实现状态表见第六章（见第三章与第六章）。

**打包**：游玩之前把世界书、世界树的程序与卡面合成可运行角色卡的步骤，由适配层完成。打包输出卡文件与构建清单；运行世界书按规范化路径进入内存文件系统，记账开启与关闭的协议文本各生成一份（见第一、六章）。

**构建清单**：随角色卡携带的版本标识，至少记录卡ID、卡版本、程序版本、记录格式、程序指纹、世界书哈希与兼容程序列表，用于判断聊天中的楼层记录能否由当前卡继续使用（见第六章）。

**程序指纹**：对一次构建实际打入卡内的程序与模板计算的固定哈希，用来识别程序内容。卡版本号不能代替程序指纹（见第六章）。

**世界书哈希**：对打包进入卡内的规范化世界书文件路径与字节计算的固定哈希。世界书变化后，旧聊天不静默继承（见第六章）。

**模板**：世界树仓库 `templates/` 下的三份协议文本模板：变量更新规则、角色通用约束、扮演准则。模板属于第一层，所有卡相同，随程序打包并计入程序指纹（见第一章）。

**占位符**：模板中待填入的位置，写作 `{{名字}}`，只有五种：纪年格式、单次增减上限、可写字段由声明生成，地点列表由地点库的条目生成，本卡扮演准则取扮演准则的原文。模板中出现其它占位符时报错（见第一章）。

**协议文本**：由模板生成、占位符按声明与世界书的相应内容填入、发给叙事模型的规则，依次为变量更新规则、角色通用约束与扮演准则，是上下文的第一部分。记账开启与关闭各有一份，每轮按当前设置选用。由第一层推出的内容不作为源文件维护。本卡扮演准则的原文经占位符填入扮演准则模板的末尾（见第一、五、六章）。

**示例**：世界树附带的公开示例世界书《三国演义》（`examples/三国演义/`），用于说明规范与工具用法；内部自动化测试夹具位于 `test/fixtures/雾港/`。

## 层

**层**：世界树按改动所受的规则与须做的检查，把卡中的字段分为五层：架构、背景设定、内容、通用文本规范、本卡文本规范。层属于字段而非文件，同一文件可以同时含有几层的字段。各文件的字段表以“层”一栏标出每个字段所属的层，整张表属于同一层时在表前写明。第一、四层的规则由世界树规定，所有卡相同。第二、五层由各卡声明。第三层是卡的具体内容（见第一章）。

**第一层**（架构）：世界树运行所依据的机制：卡由哪些对象组成，对象如何求值，状态如何写入。第一层由规范规定、内核实现，卡不能覆盖。改动第一层须修订规范，并跑内核与一致性测试（见第一章）。

**第二层**（背景设定）：卡的种类与取值，例如纪年的写法、等级序列、能力维度、事件分类、条目库及其字段、本局变量的字段与值域、剧情标记。第二层在 `设定/` 中声明。判别第二、三层的办法是：删去一项，卡失去的是一种可能，还是一个具体之物。前者属于第二层。内容的增加不改变层，为写某个新技能而增设的门类仍是第二层的改动。改动第二层后须做全量检查，不再合法的第三层内容须显式迁移，不得静默丢弃（见第一章）。

**第三层**（内容）：程序读取的具体实例：角色组与档案的结构字段，事件的时间、门槛、分支与变化，条目的 ID、取值与引用。第三层只能引用第二层已声明的种类与取值。改动后须做引用解析、结构检查与抽样（见第一章）。

**第四层**（通用文本规范）：所有卡共用的写作规则，约束一切文本字段：不用实现术语与作者维护用语，不在文本中断言本局状态，字段按规定的形态书写，不用破折号与一批陈旧写法。受第四层约束的文本字段，在字段表中标为第四层。改动这些字段后做格式与措辞检查，条件文本另须核对适用范围不变（见第一章与写作规范）。

**第五层**（本卡文本规范）：卡在第四层之上的补充，只能收紧或补充，不能放宽。能机器检查的部分声明于 `设定/文本规范.yaml`，其余写进扮演准则（见第一章）。

**机器字段**：只供程序读取、在组装时剥离的字段：门槛、确认策略、默认分支、变化、前置档案、生效条件、默认、适用分支、适用版本、关联事件（见第三、五章）。

辨析：程序读取的字段不都是机器字段。条目的类型、门类、技能等级等第三层字段随条目正文进入上下文。事件的主类型、标签、地点等虽不剥离，但路由组装事件时只取规定的字段，它们不在其列。

**文本字段**：供模型阅读的字段，即字段表中标为第四层、或在声明中以“形态”书写的字段。程序不解析文本字段的含义，只按形态与措辞检查（见第一、二章）。

**条件文本**：决定事件或台词在何种情形下成立的文本字段：叙事条件、分支条件、介入条件、触发情境、触发限制。条件文本由叙事模型判断，按文本规范书写。改动时除措辞检查外，还须核对适用范围不变（见第一章）。

辨析：门槛是由协议求值的条件，条件文本是由模型判断的文本。封卷求不出值的要求，例如所在的场景、在场的人，写进条件文本。

**编辑分级**：按改动所在的层对编辑的分级：设定级对应第二层，结构级对应第三层，文本级对应第四、五层。级别按字段判断，决定改动之前与之后须跑哪些检查（见写作规范）。

## 声明

**声明**：写在 `设定/` 中的规则，包括第二层的全部种类与取值，以及第五层中能机器检查的部分。内核与检查器只读声明，不写死任何卡的种类与取值（见第一章）。

**单一来源**：第二层的每项种类与取值只在 `设定/` 中声明一次。模型需要的清单，例如等级的高低、关系阶段的取值、可写的字段，在打包时由声明生成，正文、说明文件与协议文本不手写复述，作者资料不抄写。改动一处声明，规则文本、检查器的校验范围与协议的截断、比较依据随之改变（见第一章）。

**默认声明**：世界树仓库 `defaults/设定/` 下附带的第二层声明，供新卡复制进自己的 `设定/` 后修改，有事件分类的默认清单，以及推荐的本局变量字段关系、好感度、身份、职位、知识。复制以后即为本卡的声明（见第一章）。

**纪年**：时间的写法，声明于 `设定/纪年.yaml`：前缀、年位数、月数、每月天数，四项必写。时间写作 `{前缀}{年}年` 或 `{前缀}{年}年{MM}月{DD}日`，年补足位数，月、日两位。事件的时间写到年或写到日，不写到月。时间都表示区间：写到日的是当日，写到年的是整年，即首月首日至末月末日。区间含起点而不含终点，日的终点是次日的起点，年的终点是次年首日的起点。前者的终点不晚于后者的起点，称前者早于后者。前者的起点不早于后者的终点，称前者已过后者（见第一、三、四章）。

**等级序列**：从低到高排列的一列等级，声明于 `设定/等级.yaml`，每项以 `等级.{名字}` 引用。卡可以声明多个等级序列，例如某卡同时声明武艺与官阶两个序列（《三国演义》示例中声明了 `勇力`）。序列中的每个值称等级，等级的高低按其在序列中的位置比较（见第一章）。

**事件分类**：事件的主类型、标签与事件结果的取值，声明于 `设定/事件分类.yaml`。主类型描述事件主要改变的对象，单选。标签描述事件的形式或主题，多选。事件结果描述分支实际写入的长期结果，多选，取所有分支的并集。三者只用于检索与作者审阅，不参与门槛的求值。每项事件结果声明支撑它的本局变量字段，检查器据此在事件结果与变化表之间双向提示。“档案切期”是保留的支撑名，表示事件的某个分支被档案的生效条件引用。事件分类还声明哪个主类型表示世界事件（见第一、三章）。

**剧情标记**：世界范围的命名状态，声明于 `设定/剧情标记.yaml`，键是标记ID，值是全部取值。第一个取值是开局值，封卷时写入。门槛以等于或不等于比较标记，变化表以设定写入（见第一章）。

**角色分类**：角色包与分类两张平铺的清单，声明于 `设定/角色分类.yaml`。每个角色组属于一个角色包与一个分类，只用于开局选择时的列表，不作整包开关（见第一章）。

**文本规范声明**：`设定/文本规范.yaml`，即第五层中能机器检查的部分：追加的禁用词、ID 命名规则（只用中文、前缀字段）、档案追加的可选字段、收紧的长度预算（见第一章）。

**长度预算**：对世界书正文字数的提示阈值，按去掉空白后的字数计：说明文件 300，基本信息 500，角色印象 600，事件 800。超出只提示，不报错，也不截断。第五层只能收紧（见第一章）。

**字段声明**：条目库字段与本局变量字段的统一写法。每个字段恰好写一种性质：形态，即文本字段的书写形式；取值，即值须在某个值域内；引用，即值须是能解析的条目 ID、角色组ID 或事件ID；子字段，即由固定子键组成的结构；映射，即键任意、结构相同的字典，键与值各按同样的写法声明；数值，即有上下限的整数；集合，即无序、不重复的成员，只能逐项新增或移除。数值与集合只用于本局变量。取值与引用可加“列表”，表示值是一组。条目库字段可加“适用类型”，限定只有哪些类型的条目可以有该字段。写法同时决定字段的层：写取值、引用、数值的属于第三层，写形态的是文本字段，子字段、映射与集合按其成员定层（见第一、四章）。

**形态**：文本字段的书写形式，共五种：文本（非空的一句话）、文本列表（每项一句话）、短语列表（每项一个短语，不以 `。！？；` 等句末标点结尾）、情境列表（每项是单键映射，键写情境，值写表现）、禁区列表（每项以“不”开头）（见第二章）。

**值域**：取值字段的合法范围，可以是行内列表、某个等级序列、某个能力维度的键、纪年或某张词表（见第一章）。

**词表**：在 `设定/本局变量.yaml` 的 `词表` 下命名声明的取值表，以 `词表.{名字}` 引用，第一个值是默认值。`词表.装备状态` 必须声明，因为第一层骨架中的装备状态引用它（见第四章）。

辨析：取值表泛指任何有限的值域。词表专指命名声明的那一种。

## 目录

**固定根**：世界书根下名称与结构由第一层规定的三个目录：角色、历史、设定。角色根下每个角色组一个目录。历史根下有事件、事件串、可选的世界线、开局选项与开局方案。设定根只放声明，都是 `.yaml`。固定根不放说明文件（见第一章）。

**条目库**：同一种公共条目的集合，例如技能、装备、地点、势力。卡有哪些条目库，各库的分法、分级与字段，都声明于 `设定/条目库.yaml`。所有条目库平铺在世界书根下。每个库自成 ID 命名空间，库内 ID 唯一，别处引用条目时按库解析。技能、装备、地点三库由协议直接读取，名称与若干字段由第一层规定，卡用不到时可以不声明（见第一章）。

**条目**：条目库中的具体实例，每条一个 `.txt` 文件，文件名等于其 ID。ID 字段名为 `{库名}ID`。“名称”可选，省略时等于 ID。其余字段都须在库的声明中声明，出现未声明的键时报错（见第一章）。

辨析：世界树的条目只指条目库中的公共条目，不是酒馆世界书中的条目。

**条目正文**：条目的全部字段剥离机器字段之后的内容，对所有库相同，并非名为“正文”的字段。上下文展开条目时输出条目正文（见第一章）。

**分法**：条目库安排子目录的方式，有两种。按种类分时，各级目录名等于条目某个字段的值，依次对应哪些字段由“分级”规定，检查器校验条目所在目录与其字段值一致。按上下级分时，目录即实例，目录的嵌套即上下级，深度不限。文件与所在目录同名时，它是该目录所代表实例的条目，其上级是再上一级目录的实例。不同名时，其上级是所在目录的实例。库根下的实例没有上级。地点库固定按上下级分，协议据此判断某地点是否在另一地点之下，例如条件“角色状态”比较所在时，所在为所列地点或其下级即成立（见第一、三章）。

**分级**：按种类分的库所声明的字段名列表，依次对应各级子目录，例如《三国演义》装备库的 `[类型]` 表示 `装备/{类型}/{装备ID}.txt`，技能库可声明 `[门类]` 表示 `技能/{门类}/{技能ID}.txt`（见第一章）。

辨析：分级是条目库声明中的键，与编辑分级无关。

**上级类型**：按上下级分的库所声明的类型搭配：每种类型允许挂在哪些类型之下，空列表表示只能在顶层。声明了上级类型或适用类型的库，必须有一个名为“类型”、以行内列表为取值的字段（见第一章）。

**说明文件**：条目库根目录或分类目录下与目录同名的 `.txt`，写这一库或这一类特有的世界内容，受第四、五层约束，另禁用一批系统视角的措辞。写不出特有内容就不写，不复述第二层的种类与取值。按上下级分的库中，目录的同名文件是实例自身的条目，库根下的同名文件才是说明文件。路由展开条目时，按种类分的库附上根说明与各级分类说明，按上下级分的库只附根说明（见第一、五章）。

**文本容器**：只放供模型阅读的正文的两个目录：世界概况与扮演准则，名称固定（见第一章）。

**世界概况**：跨越各条目库、在整个可游玩时期都成立的世界内容，例如战力格局、纪年与远古历史，按主题分文件，按文件名顺序进入上下文；多世界线卡另可在 `世界概况/世界线/{世界线ID}/` 下放置该世界线专属的 `.txt` 文件，仅当选定该世界线时追加在公共概况之后（见第一、五章）。

**扮演准则**：第五层中不能机器检查的部分：叙述人称、对白比例、文风偏好与本卡的写入约束。由第一层推出的扮演规则不写在这里，而由模板生成。本卡扮演准则的原文经占位符填入其后（见第一章）。

**ID**：对象的标识。角色组、档案、预设事件、事件串、开局方案与条目的 ID 同时是其文件名或目录名。变化表的路径与映射键中的 ID 须原样书写。ID 的规则分属三层：第一层规定字符安全，不为空，首尾无空白，不含 `.`、`/`、`\`，不用保留字（`玩家`、`__proto__`、`constructor`、`prototype`），违反时报错。第四层要求 ID 是世界内有意义的短语，不用编码样式，超过 12 个字时提示。第五层按文本规范声明的命名规则报错。只给工具读的文件不重复写自身的 ID，由文件名或目录名给出。事件、角色位置与条目的文件保留 ID 字段，检查器校验它与文件名或目录名一致。档案的两份文件不写 ID，档案ID由目录名给出（见第一、二、三章）。

**名称**：对象供阅读的称呼。条目称“名称”，事件称“事件标题”，省略时都等于 ID。角色组与版本称“显示名”。进入上下文的显示名依次取所选版本的显示名、角色组的显示名、角色组ID（见第一、二、三、五章）。

**扩展名约定**：`.txt` 是供模型阅读的文件，其中的文本字段经剥离机器字段后进入上下文。`.yaml` 是工具数据，其中只有指定的几个字段进入上下文或展示给玩家，即角色组的显示名与别名，版本的显示名、别名与简介，事件串的概述，开局选项的问题与选项文字，开局方案的概述。两种文件的内容都按 YAML 书写，扩展名只表示读者，不表示语法。措辞检查扫描 `.txt` 中的文本字段与 `.yaml` 中的这些字段（见第一章）。

**包裹标签**：上下文中各部分外层以该部分名称写成的标签，例如 `<在场角色>`，由渲染时统一加上，标签名可由适配层替换。源文件不写包裹标签，检查器拒绝源文件中单独成行的包裹标签（见第一、五章）。

**索引**：能从目录推出的清单，例如有哪些角色组、哪些事件。索引不作为源文件维护，由工具直接读目录，打包时按需生成（见第一章）。

**书写风格**：YAML 的写法，例如列表块状或行内、缩进与引号。书写风格不属于任何一层，由 `ygg format` 统一 YAML 排版与键顺序；它缺省只检查，显式 `--write` 才写文件。检查器不为书写风格报错（见第一章与[参考：命令](参考/命令.md#format)）。

**作者资料**：作者为自己保留的工作资料，放在项目中世界书之外的 `作者资料/`，不进入上下文，不参与运行，不属于任何一层。世界树只规定工具要读写的部分：通读（第 0 层的通读分卷坐标账本、活词表与全局总账，`init` 预建 `通读/分卷/`）、出处、暂存、候选、生成（工具输出，不手改）、归档（撤下的内容，保留其在世界书中的相对布局），以及 `审阅器/`（`ygg view` 的缺省审阅存储目录，存批注、布局与备份，首次写入时创建）。目录详表见[写作规范](写作规范.md#作者资料)；其余资料的格式与位置由项目自定（见第一章）。

**出处**：`作者资料/出处/` 下的结构化记录，分两种：事件级记录写事件的来源，台词记录写每句收入角色位置的原台词的来源。检查器校验记录所引的事件、角色位置与台词存在，并据台词记录认定哪些候选台词是原台词（见第一章）。

**暂存**：已写好、待条件满足后接回世界书的内容，按其在世界书中的相对布局放在 `作者资料/暂存/` 下，并在暂存清单中登记类型、ID、接回位置、接回结构与接回条件（见第一章）。

**核定日志**：作者记录来源核对、设计决策与迁移的资料，格式与位置由项目自定，不抄写声明与规范的条文（见第一章）。

**创作规划**：作者记录设计理由、创作意图、进度与待办的资料，格式与位置由项目自定，不抄写声明与规范的条文（见第一章）。

**来源**：原作章节等来源资料，放在项目的 `来源资料/` 或项目配置声明的位置，供作者人工核对原台词；代码只校验 `作者资料/出处`，不读取或核对 `来源资料/`。原台词与来源原文的一致性由作者人工核对，世界树不做自动核对（见第一章）。

**原台词**：原作中角色说过的话。原台词逐字收入角色位置的候选台词，排在作者撰写的台词之前，出处写进台词记录，正文不标注。原台词中的破折号按原文保留，检查器只提示（见第一、三章）。

## 角色

**角色组**：本局变量、事件参与者与关系引用的唯一主体。每个角色组在 `角色/{角色组ID}/` 下有工具数据文件 `角色组.yaml`，写显示名、别名、角色包与分类、默认启用、默认版本、初始化方式、初始所在、版本与档案，ID 取自目录名（见第二章）。

辨析：规范行文中的“角色”泛指角色组所代表的人物。凡涉及 ID、变量与引用之处，主体都是角色组。

**版本**：同一角色组在本局可选的不同人物，开局时选定其一，例如某卡的主角角色组可设甲、乙两个可选版本。版本有版本ID、显示名、别名与简介。只有一个版本的角色组可以不写版本，此时版本ID等于角色组ID，默认版本与各档案的适用版本都省略。写了版本的角色组，即使只有一项，也须写默认版本与每份档案的适用版本（见第二章）。

**启用**：角色组参与本局。启用与所选版本在封卷时写入开局设定，没有写明的取默认启用与默认版本。未启用的角色组不会出场。核心参与者中有未启用者的事件被排除（见第二、四章）。

**别名**：用于识别本轮被提及角色的称呼，分角色组级与版本级，版本级别名只在本局选了该版本时算数。别名在组内不得重复。不同角色组之间重复时提示（见第二章）。

**档案**：版本在某段时期内稳定的事实与行为方式，又称时期档案。每份档案在 `角色/{角色组ID}/档案/{档案ID}/` 下有基本信息与角色印象两份文件，其适用版本、默认、前置档案、生效条件与初始能力写在 `角色组.yaml`。档案写“这个人会怎么做”，不写“现在是什么状态”：关系、职位、持有物、伤势、能力的取得与丧失只由事件的变化写入，所在与当前地点属于场景状态，二者都记在本局，不写进档案。核心身份、行为准则、价值优先或稳定体貌明显改变时另开档案。单纯的能力成长与装备变化不另开（见第二章）。

**档案项**：`角色组.yaml` 的档案列表中的一项，写档案ID、适用版本、默认、前置档案、生效条件、初始能力与初始装备。档案列表须与 `档案/` 下的子目录一一对应（见第二章）。

**基本信息**：档案中写身份与外观的文件，字段有姓名、称号、性别、出生年、种族、出身、稳定体貌、穿着习惯与能力特征。稳定体貌分发色发型、瞳色、体型与特征。能力特征分特征与技能补充。档案不写年龄，当前年龄由出生年与当前时间计算（见第二章）。

**角色印象**：档案中写行为方式的文件，字段有核心身份、行为准则、价值优先、表达规律、通用反应、关系表现与表现禁区。表达规律分自称与称呼、句式、语气变化、场合差异、内外差与口头特征（见第二章）。

**技能补充**：能力特征中写某个公共技能在此人身上的表现与限制，每项写技能ID，以及个体表现与个体限制，二者至少写一项。写了技能补充不等于掌握该技能。进入上下文时只留本局可用技能的项（见第二、五章）。

**默认档案**：不写生效条件、恒成立的档案，每个版本至多一份（见第二章）。

**前置档案**：表示同一版本内的先后的档案。前置链不成环。成立的档案若是另一成立档案前置链上的祖先，则被取代。前置不表示优先级（见第二章）。

**生效条件**：非默认档案成立所需的条件，须含正向引用的“事件确认”或“世界线”条件（二者至少其一），不能只写时间等其它条件。代表取得身份的档案只引用实际达成结果的分支。生效条件不引用该档案自身将赋予的状态，也不得含封卷不可求值的条件（见第二、三章）。

**档案解析**：每轮确定角色组当前档案的计算。只考虑适用版本包含本局所选版本的档案。默认档案恒成立，其余档案在生效条件成立时成立。成立的档案若是另一成立档案前置链上的祖先，则被取代。前置链只沿适用于本版本的档案追溯，遇到不适用的档案即停止。剩一份时为当前档案。剩多份为档案冲突，一份也没有为解析异常，两种情况下档案都不进入上下文。档案解析不写入本局（见第二、四章）。

**切期**：当前档案由一份换为另一份。切期不单独登记：本局改变后生效条件的成立情况随之改变，读取时解析出另一份当前档案，通常由所引事件的确认引起。切期不触发初始化（见第二、四章）。

**共享档案**：适用版本含多个版本的档案，这些版本读到的是同一份档案（见第二章）。

**镜像档案**：不同版本同一时期各自独立的档案，内容可以部分相同，但分别存放（见第二章）。

**初始能力**：`角色组.yaml` 中档案项所写的能力，由首次登场初始化写入本局。初始能力以维度名为键，写法同变化表的“提升”与“新增”（见第二章）。

**初始装备**：`角色组.yaml` 中档案项所写的装备，由首次登场初始化写入本局，每项为装备ID、状态与位置（见第二章）。

**初始所在**：`角色组.yaml` 中的地点ID。本局从未写过某角色组的所在时，取此值（见第二、四章）。

**出场**：角色组在剧情中实际露面。角色组视为在场、已初始化，或是某个已确认事件的实际参与者，即为已出场。启用、被提及、出现在候选与被排除的事件中都不算。条件“角色已出场”判断的就是出场（见第三、四章）。

辨析：在场是当下的场景状态，随剧情变化。出场按上述三项求值，角色组离场后，只要已初始化或是已确认事件的实际参与者，仍为已出场。

**首次登场初始化**：把当前档案的初始能力与初始装备写入本局的一次性写入，用以补出角色组在本局实际登场之前已有的能力与装备。何时进行，由初始化方式决定。初始化写入记录 `初次登场·{角色组ID}`（分支“初始化”），只填本局尚未记载的部分：等级维度只填没有值的键，集合维度只在本局没有该字段时写入，装备只在本局未持有时加入（声明 `唯一: true` 且已被他人持有的装备跳过），能力移除记录中的字段不补回。每个角色组只初始化一次，空起点同样标为已初始化。切期不再初始化，封卷不初始化未做开局落盘定制的角色组（见第二、四章）。

**初始化方式**：角色组完成首次登场初始化的方式，写在 `角色组.yaml`，缺省为显式确认。两种方式都只初始化已启用、未初始化且当前档案成立的角色组。显式确认的角色组在视为在场时以待初始化预览进入上下文，由正文产生的确认初始化命令写入。出场自动的角色组在成为某次写入的实际参与者或视为在场时，于同一次提交中自动初始化，当前档案不成立时跳过并记入审计（见第二、四章）。

**玩家模式**：玩家参与本局的方式，封卷时写入，缺省为自建。双模式均可在 `开局.玩家` 中可选定制 `自定义装备`、`自定义技能`、`额外技能` 与 `移除技能`，且封卷末尾对玩家持有的 `唯一: true` 装备执行全本局强制唯一归属清理。扮演模式下玩家扮演某个已启用的角色组，即扮演角色组，叙事模型不替他决定言行，并支持在当前时期现状基线上作能力与装备的增量定制落盘。自建模式下玩家的身份写在 `开局.玩家.档案`，字段取基本信息的子集，并可写 `初始能力` 与 `初始装备`，本局状态记在保留的角色组ID“玩家”之下。“玩家”只在自建模式下可写，预设事件与门槛都不能引用它（见第二、三、四章）。

## 事件

**事件**：历史的单位，分预设事件与动态事件。每个预设事件在 `历史/事件/{事件ID}/` 下有模型可见的 `事件.txt` 与存放角色位置的 `角色/` 目录。事件文件写事件在何时可以发生、需要什么、由谁参与、可能走向哪些分支，以及每个分支写入本局的变化。事件ID是世界内中性的短语，按发生的行动命名，不带来源前缀（见第三章）。

**预设事件**：写在世界书中的事件（见第三章）。

**动态事件**：游玩中由记账结果或关闭记账时的正文命令登记的事件，没有门槛与分支，由命令给出事件ID、摘要、实际参与者与变化，记录的分支为“完成”，并可声明某个在有效本局中进行中的事件串到此结束（见第四章）。

**确认策略**：事件如何被确认，共三种。自动确认：封卷时按门槛补入；游玩中窗口结束时仍未确认，而门槛成立且选得出分支，即成为待登记。条件确认：封卷时同样按门槛补入；游玩中须由叙事正文确认，窗口结束时仍未确认即排除。仅作候选：不参加封卷，只在游玩中作为候选，由叙事正文确认。确认策略是机器字段（见第三、四章）。

**触发时间**：事件可以发生的窗口，写最早与最晚，最晚不可省略。窗口从最早的起点到最晚的终点，最早与最晚当日（或当年）都在窗口之内。当前时间早于最早为未到。当前时间已过最晚而事件仍未发生即排除，自动确认的事件若门槛成立且选得出分支，则成为待登记。事件本身没有持续时间，持续的过程由事件串表达。前置事件的最晚不晚于后续事件（见第三章）。

**核心参与者**：缺了事件就不成立的角色组，其中有未启用者时事件排除。世界事件通常没有核心参与者（见第三、四章）。

**实际参与者**：事件记录中的参与者：封卷与待登记时即核心参与者，由正文确认时为核心参与者与确认命令另列的参与者的并集（见第四章）。

**门槛**：由协议求值、决定事件能否发生的条件，分事件门槛与分支门槛：事件门槛决定事件能不能发生，分支门槛决定这个分支能不能走。门槛只写真正的因果，即“没有它，这件事就不会发生”，不写原作中的先后（见第三章）。

**条件**：门槛与档案生效条件的写法。条件是单键映射，键为条件类型或组合词 all（全部成立）、any（任一成立）、none（全部不成立），组合词的列表不能为空。条件类型属于第一层，共十二种：角色启用、角色版本、事件确认、事件串状态、当前时间、剧情标记、角色状态、同处、角色已出场、当前场景、在场实力人数、世界线。依赖条目库、能力维度或世界线的条件，在卡没有声明所依赖项时不可用（见第三章）。

**三值**：条件的求值结果：成立、不成立、未知。变量缺失或封卷前读取为未知。组合时，all 有一项不成立即不成立，否则有一项未知即未知。any 有一项成立即成立，否则有一项未知即未知。none 是 any 的取反，未知取反仍为未知。门槛与生效条件求值为未知时，按不成立处理（见第三、四章）。

**排斥**：门槛中处于否定之下的“事件确认”，即以 none 写出的对某事件的否定。排斥是终身的：事件确认之后，后来的确认不得使它的门槛变为不成立。因此，事件甲的门槛须以 none 排斥乙才能成立时，甲一经确认，乙就不能再确认。协议在每次提交前以排斥检查把关。只想表达“在它之前”时，用当前时间或事件串状态（见第三、四章）。

**正向引用**：条件中不处于否定之下的“事件确认”，即不在 none 之内，或处于偶数层 none 之内。事件串的起点与依赖、候选前置只认正向引用。处于否定之下的引用是排斥（见第三、五章）。

**前置事件**：门槛以正向引用的“事件确认”要求其已经确认的事件。前置事件的触发时间最晚不得晚于后续事件。所有路径上的前置事件都不可能在后续事件的窗口之内发生时，检查器报前置超出窗口。所有路径上前置事件的最晚都晚于后续事件时，报前置倒流（见第三章）。

**封卷不可求值的条件**：“当前场景”与“在场实力人数”。封卷在幕后补出开局之前的历史，没有当前场景，也没有在场者，这两种条件求不出值。确认策略不是仅作候选的事件，其门槛与分支门槛不得含它们。档案的生效条件同样不得含它们（见第三章）。

**分支**：事件可能的走向。每个分支有分支ID、门槛（可选）、分支条件、分支结果与变化表，还可按需声明本分支专属的 `事件概要`、`影响范围`、`公开信息` 与 `隐秘信息`（已确认经历与待登记按所走分支覆盖顶层同名字段，候选不输出）。分支条件是条件文本，各分支之间须能区分。游玩时叙事模型只能在门槛成立的分支中选择，门槛未知的分支不能选。封卷与待登记按“分支的选择”选出一个分支（见第三、四、五章）。

**默认分支**：封卷时没有其它因素决定时所走的分支（见第三章）。

**兜底分支**：不带门槛的分支。自动确认的事件只要有一个分支带门槛，就必须有兜底分支，否则所有分支门槛都不成立时事件被排除，其后果随之消失（见第三章）。

**变化表**：分支写入本局的变化，动态事件也以同样的写法给出变化。每条变化有路径、操作与值。路径以 `世界.剧情标记.{标记ID}`、`世界.{二层世界字段}` 或 `角色.{角色组ID}.{字段}` 起头，一律写到要改的那一格。操作按字段的类型而定：单值设定；数值，包括值为数值的映射（例如某卡的好感度），只能增加或减少，值为不超过单次增减上限的正整数，本局没有值时从 0 起算，结果截断在值域之内，即低于下限取下限、高于上限取上限；其余映射设定、新增（键不存在时才写入）或移除（不带值）；等级提升、设定或移除；集合只能逐项新增或移除，不能整体覆盖。值按第二层的声明校验。路径与映射键中的角色组须保证已启用。能力移除记录与已初始化不能由变化表写入。同一事件的变化只写一次（见第二、三章）。

**提升**：等级维度的变化操作。本局没有值或新值更高时写入，否则不变。写入时清除该字段的能力移除记录。能力的取得与晋级用提升，重复确认不会降级。明确的降级用设定（见第二章）。

**公开信息**：事件中众所周知的事实，随候选事件与已确认经历进入上下文（见第三、五章）。

**隐秘信息**：事件中只有知情者知道的事实，只随已确认经历进入上下文。隐秘信息属实，但只有角色位置的角色知情或主观记忆写到的人知道（见第三、五章）。

**角色位置**：某角色组在某事件中的个人视角，位于 `历史/事件/{事件ID}/角色/{角色组ID}.txt`，有角色概要、角色定位、适用分支、介入条件、角色知情、主观记忆、按分支与事件触发语料等字段。角色位置不复制事件正文与变化表。角色知道、猜测或记得某事，不等于它在世界中成立。适用分支省略时适用于全部分支。各分支的知情与记忆不同时，共用的部分写在外层，分支专属的写在“按分支”下，其键须在适用分支之内，值只含角色知情与主观记忆。进入上下文时，外层与本局所走分支的内容合并。事件确认后，在场者适用于所走分支的角色位置随经历进入上下文，角色知情与主观记忆只在此时进入。事件为候选时，只取适用分支与门槛成立的分支有交集的角色位置（见第三、五章）。

辨析：角色位置指角色在事件中所处的位置，不是角色所在的地点。后者是本局变量“所在”。

**事件触发语料**：角色位置中供模型取用的台词素材，每项有触发情境与候选台词（必填）、表达目的、情绪或语气与触发限制（可选）。候选台词只收本角色自己说的话，原台词排在前面。原作没有适用台词时才由作者撰写。事件为候选时，在场者的触发语料随之进入上下文（见第三、五章）。

**事件树**：全部事件由门槛与分支门槛连成的结构，可以分岔，也可以在某处汇合。原作走向、作者改编与 if 线在结构上没有区别，都是事件树中的路径（见第三章）。

**可达**：检查器按乐观假设对事件与分支的静态判断：正向引用的事件或分支本身可达、且在时间上可能早于引用者时，视为可能成立。事件串状态在该事件串有可达的起点时视为可能成立。其余条件都视为可能成立。这样仍不可能成立的事件或分支，检查器提示不可达。判为可达的只是不被排除，不保证在某一局中发生（见第三章）。

**事件串**：事件树中被命名的部分，表达有开头、有结局的过程，例如师从、救援。事件串的文件 `历史/事件串/{事件串ID}.yaml` 只写概述、成员事件与结局，不规定结构。串内的先后与分岔仍只由门槛给出。每个事件至多属于一个事件串，不属于任何事件串的称独立事件（见第三章）。

**起点**：事件门槛中没有正向引用本串其它成员的成员事件，由工具推出，不另写。每个事件串至少有一个起点（见第三章）。

**结局**：作者为事件串声明的终点，每项为一个事件，可附分支ID。该事件或该分支确认，事件串即走到结局（见第三章）。

**事件串状态**：未开始、进行中、已结束，由已确认事件推出，不存入本局。依次判断：有结局确认，或有动态事件声明本串结束，为已结束。否则有起点确认为进行中。其余为未开始。进行中的事件串作为世界当前状态进入上下文（见第三、四章）。

**if 线**：与默认路径不同的路径：某件事没有发生、走了另一个分支、某个角色组没有启用，后面的世界随之调整。if 线不是另一类事件，也不另建一棵树，只是事件树中的另一条路径。实现 if 线是世界树的主要目的（见第三章）。

**世界事件**：到时间就发生、只写世界层面变化的事件，通常没有核心参与者。哪个主类型表示世界事件由事件分类声明。世界事件的门槛正向引用非世界事件时，检查器提示（见第三章）。

**个人后果**：世界事件对某个角色组的后果，各写成一个事件，门槛是世界事件已确认，分支门槛读当时的状态（见第三章）。

**倒流**：较晚事件的变化使较早事件成立。封卷时倒流报时间顺序冲突。待登记时该事件不写入，因窗口已过而排除（见第三、四章）。

**世界线**：跨整条时间轴生效的平行设定，写在可选目录 `历史/世界线/{世界线ID}.yaml` 中，含 `概述` 以及可选的 `默认` 与 `角色组` 覆写。封卷时写入 `开局.世界线`，可被事件门槛、档案生效条件与 `世界概况/世界线/{世界线ID}/` 引用（见第一、二、三章）。

**开局选项**：`历史/开局选项.yaml` 中声明的、开局时可以选择的开局前事件。每项写 `事件ID`、可选的 `问题`（省略时界面回退事件标题或事件ID）与 `选项`。选项的键是分支ID或“未发生”，值是给玩家看的简明文字。只有触发时间最晚早于开局时间的事件可选。前面的选择使后面某事件的门槛不成立时，该项不出现。“自由组合”为否时，玩家只在默认历史与开局方案之间选择；为是时，还可以在方案的基础上逐项修改（见第三章）。

**开局方案**：作者预设的开局组合，每个方案一个文件 `历史/开局方案/{方案ID}.yaml`，写 `概述`，可写 `世界线`（多世界线卡必填）、`开局时间`、`开局地点`、`角色组` 与 `历史选择`。历史选择只能用开局选项中声明的事件与选项（见第三章）。

**历史选择**：开局时为开局前事件指定的分支或“未发生”。指定了分支的事件只能走该分支，其门槛不成立时报错，不退回默认分支。指定“未发生”的事件记为排除。历史选择与所用方案写入开局设定（见第三、四章）。

**“如果”视图**：`ygg if` 与作者视图“如果视图”提供的路径对比，两处共用 `core/what-if.mjs` 的唯一结果。它以时间轴末尾为开局时间封卷两次，一次按默认规则，一次按作者给出的开局方案、排除的事件、指定的分支与停用的角色组，比较两次封卷的结果，列出没发生的事件、新发生的事件、分支不同的事件与停住的事件串，另输出影响面与异常（见第三章与[参考：命令](参考/命令.md#if)）。

**影响面**：`ygg if` 的一项输出，按事件列出假设只有它没发生时，下游随之不能发生的事件与引用位置；推算只看事件门槛中的正向事件确认，其余条件不作限制。影响面大时，用于发现写得过死的门槛（见第三章与[参考：命令](参考/命令.md#if)）。

## 本局

**本局**：正在进行的游戏的全部存储状态，存放在本局变量中。封卷写入开局设定与开局前的历史，此后只经命令写入。当前档案、当前能力、事件有效状态与事件串状态由协议每轮计算，不写回本局。适配层按楼与 swipe 保存本局快照和命令，用最近前楼作底并重放命令完成存档与回档（见第四、六章）。

**本局变量**：本局的存储结构，分一层骨架与二层字段。一层骨架由规范规定，所有卡相同：世界（当前时间、当前地点、剧情标记）、开局、角色、事件、待定项。二层字段由卡在 `设定/本局变量.yaml` 声明，例如《三国演义》示例的关系、身份、职位、知识，以及通用卡中常见的好感度、身体状态与天气。字段名不得与一层骨架重名，角色字段也不得与能力维度重名。数值字段单次增减的上限也在此声明，缺省为 100（见第四章）。

**开局设定**：本局变量的 `开局` 部分，封卷时写入，此后只读：可选的世界线、开局时间、已封卷、历史选择、所用方案、各角色组的启用与版本、玩家模式与玩家定制（见第四章）。

**角色变量**：本局中 `角色.{角色组ID}` 下的状态：在场、所在、各能力维度、装备、能力移除记录、已初始化与二层角色字段。角色变量在首次写入时创建，不为全部已启用的角色组预建（见第四章）。

**事件记录**：本局中 `事件.{事件ID}` 下的记录：状态（1 为确认，2 为排除）、分支、实际时间与实际参与者，动态事件另有摘要与可选的结束事件串。场景状态以外的持久字段，都能在事件记录中找到写入它的事件（见第四章）。

**待定项**：叙事正文一时不能确定某字段该取何值时留下的记录，不覆盖原值，含字段路径、候选值、事件ID（须是已确认的记录）与说明。剧情明确后写入结果并移除待定项。待定项以命令写入，不产生事件记录，原样进入世界当前状态。在场与所在不能作为待定项（见第四章）。

**楼层记录**：存放在一个助手楼、一个 swipe 上的本局记录，含本局快照、可重放命令、失败、已写入、归属、记账信息与运行清单。第 0 楼记录来自默认开局与开场命令；玩家楼上的复制变量不能作记录（见第六章）。

**归属**：楼层记录与其楼号、角色、当前 swipe 和正文指纹的一致性标记。正文或选择的分支改变后，旧归属失配，记录不能继续作为该楼的本局（见第六章）。

**正文指纹**：正文 UTF-8 字节的 SHA-256，用于发现外部编辑、复制楼层变量和过期记账结果。归属另保存楼号，并与正文指纹一起校验（见第六章）。

**命令重放**：不调用模型，把楼层记录中已经成功执行过的命令依次应用到最近可用前楼的本局。编辑、删除、切换 swipe、重载与重新记账后，用它恢复当前分支（见第六章）。

**场景状态**：当前时间、当前地点、在场、所在四项。角色走动、时间推进时，由叙述正文产生的写场景命令直接写入，不必登记事件。事件的变化表也可以写所在（见第四章）。

**当前时间**：本局的时间，按纪年书写，只能推进，不能倒退。时间推进后，新到期的待登记事件随之登记（见第四章）。

**当前地点**：由地标与场景组成：地标是地点ID，场景是描述所处之处的文本，例如《三国演义》示例的地标“涿县”、场景“张榜处”。当前地点决定地点链（见第四、五章）。

辨析：“场景”有三种用法：当前地点的子字段“场景”；场景状态，即四项的合称；条件“当前场景”，比较当前地点的地标与场景。

**在场**：角色组此刻是否在当前场景中。在场的角色组随当前地点移动（见第四章）。

**所在**：角色组所处的地点ID，卡声明了地点库时才有。在场的角色组，其所在视为当前地点的地标。离场时没有写下所在的，存为写入前的地标。所在从未写过时取初始所在，也没有初始所在时为未知（见第四章）。

**视为在场**：协议判断在场的口径：本局在场为真的角色组。当前地点已写入时，扮演角色组与自建玩家也视为在场（见第四章）。

**能力**：角色组在本局的当前能力状态，按能力维度记录。第一层规定维度的类型、比较与变化操作，第二层在 `设定/能力.yaml` 声明本卡有哪些维度及技能可用的规则（见第二章）。

**能力维度**：能力的分项，类型有三种：等级映射按键各记一个等级，例如某卡声明的武艺。单值等级记一个等级，例如《三国演义》示例的勇力。集合记一组无序、不重复的成员，例如某卡声明的天赋与习惯。维度之间相互独立，不由某一维度的值推出其它维度（见第二章）。

**键**：等级映射的分项，例如武艺分项下的剑术、骑射（见第二章）。

**键组**：等级映射的键的分组。技能可用的规则可以用键组限定只看某一组（见第二章）。

**综合实力**：条件“在场实力人数”所读取的单值等级维度，在能力声明中以“综合实力: true”标出，至多一个。综合实力独立评定，不从其它维度推出（见第二章）。

**技能**：技能库中的公共条目，描述技能本身的作用与边界。角色组掌握哪些技能，不由技能条目或档案决定，而由技能可用的规则从本局的能力推出（见第一、二章）。

辨析：能力是本局状态。可用技能由规则从能力推出。技能条目描述公共的作用。技能补充只描述个体的表现与限制，不授予技能。

**技能可用**：判断技能对某角色组是否可用的规则，形状有两种：等级门槛，即技能的键字段所指的键在本局已有值，且不低于技能的等级字段；集合持有，即技能ID在指定的集合维度中。每条规则以“适用”按技能字段的取值选出它管辖的技能，每个技能恰好适用一条规则。规则引用的技能字段即技能库的必需字段（见第二章）。

**当前能力**：协议从有效本局读出的能力，不从档案重新合并。没有值的等级维度省略，集合没有成员时输出空集合（见第二、四章）。

**可用技能**：据技能可用的规则从当前能力算出的技能，按技能库的读取顺序输出（见第二、四章）。

**装备**：本局中 `角色.{角色组ID}.装备` 下以装备ID（或动态写入/开局落盘的本局自定义装备名称）为键的持有物，值为状态与位置，状态取 `词表.装备状态`。取得写新增，本局已持有时保留原有的状态与位置；装备条目声明 `唯一: true` 时执行全本局强制唯一归属（见第一、二、四章）。

**能力移除记录**：协议维护的、被移除过的能力字段的清单，例如 `武艺.剑术` 或 `勇力`。移除时记入，提升或设定时清除。首次登场初始化不补回其中的字段。能力移除记录不能由变化表写入，也不进入上下文（见第二、四章）。

**已初始化**：协议维护的标记，表示角色组已完成首次登场初始化，不能由变化表写入（见第二、四章）。

## 协议

**协议**：内核中读写本局的部分。读取时计算事件有效状态、事件串状态、当前档案、当前能力与可用技能，写入时执行封卷与各条命令。协议只读本局与世界书，不调用模型。写入不修改传入的本局，成功时返回新的本局，失败时报错而不写入任何内容（见第四章）。

辨析：协议是执行规则的程序，协议文本是发给模型的规则。

**有效本局**：把待登记事件按求解顺序写到本局的草稿上所得的本局。一切读取都按有效本局计算，因此待登记事件在其它条件中视为已确认，它写入的状态在后面的读取中都看得到。封卷之前没有待登记事件，有效本局即本局（见第四章）。

**时间语境**：求值时作为当前时间的时间。读取时就是本局的当前时间。历史求解为某个事件求值时，以该事件的触发时间最晚为时间语境，条件“当前时间”与之比较，其余条件仍读取当时的状态（见第四章）。

**事件有效状态**：预设事件在本局中的状态，每次读取时计算，不写回本局。依次取第一个符合的：有确认记录为已确认，有排除记录为已排除，在待登记列表中为待登记，未封卷或当前时间缺失为未到，有核心参与者未启用为已排除，当前时间早于触发时间最早为未到，当前时间已过触发时间最晚为已排除，事件门槛成立且至少一个分支门槛成立为候选，其余为不适用（见第四章）。

**待登记**：已过窗口、本应自动发生而尚无记录的事件：确认策略为自动确认，当前时间已过触发时间最晚，门槛成立且选得出分支。待登记事件由历史求解求出，在有效本局中视为已发生，在上下文中完整列出并标为“已经发生”，于下一次写入时随之登记（见第四章）。

**候选**：窗口之内、核心参与者都已启用、事件门槛成立且至少一个分支门槛成立、等待叙事正文确认的预设事件。路由从候选中选出与当前场景相关的若干进入上下文（见第四、五章）。

**不适用**：当前时间在窗口之内、核心参与者都已启用，而事件门槛不成立，或没有一个分支的门槛成立的事件有效状态。不适用与已排除不同，本局的状态改变之后，事件仍可能成为候选（见第四章）。

辨析：作者资料中的 `候选/` 是尚未定下的创作内容，候选台词是角色位置中的台词，二者都与事件的候选状态无关。

**历史求解**：封卷与待登记共用的补出事件的过程。参加求解的事件按触发时间最晚的起点排序，同时刻按事件ID的码点顺序。每一轮按此顺序找第一个尚未写入、核心参与者都已启用、以触发时间最晚为当前时间时门槛成立且选得出分支的事件，写入记录并按所选分支写入变化，然后从头再找，直至找不到为止（见第四章）。

**分支的选择**：封卷与待登记为事件选出分支的规则：指定了分支时只考虑该分支。否则默认分支的门槛成立就选默认分支。否则按书写顺序取第一个门槛成立的分支。门槛未知视为不成立，都不成立则选不出分支（见第三、四章）。

**封卷**：开局时的写入。封卷以开局时间、开局方案、角色组、玩家模式与历史选择为输入，写下开局设定，把当前时间设为开局时间、剧情标记设为开局值，再以历史求解补出开局前事件，没有写入的开局前事件记为排除。封卷不写当前地点与在场，不初始化角色组。指定的分支走不通时报历史选择错误，违反排斥时报配置冲突（见第三、四章）。

**开局前事件**：触发时间最晚早于开局时间、确认策略不是仅作候选的事件。开局前事件全部由封卷决定：或按历史求解确认，或记为排除（见第四章）。

**排斥检查**：每次提交前的检查：对写入前有效本局中已确认的预设事件（含待登记事件，封卷时为全部写入的预设事件），以写入后的记录重新求值其事件门槛与所走分支的门槛，其中“事件确认”按记录求值，其余条件记为未知。结果为不成立即排斥冲突，本次写入被拒绝（见第四章）。

**写入**：协议在本局的草稿上构造修改的过程：先登记待登记事件，再执行本次写入，然后完成出场自动的初始化，做排斥检查（见第四章）。

**提交**：写入全部通过后返回新的本局。任何一步不通过即报错，什么也不写。命令的目标事件已有记录时，该事件不重复写入，结果为“未写入”，随之登记的待登记事件与初始化照常提交（见第四章）。

**命令**：写入本局的唯一途径，共五种：确认事件、动态事件、确认初始化、写场景、待定项。每条命令是一次独立的写入，一轮的命令按顺序执行，失败的那条不写入，不影响其后的命令。默认记账时由记账 JSON 转换得到；关闭记账时使用回复末尾的 `<命令>` 标签，内为 YAML 列表（见第四、六章）。

**写场景**：写入场景状态的命令，依次处理当前时间、当前地点、在场与所在。时间推进后先登记新到期的待登记事件。从未出场的角色组写为在场时，显式确认的须先确认初始化，出场自动的在本次提交中初始化。在场与所在只能写已启用的角色组。扮演角色组与自建玩家的在场不能写，视为在场者的所在不能写（见第四章）。

**检查**：检查器对世界书的检查，分静态检查与抽样。静态检查核对目录、声明、条目、角色组与档案、事件与事件树、开局选项与方案、文本与出处，不运行协议。没有错误时才做抽样。全量检查即对全部内容做静态检查与抽样，第二层改动后必须进行（见第四章与写作规范）。

辨析：检查指检查器对世界书所做的整体检查，校验指协议与检查器对单个值或单条命令是否合法的判定。

**抽样**：检查器在若干开局时间与开局配置下，以协议试验世界书的检查，共四项。档案互斥：对每个角色组的每个版本，在各抽样年份枚举其档案生效条件所引事件的状态组合（无记录、排除、确认于各分支），在只含这些记录的封卷后本局上直接解析档案，不封卷，也不登记待登记事件，确认至多一份当前档案。组合超过 4096 种时提示并跳过该版本。运行抽样：在各抽样年份封卷，默认开局一次，全部角色组启用、各取其第 i 个版本各一次，须成功且档案不冲突。开局方案：每个方案封卷一次，须成功。开局选项：每个选项的每个分支（含“未发生”）各封卷一次，历史选择错误只提示，其它失败报错。抽样年份取全部事件触发时间最早、最晚所在的年份及其下一年，另加最早年份的前一年（不小于 0）（见第四章）。

## 上下文

**路由**：每轮只读的计算。路由以本局、最近的消息与运行参数为输入，经协议读取有效本局，组装出模型上下文与审计。路由不写任何变量（见第五章）。

**上下文**：路由每轮为叙事模型组装的输入，依次为协议文本、世界概况、世界当前状态、在场角色、被提及角色、相关条目正文与事件，没有内容的部分省略。组成与顺序属于第一层（见第五章）。

辨析：上下文是提示词的一部分。提示词中的其它内容，例如酒馆的对话历史，不由世界树规定。预算也只约束上下文中的经历、候选、在场角色与条目，不是整个提示词的上限。

**进入上下文**：内容经路由选入、组装与渲染，成为模型读到的上下文的一部分（见第五章）。

**组装**：路由每轮把选入的内容组成结构化上下文的过程。组装时剥离机器字段（见第五章）。

**渲染**：把组装好的上下文写成文本的过程。默认渲染以各部分的名称作包裹标签，协议文本与世界概况原样放入，其余部分以 YAML 写出（见第五章）。

**审计**：路由每轮留给作者的记录，不进入上下文。审计逐部分记下选入与略过的项及其理由，受预算约束的部分另记字符用量与预算，以及档案冲突、当前地点不在地点库中等异常（见第五章）。

**运行参数**：控制上下文规模的参数，写在项目根 `yggdrasill.yaml` 的 `运行参数` 之下，不属于任何一层。运行参数有经历与候选的条数与字符预算、在场角色的完整人数与字符预算、条目的字符预算（可按库分别设置）、提及窗口，值须为非负整数，未知键或不合法的取值报错。不写时取默认值：经历 6 条、3000 字符，候选 4 条、4000 字符，在场角色 6 人、12000 字符，条目每库 1500 字符，提及窗口 2 条（见第五章）。

**世界当前状态**：上下文的第三部分：当前时间、当前地点、剧情标记、有值的二层世界字段；进行中的事件串，按事件串ID的码点顺序，各附概述与本串已确认的事件（按实际时间先后）；待定项（见第五章）。

**在场者**：视为在场的已启用角色组，按角色组ID的码点顺序排列，自建玩家排在最后。每个在场者以显示名、年龄、当前档案、当前能力、可用技能与本局状态进入上下文。档案冲突或解析异常时只给角色组ID与显示名（见第五章）。

**提及**：最近若干条消息中出现角色组的显示名或别名、条目的 ID 或名称、事件的 ID 或标题。被提及而不在场的已启用角色组只给角色组ID、显示名与别名，不给档案。被提及的条目与事件按各自的规则选入。所看的消息条数称提及窗口，缺省为 2（见第五章）。

**预算**：上下文中经历、候选、在场角色与各条目库的条数、人数或字符上限，由运行参数设定。字符数是每项内容 JSON 序列化后的 Unicode 码点数，不是 token 数。条目与候选放不下时整项略过；已确认经历先去掉角色位置再试，仍放不下才略过；在场角色超出完整人数或字符预算时逐人降为精简或最小，绝不把在场者删出上下文。内容一律不截断（见第五章）。

辨析：预算决定内容能否进入上下文，长度预算是对世界书正文字数的提示，二者无关。

**相关条目正文**：上下文中的条目，按三种来源依次选入，同一条目只选一次：本局状态引用，即在场者的本局状态与集合能力中引用了条目库的值与映射键，按在场者、字段声明、值的顺序；地点链；提及。技能另须是某个在场者的可用技能。每个库有自己的字符预算，输出按条目库声明的顺序分组，组内按选入顺序（见第五章）。

**地点链**：当前地点的地标及其各级上级，从地标往上。地点链决定哪些地点条目进入上下文，也用以挑选与当前地点相关的经历与候选（见第五章）。

**已确认经历**：上下文中的已确认事件，取自有效本局中已确认的预设事件与动态事件，不含首次登场初始化的记录与待登记事件。每项须有入选理由，按优先级依次为：点名，即提及窗口内出现事件ID或标题；候选前置，即某个选入的候选事件在成立的路径上正向引用了它；当前地点，即事件的地点与地点链有交集；共同经历，即实际参与者中至少两个是在场者；在场者经历，即至少一个是在场者。同级时，点名按首次出现的位置排列，其余依次按在场的实际参与者人数从多到少、实际时间从近到远、事件ID的码点顺序排列。超出条数上限的略过。超出字符预算时先去掉角色位置，仍放不下则整条略过。入选的按实际时间先后输出，同时刻按事件ID的码点顺序（见第五章）。

**成立的路径**：从门槛的根向下、只进入求值为成立的节点所经的路径。候选前置取选入的候选事件的事件门槛与各成立分支的分支门槛中，成立的路径上的正向引用（见第五章）。

**候选的选入**：路由从候选事件中选入上下文的规则。入选须满足其一：有核心参与者在场、地点与地点链有交集，或没有核心参与者。排序依次为：属于进行中事件串的在前，与地点相关的在前，在场的核心参与者多的在前，触发时间最晚早的在前，最后按事件ID的码点顺序。每项只附门槛成立的分支，以及在场者的角色定位、介入条件与事件触发语料（取法见“角色位置”），不附隐秘信息、角色知情与主观记忆（见第五章）。

**待初始化**：上下文中列出的、初始化方式为显式确认且有待初始化预览的在场角色组，各附档案ID与预览，供正文确认初始化。待初始化预览是按首次登场初始化的填写规则算出的将要写入的能力与装备（见第四、五章）。
