## 起步

### 安装工具

工具链需要 **Node.js 20** 或更高版本。在代码仓库根目录安装依赖后即可运行命令：

```sh
git clone https://github.com/groundgrounder/Yggdrasill.git
cd Yggdrasill
npm ci
```

如果尚未把 `ygg` 链接到系统 `PATH`，可在仓库根执行 `npm link` 将 `ygg` 挂入 `PATH`，或在仓库内写成 `node cli/ygg.mjs`、在仓库外的创作项目目录写成 `node <世界树仓库>/cli/ygg.mjs`。以下示例按仓库内写法给出。

### 体验示例

仓库内置《三国演义》第一至三回示例（`examples/三国演义/`），包含 37 个角色组、45 份档案、80 个条目与 150 个事件。先跑三条只读命令，熟悉工具反馈：

```sh
# 全量检查（静态检查与抽样）
node cli/ygg.mjs check examples/三国演义/世界书

# 对比 if 分支：如果张飞在帐前怒杀董卓，后续路径如何变化
node cli/ygg.mjs if examples/三国演义/世界书 --分支 张飞怒欲杀卓:提刀杀卓

# 启动本地作者视图（省略 --storage 时自动使用临时审阅目录，不写入仓库）
node cli/ygg.mjs view examples/三国演义/世界书 --port 0
```

在当前基线上，`check` 会输出 `0 错误，10 提示；37 角色组，45 档案，80 条目，150 事件`；`if` 会列出 `没发生（30）` 个下游事件（如 `丁原吕布败董卓`、`温明园议废立`、`省中强废立` 等）；`view` 会打印本地地址（仅监听 `127.0.0.1`），在浏览器打开即可查看事件树与详情，终端按 `Ctrl + C` 停止。

### 挂载 skill

仓库在 `skills/` 下提供 9 个面向建卡与维护的自包含作者 skill，职责清单见 [`skills/README.md`](../skills/README.md)：

- **安装 skill**：在支持 Agent Skills 的编程代理环境运行 `npx skills add groundgrounder/Yggdrasill`，即可在外部创作项目目录直接调用全部 9 个 `世界树·…` skill。每个 `ygg-*` skill 目录已内置各自必需的参考与红线，脱离仓库单独安装也能独立工作。
- **在世界树仓库目录内使用编程代理**：根目录的 `.agents/skills` 符号链接指向 `../skills`，供兼容工作区级发现的编程代理自动加载全部 9 个作者 skill。
- **命令行配合**：在克隆的 Yggdrasill 仓库执行 `npm ci && npm link` 将 `ygg` 挂入 `PATH`（未链接时由代理运行 `node <世界树仓库>/cli/ygg.mjs`）。

### 初始化项目

在世界树仓库外新建自己的角色卡项目时，用 `ygg init` 生成标准目录与基础声明：

```sh
node cli/ygg.mjs init ../我的角色卡 --纪年前缀 中平 --年位数 3 --月数 12 --每月天数 30
```

`init` 会创建 16 个目录与 4 份基础声明（`纪年.yaml`、`事件分类.yaml`、`本局变量.yaml`、最小 `条目库.yaml`），生成后即可通过 `check --static-only`。作者资料各子目录的用途见[写作规范：作者资料](写作规范.md#作者资料)。

初始化后按创作来源准备材料：

- **改编原作**：将已校对的分卷或分章纯文本冻结并放进 `我的角色卡/来源资料/`，从第 0 层通读开始。
- **原创世界**：无需准备原文，跳过原文冻结，在第 0 层直接与代理通过访谈整理全局总账。

建议同时在创作项目目录初始化 git 仓库或建立备份，方便每层修改后对照差异与回退。

### 协作方式

进场建卡或接手已有项目时，先调用 **`世界树·统筹`**。它会先执行只读诊断 `ygg status`，汇总当前处于第 0–5 层的哪一阶段、已有文件计数与缺口，再决定下一步调用哪一个分层 skill。

与代理配合时可在开工前指定运行模式：

- **引导模式（默认）**：每完成一层并跑过该层出口检查后，代理停下呈报产物摘要、命令输出与待拍板项，经你确认后再进入下一层。
- **自动模式**：要求代理自动推进到指定层（例如“推进到第 3 层骨架”）。代理只在遇到改编范围未定、核心设定冲突或缺少来源原文等硬阻塞时停下询问，其余细节先按保守方案记入待复核清单。

## 搭建骨架

建卡按第 0 层至第 5 层逐层推进，先立事实坐标与可运行骨架，再补写档案与事件正文。各层最小检查矩阵正本见 [`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)。

### 第 0 层：通读原作

- **输入**：冻结在 `来源资料/` 的原作文本（或原创世界的作者大纲构想）。
- **调用 skill**：`世界树·通读`（[`skills/ygg-read/SKILL.md`](../skills/ygg-read/SKILL.md)）。
- **代理产出**：按分卷抽出分卷坐标账本与 `活词表.yaml` 写入 `作者资料/通读/分卷/`，归并消歧后形成五份全局总账（世界体系、人物总名单与分期方案、全书年表与因果事件、if 分岔与开局提案、待拍板清单）存入 `作者资料/通读/`。本层不写 `世界书/`；原创世界通过访谈产出同构总账。
- **作者审阅**：核对人物总名单是否漏人或重名、每人的分期切点是否合理、体系维度取值是否覆盖全书，并逐项拍板待决歧义。
- **通过标准**：覆盖范围内的分卷坐标可查，活词表回查无遗漏，待拍板清单全部收口。

### 第 1 层：建立设定

- **输入**：第 0 层拍板的全局总账。
- **调用 skill**：`世界树·地基`（[`skills/ygg-foundation/SKILL.md`](../skills/ygg-foundation/SKILL.md)）。
- **代理产出**：参照 `defaults/设定/` 在 `世界书/设定/` 写入本卡声明（`纪年.yaml`、`事件分类.yaml`、`本局变量.yaml` 及按需选用的 `等级.yaml`、`能力.yaml`、`条目库.yaml`、`剧情标记.yaml`、`角色分类.yaml`、`文本规范.yaml`），并在 `世界概况/` 与 `扮演准则/` 写下全局背景和文风要求。声明遵循单一来源，不在正文或作者资料里抄写种类与取值清单。

以示例《三国演义》为例，`examples/三国演义/世界书/设定/纪年.yaml` 声明时间格式：

```yaml
前缀: 中平
年位数: 3
月数: 12
每月天数: 30
```

`examples/三国演义/世界书/扮演准则/演义白话.txt` 声明本卡的文风补充（节选）：

```yaml
叙述人称: 采用第三人称章回白话行文，句段简练，不以现代语入话。
对白与描写:
  - 定交、议事、朝对以对白为主；战阵之事写其动作与号令，不铺陈血污。
```

- **作者审阅**：核对纪年、等级序列、能力维度、剧情标记初值与文风要求是否准确。
- **通过标准**：运行 `node cli/ygg.mjs check <世界书目录> --static-only` 达到 `0 错误`。

### 第 2 层：铺设条目

- **输入**：第 0 层总账与第 1 层的 `设定/条目库.yaml`。
- **调用 skill**：`世界树·条目`（[`skills/ygg-entries/SKILL.md`](../skills/ygg-entries/SKILL.md)）。
- **代理产出**：在世界书根下铺设各类公共条目（如按上下级分的地点目录、按种类分的装备与势力目录）。条目只写对象本身与领域特有的边界，不写某角色此刻是否持有或身处何地。

示例《三国演义》中的地点条目 `examples/三国演义/世界书/地点/幽州/涿县/涿县.txt`：

```yaml
地点ID: 涿县
类型: 城邑
概况: 幽州境中之县，楼桑村所在。
```

装备条目 `examples/三国演义/世界书/装备/兵器/双股剑.txt`：

```yaml
装备ID: 双股剑
类型: 兵器
简介: 双剑一式两柄，合称双股。
特点:
  - 两剑同式，成对携用。
```

- **作者审阅**：确认第 3 层将要引用的公共地点、势力、装备与技能 ID 已齐备，条目中未混入角色当前持有或所在状态。
- **通过标准**：运行 `node cli/ygg.mjs check <世界书目录> --static-only` 达到 `0 错误`。

### 第 3 层：搭建骨架

- **输入**：第 0 层年表与人物分期、第 1–2 层产物。
- **调用 skill**：`世界树·骨架`（[`skills/ygg-skeleton/SKILL.md`](../skills/ygg-skeleton/SKILL.md)）。
- **代理产出**：按总账建全名单 `角色组.yaml`（别名须用两字及以上可辨识称呼，避免单字别名误匹配）与最小合法档案壳；搭出事件树、因果门槛、if 分支、事件串、`开局选项.yaml` 与 `开局方案/`，并在 `作者资料/出处/` 记入事件级出处。此时正文字段只写足以表意的简明句，先跑通逻辑再补写正文。

示例《三国演义》中 `examples/三国演义/世界书/角色/刘备/角色组.yaml` 定义切期链（节选）：

```yaml
显示名: 刘备
别名:
  - 玄德
角色包: 第一回群像
分类: 结义兄弟
默认启用: true
初始化方式: 出场自动
初始所在: 涿县
档案:
  - 档案ID: 刘备·白身期
    默认: true
    初始能力:
      勇力: 骁勇
  - 档案ID: 刘备·结义起兵期
    前置档案: 刘备·白身期
    生效条件:
      事件确认:
        事件ID: 桃园结义
        分支ID: 结义
```

`examples/三国演义/世界书/历史/事件/张飞怒欲杀卓/事件.txt` 定义默认分支与 if 分支（节选）：

```yaml
事件ID: 张飞怒欲杀卓
默认分支: 提刀悬置
分支:
  - 分支ID: 提刀悬置
    分支条件: 张飞怒气正炽，提刀便要入帐来杀董卓。
    分支结果: 刀未落，帐前之局悬而未决。
  - 分支ID: 提刀杀卓
    分支条件: 张飞怒不可按，提刀入帐杀董卓。
    分支结果: 董卓死于张飞刀下，帐前大乱。
    变化:
      - 路径: 世界.剧情标记.董卓之命
        操作: 设定
        值: 已死于张飞之手
```

开局方案 `examples/三国演义/世界书/历史/开局方案/榜前长叹.yaml`：

```yaml
概述: 中平年间，黄巾已起，三路讨贼已发；涿县城中，刘备见招军榜文慨然长叹，张飞厉声喝问，村店又遇关羽，三英雄将在桃园结义。
开局时间: 中平001年04月02日
```

- **作者审阅**：重点检查门槛是否把“原作先后”写成了硬因果、角色切期条件是否引用了实际达成身份的分支、开局方案与 if 分支是否都能走通。
- **通过标准**：依次运行三项命令核对：
  1. `node cli/ygg.mjs check <世界书目录>`（全量检查，包含抽样）`0 错误`；反映真实因果的 `事件.世界依赖个人` 提示可保留并单列说明。
  2. `node cli/ygg.mjs if <世界书目录> --分支 <事件ID>:<分支ID>` 核对差异事件与影响面符合预期。
  3. `node cli/ygg.mjs preview <世界书目录> <角色组ID> --方案 <方案ID> --状态` 核对封卷后角色初始化与状态符合预期（例如 `examples/三国演义` 中 `preview ... 刘备 --方案 榜前长叹 --状态` 会输出 `刘备·平原县令期` 及结义、职位、装备等终态）。

### 审阅事件树

第 3 层骨架进入正文补写前，启动 `ygg view` 在浏览器中人工审阅整棵树：

```sh
node cli/ygg.mjs view <世界书目录> --port 0
```

在视图中可沿**世界主树**查看各事件串与独立事件的时间分布，在**局部关系**切换 1–5 层查看条件与排斥连线，在**角色汇总**核对每个角色组的分期与变化，在**如果视图**点选不同方案与分支。需要微调单个事件或记录审阅意见时，可在右侧**编辑与批注**面板直接修改并保存批注，批注会保存在审阅存储目录中，不污染世界书源文件。确认骨架结构无误后再锁定进入第 4 层。

视图功能范围、存储目录隔离与备份恢复机制见 [作者视图](../view/README.md)。

## 补写正文

### 第 4a 层：补写档案

- **输入**：锁定后的第 3 层骨架、第 0 层坐标账本与 `来源资料/` 原文。
- **调用 skill**：`世界树·档案`（[`skills/ygg-profile/SKILL.md`](../skills/ygg-profile/SKILL.md)）。
- **代理产出**：按角色与时期逐份精写 `基本信息.txt` 与 `角色印象.txt`。每份档案只写这一时期及以前确立的稳定事实与行为规律，不把当前职位、关系、持有物、伤势或所在写入文本。

以 `examples/三国演义/世界书/角色/刘备/档案/刘备·白身期/角色印象.txt` 为例（节选）：

```yaml
核心身份:
  - 宽和寡言而素有大志的结纳之人
表达规律:
  自称与称呼: 自称「备」，人常以字「玄德」称之。
  句式:
    - 自陈志向先言出身来历，再言欲破贼安民之愿。
```

- **作者审阅**：逐份抽查是否把后续时期才知道的事件写进了前期档案（串期），以及是否把应由事件变化表写入的状态写进了文本（越界）。写作红线速查见 [`skills/shared/写作红线.md`](../skills/shared/写作红线.md)。
- **通过标准**：全量 `ygg check` 无新增错误，`ygg format --check` 通过。

### 第 4b 层：补写事件

- **输入**：第 0 层名场面与台词坐标、`来源资料/` 原文与已通过的第 3 层事件骨架。
- **调用 skill**：`世界树·填景`（[`skills/ygg-scenes/SKILL.md`](../skills/ygg-scenes/SKILL.md)）。
- **代理产出**：按坐标回查原文，补实 `事件.txt` 的事件概要与条件文本，为参与角色写出 `角色/{角色组ID}.txt`（角色位置）。原台词逐字收入实际说话角色自己的 `候选台词`（排在作者自拟台词之前），并在 `作者资料/出处/` 记入台词级出处。

`examples/三国演义/世界书/历史/事件/桃园结义/角色/刘备.txt` 中的角色位置与候选台词（节选）：

```yaml
事件ID: 桃园结义
角色组ID: 刘备
事件触发语料:
  - 触发情境: 桃园焚香再拜，三人共誓。
    候选台词:
      - 念刘备、关羽、张飞，虽然异姓，既结为兄弟，则同心协力，救困扶危；上报国家，下安黎庶；不求同年同月同日生，只愿同年同月同日死。皇天后土，实鉴此心。背义忘恩，天人共戮！
```

对应的台词记录写在 `examples/三国演义/作者资料/出处/第001回.yaml` 第 98 行：

```yaml
- {事件ID: 桃园结义, 角色组ID: 刘备, 台词: 念刘备、关羽、张飞，虽然异姓，既结为兄弟，则同心协力，救困扶危；上报国家，下安黎庶；不求同年同月同日生，只愿同年同月同日死。皇天后土，实鉴此心。背义忘恩，天人共戮！, 来源: 三国演义第一回·行19}
```

用只读统计查看事件与台词覆盖情况，并用 `format` 检查 YAML 排版：

```sh
node cli/ygg.mjs tree examples/三国演义/世界书 --stats-only
node cli/ygg.mjs format examples/三国演义/世界书 --check
```

在 `examples/三国演义` 当前基线上，`tree --stats-only` 输出：`事件 150（独立 24），事件串 15；可达 150，不可达 0，结构异常 0`、`候选台词 181：原台词 181（100.00%），作者台词 0；台词记录 181 条`、`有事件级出处 150 个事件`。

- **作者审阅**：人工核对原台词是否真的出自该角色之口（不把他人对他说的台词误收进他的候选台词）、条件文本修改后五槽适用范围是否未变，以及台词记录与来源原文逐字一致。
- **通过标准**：全量 `ygg check` 无新增错误，需要统一排版时先确认差异再运行 `ygg format <世界书目录> --write` 并重跑 `check`。

### 试跑上下文

正文补完后，打包前先试跑一轮真实场景，确认某时某地、某些人在场时进入上下文的字符数与预算占用是否合理：

```sh
node cli/ygg.mjs context examples/三国演义/世界书 --方案 榜前长叹 --地点 涿县 --在场 刘备 --在场 张飞
```

该命令在 `examples/三国演义` 上实测输出：

- **汇总**：`总字符：8255`（`协议：3356`、`世界概况：473`、`世界状态：300`、`在场角色：1548`、`条目：100`、`事件：2468`）。
- **预算与审计**：`经历：6/6 条、1283/3000 字符`（按候选前置、当前地点与在场者经历选入 6 条并列出略过的 38 条及原因），`候选：1/4 条、697/4000 字符`（选入 `榜前定交`），`条目.地点：82/1500 字符`（选入地点链 `涿县`、`幽州`）。

也可在 `ygg view` 切换到**上下文预览**页面以图形表单运行同一计算，并勾选查看完整渲染正文。若发现重要经历或关键条目因超预算被略过，可在项目根目录创建或修改 `yggdrasill.yaml` 调整 `运行参数`（配置字段见 [参考：路由](参考/路由.md)），或精简过长的正文字段。

## 打包试玩

### 第 5 层：打包角色卡

- **输入**：全量 `check` 通过的世界书。
- **调用 skill**：`世界树·打包`（[`skills/ygg-pack/SKILL.md`](../skills/ygg-pack/SKILL.md)）。
- **代理产出**：在项目根目录编写 `卡面.yaml`，定稿跨版本稳定的 `卡ID`、`卡版本`、`名称`、`描述`、`开场白`（纯正文，不含 `<命令>`）、默认 `开局` 与 `开场命令`。

以 `examples/三国演义/卡面.yaml` 为例（节选核心字段）：

```yaml
卡ID: yggdrasill.sanguo-yanyi.ch01-03
卡版本: 0.2.0
名称: 三国演义·第一至三回
开局:
  开局时间: 中平001年04月02日
  方案: 榜前长叹
开场白: |-
  中平元年四月，涿县城中。
  ……
开场命令:
  - 确认初始化: {角色组ID: 刘备}
  - 确认初始化: {角色组ID: 张飞}
  - 写场景: {当前地点: {地标: 涿县, 场景: 招军榜文之前}, 在场: {刘备: true, 张飞: true}}
```

执行打包命令生成酒馆角色卡 JSON（`[项目目录]` 与 `--face` 均相对当前工作目录解析；省略 `--face` 时默认读取 `<项目目录>/卡面.yaml`）：

```sh
node cli/ygg.mjs pack examples/三国演义
```

产物输出到 `adapter/dist/<名称>.json`（旧脚本 `node adapter/build.mjs examples/三国演义 --face ../examples/三国演义/卡面.yaml` 仍保留向后兼容）。打包前务必核对构建日志中的开场命令全部执行成功、构建清单（`卡ID`、`卡版本`、`程序指纹`、`世界书哈希`）与卡内一致，且产物不含 `/作者资料/` 路径。

### 导入酒馆

打包完成后，按以下 3 步导入 SillyTavern 游玩：

1. **导入预设（可选）**：仓库里的 `presets/yggdrasill.json` 为**可选开箱预设**；已有常用的酒馆预设可直接沿用，无需替换，只需确保主提示词不要求模型在正文输出 `<命令>` 或状态块。
2. **导入角色卡**：导入 `adapter/dist/<名称>.json`，导入并打开聊天时**允许启用卡内世界树脚本**。若在卡内设置面板关闭独立记账回到旧版正文 `<命令>` 模式，还须允许并启用卡内局部正则。
3. **新建聊天开局**：进入开局前端调整开局时间、方案、启用角色组与版本、玩家模式及历史选择，提交封卷后即可开始游玩。未修改设置时默认开启独立记账（应答格式为提示词 JSON）。

### 修补记账

游玩中如果发现某一助手楼漏记事件或状态写偏，点击该助手楼记录旁的**「修补」**按钮打开弹窗：

- **留空直接提交**：只针对本楼失败项做定向补记；如果该楼本来就没有失败项，则不会发起模型请求。
- **输入一句自然语言说明后提交**：按你的说明（例如补记漏掉的事件、修改某字段或撤回误记内容）从上一楼底本重新生成本楼记账命令。

无论哪种方式，修补都会校验不丢失既有合法已写入；一旦遇到接口错误、格式错误、残留局部失败或任务已过时，适配层绝不覆写原记录，而是保留输入框中的说明并展示报错原因供重试。修补成功后会自动向后续楼层重放并刷新本轮上下文。

### 恢复只读

在酒馆流式生成或中断时，酒馆可能会先建出一条正文为空、但复制了上一楼变量的末尾占位助手楼。遇到生成未完成或存在末尾空助手楼时，先等待生成结束或删掉空尾楼，不要在此时点击「重新记账」或「修补」（系统会弹出警告提示等待，不会误锁整局）。

如果因为损坏的末尾楼层导致当前聊天进入「存档不可用（只读）」保护状态，直接在酒馆聊天界面删去问题尾楼即可：适配层在删除后会自动重新审计剩余楼层，确认记录链合法后立即恢复正常续写。

## 后续维护

### 局部修订

角色卡建成后需要局部修改时，呼叫 **`世界树·修订`**（[`skills/ygg-edit/SKILL.md`](../skills/ygg-edit/SKILL.md)）。先依据本次改动所涉及的**字段**判定最高改动级别（混合改动按最高级处理）：

- **设定级**：修改 `设定/` 中的第二层声明。需先在一次性临时副本做删改并跑 `check --static-only --json` 列出反向清单，连同文本检索命中项一并交作者确认迁移方案后，再改真文件，改后跑全量 `check` 与相关 `if`。
- **结构级**：修改事件时间/门槛/分支/变化、事件串、开局、角色组、档案生效条件或条目 ID 与引用。改前先用 `ygg trace` 查出“引用它”的全部位置，逐项同步，改后跑全量 `check`、相关 `if` / `preview` 与 `format --check`。
- **文本级**：修改档案正文、事件概要、条件文本、角色位置正文、条目、世界概况、扮演准则或 `设定/文本规范.yaml`。改动条件文本前先写下五槽适用范围，改后逐槽对照不走样，再跑 `check` 与 `format --check`（纯文本改动不要求跑 `if`）。

按级改前、改后的完整步骤清单见 [参考：命令：按级编辑操作清单](参考/命令.md#按级编辑操作清单)，最小检查矩阵见 [`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)。

### 升级角色卡

修改世界书或更新世界树程序后重新打包，旧聊天继续打开时会按以下规则处理（完整契约见 [第六章“酒馆适配”：兼容升级](06-酒馆适配.md#兼容升级)）：

1. **世界书变更（A/B/C 三级试重放）**：只要 `卡ID`、记录格式与程序指纹仍兼容，适配层会在内存中用新世界书对历史楼层做只读试重放：
   - **A 级（自动兼容）**：仅改写纯文本措辞或增加未到期的未来事件，重放结果与原保存快照完全一致。旧聊天直接放行、旧楼零改写，新楼继续使用新清单。
   - **B 级（纯增补待升级）**：仅在 `开局.角色组` 或 `世界.剧情标记` 新增默认键，既有历史零冲突。聊天暂锁生成并展示新增清单与「升级本局存档」按钮，玩家点击确认后逐楼无损升级。
   - **C 级（破坏性冲突）**：删改了既有角色组、剧情标记或引发重放失败/状态变化。存档保持严格只读（零覆写），面板按楼号列出具体差异供排查。
2. **程序指纹变更（`--compatible`）**：如果升级了世界树内核、适配脚本或协议模板导致 `程序指纹` 改变，必须在核对兼容性后，于打包时显式传入旧版 `程序指纹`（可重复传入多个）：

```sh
node cli/ygg.mjs pack <项目目录> [--face <卡面文件>] --compatible <64位旧程序指纹>
```

未列入 `兼容程序` 的旧聊天会按程序不兼容拒载，避免静默破坏已有存档。
