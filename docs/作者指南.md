# 作者指南

本文面向使用世界树制作、检查和维护角色卡的作者。用世界树做卡，通常不需要手工编写大量 YAML：装好本地工具和 11 个 AI skill 后，由编程代理按层生成内容，作者负责定方向、在关键节点拍板、用作者视图审树，以及在酒馆里试玩抽查。

机制原理、写作细则和命令参数留在各自的正本，按需查阅：

| 想查什么 | 去哪里 |
|---|---|
| 文本写法、越界清单和写作约束 | [写作规范](写作规范.md) |
| 11 个 `ygg` 命令的参数用法 | [参考：命令](参考/命令.md) |
| 11 个 AI skill 的职责清单 | [`skills/README.md`](../skills/README.md) |
| 本地可视化工具 `ygg view` 的用法 | [作者视图](../view/README.md) |
| 底层机制、字段表和酒馆适配细节 | [规范正本](README.md) |

## 环境准备

### 安装工具

本地工具链需要 **Node.js 20** 或更高版本：

```sh
git clone https://github.com/groundgrounder/Yggdrasill.git
cd Yggdrasill
npm ci
```

建议在仓库根目录执行 `npm link`，之后可在任意项目目录直接使用 `ygg`。若未链接，将下文中的 `ygg` 替换为 `node <世界树仓库>/cli/ygg.mjs`。

想先熟悉工具反馈，可对仓库内置的《三国演义》第一至三回示例（`examples/三国演义/世界书`，37 角色组、45 档案、80 条目、150 事件）跑两条只读命令：

```sh
ygg check examples/三国演义/世界书
ygg view examples/三国演义/世界书 --port 0
```

### 安装 Skill

仓库在 `skills/` 下提供 11 个自包含作者 skill，脱离仓库单独安装也能工作：

- **外部创作项目（推荐）**：在支持 Agent Skills 的编程代理环境中运行 `npx skills add groundgrounder/Yggdrasill`。
- **仓库目录内**：根目录已通过 `.agents/skills` 软链指向 `../skills`，兼容工作区级发现的代理会自动加载全部 11 个 skill。

### 初始化项目

在世界树仓库之外新建自己的角色卡项目目录：

```sh
ygg init ../我的角色卡 --纪年前缀 中平 --年位数 3 --月数 12 --每月天数 30
```

`init` 会建好标准目录和 4 份基础声明（`纪年.yaml`、`事件分类.yaml`、`本局变量.yaml`、最小 `条目库.yaml`），生成后即可通过 `ygg check --static-only`。建议同时在项目目录初始化 git 仓库，方便每层改动后对照和回退。

## 选择起点

开工前先按素材来源选好入口，三条路在第 0 层都会产出同构的五份全局总账，之后流程完全一致：

### 改编原作

将校对好的分卷或分章纯文本放进 `我的角色卡/来源资料/` 后冻结，调用 `世界树·通读`（[`skills/ygg-read/SKILL.md`](../skills/ygg-read/SKILL.md)）抽取分卷坐标、活词表和全局总账。

### 原创世界

无需准备原文，直接调用 `世界树·通读`，通过访谈梳理世界体系、人物分期、事件年表和分支构想，产出同样的五份全局总账。

### 迁移旧卡

手头已有 SillyTavern 角色卡（V1/V2/V3 的 PNG 或 JSON）或独立世界书 JSON 时，调用 `世界树·迁移`（[`skills/ygg-migrate/SKILL.md`](../skills/ygg-migrate/SKILL.md)）。它内置零依赖拆包脚本 `unpack-card.mjs`，会自动拆解原卡、识别 EJS/MVU/正则特征并输出映射对账表和同构总账，不动 `世界书/`。

## 协作方式

进场建卡或接手已有项目时，先呼叫 **`世界树·统筹`**（[`skills/ygg-guide/SKILL.md`](../skills/ygg-guide/SKILL.md)）。它会先跑 `ygg status` 诊断当前处于哪一层、缺什么文件，再按顺序调度对应的分层 skill。

开工前可以告诉代理采用哪种节奏：

- **引导模式（默认）**：每完成一层并跑过该层检查后停下汇报摘要、命令输出和待拍板项，经你确认再往下走。
- **自动模式**：直接让代理推进到指定阶段（例如“先搭到第 3 层骨架”）；只有在遇到范围未定、设定冲突或缺少原文等硬阻塞时才停下询问。

## 分层建卡

整张卡按第 0 层到第 5 层推进，原则是**先立事实坐标和逻辑骨架，确认结构无误后再补正文**。每层详细检查矩阵见 [`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)。

### 第 0 层：全局总账

- **调用**：`世界树·通读`（改编/原创）或 `世界树·迁移`（旧卡迁入）。
- **产出**：`作者资料/通读/` 下的五份全局总账（世界体系、人物总名单和分期方案、全书年表、分支和开局提案、待拍板清单）。本层不写 `世界书/`。
- **作者把关**：核对人物名单有没有漏人或重名、每人分期切点是否合理、体系维度是否覆盖全书，并逐项拍板待决歧义。

### 第 1 层：设定地基

- **调用**：`世界树·地基`（[`skills/ygg-foundation/SKILL.md`](../skills/ygg-foundation/SKILL.md)）。
- **产出**：`世界书/设定/` 下的各类声明，以及 `世界概况/`、`扮演准则/`。种类和取值只在 `设定/` 里声明一次，不在正文重复抄写。
- **作者把关**：核对纪年、等级序列、能力维度、剧情标记初值和文风要求；确认 `ygg check <世界书目录> --static-only` 达到 `0 错误`。

### 第 2 层：公共条目

- **调用**：`世界树·条目`（[`skills/ygg-entries/SKILL.md`](../skills/ygg-entries/SKILL.md)）。
- **产出**：地点、势力、技能、装备等公共条目库。条目保持一物/一技/一地一文件的原子粒度，同类共性放进分类说明文件，世上独一件的神兵可标 `唯一: true`。
- **作者把关**：确认第 3 层将要引用的地点、装备、技能 ID 已齐备，且条目正文没有混入“某角色当前持有或身处何地”的动态状态；确认 `ygg check <世界书目录> --static-only` 为 `0 错误`。

### 第 3 层：逻辑骨架

- **调用**：`世界树·骨架`（[`skills/ygg-skeleton/SKILL.md`](../skills/ygg-skeleton/SKILL.md)）。
- **产出**：全名单 `角色组.yaml`、最小合法档案壳、全书事件树、事件串、if 分支、`开局选项.yaml`、开局方案，以及事件级出处记录。本层正文先写简明占位，优先跑通结构。
- **出口检查**：

```sh
ygg check <世界书目录>
ygg if <世界书目录> --分支 <事件ID>:<分支ID>
ygg preview <世界书目录> <角色组ID> --方案 <方案ID> --状态
```

### 审树门禁

进入第 4 层补正文前，先用本地作者视图审一遍整棵树：

```sh
ygg view <世界书目录> --port 0
```

在浏览器里重点核对三件事，确认无误再锁定骨架：

1. **门槛是不是真因果**：有没有把“原作里它排在前面”误写成硬前置。
2. **切期分支对不对**：代表取得身份、任职或成婚的档案，生效条件是否引用了真正达成结果的分支。
3. **改写历史顺不顺**：在「如果视图」里点选关键 `if` 分支，确认失效的下游事件能自动截断，开局方案都能正常封卷。

视图用法和网页内编辑边界见[作者视图](../view/README.md)。

### 第 4 层：角色档案

- **调用**：`世界树·档案`（[`skills/ygg-profile/SKILL.md`](../skills/ygg-profile/SKILL.md)）。
- **产出**：逐份精写 `基本信息.txt`、`角色印象.txt`。
- **作者把关**：重点抽查两条红线：**不串期**（前期档案不提后期才出现的人和事）、**不越界**（不把当前职位、关系、持有物、伤势或所在写死进人设正文）。速查见 [`skills/shared/写作红线.md`](../skills/shared/写作红线.md) 和[写作规范](写作规范.md#档案)。

### 第 4 层：事件正文

- **调用**：`世界树·填景`（[`skills/ygg-scenes/SKILL.md`](../skills/ygg-scenes/SKILL.md)）。
- **产出**：按第 0 层坐标回查原文，补实 `事件.txt` 和各参与角色的 `角色/{角色组ID}.txt`；原台词逐字收入说话角色自己的 `候选台词`，并写入 `作者资料/出处/`。
- **作者把关**：抽查原台词有没有张冠李戴（别人对他说的台词不能收进他的候选台词），以及条件文本改写后适用范围有没有变窄或变宽。跑两条只读命令核对覆盖率和排版：

```sh
ygg tree <世界书目录> --stats-only
ygg format <世界书目录> --check
```

### 上下文校准

正文补完、打包之前，先抽几个典型场景试跑一轮真实路由，确认单轮字符数和各区块预算是否合理：

```sh
ygg context <世界书目录> --方案 <方案ID> --地点 <地点ID> --在场 <角色组ID>
```

也可以在 `ygg view` 的「上下文预览」页用表单运行同样计算。如果关键经历或条目因超预算被略过，可在项目根目录创建或修改 `yggdrasill.yaml` 调整运行参数（字段见[参考：路由](参考/路由.md)），或者精简过长的文本。

### 第 5 层：打包成卡

- **调用**：`世界树·打包`（[`skills/ygg-pack/SKILL.md`](../skills/ygg-pack/SKILL.md)）。
- **产出**：在项目根目录定稿 `卡面.yaml`（含跨版本稳定的 `卡ID`、`卡版本`、`名称`、`描述`、纯正文 `开场白`、默认 `开局` 和 `开场命令`），然后执行打包：

```sh
ygg pack <项目目录>
```

产物输出到 `adapter/dist/<名称>.json`。打包日志里确认三件事：开场命令全部执行成功、清单中的 `卡ID` / `卡版本` 正确、产物不含 `/作者资料/` 路径。

## 大卡验收

对于体量较大的卡（例如文件数 ≥ 200、角色组 ≥ 15、事件 ≥ 50、含多世界线或准备公开发布），推荐在打包后、进酒馆前跑一轮第 5.5 层离线试玩验收（轻量单幕卡可跳过）：

- **调用**：`世界树·验收`（[`skills/ygg-playtest/SKILL.md`](../skills/ygg-playtest/SKILL.md)）。
- **做法**：通过自带的零依赖脚本 `mount-card.mjs` 直接只读挂载打包好的角色卡 JSON，围绕静态检查覆盖不到的五个维度做推演：默认期防剧透、转折点改写后跨年不覆盖、多年沙盒的经历预算淘汰曲线、停用主角后的依赖图检查，以及开局前端和记账对抗测试。
- **处置**：发现的问题按卡侧缺陷、已知边界、引擎问题三分流；卡侧缺陷交给 `世界树·修订` 最小修复后重打。

## 酒馆试玩

拿到打包产物后，在 SillyTavern 做一轮实机确认：

1. **导入预设**：推荐导入仓库提供的配套**可选开箱预设** [`presets/yggdrasill.json`](../presets/yggdrasill.json)；若沿用自己常用的酒馆预设，必须先关闭预设中要求模型输出变量、状态栏或 `<命令>` 块的条目。
2. **导入角色卡**：导入 `adapter/dist/<名称>.json`（打包卡不含酒馆原生世界书）。需安装酒馆助手并在打开聊天时允许启用卡内脚本；若在设置中关闭独立记账回到旧版正文命令模式，另需开启卡内局部正则。
3. **开局实测**：新建聊天依次测试世界线切换、预设或自由开局、扮演或自建玩家、四模式开场白，以及在「设置 → 记账」中为后台记账指定便宜快模型（默认使用「提示词要求 JSON」）。

游玩过程中的单楼手动修补、流式中断空尾楼保护及删楼自愈机制，见[第六章“酒馆适配”](06-酒馆适配.md#手动修补)和[重放规则](06-酒馆适配.md#空尾楼保护)。

## 局部修订

角色卡建成后需要局部改卡时，呼叫 **`世界树·修订`**（[`skills/ygg-edit/SKILL.md`](../skills/ygg-edit/SKILL.md)）。改动按所涉及的**字段**分成三级，混合改动按最高级处理：

- **设定级**：改 `设定/` 中的声明。先在临时副本删改并跑 `ygg check --static-only --json` 拉出影响清单，确认迁移方案后再改真文件。
- **结构级**：改事件时间、门槛、分支、变化、事件串、开局、角色组、档案生效条件或条目 ID。改前先用 `ygg trace` 查清全部引用处，逐项同步后再跑全量 `check`、`if`、`preview` 和 `format --check`。
- **文本级**：改档案正文、事件概要、条件文本、角色位置、条目正文、世界概况或扮演准则。改条件文本前先核对适用范围不变，改后跑 `check` 和 `format --check`。

完整步骤见[参考：命令：按级编辑操作清单](参考/命令.md#按级编辑操作清单)。

## 版本升级

改完世界书或升级世界树工具链后重新打包，旧聊天继续打开时会走兼容校验（完整契约见[第六章“兼容升级”](06-酒馆适配.md#兼容升级)）：

- **世界书改动（A/B/C 三级试重放）**：只要 `卡ID` 和程序指纹兼容，适配层会在内存里用新世界书试重放旧楼。纯改文本或只增未来事件（**A 级**）直接无感放行；仅在开局角色组或剧情标记新增默认键（**B 级**）会提示一键无损升级；删改既有结构或引发状态差异（**C 级**）则锁定只读并列出冲突楼层。
- **引擎程序更新（`--compatible`）**：升级世界树程序导致 `程序指纹` 变化时，在核对兼容后通过 `--compatible` 显式声明兼容的旧程序指纹（可重复传入），避免旧存档被误拒：

```sh
ygg pack <项目目录> --compatible <64位旧程序指纹>
```
