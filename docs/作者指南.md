## 1. 5 分钟看懂世界树

### 和酒馆传统世界书有什么不同

酒馆传统世界书靠消息里的**关键词**触发插入提示词。世界树里的 `世界书/` 是作者维护的**源文件目录**，游玩时由世界树程序读取：每轮由路由根据本局状态（当前时间、地点、在场角色、已发生事件）精准挑选相关档案、条目、经历与候选进入上下文，不按关键词触发。

世界书本身也不是最终角色卡。打包时，把 `世界书/`、运行参数 `yggdrasill.yaml`、世界树内核与适配脚本、协议文本模板，以及 `卡面.yaml`（卡名、开场白、默认开局与开场命令）合成在一起，才是导入酒馆的角色卡 JSON。

### 五个核心零件

以 `examples/三国演义` 中的真实对象为例，一张卡只围绕五个零件运转：

| 零件 | 它是什么 | 三国演义真实例子 |
|---|---|---|
| **角色组与档案** | 角色组是本局变量、事件与关系引用的唯一主体；档案是角色在某段时期内稳定的事实与行为方式 | `刘备` 经 `刘备·白身期` → `刘备·结义起兵期` → `刘备·安喜县尉期` → `刘备·平原县令期` 随事件确认切期 |
| **事件与 if 分支** | 预设事件记录时段、因果门槛、核心参与者、分支与状态变化 | `桃园结义` 写入三兄弟结义关系；`张飞怒欲杀卓` 若走 `提刀杀卓` 分支，后续 30 个事件不再发生 |
| **条目库** | 地点、装备、势力、技能等公共对象库，只写对象本身，不写谁此刻持有或身在何处 | 地点 `涿县`、装备 `双股剑`、势力 `涿县义军` |
| **本局** | 正在这一局里实时生效的唯一状态事实源，只能经封卷和命令写入 | 谁在场、当前时间地点、刘备的 `职位` 与 `知识`、哪些事件已确认 |
| **文本容器** | 全卡共享的背景正文与叙事文风要求 | `世界概况/天下大势与朝纲.txt`、`扮演准则/演义白话.txt` |

### 先分清两个「层」

新人最容易把两种完全不同的“层”混在一起：**建卡第 0–5 层**讲的是**建卡按什么顺序做**；**规则五层 / 修改三级**讲的是**改一个字段受什么约束、跑什么检查**。

| 维度 | 建卡第 0–5 层（做事顺序） | 规则五层 / 修改三级（改字段受什么约束） |
|---|---|---|
| 核心问题 | 从零做一张卡先做什么、后做什么 | 改某个具体字段时，影响范围有多大、要跑哪几项检查 |
| 划分依据 | 建卡流水线的阶段（0 通读 → 1 地基 → 2 条目 → 3 骨架 → 4a 档案 & 4b 填景 → 5 打包） | **字段的属性**（第一层架构不可由卡改；第二层=设定级；第三层=结构级；第四/五层=文本级） |
| 常见误区 | 以为“先写好档案再补事件”，其实必须先在第 3 层跑通骨架再在第 4 层填肉 | 以为 `.txt` 都是文本级、`.yaml` 都是结构级——其实 `事件.txt` 里门槛是结构级、概要是文本级；`角色组.yaml` 里显示名和简介也受文本规范检查 |

### 项目目录与世界书目录

一个世界树项目根目录下通常有四样东西：

| 路径 | 用途 | 是否打包进卡 |
|---|---|---|
| `世界书/` | 作者书写的核心源文件目录 | 是 |
| `作者资料/` | 第 0 层通读账本、出处、暂存、候选、生成物、归档与审阅存储 | 否 |
| `来源资料/` | 原作纯文本或设定集，仅供作者与第 0/4 层人工核对，工具不读取 | 否 |
| `yggdrasill.yaml` | 运行参数（经历、候选、各条目库预算与提及窗口），可选 | 是（仅运行参数） |

`世界书/` 根下只有三类目录（以 `examples/三国演义/世界书/` 为例）：

- **固定根**（名称与结构由第一层规定）：`设定/`（只放 `.yaml` 声明，如 `设定/纪年.yaml`）、`角色/`（如 `角色/刘备/角色组.yaml` 与 `角色/刘备/档案/刘备·白身期/`）、`历史/`（`历史/事件/桃园结义/事件.txt`、`历史/事件串/榜文聚义.yaml`、`历史/开局选项.yaml`、`历史/开局方案/榜前长叹.yaml`）。
- **文本容器**（名称固定）：`世界概况/`（如 `世界概况/天下大势与朝纲.txt`）与 `扮演准则/`（如 `扮演准则/演义白话.txt`）。
- **条目库**（在 `设定/条目库.yaml` 中声明后平铺在根下）：三国示例声明了 `地点/`（按上下级分，如 `地点/幽州/涿县/涿县.txt`）、`装备/`（按种类分，如 `装备/兵器/双股剑.txt`）、`势力/`（按种类分，如 `势力/义军/涿县义军.txt`）。

世界书文件的内容**全按 YAML 语法书写**，扩展名只表示读者：`.txt` 供叙事模型阅读，组装上下文时剥离机器字段；`.yaml` 给工具读取，只有显示名、别名、版本简介、事件串概述、开局选项文字与开局方案概述会进入上下文或展示给玩家。

### 作者资料目录

`作者资料/` 放在 `世界书/` 之外，不进入上下文、不参与运行、不属于规则五层：

| 目录 | 用途 | 维护方式 |
|---|---|---|
| `通读/` | 第 0 层的分卷坐标账本、活词表与五份全局总账 | `init` 预建 `通读/分卷/`；按“通读”skill 两遍读法维护 |
| `出处/` | 结构化来源记录：事件级记录写事件来源，台词记录写每句原台词来源 | YAML 列表；`check` 与 `tree` 读取核对，见[参考：世界书](参考/世界书.md#出处记录) |
| `暂存/` | 已写好、待条件满足后接回世界书的内容 | 按世界书相对布局存放，并在 `暂存/暂存清单.yaml` 登记；接回后删项 |
| `候选/` | 尚未定下的创作内容 | 定下写入世界书后从 `候选/` 删除，避免两处重复 |
| `生成/` | 工具导出的文件（如 `ygg tree --out`） | 工具生成，不手改 |
| `归档/` | 撤下的内容 | 保留世界书中的相对布局，便于回查 |
| `审阅器/` | `ygg view` 缺省审阅存储（批注、节点布局、保存前备份） | 视图首次写入时自动创建与维护，不手改 |

## 2. 准备工作：环境、体验、初始化与挂载 Skill

### 环境要求与三国体验

需要 **Node.js 20+**，在仓库根目录执行 `npm ci` 安装依赖后即可运行。先在仓库根目录跑三条只读命令，直观感受《三国演义》示例（若未将 `ygg` 链接到 `PATH`，统一写成 `node cli/ygg.mjs`，或跨项目写成 `node <世界树仓库>/cli/ygg.mjs`）：

```sh
# 1. 全量检查（静态检查 + 协议抽样）
node cli/ygg.mjs check examples/三国演义/世界书

# 2. 推演 if 线：如果张飞在帐前怒杀董卓，后续会发生什么？
node cli/ygg.mjs if examples/三国演义/世界书 --分支 张飞怒欲杀卓:提刀杀卓

# 3. 启动图形作者视图（仓库内示例必须把 --storage 指到仓库外）
node cli/ygg.mjs view --worldbook examples/三国演义/世界书 --storage /tmp/三国演义-审阅 --port 0
```

在当前基线上，`check` 会汇报 `0 错误，10 提示；37 角色组，45 档案，80 条目，150 事件`；`if` 会直观列出 `没发生（30）` 个下游事件（如 `丁原吕布败董卓`、`温明园议废立`、`省中强废立` 等）。

### 新建项目

在世界树仓库外新建一张自己的卡，先用 `ygg init` 生成脚手架：

```sh
node cli/ygg.mjs init ../我的世界卡 --纪年前缀 中平 --年位数 3 --月数 12 --每月天数 30
```

`init` 会创建 16 个目录与 4 份基础声明文件（`纪年.yaml`、`事件分类.yaml`、`本局变量.yaml`、最小 `条目库.yaml`），开箱即可通过 `check --static-only`。随后：

- **改编原作**：将分卷/分章纯文本冻结并放进 `我的世界卡/来源资料/`，从第 0 层通读起步；
- **原创世界**：无需原文，直接与代理通过大纲访谈产出同构总账。

### 挂载 9 个作者 Skill

仓库 `skills/` 下共有 9 个按职责分工的作者 skill（清单与分工见 [`skills/README.md`](../skills/README.md)）：

- **在世界树仓库目录内启动代理**：仓库根的 `.omp/skills` 符号链接指向 `../skills`，代理会自动发现全部 9 个 `世界树·…` skill；
- **在其他项目目录跨项目使用**：把本仓库 `skills/` 的**绝对路径**登记到代理配置的 `skills.customDirectories`。**不要把 `skills/` 复制到仓库外**：skill 内部指向 `docs/`、`cli/`、`adapter/`、`shared/` 的指针都是仓库相对路径，复制出去会断链。

### 怎么和代理配合

进场或接手已有项目时，先点名调用 **`世界树·统筹`**。它会先跑只读 `ygg status`，盘点第 0–5 层现状、计数与缺口，再决定下一步。配合时有两种运行模式，开工前向代理说明即可：

- **引导模式（默认）**：每完成当前层并跑过出口门禁，代理即停下呈报产出摘要、工具结果与待拍板清单，经你确认后再进入下一层；
- **自动模式**：要求代理自动推进到指定层（例如“推进到第 3 层骨架”），代理只会在硬阻塞（改编范围未定、核心设定冲突、缺少来源原文）时停下询问，其余细节先取保守方案记入待复核清单。

## 3. 从零建卡实战：第 0 → 5 层走读

建卡严格按 `0 → 1 → 2 → 3 → 4a/4b → 5` 推进，核心原则是**先立坐标账本、再搭可运行逻辑骨架、最后填文采与台词**。各层出口检查矩阵以 [`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md) 为准。

### 第 0 层·通读

- **做什么**：两遍读法的第一遍。分批 Map 读原作（每批 1 卷或 3–5 章），抽出时间地点、体系规则、人物轨迹、事件原子、名场面坐标与跨卷伏笔六张结构表进 `作者资料/通读/分卷/`，同步维护 `活词表.yaml`；全部读完后 Reduce 消歧归并，产出五份全局总账（世界体系、人物总名单与分期方案、全书年表与因果事件、if 分岔与开局提案、待拍板清单）进 `作者资料/通读/`。本层**不写 `世界书/`**。无原作的原创世界走作者访谈产出同构总账。
- **呼叫哪个 skill**：`世界树·通读`（`skills/ygg-read/SKILL.md`）。
- **作者要拍什么板**：冻结原文版本与覆盖范围；拍板人物总名单、每人分期切点、体系维度取值与未决歧义。
- **出口门禁**：覆盖范围内每卷每章坐标可查，跨卷先验词与词表回查通过，待拍板项收口。

### 第 1 层·地基

- **做什么**：依据拍板总账复制并改写 `defaults/设定/` 到 `世界书/设定/`（3 份必需 `纪年.yaml`、`事件分类.yaml`、`本局变量.yaml`，按需补 `等级.yaml`、`能力.yaml`、`条目库.yaml`、`剧情标记.yaml`、`角色分类.yaml`、`文本规范.yaml`），并建立 `世界概况/` 与 `扮演准则/`。牢记**单一来源原则**：种类与取值只在 `设定/` 声明一次，不在正文或作者资料里抄写清单。
- **呼叫哪个 skill**：`世界树·地基`（`skills/ygg-foundation/SKILL.md`）。
- **作者要拍什么板**：纪年格式、等级序列、能力维度、条目库结构、剧情标记初始值与叙事文风准则。
- **三国演义真实样本**：

`examples/三国演义/世界书/设定/纪年.yaml`：
```yaml
前缀: 中平
年位数: 3
月数: 12
每月天数: 30
```

`examples/三国演义/世界书/扮演准则/演义白话.txt`（节选）：
```yaml
叙述人称: 采用第三人称章回白话行文，句段简练，不以现代语入话。
对白与描写:
  - 定交、议事、朝对以对白为主；战阵之事写其动作与号令，不铺陈血污。
```

- **出口门禁**：`ygg check <世界书> --static-only` 0 错误。

### 第 2 层·条目

- **做什么**：按 `设定/条目库.yaml` 铺公共条目库舞台（如地点树、势力、装备、技能）。条目标注对象本身与领域特有边界，**绝不写**某个角色此刻持有或身处何地；细部文采可先留简，留待第 4b 层润色。
- **呼叫哪个 skill**：`世界树·条目`（`skills/ygg-entries/SKILL.md`）。
- **作者要拍什么板**：需要哪些公共地点、势力与关键器物，以及目录树上下级/分类归属。
- **三国演义真实样本**：

按上下级分的地点条目 `examples/三国演义/世界书/地点/幽州/涿县/涿县.txt`：
```yaml
地点ID: 涿县
类型: 城邑
概况: 幽州境中之县，楼桑村所在。
```

按种类分的装备条目 `examples/三国演义/世界书/装备/兵器/双股剑.txt`：
```yaml
装备ID: 双股剑
类型: 兵器
简介: 双剑一式两柄，合称双股。
特点:
  - 两剑同式，成对携用。
```

- **出口门禁**：`ygg check <世界书> --static-only` 0 错误，第 3 层将引用的公共 ID 全部就绪。

### 第 3 层·骨架

- **做什么**：**逻辑跑通再填肉**。按总账建全名单 `角色组.yaml`（注意别名用两字及以上可辨识称呼，**禁用单字别名**以防路由误匹配），建最小合法档案壳；搭全书事件树、真正因果门槛与 if 分支、事件串、开局选项与开局方案，并在 `作者资料/出处/` 记好事件级来源。正文字段此时只写足以过检与表意的短句。
- **呼叫哪个 skill**：`世界树·骨架`（`skills/ygg-skeleton/SKILL.md`）。
- **作者要拍什么板**：角色切期条件、关键因果链（不把原作顺序写成硬门槛）、if 分岔分支、开局选项与开局方案（建议配合 `ygg view` 审树后拍板）。
- **三国演义真实样本**：

`examples/三国演义/世界书/角色/刘备/角色组.yaml`（节选，展示切期链）：
```yaml
显示名: 刘备
别名:
  - 玄德
角色包: 第一回群像
分类: 结义兄弟
默认启用: true
初始化方式: 出场自动
初始所在: 涿县
档案:
  - 档案ID: 刘备·白身期
    默认: true
    初始能力:
      勇力: 骁勇
  - 档案ID: 刘备·结义起兵期
    前置档案: 刘备·白身期
    生效条件:
      事件确认:
        事件ID: 桃园结义
        分支ID: 结义
```

`examples/三国演义/世界书/历史/事件/张飞怒欲杀卓/事件.txt`（节选，展示双分支 if 线）：
```yaml
事件ID: 张飞怒欲杀卓
默认分支: 提刀悬置
分支:
  - 分支ID: 提刀悬置
    分支条件: 张飞怒气正炽，提刀便要入帐来杀董卓。
    分支结果: 刀未落，帐前之局悬而未决。
  - 分支ID: 提刀杀卓
    分支条件: 张飞怒不可按，提刀入帐杀董卓。
    分支结果: 董卓死于张飞刀下，帐前大乱。
    变化:
      - 路径: 世界.剧情标记.董卓之命
        操作: 设定
        值: 已死于张飞之手
```

开局方案 `examples/三国演义/世界书/历史/开局方案/榜前长叹.yaml`（另有 `温明园盛宴.yaml`）：
```yaml
概述: 中平年间，黄巾已起，三路讨贼已发；涿县城中，刘备见招军榜文慨然长叹，张飞厉声喝问，村店又遇关羽，三英雄将在桃园结义。
```

## 5. 导入酒馆试玩与后续更新维护

### 进酒馆 3 步

1. **导入配套预设**：在酒馆中导入仓库 `presets/yggdrasill.json`（主提示词限定叙述者只写正文，可按文风微调，不影响协议与检查）。
2. **导入角色卡 JSON**：导入 `adapter/dist/<名称>.json`，导入并打开聊天时**允许启用卡内世界树脚本**（若在设置中关闭独立记账回到旧 `<命令>` 模式，还须允许并启用卡内局部正则）。
3. **新建聊天开局**：进入开局前端按需调整开局时间、方案、启用角色组与版本、玩家模式及历史选择，提交封卷后即可开始游玩。

### 试玩期实用说明

- **默认记账**：未改设置时默认开启**独立记账**（应答格式为提示词 JSON）。叙事模型只写纯净剧情正文，适配层另发一次不写正文的记账请求转换为协议命令。
- **漏记或误记怎么修**：点击该助手楼的**「修补」**按钮——留空提交会仅针对本楼失败项定向补记；写一句自然语言说明（如补记漏掉的事件、修改或撤回某条写入）则会按说明从前楼底本重出，且**校验不丢失既有合法已写入、遇到失败零覆写**。
- **遇到生成中或末尾空楼不要慌**：酒馆生成新回复时可能会先建出正文为空的末尾占位助手楼；此时先等生成结束或手动删掉该空尾楼，不要急着点击「重新记账」或「修补」。
- **误入只读如何自愈**：若因损坏尾楼触发存档只读保护，直接在酒馆中删去问题尾楼，适配层会重新审计剩余楼层，校验合法后自动恢复正常注入与续写。

### 旧存档兼容与 A/B/C 三级升级

日后继续润色世界书或连载增补内容并重新打包后，打开旧酒馆聊天时，适配层会在内存中用新世界书对历史楼层做一次只读试重放，按**世界书更新 A/B/C 三级**处理（底层机制详见[第六章“酒馆适配”](06-酒馆适配.md#卡世界书与旧记录)）：

| 级别 | 什么改动会落入这一级 | 旧聊天怎么处理 |
|---|---|---|
| **A 级（无缝兼容）** | 纯改档案/事件/条目文案措辞、增补未来未到期事件等，试重放零差异 | 自动无缝放行、旧楼零改写，直接续写新楼 |
| **B 级（纯增补待升级）** | 连载纯新增 `角色组` 或新 `剧情标记`，原有历史、事件与既有字段 100% 不变 | 暂锁生成，展示新增明细与「升级本局存档」按钮，玩家确认后一键无损升级 |
| **C 级（破坏性冲突）** | 删改已有角色组/剧情标记、改坏历史事件或引发重放命令失败 | 严格只读保护（零覆写），展示带楼号与具体字段/命令原因的精准差异明细 |

若不是世界书本身变化，而是升级了世界树内核/适配程序（`程序指纹` 变化），请在核对兼容性后于打包时显式传入 `--compatible <64位旧程序指纹>`（可重复传入），构建清单才会放行旧程序指纹创建的聊天。

## 6. 建成后日常修订与人工审阅

### 建成后局部修订

卡片建成后做局部修改，呼叫 **`世界树·修订`**（`skills/ygg-edit/SKILL.md`）。先按**所改字段**判定本次最高改动级别（混合改动取最高级，连贯改完后再跑检查）：

| 级别 | 改了什么字段 | 必做关键动作（改前 → 改后） |
|---|---|---|
| **设定级** | `设定/` 中的第二层声明 | 在临时副本改/删取值跑 `check --static-only --json` 得反向清单 + 文本检索，与作者确认迁移值后再改真文件，改后跑全量 `check` 与相关 `if` |
| **结构级** | 事件时间/门槛/分支/变化、事件串、开局、角色组、档案生效条件、条目 ID 与引用 | 改前跑 `ygg trace` 列出“引用它”并逐项同步；改后跑全量 `check`、相关 `if`/`preview` 与 `format --check` |
| **文本级** | 档案正文、事件概要与条件文本、角色位置正文、条目、概况、准则、`文本规范.yaml` | 条件文本改前写五槽、改后对照五槽不走样；改后跑 `check` 与 `format --check`（纯文本不要求跑 `if`） |

详尽的按级改前/改后步骤清单见[参考：命令](参考/命令.md#按级编辑操作清单)，最小检查矩阵正本见[`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)。

### 维护作者资料

- **`出处/`**：坚持维护事件级（`事件ID`、`来源`）与台词级（`事件ID`、`角色组ID`、`台词`、`来源`）两种记录；台词记录中的原台词在 `check` 中豁免陈旧写法提示、破折号降为提示，并在 `ygg tree` 中统计为原台词。
- **`暂存/`**：条件未熟暂未接回的内容按世界书相对布局放进 `暂存/`，并在 `暂存/暂存清单.yaml` 逐项登记；接回世界书后删去清单对应项。
- **`候选/` 与 `归档/`**：未定构想放 `候选/`，定下写入世界书后立即从 `候选/` 删除；撤下的旧内容移入 `归档/` 并保留相对布局，不用 `归档/` 代替 `候选/` 或 `暂存/`。

### 人工审阅 6 项核心要点

工具能查语法与引用，语义仍须作者把关。一次人工审阅至少核对这 6 项（红线唯一出处见[`skills/shared/写作红线.md`](../skills/shared/写作红线.md)）：

1. **引用同步**：结构级改动前后跑 `trace`，核对“引用它”的每一处文件与字段都已同步。
2. **出处与台词归属**：原台词是否真在当前角色的候选台词中，有无误收别人对他说的话，台词记录是否齐全。
3. **档案时期与越界断言**：档案正文是否只写本时期及之前已确立的事实，有无把“当前职位/关系/持有物/伤势/所在”写进文本。
4. **条件文本五槽适用范围**：叙事条件、分支条件、介入条件、触发情境、触发限制改字后，对象/地点/时间/分支/触发情形五槽范围是否保持不变。
5. **事件串结局可达**：结合 `check` 的 `事件串.结局不可达` 提示与 `if` 的“停住的事件串”，确认是结构切断还是有意留白。
6. **检查结果区分已有与新增**：永远把“改动前已有”和“本次新增”分开列明，不把 `check` 退出码 0 当成“没有提示”。

## 7. 新人最容易踩的 6 个坑

1. **把当前状态写进档案或事件正文**：在档案里写“现任安喜县尉”“与关张已结义”或“腰间佩着双股剑”。这些全属于本局状态，只能由事件变化表或写场景命令写入。
2. **把“原作顺序”写成事件门槛，或误用 `none` 表示“在它之前”**：门槛只写真正的因果（没它就不可能发生）；`none` 表示**终身排斥**，一旦确认本事件，被排斥事件就永远不能再确认。只想表达先后请用 `当前时间` 或 `事件串状态`。
3. **把别人说的话写进当前角色的候选台词，或把整句台词写进档案**：原台词只收**实际说话人自己说的话**进角色位置；档案只写表达规律与句式，写入整句台词会导致每轮进入上下文被模型反复套用。
4. **把建卡第 0–5 层与规则五层/修改三级搞混，按扩展名判层**：只改 `事件.txt` 的 `事件概要` 是文本级（第四层），而改 `角色组.yaml` 的 `生效条件` 是结构级（第三层），别按 `.txt`/`.yaml` 扩展名决定要跑什么检查。
5. **看到 `check` 退出码为 0 就忽略提示，或把 `format` 当内容检查**：只有错误会让 `check` 返回非零，但提示（如 `事件串.结局不可达`、`文本.长度`）往往暴露真问题；`format` 只管 YAML 缩进和键序，不查内容与引用。
6. **改了已有对象 ID 或删了既有角色组/剧情标记，还指望旧聊天无缝兼容**：对象 ID 与既有角色组/剧情标记是旧楼层存档的锚点，删改后旧聊天会直接落入 C 级只读保护；改动 ID 前务必确认没有需兼容的旧存档。
