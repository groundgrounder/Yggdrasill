# 作者指南

本文写给写卡作者，不面向内核、检查器或酒馆适配的实现者。它说明一张世界树卡从目录、写作到检查与审阅的常用路径；机制与字段的完整规定仍在[世界树文档](README.md)中，本文只做入口与索引。

开始前至少读一遍[第一章“世界书”](01-世界书.md)与[写作规范](写作规范.md)。前者解释世界书怎样被程序与模型读取，后者规定文本怎样写。字段表在[参考](参考/世界书.md)，检查器的规则名在[参考：检查规则](参考/检查规则.md)。

最短路径：

1. 以 `examples/雾港/` 为目录参照，认清世界书、作者资料与各个固定目录。
2. 按写作规范写档案、事件、条目与文本；不确定改哪一层时，先看本文第 2 节。
3. 在项目目录跑 `check`，结构改动先跑 `trace`，路径改动用 `if`，排版用 `format`；按级最小检查的口径见 [`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)。
4. 按本文第 3 节选择 skill，按第 5 节维护出处、候选与审阅清单。

## 1. 项目、世界书与作者资料

### 1.1 项目根

一个世界树项目是这张卡的工作目录。根下通常有：

| 路径 | 用途 | 是否参与运行 |
|---|---|---|
| `世界书/` | 作者书写的源文件目录，程序与检查器读取它 | 是 |
| `作者资料/` | 出处、暂存、候选、生成物与归档等工作资料 | 否 |
| `来源资料/` | 原作、设定集等来源材料，可选 | 否 |
| `yggdrasill.yaml` | 运行参数，例如各部分每轮的条数与字符预算，可选 | 是，仅运行参数 |

仓库中的示例项目是 `examples/雾港/`：`examples/雾港/世界书/` 是它的世界书，`examples/雾港/作者资料/` 是它的作者资料。代码只校验 `作者资料/出处` 的记录与所引对象；`来源资料/` 供作者人工核对，不被读取或校验。

世界树的世界书是**作者书写的源文件目录**。它与酒馆中按关键词触发的“世界书”不是同一种东西：酒馆条目按消息中的关键词决定是否插入；世界树的世界书由程序读取，每轮把哪些部分交给叙事模型，由路由按本局状态挑选，不按关键词触发。它也不是最终角色卡：打包时，世界书与世界树的程序、卡名、头像、开场白等卡面内容合在一起，才生成角色卡。本指南只写世界书这一侧。

### 1.2 世界书目录

世界书的根下只有三类目录：

| 类 | 目录 | 内容 | 雾港中的例子 |
|---|---|---|---|
| 固定根 | `设定/` | 第二、五层的声明，只放 `.yaml` | `设定/剧情标记.yaml`、`设定/能力.yaml`、`设定/文本规范.yaml` |
| 固定根 | `角色/` | 每个角色组一个目录，含 `角色组.yaml` 与 `档案/` | `角色/灯塔学徒/角色组.yaml`、`角色/灯塔学徒/档案/林澜·学徒期/` |
| 固定根 | `历史/` | 事件、事件串、开局选项与开局方案 | `历史/事件/拜师/事件.txt`、`历史/事件串/学徒修习.yaml`、`历史/开局方案/码头少年.yaml` |
| 文本容器 | `世界概况/` | 跨越各条目库、在整个可游玩时期都成立的世界正文 | `世界概况/海况与雾季.txt` |
| 文本容器 | `扮演准则/` | 叙述人称、对白比例、文风与写作约束 | `扮演准则/海港白描.txt` |
| 条目库 | 由 `设定/条目库.yaml` 声明，平铺在根下 | 技能、装备、地点、势力、船只等公共对象 | `技能/灯语/灯语·短讯.txt`、`地点/北湾/雾港/灯塔/灯塔.txt` |

固定根的名称与结构由第一层规定，不能改名。文本容器的名称也固定。条目库有哪些、各库怎样分目录、有哪些字段，由这张卡的 `设定/条目库.yaml` 声明；不同卡可以没有技能库或地点库，也可以增加自己的库。根下出现未声明的目录，检查器报错。

世界书的文件都按 YAML 书写，扩展名只表示读者：

- `.txt` 是供叙事模型阅读的文件。程序在组装上下文时剥离机器字段，剩下的文本字段进入上下文。
- `.yaml` 是工具数据。只有角色组与版本的显示名、别名，版本的简介，事件串的概述，开局选项的问题与选项文字，开局方案的概述这几类内容会进入上下文或展示给玩家；其余字段只给工具读。

`.txt` 与 `.yaml` 不是两种语法，写错 YAML 一样会解析失败。

对象 ID 通常来自目录名或文件名。角色组、档案、事件、事件串、开局方案与条目的 ID 同时是目录名或文件名；事件与条目的 `.txt` 会再写一次 ID，必须与文件名或目录名一致。档案的两份文件不写档案 ID，档案 ID 由目录名给出。

### 1.3 角色组、档案、事件、条目

| 对象 | 放在哪里 | 是什么 | 雾港中的例子 |
|---|---|---|---|
| 角色组 | `角色/{角色组ID}/角色组.yaml` | 本局变量、事件参与者与关系引用的主体 | `灯塔学徒`、`秦守`、`白棠`、`周岚` |
| 版本 | `角色组.yaml` 的 `版本` 与 `档案` | 同一角色组可选的不同人物；开局选定其一 | `灯塔学徒` 的 `林澜` 与 `林汐` |
| 档案 | `角色/{角色组ID}/档案/{档案ID}/` | 一个版本在某段时期内稳定的事实与行为方式 | `林澜·学徒期/基本信息.txt`、`林澜·学徒期/角色印象.txt` |
| 事件 | `历史/事件/{事件ID}/事件.txt` | 本局改变的单位：时段、门槛、核心参与者、分支与变化 | `拜师`、`大雾之夜`、`学徒守灯` |
| 角色位置 | `历史/事件/{事件ID}/角色/{角色组ID}.txt` | 某个角色组在某个事件中的视角、知情、记忆与台词 | `历史/事件/拜师/角色/秦守.txt` |
| 事件串 | `历史/事件串/{事件串ID}.yaml` | 事件树中有开头、有结局的一段过程 | `学徒修习`、`雾夜余波` |
| 开局选项 | `历史/开局选项.yaml` | 开局之前可选择的历史分支 | `拜师` 的“拜师 / 未拜师” |
| 开局方案 | `历史/开局方案/{方案ID}.yaml` | 作者预设的开局组合 | `码头少年`、`补考之年` |
| 条目 | 已声明的条目库中，一条一个 `.txt` | 技能、装备、地点、势力等公共对象 | 技能 `灯语·短讯`、地点 `灯塔` |

角色组是主体，版本是它的不同可能，档案是版本在某段时期的稳定设定。`灯塔学徒` 有两个版本 `林澜` 与 `林汐`，各自按少年期、学徒期、守塔期写档案。当前适用哪一份档案由协议在读取时解析，不由文件顺序决定。

事件写本局的变化。`拜师` 的 `拜师` 分支写入所在、身份、技艺与关系；`未拜师` 分支写入另一种身份。事件串只命名过程与结局，不规定结构；串内先后仍由门槛给出。开局选项只处理开局之前的历史；开局方案把它与开局时间、角色组组合起来。

条目写公共对象本身，不写某一局中它此刻的状况。`灯语·短讯` 写这个技能是什么、怎样使用、有什么边界；不写“林澜已经学会它”。`灯塔` 写地点本身；谁此刻在灯塔里，由场景状态写入。

文本容器写稳定的世界内容与写作约束。`世界概况/` 写在整个可游玩时期都成立的世界背景；`扮演准则/` 写叙述人称、对白比例、文风偏好与本卡的写入约束。二者都不写本局状态。

### 1.4 四种写作分工

写作时最常混的是这四件事：

| 写什么 | 放到 | 不要写成 |
|---|---|---|
| 稳定的事实与行为方式：身份感、体貌、表达规律、通用反应 | 档案的 `基本信息.txt` 与 `角色印象.txt` | 当前关系、当前职位、当前穿着、当前持有物、当前伤势 |
| 状态变化：关系、婚姻、家系、职位、资产、持有物、伤势、能力的取得与丧失、所在 | 事件的变化表，或场景命令 | 档案正文、事件概要、分支结果里的状态断言 |
| 公共对象：技能、装备、地点、势力、船只 | 条目库中的条目 | 某个角色此刻是否持有、是否已经学会 |
| 世界背景与文风约束 | `世界概况/`、`扮演准则/`、`设定/文本规范.yaml` | 本局的时间、地点、在场者或关系状态 |

档案写“这个人会怎么做”，不写“现在是什么状态”。事件负责“发生了什么变化”。条目承载公共对象，文本字段不替代本局状态。当前所在与当前地点属于场景状态，由写场景写入，不靠档案或事件概要交代。

原台词逐字收进**实际说话角色**的角色位置。`拜师` 中秦守的台词在 `历史/事件/拜师/角色/秦守.txt` 的候选台词中，出处记在 `作者资料/出处/`；不要把别人的台词写进秦守的角色位置，也不要把台词写进秦守的档案。名单外说话人的台词不收录，只在核定日志中按章计数。

同一信息只写在职责最贴切的一处。换一种说法复述也算重复；档案、事件、条目与说明文件之间不要互相抄写。

## 2. 五层：改什么，谁来改

层是**字段的属性**，不是文件的属性，也不是按文件名做的简单分类。同一个文件常常同时含有结构字段与文本字段：`角色组.yaml` 里有版本、档案项与初始能力，也有按文本规则书写的显示名与简介；别名用于识别被提及的称呼，属第三层，按别名的结构规则核对。`事件.txt` 里有门槛、分支与变化，也有事件标题、事件概要与叙事条件。判断一层，看改动这个字段时受哪一层规则约束、要做哪一层检查。

| 层 | 名称 | 内容 | 作者能做什么 | 雾港中的例子 | 改动后 |
|---|---|---|---|---|---|
| 一 | 架构 | 世界树运行所依据的机制：对象、求值、状态写入 | 不能由卡覆盖；只能修订世界树的规范 | 事件确认、档案解析、命令与封卷 | 跑内核与一致性测试 |
| 二 | 背景设定 | 这张卡自己的种类与取值 | 可以改 `设定/` 中的声明，但要迁移受影响的第三层内容 | `剧情标记.yaml` 的 `灯塔状态` 取值、`等级.yaml`、`条目库.yaml` 的字段 | 全量检查；逐项迁移旧值，经作者同意，不静默丢弃 |
| 三 | 内容 | 程序读取的具体实例 | 可以增删改具体对象 | `拜师` 的门槛与分支、`林澜·学徒期` 的初始能力、条目 `灯语·短讯` 的等级 | 结构检查、抽样，并按需用 `if` 核对路径 |
| 四 | 通用文本规范 | 所有卡共用的写作规则 | 按规则写文本；不能由一张卡改写规则 | 档案正文、事件概要、叙事条件、条目正文、世界概况、扮演准则 | 格式与措辞检查；条件文本另核对适用范围 |
| 五 | 本卡文本规范 | 这张卡在第四层之上的补充 | 可以收紧或补充第四层，不能放宽 | `设定/文本规范.yaml` 的禁用词、ID 命名、长度预算；扮演准则中的文风要求 | 对受约束的文本重做检查 |

第一层只能经修订世界树的规范改变。卡里写不了新的条件类型、新的档案解析规则或新的命令。遇到“想加一种机制”的需求，先报告项目维护者，按规范修订处理，不在卡里自行实现。

第二层是这张卡的“可能性清单”。删去一种装备种类，这一类的装备都无处安放；增加一个剧情标记的取值，事件与条件才有这个值可用。第二层的改动波及最广。等级改名、取值删除之后，凡是用到它的档案初始能力、事件变化、条目等级都不再合法。必须列出全部受影响的第三层字段，逐项迁移，不静默丢弃。

第三层是具体之物。删去一件具体的装备，世界里只是少了这一件；增加一个事件分支，只是多了一条可能的走向。第三层只能引用第二层已经声明的种类与取值；需要新的种类时，先改第二层。

第四层约束一切文本字段。它要求文本用世界之内的直接叙述，不出现“变量”“ID”这类实现用语；不在文本中断言本局状态；按规定的形式书写短语列表、情境列表与以“不”开头的禁区列表；不用破折号与一批陈旧的写法。事件概要由作者撰写，但改动它只受文本规范约束，所以属于第四层。

第五层只能收紧或补充第四层，不能放宽。能机器检查的部分写进 `设定/文本规范.yaml`，例如禁用词、ID 命名规则、档案追加字段与长度预算；不能机器检查的文风要求写进 `扮演准则/`，由叙事模型遵循。第五层不能删改第四层已有的字段形式，也不能把第四层禁止的写法重新放开。

一个常见的误判是按文件判层：`事件.txt` 不是“第三层文件”，其中事件概要与叙事条件是第四层；`角色组.yaml` 也不是“第三层文件”，其中显示名、别名与简介进入上下文，按文本规则书写。改字段之前先看字段表或声明，不要按扩展名决定。

## 3. 作者 skill

作者 skill 是分层建卡的流程入口：[`世界树·统筹`](../skills/ygg-guide/SKILL.md) 只读诊断项目所处分层（第 0–5 层）与缺口并编排推进；其余八个按建卡分层与日常维护分工。全部是 model-invoked。仓库根的 `.omp/skills` 指向 `../skills`，在仓库 cwd 启动的 omp 会按项目级目录扫描到它们，`skill://世界树·…` 可读取；模型按各文件开头的 `description` 触发，也可以直接用 `name` 点名。跨项目使用时，把本仓库 `skills/` 的绝对路径登记进 omp 的 `skills.customDirectories`；本仓库不代改全局配置。复制安装不受支持：`shared/` 是公共引用页，不是可调用的 skill，`docs/`、`cli/` 与 `shared/` 的指针都是仓库相对路径，复制到仓库外会断链。

九个 skill 的职责摘要、分层流程与文件入口只在[`skills/README.md`](../skills/README.md)维护；工具调用与按级最小检查口径只在[`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)维护；越界清单与条件文本五槽速查只在[`skills/shared/写作红线.md`](../skills/shared/写作红线.md)维护。本文不复制这三处的内容。

选择顺序：

1. 新项目或接手项目，先用“统筹”诊断当前分层与缺口；默认引导模式，跑过当前层门禁即停下呈报，作者要求时切自动模式推进到指定层，硬阻塞（改编范围、核心设定冲突、缺少来源原文）仍停下等作者。
2. 分层建卡按序点名：“通读”→“地基”→“条目”→“骨架”→“档案”与“填景”→“打包”；各层出口门禁见对应 skill。
3. 建成卡后的局部改动用“修订”：按所改字段判级别（设定级、结构级、文本级），一次工作内连贯修改关联的结构与文本，只跑最小必要检查。

几个常见场景：拿到一部原作要从零建卡，从“通读”开始；要判断手头项目卡在第几层、下一步做什么，用“统筹”；已建成卡想给某事件加一个分支并顺带调整对应角色位置，用“修订”。其余场景按[`skills/README.md`](../skills/README.md)的职责列选择。

版本与角色位置没有独立的 `trace` 对象类型：版本查所属 `角色组:`，角色位置随所属 `事件:`；开局选项与开局方案用 `开局选项:<序号>`、`开局方案:<方案ID>` 直接查询。

## 4. 工具

### 4.1 调用方式

以下命令可在任意创作项目目录执行，`<世界书目录>` 按当前目录写路径。`ygg` 是 `package.json` 中 `cli/ygg.mjs` 的可执行名；没有把 CLI 链接到 `PATH` 时，把 `ygg` 换成 `node <世界树仓库>/cli/ygg.mjs`（仓库内相对写法即 `node cli/ygg.mjs`）：

```sh
ygg check <世界书目录> [--static-only] [--json]
ygg trace <世界书目录> <对象键> [--json]
ygg if <世界书目录> [--方案 <方案ID>] [--排除 <事件ID>]... [--分支 <事件ID>:<分支ID>]... [--停用角色组 <角色组ID>]... [--json]
ygg preview <世界书目录> <角色组ID> [--开局 <纪年>] [--方案 <方案ID>] [--本局 <本局JSON>] [--状态] [--json]
ygg context <世界书目录> [--开局 <纪年>] [--方案 <方案ID>] [--本局 <本局JSON>] [--地点 <地标ID>] [--场景 <场景文本>] [--在场 <角色组ID>]... [--消息 <文本>]... [--不自动初始化] [--raw] [--json]
ygg tree <世界书目录> [--out <文件路径>] [--stats-only] [--json]
ygg status [项目目录或世界书目录] [--json]
ygg init <项目目录> [--纪年前缀 <前缀>] [--年位数 <整数>] [--月数 <整数>] [--每月天数 <整数>] [--force] [--json]
ygg view --worldbook <世界书目录> [--storage <审阅存储目录>] [--port <端口>]
ygg format <世界书目录> [--check] [--write] [--json]
```

`check` 省略世界书目录时检查当前目录下的 `世界书`；`trace`、`if`、`preview`、`context`、`tree`、`format` 要求写明世界书目录；`status` 省略目录时诊断当前目录；`view` 用 `--worldbook` 给出；`init` 给出要创建的项目目录。

十个命令中，`check`、`trace`、`if`、`preview`、`context`、`tree`、`status` 只读；`init` 只向指定的新项目目录写入分层骨架，目标已有脚手架文件时先预检拒绝，显式 `--force` 才覆盖脚手架文件；`view` 启动只读/预览的本地服务，只有作者在界面里显式保存时才写回目标事件或角色位置（含新建）；`format` 缺省也只检查，只有显式 `--write` 才写文件。所有命令都不调用叙事模型。

各命令参数与运行错误码见[参考：检查规则](参考/检查规则.md#命令)。

### 4.2 `check`：全量检查与静态检查

`check` 是日常检查的入口。它先做静态检查，核对目录、声明、条目、角色组、事件、角色位置、事件串、开局、出处与文本；静态检查没有错误时，再以协议做抽样。

| 用法 | 做什么 |
|---|---|
| `ygg check <世界书目录>` | 全量检查：静态检查通过后执行抽样 |
| `ygg check <世界书目录> --static-only` | 只做静态检查，不封卷、不抽样 |
| `ygg check <世界书目录> --json` | 输出机器可读的错误、提示与摘要 |

抽样用协议试验世界书，不调用模型，主要核对：

- 每个版本至多适用一份档案，即档案互斥；
- 在各个抽样年份以默认配置封卷一次，再全部角色组启用、按版本序号逐轮取各版本封卷，封卷须成功；
- 每个开局方案各自封卷一次；
- 开局选项的每个分支，包括“未发生”，各以默认开局加这一项历史选择封卷一次。

静态检查有错误时，全量检查不会继续抽样，并给出一条 `抽样.未执行` 提示。结果分错误与提示两级：错误须改正，提示由作者判断。命令的退出码只在有错误时非零；只有提示时仍为 0。不要因为退出码为 0 就忽略提示。

每次改动前先跑一次，记下已有的错误与提示；改动后用同一命令重跑，把“改动前已有”和“本次新增”分开报告。没跑的检查不说通过。

### 4.3 `trace`：引用与出处

`trace` 查询一个对象在全书中的位置：谁引用它、它引用谁、它的出处，以及查询中发现的异常。它先建立一次只读引用索引，不修改世界书。

对象键有八类：

| 类型 | 对象键写法 | 例子 | 说明 |
|---|---|---|---|
| 事件 | `事件:<事件ID>` | `事件:拜师` | 预设事件；动态事件不在世界书的引用索引中 |
| 事件串 | `事件串:<事件串ID>` | `事件串:学徒修习` | 成员与结局 |
| 角色组 | `角色组:<角色组ID>` | `角色组:灯塔学徒` | 版本、档案项与引用它的条件、变化 |
| 档案 | `档案:<角色组ID>:<档案ID>` | `档案:灯塔学徒:林澜·学徒期` | 档案项、生效条件与正文引用 |
| 条目 | `条目:<库名>:<条目ID>` | `条目:技能:灯语·短讯` | 条目必须带库名 |
| 剧情标记 | `剧情标记:<标记ID>` | `剧情标记:灯塔状态` | 声明中的标记 |
| 开局选项 | `开局选项:<序号>` | `开局选项:1` | 开局选项文件中第 N 个选项及其事件引用 |
| 开局方案 | `开局方案:<方案ID>` | `开局方案:码头少年` | 方案的历史选择、角色组与扮演设置 |

输出分为五区：

- `对象`：对象键、类型、ID 与定义文件；
- `引用它`：哪些对象、在哪个文件、哪个字段引用它，并标出引用种类与极性；
- `它引用`：它引用了哪些对象；
- `出处`：`作者资料/出处/` 中与该对象关联的记录；
- `异常`：引用目标不存在、同键歧义、对象不存在等问题。

结构级改动之前必须跑 `trace`，把“引用它”的每个文件与字段列出来，逐项同步。事件门槛与分支门槛的 `none` 会以“排斥”标出，不会与正向前置混在一起。`trace` 只列引用，不推算影响面；影响面用 `if` 查看。

版本与角色位置没有独立的 `trace` 对象键，分别查所属 `角色组:` 与 `事件:`。变化表取值中的对象引用也会列出：集合能力成员、集合变量成员按 `变化.声明引用` 登记，映射键按 `变化.映射键` 登记，合法的 `移除`（不带值）不会误报。任何错误级异常（含 `引用.目标不存在`、`引用.结构`、`出处.结构` 等）都使 `trace` 退出非零；仅提示级异常（如 `事件树.不可达`）仍退出零。

### 4.4 `if`：路径对比与影响面

`if` 以全部事件窗口都已结束的时间轴末尾为开局时间，封卷两次：一次按默认规则，一次按作者给出的方案与覆盖项，然后比较两条路径。它没有 `--时间` 选项；要改开局时间，用开局方案或在副本上改事件窗口。

| 选项 | 作用 |
|---|---|
| `--方案 <方案ID>` | 以 `历史/开局方案/<方案ID>.yaml` 为 if 路径的起点 |
| `--排除 <事件ID>` | 让某个事件不发生；可重复 |
| `--分支 <事件ID>:<分支ID>` | 让某个事件走指定分支；可重复 |
| `--停用角色组 <角色组ID>` | 关闭某个角色组；可重复 |
| `--json` | 输出固定顶层键的机器可读结果 |

自定义的排除、分支与停用角色组会覆盖方案中的同项。选项可以叠加。

输出比较四类差异：

| 分区 | 含义 |
|---|---|
| 没发生 | 默认路径中发生、这条路径中没有发生的事件；这是 if 线的缺口，由作者判断是否补写 |
| 新发生 | 默认路径中没有发生、这条路径中发生的事件 |
| 分支不同 | 两条路径都发生、但所走分支不同的事件，写出默认分支与 if 分支 |
| 停住的事件串 | 已经开始、却没有任何结局可达的事件串 |

另有两个分区：

- `影响面`：按事件列出下游随之不能发生的事件，并给出引用位置。推算只看事件门槛中的事件确认：所引用的事件已缺失，正向引用即不成立，其余条件都不作限制。影响面大时，回查门槛是否写成了原作顺序或过死的必经链；它是提示，不是新的门槛。
- `异常`：读取、方案、事件、分支、角色组或封卷配置的错误。有错误时退出码非零。

例如：

```sh
ygg if examples/雾港/世界书 --方案 码头少年
```

会看到 `拜师` 与 `学徒守灯` 的分支不同，以及 `出师考核`、`夜间值守`、`正式守灯` 没发生。事件或分支改动后，先跑默认路径确认没有意外差异，再跑相关方案、排除或分支，确认只有预期路径变化。

`if` 比较的是预设事件与分支；首次登场初始化与动态事件不进入比较。它不评价叙事质量，只核对结构上的路径。

### 4.5 `format`：排版，不属于任何层

`format` 只统一 YAML 的排版，不改变世界书的内容与语义。YAML 的书写风格，例如列表写成块状还是行内、缩进与引号，不属于任何一层，检查器不为它报错；需要统一时用它。

| 用法 | 行为 |
|---|---|
| `ygg format <世界书目录>` | 缺省只检查；有差异时列出文件并返回非零 |
| `ygg format <世界书目录> --check` | 显式检查，与缺省相同 |
| `ygg format <世界书目录> --write` | 只重写确有差异的文件 |
| `ygg format <世界书目录> --json` | 输出 `项目`、`文件`、`异常`、`已写入` 四区 |

`--check` 与 `--write` 不能同时使用。

格式化使用 2 空格缩进与 LF，非空映射与列表用块式，空集合写 `{}`、`[]`；已知字段按参考各表的字段顺序，未知字段排在其后按码点排序。列表与数组的顺序、字段值、文本、注释、别名与合并关系都不改；重复键、循环别名与解析失败不写文件。它只处理已识别的世界书 `.yaml` 与 `.txt`，不跟随符号链接，写入用同目录临时文件原子替换并保留权限。

`format` 不是检查器，不核对结构、引用或文本写法；排版之后仍要跑 `check`。真实项目先不带 `--write` 检查差异，确认符合预期后再 `--write`；仓库示例（如 `examples/雾港/`）只在副本试验。

### 4.6 `preview`：初始化预览

`preview` 只读地封卷一次，再调用协议的 `initializationPreview`，输出某个角色组首次登场时将写入的档案、能力与装备；传入 `--状态` 时，另只读输出封卷（或 `--本局`）后该角色组的完整状态。它不写本局、不写世界书、不调用模型，也不另造封卷或初始化解析。

| 选项 | 作用 |
|---|---|
| `--开局 <纪年>` | 指定开局时间；省略时按 `if` 的时间轴末尾规则，即全部事件窗口都已结束的时间 |
| `--方案 <方案ID>` | 用 `历史/开局方案/<方案ID>.yaml` 的配置封卷；省略 `--开局` 时仍用时间轴末尾，方案的 `开局时间` 不覆盖它 |
| `--本局 <本局JSON>` | 读取一份已封卷的本局状态，不再封卷；不能与 `--开局`、`--方案` 同用 |
| `--状态` | 另输出封卷（或 `--本局`）后目标角色组的完整状态（含 `所在`、`职位`、`身份`、`关系`、能力、装备等）；人类可读输出在 `预览` 与 `异常` 之间增加 `状态` 块 |
| `--json` | 输出固定顶层键 `角色组`、`开局`、`方案`、`预览`、`原因`、`异常`；传入 `--状态` 时为七键，在 `原因` 后增加 `状态` |

`预览` 为 `{档案ID, 能力, 装备}`；不需要初始化时为 `null`，`原因` 给出 `未启用`、`已初始化` 或 `当前档案不成立`。`--本局` 用于核对本局已有值：已初始化的角色组得到 `预览: null` 与原因 `已初始化`。传入 `--状态` 时，即使目标角色组处于 `未启用` 或 `已初始化`（`预览: null`），仍返回其封卷或本局状态对象（尚无写入记录时为空对象 `{}`）；前置失败时 `状态` 为 `null`。

```sh
ygg preview examples/雾港/世界书 秦守
ygg preview examples/雾港/世界书 灯塔学徒 --开局 潮历071年01月05日 --json
ygg preview examples/雾港/世界书 灯塔学徒 --开局 潮历072年 --状态 --json
ygg preview examples/雾港/世界书 秦守 --本局 /tmp/本局.json
```

`preview` 只核对首次登场初始化与封卷后的角色状态，不评价叙事质量，也不代替 `check` 的抽样。封卷失败、角色组或方案不存在、时间轴无法确定时，按 §4.1 的错误码退出非零。

### 4.7 `view`：本地作者视图

`view` 启动只监听 `127.0.0.1` 的本地作者工具，以现行世界书为输入，提供世界主树、局部关系、角色汇总、如果视图、上下文预览与事件详情/相关角色，并覆盖 A 档图形化编辑：单事件结构化表单与 YAML 原文双模式、新建事件、角色位置编辑与新建，另有台词统计与 Markdown 事件树预览/下载。它复用现行 `core/`、`checker/` 与 `cli/ygg.mjs` 的检查、引用、事件树、`if`、`context` 与 `tree` 计算，不读取旧创作项目、旧 forge 解析器或旧索引文件。

| 用法 | 做什么 |
|---|---|
| `ygg view --worldbook <世界书目录> [--storage <审阅存储目录>] [--port <端口>]` | 启动本地视图；`--port 0` 输出实际空闲端口 URL |
| 缺省存储 | `<世界书父目录>/作者资料/审阅器`，必须在实现仓库与世界书之外 |

预览在包含世界书、`作者资料/出处` 与 `yggdrasill.yaml` 的临时副本上执行现行静态检查；保存前把旧原文与 `修改说明.json` 写入 `修改备份/`，原子写回后执行全量检查。预览令牌 15 分钟有效，原文或依赖变化、再编辑、并发保存、目标文件在保存前被外部创建均返回 409；静态预览不冒充全量检查。批注与布局写入 `审阅状态.json`，与事件正文分离。表单模式按规范键序重排且不保留行内注释，YAML 原文模式保留注释与顺序。完整参数、存储 schema、备份与安全边界见[作者视图](../view/README.md)。

视图内不做的：事件与角色位置的删除、`事件ID`/`角色组ID` 改名、跨文件引用迁移，以及设定声明/角色组/档案/条目库/事件串/开局文件的编辑——仍在源文件、CLI 或 skill 中完成；视图不读取 `来源资料/`，不调用叙事模型，不访问外网。

### 4.8 `context`：路由上下文与预算预览

`context` 只读地封卷一局（或读入 `--本局`），按需推演一个场景，再调用现行路由渲染完整上下文，输出总字符、各分块字符与经历、候选、各条目库的预算占用。它不写本局、不写世界书、不调用模型。

| 选项 | 作用 |
|---|---|
| `--开局 <纪年>` | 指定开局时间；省略时先取方案的 `开局时间`，再按时间轴末尾 |
| `--方案 <方案ID>` | 按 `历史/开局方案/<方案ID>.yaml` 封卷；不能与 `--本局` 同用 |
| `--本局 <本局JSON>` | 读入一份已封卷的本局状态，不再封卷 |
| `--地点 <地标ID>` | 推演当前地点；省略 `--场景` 时场景取地标 ID |
| `--场景 <场景文本>` | 推演当前地点内的场景；仅传它时本局须已有当前地点 |
| `--在场 <角色组ID>` | 推演在场角色组；可重复，按码点排序 |
| `--消息 <文本>` | 供提及检测的最近消息；可重复 |
| `--不自动初始化` | 不为未出场的在场角色组预做首次登场初始化；门禁触发时报 `上下文.场景` |
| `--raw` | 直接输出渲染后的完整正文 |
| `--json` | 输出固定顶层键 `输入`、`汇总`、`预算`、`审计`、`正文`、`异常` |

未传 `--不自动初始化` 且推演在场包含尚未出场的角色组时，默认先尝试协议的首次登场初始化并把成功者记入 `输入.模拟初始化`，避免模拟在场被首登场门禁卡死。`汇总` 按码点统计总字符与每个实际渲染分块；`审计` 给出经历与候选的选入/略过原因、各条目库的已用字符与预算，数字与路由每轮实际产出一致。它不评价叙事质量，也不代替 `check`。

### 4.9 `tree`：Markdown 事件树导出与台词统计

`tree` 只读导出确定性 Markdown 事件树，并附纯静态台词统计。它不读取 `来源资料/`；原台词只按 `作者资料/出处` 的台词记录精确匹配候选台词来认定，与来源原文的逐字一致由作者人工核对。

| 用法 | 做什么 |
|---|---|
| `ygg tree <世界书目录>` | 输出完整 Markdown 事件树至终端；重复运行逐字节一致 |
| `ygg tree <世界书目录> --stats-only` | 只输出事件树与台词统计摘要 |
| `ygg tree <世界书目录> --out <文件路径>` | 写入 Markdown（缺省覆写），适合生成到 `作者资料/生成/事件树.md` |
| `ygg tree <世界书目录> --json` | 输出 `世界书`、`摘要`、`事件串`、`独立事件`、`台词统计`、`markdown`、`输出文件`、`异常` |

导出路径经安全校验：落在 `<世界书目录>` 内部（含等于其本身）即报 `事件树导出.路径` 退出非零，不创建任何文件。正文含事件的时间窗口、分类、确认策略、核心参与者、地点、正向前置与排斥依赖、可达状态、分支（含默认与变化条数）与台词数；另含事件串结构、按角色组的台词汇总、缺台词角色位置与结构异常。

### 4.10 `status`：项目分层诊断

`status` 只读盘点项目根（或 `世界书/` 目录）的第 0–5 层：通读账本、设定声明与全局文本、各条目库条目数、角色组与事件骨架（含一次只读静态检查）、角色位置与台词统计、暂存/候选文件数与卡面文件。输出 `当前阶段`、具体 `缺口` 与 `推荐skill`。

| 用法 | 做什么 |
|---|---|
| `ygg status [项目目录或世界书目录]` | 省略目录时诊断当前目录；目录识别为项目根或其中的 `世界书/` |
| `ygg status <目录> --json` | 输出 `项目`、`各层`、`计数`、`台词统计`、`静态检查`、`当前阶段`、`缺口`、`推荐skill`、`异常` |

静态检查有错只标注在结果中，不改变退出码；只有路径不存在或诊断本身失败才退出非零。它不改动任何文件，也不代替各层的出口门禁。

### 4.11 `init`：新项目脚手架

`init` 创建新项目的分层骨架：`世界书/` 九个目录、`作者资料/` 六个目录与 `来源资料/`，并生成 `设定/纪年.yaml`（按参数）、复制仓库默认的 `事件分类.yaml` 与 `本局变量.yaml`、写入最小 `条目库.yaml`（声明 `地点` 与 `势力`，匹配默认 `职位` 的键引用）。生成的脚手架直接通过 `check --static-only`。

| 选项 | 作用 |
|---|---|
| `--纪年前缀 <前缀>` | 纪年前缀，默认 `纪元` |
| `--年位数`、`--月数`、`--每月天数` | 纪年参数，默认 `4`、`12`、`30`，均须为不小于 1 的安全整数 |
| `--force` | 覆盖已存在的四份脚手架文件；不删除、不覆盖其他任何文件 |
| `--json` | 输出 `项目目录`、`世界书目录`、`纪年`、`已创建目录`、`已写入文件`、`跳过或覆盖说明`、`异常` |

未传 `--force` 时先预检全部拟写文件，任一已存在即报 `初始化.已存在` 退出非零，不留半套覆盖文件。

### 4.12 分层与按级的编辑流程

建卡期按分层出口门禁推进（见[`skills/README.md`](../skills/README.md)）；建成后按改动级别执行，分级与最小检查矩阵以[`skills/shared/工具与检查.md`](../skills/shared/工具与检查.md)为准。下面只说明在作者工作里怎样按级执行，不另立规则。

共同的前置：

1. 先跑 `check --static-only --json`，把已有的错误与提示记作基线；需要抽样时另跑全量 `check`。
2. 记下这次要改的文件、字段、对象键与预期结果；条件文本另写下五槽适用范围。

#### 设定级

改前：

- 找到要改的声明文件与键，读出全部取值与引用规则。
- 有对象键的声明用 `trace`：剧情标记查 `剧情标记:<ID>`，条目查 `条目:<库>:<ID>`。变化表取值中的对象引用也会列出；剧情标记、等级与词表的枚举取值不构成对象引用，仍用设定级的反向清单与文本搜索补齐。
- 等级、能力、条目库与词表声明没有对象键：在一次性临时副本上删去或改名待改取值，跑 `check --static-only --json`，把报出的文件、规则与说明记成反向清单，用完即弃。
- 纯文本提及用 `grep -rn '<旧值>' <世界书目录> <作者资料>` 逐条举证；每条写明迁移、保留为 ID 或名称、或删除。
- 把仍使用旧值的第三层字段列成“文件 → 字段 → 当前值 → 迁移后值”；没有迁移后值的项标为“拟删除”，交作者逐项确认。

改后：

- 先改声明，再按清单迁移第三层内容；不静默丢弃，也不把旧值留在无法解析的字段里。
- 跑静态检查与全量 `check`；对照基线，只对新增错误负责。
- 触及事件门槛、变化、事件串或开局时，跑相关方案、排除或分支的 `if`，差异逐项对应迁移清单。
- 报告写清声明旧值与新值、反向清单与文本命中清单、每项的去向、检查与 `if` 比较结果。

#### 结构级

改前：

- 用 `trace` 查询待改对象；事件串查 `事件串:<ID>`，角色组与档案分别查 `角色组:<ID>`、`档案:<组ID>:<档案ID>`。
- 把“引用它”的每个来源对象、文件与字段逐项列出；这些位置在改动后都要同步。

改后：

- 同步全部引用与受影响的文本；改动涉及 ID 时，先确认没有需要兼容的存档，或建立旧 ID 到新 ID 的迁移表。
- 跑静态检查与全量检查；事件、分支、事件串或开局改动再跑相关 `if`，只应出现预期路径变化；首次登场的初始化有变时另跑 `preview`。
- 重跑 `format --check --json`；本次改动文件不新进入差异集，差异总数按新建或删除文件解释。
- 报告写清对象键、引用清单的前后变化、`if` 的路径差异、静态检查与全量检查结果，以及未解决项。

#### 文本级

改前：

- 写明要改的文件、字段与当前文本；区分普通文本与条件文本。条件文本是叙事条件、分支条件、介入条件、触发情境与触发限制；分支结果是普通文本。
- 条件文本先写下五槽适用范围：对象、地点、时间、分支、触发情形（见[`skills/shared/写作红线.md`](../skills/shared/写作红线.md)）。

改后：

- 只改文本字段；不顺带改结构、声明、测试或检查器。
- 条件文本按五槽逐条对照；范围变了就退回原文，或把改动拆出来交给结构级处理。`check` 与 `if` 不判语义范围，这一项由人工核对。
- 跑 `check` 与 `format --check --json`；本次改动文件不新进入差异集。纯文本改动不要求跑 `if` 对比。
- 改 `设定/文本规范.yaml` 时确认第五层没有放宽第四层。
- 报告写清文件与字段、普通文本或条件文本、五槽前后对照、人工复核记录、检查结果。

无论哪一级，报告至少写：改了什么、属于哪一级、跑了哪些检查与结果、改动前已有的问题与本次新增的问题。没跑的检查不说通过；`check` 通过不等于状态断言或条件范围没有变化；不为让检查通过而改测试、检查器或声明。

## 5. 作者资料、出处、候选与审阅

### 5.1 作者资料的目录

`作者资料/` 在 `世界书/` 之外，不进入上下文，不参与运行，不属于任何一层。世界树只规定工具要读写的部分，其余格式与位置由项目自定。

| 目录 | 用途 | 维护方式 |
|---|---|---|
| `通读/` | 第 0 层的通读工作资料：分卷坐标账本、活词表与五份全局总账 | `init` 预建 `通读/分卷/`；分卷表与总账按“通读”skill 的两遍读法维护（见[`skills/README.md`](../skills/README.md)） |
| `出处/` | 结构化的来源记录：事件级记录写事件来源，台词记录写每句原台词的来源 | YAML，文件划分由项目自定；字段见下 |
| `暂存/` | 已经写好、待条件满足后接回世界书的内容 | 按世界书中的相对布局存放，并在 `暂存/暂存清单.yaml` 逐项登记 |
| `候选/` | 尚未定下的内容 | 定下之后写入世界书，并从候选中删除 |
| `生成/` | 工具的输出 | 不手改 |
| `归档/` | 撤下的内容 | 保留它在世界书中的相对布局 |
| `审阅器/` | `ygg view` 的缺省审阅存储目录：批注、布局与保存备份 | 视图首次写入时自动创建；批注与备份随视图保存维护，不手改 |

`出处/` 的记录只有两种：

| 记录 | 字段 | 检查器核对 |
|---|---|---|
| 事件级记录 | `事件ID`、`来源` | 事件存在；记录中没有其它键 |
| 台词记录 | `事件ID`、`角色组ID`、`台词`、`来源` | 事件存在；该事件有这个角色组的角色位置；台词在该角色位置的候选台词中 |

`来源` 是文本。台词记录所列的台词，措辞检查视为原台词，破折号只提示、`文本.写法` 豁免。检查器能核对记录引用的事件与角色位置存在，且台词已收在该角色位置的候选台词中；台词是否在来源原文中逐字存在、说话人是否与来源一致，由作者人工核对，世界树不做原文自动核对，`ygg tree` 的台词统计只对照台词记录区分原台词与作者台词。

`暂存/暂存清单.yaml` 的每项写 `类型`（档案、事件或条目）、`ID`、`接回位置`、`接回结构` 与 `接回条件`。接回之后删除对应的项。检查器不读取暂存清单，接回时靠作者按清单执行。

`候选/` 放尚未定下的内容。候选不是世界书的一部分，不进入上下文；确定之后写入世界书，并从候选中删除，避免同一内容在两处各有一份。`生成/` 是工具输出，不要手改；`归档/` 是撤下的内容，保留它在世界书中的相对布局，便于回查。

创作规划与核定日志的格式由项目自定，只写设计理由、创作意图、进度与待办；不抄写第二、五层的声明，也不重述规范条文，需要时引用文件与章节。名单外说话人的台词数记在核定日志中，不写进世界书。

### 5.2 分层建卡中的出处、候选与暂存

建卡按第 0–5 层分层推进，作者资料在其中各司其职；分层的全貌与各层出口门禁见[写作规范](写作规范.md)与[`skills/README.md`](../skills/README.md)。

1. 第 0 层通读：两遍读法的第一遍分卷读原作，把分卷坐标账本与活词表写进 `作者资料/通读/`，Reduce 归并出五份全局总账；名单、分期与体系取值经作者拍板后，才进入下一层。
2. 第 1–3 层依据拍板的总账建声明、条目库与事件骨架，正文字段先写简明占位；此间尚未定下的内容逐条记进 `候选/`，写明建议的结构去向：事件变化、角色组元数据、条目或场景。
3. 第 4a/4b 层骨架锁定后，按坐标回查原文，精写档案正文、补实事件正文与角色位置，逐字摘录原台词；每句原台词在 `出处/` 写台词记录，填事件、角色组、台词与来源，事件级来源另写事件级记录。
4. 候选定下后，把内容写进世界书对应的位置，再从 `候选/` 删除对应的候选；已经写好但条件尚未满足的内容放进 `暂存/`，按相对布局存放，并在暂存清单登记接回位置、结构与条件，条件满足、接回世界书后删除对应项。
5. 撤下的内容放进 `归档/`，保留相对布局；不要用归档目录代替候选或暂存。

作者资料不是第二份世界书。它只写设计理由、进度、出处与候选，不复述声明或规范条文；世界书中的字段仍以世界书为准。

### 5.3 一次审阅至少核对什么

审阅不是只跑一遍命令。命令能查结构，含义仍要人看。至少核对：

| 核对项 | 怎么查 | 看什么 |
|---|---|---|
| 引用 | 改动前后各跑一次 `trace`，再跑 `check` | “引用它”的文件与字段是否全部同步；有无 `引用.目标不存在` 等异常 |
| 出处 | `trace` 的“出处”区；`check` 的出处规则 | 每个收入的原台词是否有台词记录；事件级来源是否存在；记录字段是否只有规定的几项 |
| 台词归属 | `trace` 事件时看台词的 `角色组ID`，再打开对应角色位置 | 台词是否在该事件、该角色组自己的角色位置；是否误收别人的话；名单外说话人是否只计数 |
| 档案时期 | 读档案正文与档案项的生效条件，对照事件窗口 | 是否写进了本时期之后才出现的人物、身份或事件；是否把当前状态写成了稳定事实 |
| 条件适用范围 | 对照文本级改前记录的五槽 | 叙事条件、分支条件、介入条件、触发情境与触发限制是否仍适用于同一批对象、地点、时间、分支或情形；`check` 与 `if` 不判这一项 |
| 越界 | 按 [`skills/shared/写作红线.md`“越界”](../skills/shared/写作红线.md#越界) 的清单逐条读两份档案、事件概要、分支结果与角色位置 | 清单所列状态事实是否被写成文本；`check` 不报不代表没有 |
| 事件串结局可达 | `check` 的 `事件串.结局不可达` 提示；`if` 的“停住的事件串” | 结局是否属于本串；是否至少有一个结局可达；若停住，是结构切断还是有意为之 |
| 检查结果 | `check` 的错误与提示；`if` 的路径差异；必要时 `format` | 是否分开列出改动前已有与本次新增；是否把提示误当通过；`format` 只作排版，不替代 `check` |

另外核对：

- 事件门槛只写真正的因果，不把“原作中它排在前面”写成门槛；只想表达先后时，用 `当前时间` 或 `事件串状态`，不用 `none`。
- 自动确认的事件若有带门槛的分支，是否有不带门槛的兜底分支。
- 角色的初始能力、初始所在与别名是否按声明书写；档案项与 `档案/` 目录是否一一对应；每个版本是否至少有一份适用档案。
- 开局选项是否只用开局前事件与可选分支；开局方案的历史选择是否在选项内，且不晚于开局时间。
- 条目是否只写对象本身，没有写当前持有、当前所在地或当前关系。

审阅报告应能按对象键复核每一处引用同步，并写明未解决项的位置与是否影响本次范围。

## 6. 当前边界

本指南只描述当前已验收的工具与流程。以下是当前工具的边界与尚未交付的入口，不要按不存在的命令或界面操作：

- **`preview` 只核对首次登场。** 它按封卷结果输出一个角色组将写入的档案、能力与装备，不列出路由上下文、不检查叙事质量，也不代替 `check` 的抽样。已初始化、未启用或当前档案不成立时输出 `null` 与原因。
- **`trace` 没有版本与角色位置对象键。** 开局选项与开局方案用 `开局选项:<序号>`、`开局方案:<方案ID>` 直接查询；版本查所属 `角色组:`，角色位置随所属 `事件:`。
- **`trace` 列变化表取值中的对象引用。** 集合能力成员、集合变量成员按 `变化.声明引用` 登记，映射键按 `变化.映射键` 登记，合法的 `移除`（不带值）不误报；等级与词表的取值不构成对象引用，仍用设定级的反向清单补齐。
- **图形作者视图覆盖 A 档编辑。** `ygg view` 提供世界主树、局部关系、角色汇总、如果视图、上下文预览、台词统计与 Markdown 事件树预览/下载；编辑范围是单事件结构化表单与 YAML 原文双模式、新建事件、角色位置编辑与新建。删除、改名与跨文件引用迁移仍需在源文件中处理；设定声明/角色组/档案/条目库/事件串/开局文件的编辑仍走源文件、CLI 或 skill。预览是静态检查，保存后才执行全量检查；表单产物经服务端格式化，保存后即通过 `ygg format --check`（该文件自身）。
- **其余命令仍是命令行。** `check`、`trace`、`if`、`preview`、`context`、`tree`、`status` 只读；`init` 只写入新项目骨架（`--force` 才覆盖脚手架文件）；`format --write` 与 `view` 的保存会写文件。不要按不存在的自动抽取入口操作。
- **`check` 的抽样不是模型试玩。** 它用协议封卷，能核对档案互斥、运行封卷、开局方案与开局选项；它不评价文风、叙事质量或模型的实际扮演。文本质量仍要作者与审阅判断。
- **`format` 不是内容检查。** 它只统一排版，不核对字段、引用、条件或文本写法；排版后仍要跑 `check`。
- **出处原文不自动核对。** 检查器能核对记录引用的事件、角色位置与台词存在；来源文本中的台词是否逐字一致、说话人是否一致，由作者人工核对，不在自动核对范围。
- **完整迁移案例仍待写。** 本指南不含完整迁移案例；该案例仍列在[世界树文档的“待写”](README.md#待写)中。不要把你手头的项目当成已验证的大体量迁移样本。
- **世界书不等于角色卡。** 打包、酒馆适配与开局前端的正式产品化、运行参数的产品化不在本指南范围内；需要时看[第六章“酒馆适配”](06-酒馆适配.md)。

写作时守住边界：日常创作直接基于真实项目工作，动手前确认 git 或备份保护；仓库示例 `examples/雾港/` 与破坏性探测（如设定级反向清单探针）才使用一次性临时副本。发现规范缺口时报告维护者，不自行改 skill、CLI、协议、检查器或预设来绕过问题。
