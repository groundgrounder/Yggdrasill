# 世界书

世界树是为 SillyTavern（下称酒馆）的角色卡制定的规范及其工具链。制作以世界树为基底的角色卡时，作者书写的是世界书，即以 YAML 书写的目录，载有卡的世界内容，以及卡自己规定的种类与取值，不含程序。游玩之前，世界书与世界树的程序合在一起，再加上酒馆角色卡所需的卡名、头像与开场白等卡面内容，生成角色卡，这一步称为打包。世界书之名沿用自酒馆，含义却不同：酒馆的世界书是按关键词触发、插入提示词的条目；世界树的世界书是作者书写的源文件目录，模型每轮读到什么由程序挑选，不按关键词触发。世界书的内容按字段分为五层，每层由谁规定、怎样书写、改动后须做哪些检查，各不相同。本章先说明世界书在写作与游玩中怎样被读写，并借此交代所需的术语，再依次说明层、声明与目录，最后以示例《三国演义》串联上述内容。目录、文件、ID、声明与模板的逐项清单，见参考“世界书”。作者怎样书写，见写作规范。

## 运行

本节先说明游玩中世界书怎样被读写，再说明游玩之前的打包与开局，最后说明写卡时的检查，使每个术语都在用到之前讲清。世界书有两类读者。世界树的程序读取全部文件。叙事模型，即扮演世界与角色、推进剧情的语言模型，只读到程序为它挑选的部分。叙事模型不直接读取世界书，也不直接改动状态：程序每轮为它组装输入，称为上下文。默认记账时，它只写正文，由适配层的记账调用从正文提取变化；关闭记账时，它直接在正文末尾写命令。两种来源的命令都由程序校验后执行（见第六章）。

游玩中的一切状态，包括时间与地点、角色之间的关系、能力与装备、已经发生的事件，合称本局，存放在本局变量中。本局按角色组记录角色的状态：角色组是本局变量、事件参与者与关系引用的主体，同一角色组可以有不同的版本，即本局可选的不同人物，开局时选定其一（见第二章）。能由存储的状态推出的，例如角色此刻适用的档案，即角色在某段时期内稳定的设定，在读取时计算，不写回本局。

改变本局的基本单位是事件。预设事件写在世界书中，写明它可以发生的时段，即触发时间；它的前提，即门槛；缺了就不成立的角色组，即核心参与者；以及它可能走向的各个分支。门槛由程序求值，结果为成立、不成立、未知三者之一。每个分支还可以有自己的门槛，决定这个分支能不能走。每个分支写入本局的变化列为变化表，每条变化写明路径、操作与值，即改哪个字段、用哪种操作、写入什么值。作者为每个事件指定默认分支，程序替事件选择走向时优先走它。核心参与者都在本局之中、触发时间之内、门槛成立且有分支可走的事件成为候选，可由叙事正文确认。事件还写明确认策略，确认策略为自动确认的事件，过了触发时间仍未确认而门槛成立时，由程序自行登记，其余事件过了触发时间即排除。事件确认之后，本局记下所走的分支、实际时间与实际参与者，后者是核心参与者，以及正文确认时另外列入的角色组，并写入该分支的变化，同一事件只写一次。叙事正文也可以写出世界书中没有预写的事件，由记账结果或关闭记账时的正文命令登记为动态事件。事件的规则详见第三章。

本局的写入一律经由命令，共五种：确认事件、动态事件、确认初始化、写场景、待定项。命令可以由正文记账结果转换而来，也可以来自关闭记账时叙事模型写出的旧命令。前两种分别确认候选事件、登记动态事件。初始化在角色首次出场时，把档案所载的初始能力与初始装备写入本局，补出角色在本局出场之前已有的能力与装备，按角色组的设定由命令确认，或自动完成。待定项记下叙事模型一时不能确定的取值，待剧情明确后再写。当前时间、当前地点，以及角色是否在当前场景中（在场）与身在何处（所在），合称场景状态，由命令“写场景”直接写入，不必登记事件。场景以外的持久状态，都由事件写入。另有两项记录只由程序维护，命令不能写入：能力移除记录，即被移除过的能力字段，初始化时不会补回；已初始化，即角色组是否已完成初始化。

程序中执行这些读写的部分，属于世界树的程序库，即内核。内核读取卡的声明，即卡在 `设定/` 中写下的种类与取值（见“声明”），以及世界书的其余文件。它求值条件，校验变化，并包含游玩时运行的协议与路由。协议读写本局：读取时计算事件的状态与角色当前的能力，写入时执行命令。它只读本局与世界书，不调用模型，每条命令先经校验，有一处不合即报错，什么也不写。路由是每轮只读的计算：它经协议读取本局，按当前的场景挑选相关的档案、事件与条目，组装成上下文。条目是技能、装备、地点这类公共对象，同一种条目的集合称为条目库（见“条目库”）。

打包由适配层完成，即把世界树卡接入酒馆这类具体运行环境的部分。打包时，适配层除合成角色卡外，还生成协议文本，即发给叙事模型的规则：变量更新规则、角色通用约束与扮演准则。协议文本由世界树的模板生成，模板中的占位符按卡的声明与世界书的相应内容填入（见“生成”）。记账开启与关闭各有一份协议文本，前者只要求正文，后者保留正文命令；两份都在打包时生成，此后每轮按设置选择一份。游玩中，适配层每轮调用路由；默认独立记账并从正文生成命令，关闭记账时解析正文命令，二者都交协议执行。适配层另把本局与命令按楼保存并负责重放（见第六章）。

开局时，玩家在开局前端，即适配层提供的开局界面，选定世界线（多世界线卡）、预设或自由开局、开局时间与地点、玩家定制、开场白模式，以及按需展开的高级角色组与历史选择，协议随即封卷：把这些选择写入本局，称为开局设定，并按事件的触发时间与门槛，补出开局之前已经发生的历史。封卷之后，本局只经命令写入。开局前端已在适配层中实现并验证六类选择、预演、原子封卷与失败不写半份本局；跨记录格式大版本的旧存档迁移暂不在当前版本范围内，前端的预演、最终封卷与各能力实现状态见第六章。

写卡时，作者每次改动世界书，都交由检查器检查。检查器建立在内核之上，与协议共用同一套校验，分两步进行：先做静态检查，核对目录、声明、条目、角色组、事件与措辞，不运行协议；没有错误时再做抽样，以协议试验世界书，确认它在若干开局时间与开局配置下都能封卷，且每个角色组至多适用一份档案。检查的结果分错误与提示两级，错误须改正，提示由作者判断。

## 层

程序读取的字段与模型阅读的文本，要求不同：前者的取值须合法，引用须能解析；后者须按规定的写法措辞，不能替事件断言状态。世界书中的字段因此按改动所受的规则与须做的检查，分为五层：架构、背景设定、内容、通用文本规范、本卡文本规范，依次称第一至第五层。层是字段的属性，不是文件的属性：同一文件常常同时含有几层的字段，参考各表在每份文件的字段表中以“层”一栏标出每个字段所属的层，整张表属于同一层时则在表前写明。判定的依据是改动字段时受哪一层的规则约束、须做哪一层的检查，与谁写下它的值无关。五层中，第一、四层的规则由世界树规定，所有卡相同。第二、五层由各卡声明。第三层是卡的具体内容。作者为自己保留的工作资料不属于任何一层（见“作者资料”）。

### 第一层

第一层是架构，即世界树运行所依据的机制。它规定世界书由哪些对象组成：角色组与档案，事件与分支，条目库与条目，本局变量。它规定这些对象怎样求值：档案怎样解析出当前适用的一份，门槛怎样按三值求值，事件处于什么状态。它也规定状态怎样写入：本局在封卷之后只经命令写入，场景状态由写场景直接写入，其余持久状态由事件的变化写入，能力移除记录与已初始化只由协议维护。第一层由世界树的规范规定、内核实现，所有卡相同，卡不能覆盖。改动第一层只能修订规范，并须跑内核与一致性测试。

### 第二层

第二层是背景设定，即卡自己的种类与取值：纪年，即时间的写法；有哪些等级，各自从低到高怎样排列；角色的能力分哪些维度；事件分哪些类型与标签；有哪些条目库，各库有哪些字段；本局要为角色和世界记录哪些状态，各取什么值；世界范围有哪些命名的状态，即剧情标记，各取什么值。第一层只给出抽象的形状，例如能力维度可以按门类各记一个等级（等级映射），只记一个等级（单值等级），或记一组成员（集合）。第二层声明本卡有哪些维度，各分哪些门类，各用哪些等级。第二层由各卡的作者在 `设定/` 中声明。

第二层的改动波及最广。等级改名、取值删除之后，凡是用到它的地方，例如档案的初始能力、事件的变化、条目的等级，都不再合法。改动第二层之后须做全量检查，即对全部内容做静态检查与抽样。不再合法之处须显式迁移，不得静默丢弃。

### 第三层

第三层是内容，即程序读取的具体实例：角色在什么条件下适用哪份档案，首次出场时带着什么能力与装备；事件在什么时段发生，门槛是什么，有哪些分支，每个分支写入什么；条目的标识（ID）、种类、等级与上下级。第三层由作者撰写，只能引用第二层已经声明的种类与取值，需要新的种类时先改第二层。第三层的改动只影响它自身与引用它的地方，改动后须做引用解析、结构检查与抽样。

第二、三层都由作者填写，判别的办法是：删去一项，卡失去的是一种可能，还是一个具体之物。删去一种装备种类，这一类的装备都无处安放，世界里不再能有这类装备，这是第二层。删去一件具体的装备，世界里只是少了这一件，这是第三层。内容的增加不改变层：修习体系、技能门类会随着内容的增加而增加，但每增加一项都是第二层的改动，哪怕它只是为了写某个新技能而加。剧情标记往往在写事件时才想到，但声明标记及其取值属于第二层，事件读写这个标记属于第三层。

### 第四层

第四层是通用文本规范，即所有卡共用的写作规则。它约束一切文本字段，即供模型阅读、程序不解析其含义的字段：文本用世界之内的直接叙述，不出现“变量”“ID”这类实现用语；不在文本中断言本局的状态，因为状态只由事件与命令写入；字段按规定的形式书写，例如短语列表、情境列表、以“不”开头的禁区列表；不用破折号与一批陈旧的写法。第四层由世界树规定，所有卡相同。受第四层约束的文本字段，在字段表中标为第四层。改动这些字段后，须做格式与措辞检查。事件概要由作者撰写，但改动它只受文本规范约束，只做格式与措辞检查，所以属于第四层。

与文本字段相对的是机器字段，即只供程序读取、在组装上下文时剥离的字段，例如门槛、确认策略、默认分支与变化表。程序读取的字段并不都是机器字段：条目的类型、等级这类第三层字段，随条目进入上下文，模型读得到。事件的类型、标签与地点虽不剥离，但路由组装事件时只取规定的几项，模型并不读到它们。

文本字段中有一类决定事件或台词在何种情形下成立，称为条件文本，例如叙事条件、分支条件、触发情境。条件文本按文本规范书写，由叙事模型判断，与门槛分工：门槛由协议求值，封卷时求不出值的要求，例如事件须在某个场景中发生、须有某些人在场，写进条件文本。修改条件文本时，除措辞检查外，还须核对它的适用范围没有因此改变。

### 第五层

第五层是本卡文本规范，即卡在第四层之上的补充：叙述人称，对白与描写的比例，本卡禁用的来源用语，ID 的命名规则，档案追加的字段。第五层由各卡的作者规定，只能收紧或补充第四层，不能放宽。其中能机器检查的部分声明在 `设定/文本规范.yaml`，由检查器核对。不能机器检查的文风要求写进扮演准则（见“文本容器”），由叙事模型遵循。改动第五层后，须对受它约束的文本重做格式与措辞检查。

## 声明

第二层的全部种类与取值，与第五层中能机器检查的部分，由卡自己声明。声明写在固定根 `设定/` 中，固定根是名称与结构由第一层规定的目录（见“固定根”）。内核与检查器只读声明，不写死任何卡的种类与取值，同一套程序因此能运行种类各异的卡。

### 设定

`设定/` 只放 `.yaml`，只给工具读。声明按内容分为九份文件：

| 文件 | 声明什么 |
|---|---|
| `纪年.yaml` | 时间的写法 |
| `等级.yaml` | 各个等级序列 |
| `能力.yaml` | 能力维度及其类型、所用的等级序列或成员，角色能用哪些技能的规则 |
| `事件分类.yaml` | 主类型、标签、事件结果，以及每项结果由哪些字段支撑 |
| `条目库.yaml` | 有哪些条目库，各库的分法、分级与字段 |
| `本局变量.yaml` | 命名的取值表，以及为角色和世界记录的第二层字段 |
| `剧情标记.yaml` | 剧情标记及其取值 |
| `角色分类.yaml` | 角色包与分类 |
| `文本规范.yaml` | 第五层中能机器检查的部分 |

纪年、事件分类、本局变量三份是必需的，其余在用到时才需要，例如有技能库就须有能力的声明。世界树在 `defaults/设定/` 下附带一套默认声明，即事件分类的默认清单，以及关系、好感度、身份、职位、知识等推荐的本局变量字段，供新卡复制进自己的 `设定/` 后修改。复制以后即为本卡的声明。能力与本局变量的写法分别在第二章与第四章说明，条目库的声明见“条目库”。以下说明其余几份。

纪年声明前缀、年位数、月数与每月天数，四项都须写。时间写作 `{前缀}{年}年` 或 `{前缀}{年}年{MM}月{DD}日`；纪元前年份加 `前` 字，写作 `{前缀}前{年}年` 或 `{前缀}前{年}年{MM}月{DD}日`（禁止 `前` 后接全零，如 `前000年`），年补足位数，月、日各两位。事件的时间写到年或写到日，不写到月。时间都表示区间：写到日的是当日，写到年的是整年，即首月首日至末月末日。区间含起点而不含终点，日的终点是次日的起点，年的终点是次年首日的起点。前者的终点不晚于后者的起点，称前者早于后者。前者的起点不早于后者的终点，称前者已过后者。事件是否已到、是否已过、是否属于开局之前，都按这两种关系判断。

等级序列是从低到高排列的一列等级，以 `等级.{名字}` 引用。卡可以声明几个等级序列，分别用于不同的字段。序列中的每个值称等级，等级的高低按它在序列中的位置比较。

事件分类声明三项的取值。主类型描述事件主要改变的对象，单选；标签描述事件的形式或主题，多选；事件结果描述分支实际写入的长期结果，多选，取所有分支的并集。三者只用于检索与作者审阅，不参与门槛的求值。每项事件结果另声明支撑它的本局变量字段，检查器据此双向提示：变化表写了某个字段，而事件结果中没有对应的一项；或事件结果写了某一项，而变化表中没有支撑它的变化。档案在什么条件下适用，写在它的生效条件中。“档案切期”是保留的支撑名，表示事件的某个分支被档案的生效条件引用。事件分类还声明哪个主类型表示世界事件，即到时间就发生、只写世界层面变化的事件（见第三章）。

剧情标记的声明列出每个标记的全部取值，第一个取值是开局值，封卷时写入。门槛以等于或不等于比较标记，事件的变化以“设定”操作写入新的取值。

角色分类声明角色包与分类两张平铺的清单。每个角色组属于一个角色包与一个分类，只用于开局时列出可选的角色，不作整包开关。

文本规范声明第五层中能机器检查的部分：追加的禁用词；ID 的命名规则，例如只用中文，或某类 ID 须以某个字段的值加“·”开头；档案追加的可选字段；收紧的长度预算。长度预算是对世界书正文字数的提示阈值，按去掉空白后的字数计，超出只提示，不报错。第五层只能把它收紧。

### 字段

条目库与本局变量都要声明字段，二者用同一套写法。每个字段恰好写一种性质：

| 写法 | 含义 |
|---|---|
| 形态 | 文本字段，书写形式见下文 |
| 取值 | 值须在某个值域，即合法的取值范围之内 |
| 引用 | 值须是能解析的条目 ID、角色组ID 或事件ID |
| 子字段 | 由固定的子键组成，每个子键按同样的写法声明 |
| 映射 | 键任意、结构相同的字典，键与值各按同样的写法声明 |
| 数值 | 有上下限的整数，结果越界时截断，只用于本局变量 |
| 集合 | 无序、不重复的成员，只能逐项新增或移除，只用于本局变量 |

取值与引用可加“列表”，表示值是一组。条目库的字段可加“适用类型”，限定只有哪些类型的条目可以有这个字段。

形态是文本字段的书写形式，共五种：文本，即非空的一句话；文本列表，每项一句话；短语列表，每项一个短语，不以句末标点（如 `。！？；` 等）结尾；情境列表，每项是单键映射，键写情境，值写表现；禁区列表，每项以“不”开头。

值域可以是行内列出的值、某个等级序列、某个能力维度所分的门类（称为键）、纪年，或词表。词表是在 `设定/本局变量.yaml` 的 `词表` 之下命名声明的取值表，以 `词表.{名字}` 引用，第一个值是默认值。装备状态的词表必须声明，因为第一层的装备记录引用它。

写法同时决定字段的层。写取值、引用、数值的字段属于第三层，检查器校验每个值是否在值域之内、引用能否解析。写形态的是文本字段，受第四、五层约束。子字段、映射与集合按其成员定层。第二层声明字段，也就规定了检查器怎样对待这个字段的值。

### 生成

声明规定的种类与取值，模型也须知道。第二层的每项种类与取值只在 `设定/` 中声明一次，模型需要知道的清单，例如等级的高低、关系可取的值、动态事件可以写哪些字段，在打包时由声明生成。世界书的正文与协议文本不手写复述，作者的工作资料也不抄写。

生成经由模板。世界树仓库的 `templates/` 下有三份协议文本的模板：变量更新规则、角色通用约束与扮演准则，它们属于第一层，所有卡相同。模板中的占位符写作 `{{名字}}`，只有五种，来源各不相同。纪年格式、单次增减上限（即数值字段每次增加或减少的上限）与可写字段由声明生成。可写字段列出动态事件可以写入的每个字段，每行写路径、操作与取值，由剧情标记、本局变量与能力的声明生成。地点列表由地点库的条目生成，列出全部地点及其上下级与类型。本卡扮演准则取扮演准则的原文。模板中出现其它占位符时报错。

于是同一份声明同时作用于三处：打包生成的规则文本，检查器的校验范围，协议在游玩中截断数值、比较等级的依据。改动一处声明，三者随之改变，不必另行同步。

## 目录

声明本身也是世界书中的文件。世界书的根下只有三类目录：固定根、文本容器与条目库。作者的工作资料不在世界书之内（见“作者资料”）。

### 固定根

固定根是名称与结构由第一层规定的三个目录：角色、历史、设定，所有卡相同，工具据此找到角色组、事件与声明。角色根下每个角色组一个目录，其中有 `角色组.yaml` 与各个时期的档案。历史根下有事件、事件串、可选的世界线、开局选项与开局方案：事件串是被命名的一段有开头、有结局的过程，由若干事件组成；世界线用于表达跨整条时间轴生效的平行世界线；开局选项是开局时可以改选的、开局之前的事件分支。设定根下是全部声明。

### 文本容器

文本容器是只放供模型阅读的正文的两个目录：世界概况与扮演准则，名称固定。世界概况写跨越各条目库、在整个可游玩时期都成立的世界内容，例如战力格局、纪年与远古的历史，按主题分文件，按文件名的顺序进入上下文；多世界线的卡还可在 `世界概况/世界线/{世界线ID}/` 下放置该世界线专属的 `.txt` 文件，仅当本局选定对应世界线时按文件名码点顺序追加在公共概况之后。扮演准则写第五层中不能机器检查的部分：叙述人称、对白比例、文风偏好与本卡的写入约束。由第一层推出的扮演规则不写在这里，而由模板生成。本卡扮演准则的原文，经占位符填入扮演准则模板的末尾。

### 条目库

条目库是同一种公共条目的集合，例如技能、装备、地点、势力。卡有哪些条目库，各库怎样分目录、有哪些字段，都由第二层在 `设定/条目库.yaml` 中声明，规范不预设。所有条目库平铺在世界书的根下，不以“战斗”“经济”这类分组目录收纳。跨越几个库的格局，例如世界的战力格局，写进世界概况。每个库自成 ID 命名空间，库内 ID 唯一，别处引用条目时按库解析。

条目是条目库中的具体实例，每条一个 `.txt` 文件，文件名等于它的 ID。ID 字段名为 `{库名}ID`。“名称”可选，省略时等于 ID。其余字段都须在库的声明中声明过，出现未声明的键即报错。条目的全部字段剥离机器字段之后的内容，称为条目正文，是上下文展开条目时输出的内容。

库内的子目录有两种分法。按种类分时，各级目录名等于条目某个字段的值，依次对应哪些字段由声明中的“分级”规定，检查器校验每个条目所在的目录与它的字段值一致。按上下级分时，目录即实例，目录的嵌套即上下级，深度不限：文件与所在目录同名时，它是该目录所代表的实例的条目，其上级是再上一级目录的实例；不同名时，其上级是所在目录的实例；库根下的实例没有上级。按上下级分的库可以声明上级类型，规定每种类型允许挂在哪些类型之下，检查器据此校验搭配。声明了上级类型的库须有名为“类型”的字段。

库的根目录与按种类分的各级分类目录，可以有与目录同名的说明文件，写这一库或这一类特有的世界内容。说明文件受第四、五层约束，另禁用一批系统视角的措辞。写不出特有的内容就不写，也不复述第二层声明的种类与取值。按上下级分的库中，目录的同名文件是实例自身的条目，只有库根的同名文件是说明文件。路由展开条目时，按种类分的库附上根说明与条目所在各级分类的说明，按上下级分的库只附根说明。固定根不放说明文件。

技能、装备、地点三个库由协议直接读取，它们的名称与若干字段由第一层规定：技能库供协议计算角色可用的技能，本局按装备ID记录角色持有的装备，地点库给出地点的上下级。装备条目另支持可选的一层内建布尔字段 `唯一`（缺省为 `false`），标示世上独一件的器物，条目本身仍不写原主或当前归属状态；协议据此执行全本局强制唯一归属（见第二、四章）。地点库固定按上下级分。当前地点由地标与场景组成，地标是地点库中的地点。协议据上下级判断某地点是否在另一地点之下，路由据此从当前地点推出地点链，即当前地标及其各级上级，地点链上的条目，以及发生在这些地点的已确认事件与候选，因此进入上下文。卡用不到这三个库时，可以不声明它们。

### 文件

世界书的文件，内容都按 YAML 书写，扩展名只表示读者，不表示语法。`.txt` 是供模型阅读的文件，其中的文本字段在组装时剥离机器字段后进入上下文。`.yaml` 是工具数据，其中只有指定的几个字段进入上下文或展示给玩家：角色组与版本的显示名，即进入上下文时的称呼，与别名，即用来识别角色被提及的称呼；版本的简介；事件串的概述；世界线的概述；开局选项的问题（可选）与选项文字；开局方案的概述。其余字段只给工具读。措辞检查扫描 `.txt` 中的文本字段与 `.yaml` 中的这几个字段。

ID 是对象的标识。角色组、档案、预设事件、事件串、世界线、开局方案与条目的 ID，同时是它们的文件名或目录名，因此 `.yaml` 不重复写自身的 ID。事件与条目的 `.txt` 保留 ID 字段，因为记账结果或关闭记账时的正文命令要把它原样写回，检查器校验它与文件名或目录名一致。档案的两份文件不写 ID，档案ID由目录名给出。ID 的规则分属三层。第一层规定字符安全：ID 不为空，首尾不留空白，不含 `.`、`/`、`\`，不用保留字 `玩家`、`__proto__`、`constructor`、`prototype`（完整列表见[参考：世界书](参考/世界书.md)）。变化表的路径按点分段，带点的 ID 会使路径无法解析。第四层要求 ID 是世界内有意义的短语，不用编码样式，超过 12 个字时提示。第五层按文本规范声明的命名规则报错。

名称是对象供阅读的称呼。条目称“名称”，事件称“事件标题”，省略时都等于 ID。角色组与版本称“显示名”，进入上下文的显示名依次取所选版本的显示名、角色组的显示名与角色组ID。

每份源文件只写它的字段表所列的字段。`.txt` 写程序读取的结构字段与供模型阅读的文本字段，例如事件写事件ID、触发时间、门槛、分支与事件概要，条目写 `{库名}ID`、名称与库的声明所列的字段，档案分基本信息与角色印象两份文件，写角色在这一时期的身份、外观与行为方式。`.yaml` 写声明，或角色组、事件串、开局选项与开局方案这类工具数据。字段表或声明之外的键，检查器报错。世界概况、扮演准则与说明文件写正文，键由作者拟定，同样受措辞检查。上下文中每一部分外面的包裹标签，例如 `<在场角色>`，在渲染，即把组装好的上下文写成文本时统一加上。源文件中单独成行的包裹标签，检查器报错。有哪些角色组、哪些事件这类清单称为索引，由工具读目录得到。YAML 的书写风格，例如列表写成块状还是行内、缩进与引号，不属于任何一层，由 `ygg format` 统一 YAML 排版与键顺序。它缺省只检查，有差异时列出文件；显式加 `--write` 才写文件。检查器不为书写风格报错。用法见[参考：命令](参考/命令.md#format)。以 `.` 开头的文件与目录不读取。

### 作者资料

项目是卡的工作目录，根下有世界书与作者资料，可选 `来源资料/` 与 `yggdrasill.yaml`。参与运行的是世界书，以及 `yggdrasill.yaml` 中控制上下文规模的运行参数，例如各部分每轮进入上下文的条数与字符上限，称为预算。角色卡所需的其余部分，例如卡面内容，由适配层规定。作者资料是作者为自己保留的工作资料，放在世界书之外的 `作者资料/`，不进入上下文，不参与运行，不属于任何一层。

世界树只规定作者资料中工具要读写的部分。`通读/` 放第 0 层的通读分卷坐标账本、活词表与全局总账，`init` 预建 `通读/分卷/`。`出处/` 是结构化的来源记录，分两种：事件级记录写事件的来源，台词记录写每句收入事件的原作台词的来源。检查器校验记录所引的事件与台词存在，并据台词记录认定事件中哪些台词出自原作，这些台词中的破折号按原文保留，只作提示。`暂存/` 按世界书中的相对布局，存放已经写好、待条件满足后接回世界书的内容，并在清单中逐项登记接回的位置、结构与条件。`候选/` 放尚未定下的内容，`生成/` 放工具的输出、不手改，`归档/` 放撤下的内容、保留其在世界书中的相对布局。`审阅器/` 是 `ygg view` 的缺省审阅存储目录，存批注、布局与保存备份，首次写入时创建。目录详表见[写作规范](写作规范.md#作者资料)；其余资料，例如核定日志与创作规划，格式与位置由项目自定，只写设计理由、进度与待办，不抄写声明与规范的条文。

`来源资料/` 是可选的来源材料目录，供作者人工核对原作。代码只校验 `作者资料/出处` 的记录与所引对象，不读取、也不核对 `来源资料/` 的内容。

## 实例

下面以公开示例《三国演义》（`examples/三国演义/`）说明上述规定在具体的卡上怎样落实，对主示例未使用的少量语法特性辅以中性通用示意。《三国演义》示例基于维基文库公版《三国演义》第一至三回，共有 37 个角色组、45 份档案、150 个事件、15 个事件串，以及 3 个条目库中的 80 个条目（地点 59、装备 13、势力 8），两种分法、多类字段写法与五层都有体现。示例使用等长月历：纪年 `中平` 为 3 位年、每年 12 个月、每月 30 天；若某卡使用不等长月份（如四季历 `每月天数: [91, 91, 91, 92]`），同样在 `设定/纪年.yaml` 中按月列出天数。

### 能力与五层

勇力是《三国演义》的能力维度之一，从中可以看到第二层声明怎样贯穿第三至五层。`设定/等级.yaml` 声明等级序列 `勇力: [常人, 骁勇, 绝伦]`，`设定/能力.yaml` 声明其为单值等级且作为综合实力维度：

```yaml
维度:
  勇力:
    类型: 单值等级
    等级: 勇力
    综合实力: true
技能可用: []
```

第三层的档案初始能力与事件变化引用这一声明，例如 `刘备` 各期档案的初始能力写 `勇力: 骁勇`，`张角·太平道期` 写 `勇力: 常人`。若某卡进一步声明了等级映射维度的能力与技能库（例如声明 `武艺` 维度含 `剑术`、`骑射` 等键，并在 `技能可用` 中规定某技能须 `武艺.剑术` 达到指定等级方可使用），检查器同样按第二层声明校验键名与等级值域。

修改第二层声明时，凡未同步迁移的第三层引用都会失效：例如把等级序列中的某一级改名后，在临时副本上跑全量检查，检查器会列出所有仍写着旧等级名的档案、条目与事件变化；只改声明而不显式迁移，静态检查就会报错，抽样也不会执行。

```yaml
        操作: 设定
        值: 已死于张飞之手
      - 路径: 角色.董卓.职位.汉廷
        操作: 移除
      - 路径: 角色.董卓.身份
        操作: 新增
        值: 死于张飞刀下之将
```

同一文件中几层的字段并存。事件概要、分支结果是文本字段，分支条件是条件文本，都受第四、五层约束：检查器扫描其中的禁用词、破折号与陈旧的写法，《三国演义》在 `设定/文本规范.yaml` 的第五层另外追加了禁用词（如“史书”“译文”“回目”“毛本”“罗贯中”等）。主类型、标签、事件结果、触发时间、地点、核心参与者与分支ID属于第三层：触发时间须符合 `中平` 纪年写法，地点“董卓军寨（未名）”须在地点库中，主类型、标签与事件结果须在事件分类的声明中。每条变化的路径、操作与取值都须符合第二层：`董卓之命` 是 `设定/剧情标记.yaml` 声明的标记，`职位` 与 `身份` 是 `设定/本局变量.yaml` 声明的角色字段，`已死于张飞之手` 在 `董卓之命` 的取值表中。确认策略、默认分支与变化是机器字段，在组装时剥离。模型读到的，是路由为事件选取的几项：作为候选时，是事件ID、标题、概要、影响范围、公开信息、触发时间的最晚，以及门槛成立的分支的分支ID、分支条件与分支结果；确认之后，是事件ID、标题、概要、影响范围、实际时间、所走分支的分支结果、公开信息与隐秘信息。主类型、标签与地点虽然没有剥离，模型并不读到它们。

触发时间的最早与最晚都写到 `中平001年05月15日`，事件可以发生的时段就是这一日。以 `中平001年04月02日`（开局方案 `榜前长叹`）开局时，这一时段不早于开局时间，该事件不属于开局之前，封卷不补入。以 `中平006年06月13日`（开局方案 `温明园盛宴`）开局时，这一时段早于开局时间，封卷按默认分支 `提刀悬置` 补入，记录为确认于 `提刀悬置` 分支、实际时间为 `中平001年05月15日`。

### 地点

《三国演义》在 `设定/条目库.yaml` 中声明地点库按上下级分，并声明 `类型` 与 `概况` 两个字段：

```yaml
地点:
  分法: 按上下级
  字段:
    类型:
      必填: true
      取值: [州郡, 城邑, 宫殿, 官署, 村落, 庄园, 山地, 战场, 道路, 军营, 陵墓]
    概况:
      必填: true
      形态: 文本
```

`地点/幽州/涿县/涿县.txt` 与所在目录同名，是“涿县”这个实例的条目，它的上级是上一级目录的实例“幽州”；`地点/幽州/涿县/楼桑村.txt` 与所在目录不同名，是“楼桑村”的条目，它的上级是所在目录的实例“涿县”。若卡另外声明了 `上级类型`（例如限定“村落”只能挂在“城邑”之下），检查器还会校验各级搭配。

叙事模型把当前地点写为 `楼桑村` 之后，路由得到的地点链是 `楼桑村`、`涿县`、`幽州`。三者的条目正文进入上下文，共 142 字符，在每库 1500 字符的默认预算之内。条件“刘备的所在属于幽州”对身在 `楼桑村` 或 `涿县` 的刘备均成立，因为二者都在 `幽州` 之下。

### 数值与本局变量

本局变量的数值写法可由通用的好感度声明说明。例如某卡在 `设定/本局变量.yaml` 中声明好感度：

```yaml
好感度: {映射: {键: {引用: 角色组}, 值: {数值: [-100, 100]}}}
```

这一行规定了三件事：好感度按角色组记，键须是角色组ID；值是 -100 到 100 的整数，越界时截断；它的值属于第三层，检查器校验每个写入它的事件。打包时，`{{可写字段}}` 占位符由这一行生成发给模型的规则：

```
角色.<角色组ID>.好感度.<角色组ID>：增加、减少；-100 至 100 的整数
```

若某分支写入 `{路径: 角色.甲.好感度.乙, 操作: 增加, 值: 10}`，检查器核对增加的值是不超过单次增减上限的正整数（未声明上限时取缺省的 100），并核对甲与乙都已启用；若乙不是核心参与者且门槛未保证其启用，检查器就会报错。游玩中协议执行这条变化时，本局没有值则从 0 起算，结果截断在 -100 到 100 之内。作者若把范围改为 0 到 100，只改声明这一行，生成的规则与协议截断的界限随之同步改变，检查器对单次增减上限的校验不受影响。
