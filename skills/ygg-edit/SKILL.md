# 世界树·修订

本 skill 处理建成卡（或返工）后的局部改动。按所改字段判最高级别，允许在一次工作内连贯修改关联的结构与文本，只跑最小必要检查。按级检查矩阵、`trace` 对象键、改 `核心参与者` 连锁影响、旧存档 A/B/C 兼容评估、`作者资料/` 存放规范、五槽与越界清单见 [`./references/按级编辑与检查矩阵.md`](./references/按级编辑与检查矩阵.md)。

## 定级与分流

| 级 | 所改字段与边界 |
|---|---|
| 外观级（分流） | 修改 `<项目目录>/外观/` 不属世界书三层，也不改变 `世界书哈希` → **直接分流交 `世界树·前端`**（`theme-tool.mjs validate` + `preview` + `ygg pack`） |
| 设定级（第二层） | `设定/` 第二层声明（`纪年`/`等级`/`能力`/`事件分类`/`条目库`/`本局变量`/`剧情标记`/`角色分类`） |
| 结构级（第三层） | 事件/分支/门槛/变化/核心参与者/事件串/世界线/开局/角色组/档案生效条件/条目 ID 与引用 |
| 文本级（第四、五层） | 档案正文、事件概要与条件文本、角色位置、条目正文、概况、准则，以及 **`设定/文本规范.yaml`**（须确认第五层未放宽第四层） |

- **第一层架构卡不能覆盖**：修改第一层机制属修订世界树规范本身，不在建卡修订范围。
- **混合改动取最高级**：把关联的结构与文本一次改完，再按最高级统一跑检查。

## 流程与硬红线

1. **改前留基线与兼容评估**：先跑 `ygg check <世界书目录> --static-only --json`（或全量 `ygg check`）记下已有错误与提示，改后只对新增失败负责；对已发布卡同步评估本次改动触发的旧存档 **A / B / C 兼容级别**（改 ID、删角色组/剧情标记、改过去事件将触发 C 级只读）。
2. **设定级**：修改 `剧情标记:<ID>` 与 `条目:<库>:<ID>` 时先用 `ygg trace` 查引用；修改等级、能力、条目库或词表时，在一次性临时副本上删/改待改值跑 `ygg check <副本世界书> --static-only --json` 得反向清单，配全文检索列出全部旧值位置，逐项与作者确认迁移值后再改真实文件；改后跑全量 `ygg check` 与相关 `ygg if`。
3. **结构级**：改前用 `ygg trace <世界书目录> <对象键>` 列出指向待改对象的全部引用（“引用它”）；若修改 **`核心参与者`**，须额外核查四重连锁影响（事件排除面、变化表启用担保、开局必选角色锁定、路由候选与经历召回）。改后同步全部引用与受影响文本，再跑全量 `ygg check`、相关 `ygg if` / `ygg preview` 与 `ygg format <世界书目录> --check`（若使用 `ygg view` 图形化编辑，注意其**仅限事件与角色位置**）。
4. **文本级**：改条件文本前先写下五槽适用范围，改后逐槽对照，范围变了就退回原文或拆给结构级；**文本级绝不顺带补写事件或断言本局状态**（发现事实错位时清理越界断言、保留行为方式并指出结构缺口交结构级处理）；改后跑 `ygg check <世界书目录>` 与 `ygg format <世界书目录> --check`（纯文本改动不要求跑 `if` 对比）。
5. **通用修订红线**：
   - **严禁为让检查通过而改测试、检查器或第二层声明**；
   - 运行 `ygg format <世界书目录> --write` 后**必须重跑 `ygg check`**；
   - 暂存、候选、归档与生成产物按 `作者资料/` 标准子目录存放（见参考页），不污染 `世界书/`。

## 停下等作者

迁移值清单、ID 改名（涉及旧存档 C 级只读或迁移表）、条件适用范围变化，须作者拍板后才落盘。完成后呈报：改动清单 + 级别 + 旧存档兼容影响评估 + 检查结果（改前已有与本次新增分开列出）。
