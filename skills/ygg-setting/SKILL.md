# 世界树·设定

本 skill 只处理设定级：`设定/` 中的第二层声明，以及因声明改变而不再合法的第三层字段。声明写什么见 [`docs/01-世界书.md`“声明”](../../docs/01-世界书.md#声明)，改动规则见 [`docs/写作规范.md`“编辑”](../../docs/写作规范.md#编辑)；分级与公共检查见 [`../shared/编辑分级.md`](../shared/编辑分级.md)。

## 1. 锁定声明与基线

1. 找到声明文件与键，读出全部取值与引用规则；读项目 `作者资料/` 中与该声明有关的规划。
2. 判定这是设定级：删去或改动的是一种可能的种类或取值，而不是某个具体实例。具体实例归“事件”或“角色”。
3. 在临时副本上工作，记录输入哈希；按 shared 跑 `check --static-only --json` 与 `format --check --json`，保存基线。

完成标准：声明文件、键、旧值与新值已写明；输入哈希与两份基线已保存；改动范围只含声明与迁移。

## 2. 列反向清单

1. 有对象键的引用先用 `trace`：剧情标记查 `剧情标记:<ID>`，条目查 `条目:<库>:<ID>`，角色组、档案、事件与事件串按各自对象键。`trace` 列路径与条件引用，不列变化里的取值。
2. 等级、能力、条目库与词表声明没有对象键。把世界书复制到一次性副本，只删去或改名待改声明值，跑 `check --static-only --json`，把每条错误按“文件、规则、说明”记入反向清单；随后还原副本中的声明。错误涉及的每个字段回到原世界书定位。
3. 纯文本提及另用文本搜索逐条举证：`grep -rn '<旧值>' <世界书目录> <作者资料>`。每条命中写明“迁移、保留为 ID 或名称、或删除”，并给理由。
4. 把结构引用写成“文件 → 字段 → 当前值 → 迁移后值”；没有迁移后值的项标“拟删除”。把反向清单与文本命中清单交作者，逐项确认迁移后值与拟删除项。

完成标准：反向清单来自一次实际的 `check --static-only` 运行，每条错误都已定位；每条文本命中都有结论；作者已逐项确认迁移值与拟删除项。

## 3. 迁移

1. 先改声明，再按清单逐项改第三层字段。事件门槛与变化的字段规则见 [`docs/参考/事件.md`](../../docs/参考/事件.md)，角色组与档案见 [`docs/参考/角色.md`](../../docs/参考/角色.md)；本 skill 只负责把旧取值换成新取值。
2. 改动触及事件门槛、变化、事件串或开局时，按 shared 用改前保存的 `if --json`，改后重跑并比较。
3. 需要统一 YAML 风格时按 shared 运行 `format`，只写确有差异的文件。

完成标准：清单每项已落实，文本命中已按结论处理；没有未处理的旧值；改动文件都在清单内。

## 4. 检查与比较

1. 按 shared 重跑 `check --static-only` 与全量 `check`；只把相对基线的本次新增错误与提示列为问题。
2. 触及事件门槛、变化、事件串或开局时，两次 `if --json` 都删除 `输入.世界书` 后比较；差异只应来自迁移清单中的路径。
3. 重跑 `format --check --json`；本次改动文件不新进入差异集，差异总数只按新建、删除或既有差异解释。

完成标准：静态检查与全量检查无新增错误；`if` 差异逐项对应迁移清单；`format` 的差异变化有解释。

## 5. 报告

写明声明文件与键、旧值到新值、反向清单与文本命中清单、迁移结论、输入哈希、检查与 `if` 比较结果、改动前已有问题与未解决项。

完成标准：报告能让人按清单复核每一处迁移；未解决项写明位置与是否影响本次范围。
