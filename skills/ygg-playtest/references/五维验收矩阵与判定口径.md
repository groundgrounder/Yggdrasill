# 五维验收矩阵与判定口径

本参考页配套 `世界树·验收`（`SKILL.md`），定义大型角色卡在打包后、交付酒馆前的五维离线试玩验收标准、离线脚本调用范式、问题三分法裁决判例、可选双盲分轨协议与脱敏报告模板。

---

## 1. 五维反原作试玩验收矩阵（D1–D5）

无需手写完整小说，基于目标卡的世界观构造 **2 份最小反原作对抗剧本**（或采用作者/玩家现成的高自由度魔改开局），覆盖以下五个正交维度即可复用于任意世界树大型卡：

| 维度 | 探测目标 | 作品无关通用构造法 | 量化断言与通过/失败口径 | 常见假阳性排除 |
|---|---|---|---|---|
| **D1：早期遭遇中后期角色（默认期防剧透）** | 防止无前置事件触发时的默认档案（`默认: true`）泄漏中后期战果、后设身份、未发生人际关系或归属时期错位 | 选取最早可行开局年份，把本卡中后期才登场的核心反派、隐世强者或后段盟友拉入 `在场`，调用 `route` 检查实际进入上下文的默认档案正文，并结合 `probeCard` 产出的 `defaultProfiles` 全量精读 | **通过**：全部默认档案均不提及开局时间之后才发生的事件、胜负、羁绊、死亡或后段身份；`默认: true` 落在该角色最早出场/开局时的真实处境。<br>**失败（A 类 P0/P1）**：任一默认档案出现未来剧透或默认期错落到中后期档案 | 开局前已成既定历史的世界观背景（如上古传说、旧朝覆灭）属于合法背景，不判剧透 |
| **D2：劫持高危转折点（跨年不覆盖与分支隔离）** | 防止玩家通过动态事件提前救下、截胡或改写关键转折点后，跨年时钟推进仍触发原作单分支自动确认并覆盖现实 | 抽取本卡 2–3 个高权重「自动确认」转折事件：先在事件窗口前后通过 `applyCommands` 写入玩家介入动态事件，再将时间推进 1–3 年并检查事件状态、分支变化与相关角色知情/主观记忆 | **通过**：高危易被玩家外力打断的转折点具备合理的非默认替代分支（或门槛可被玩家介入条件拦截），且按分支正确隔离 `角色知情` 与 `主观记忆`。<br>**失败（A 类 P1）**：极易被玩家提前截胡的局部/个人决斗类单分支自动确认在玩家改写前提后仍强行覆写原作结局 | 纯世界级不可抗力天灾/宏观时代变动在未写替代世界线时按原作推进属合理边界（B 类），不应强行削弱主干 |
| **D3：反原作多年沙盒（经历预算淘汰与静态地点张力）** | 量化自由沙盒跨年运行后，玩家自创动态事件在 `经历` 预算上限下是否被同城原作幕后事件挤出记忆，以及静态地点条目与玩家巨变的张力 | 在非主线或高密度地点连续推演 3–10 年，写入多条含跨年持续影响的玩家动态事件，分别测试「独处/异地基线」与「与核心原作角色同城基线」，逐年调用 `route` 观测 `audit` 与渲染正文 | **通过**：明确测出动态事件留存/淘汰临界年与原因（条数上限 vs 字符上限），确认 `yggdrasill.yaml` 预算配置与本卡规模匹配；无意外异常。<br>**失败/边界**：若核心事件在 1–2 年内即被无关琐事挤掉且预算明显偏紧，标 A 类 P2 调优预算；长周期满额正常淘汰与静态地点词条未预知玩家建国标 B 类已知边界 | 满额 LRU/优先级淘汰是路由预算保护机制本身，不能因“多年后旧事件被挤出”直接判引擎故障 |
| **D4：停用核心主角 / 极端世界线（依赖瘫痪与幽灵主角审计）** | 量化关闭核心主角组或走极端世界线时的事件树存活率与文本硬绑定面，避免盲目制作半成品删主角补丁 | 在开局配置停用第一主角组（`角色组.<主角>: false`），先用 `probeCard(api, {disableGroups: [主角ID]})` 获取直接/级联停摆统计，再全文扫描所有角色档案与公共条目正文对停用主角的硬引用 | **通过**：产出精确的 `totalEvents`、`directDisabled`、`cascadeDisabled`、`survivingEvents` 与「幽灵主角」文本引用清单，区分历史背景引用与无主角穿帮句。<br>**判定**：单主角正史卡停主角后主线大面积停摆属 B 类合理边界（记入已知边界或规划独立平行世界线）；若声明支持“无主角自由线”但档案/条目大面积硬绑定主角，则标 A 类 P1 | 仅在某事件分支专属记忆或开局前历史传闻中提及原作人物，不构成全局硬绑定穿帮 |
| **D5：真实开局前端 + 记账对抗 + 拥挤在场预算** | 验证打包卡内嵌的开局前端、独立记账提示词与 JSON 修补鲁棒性、自定义装备/技能跨人移交与多人同场预算退化 | 1. 调用 `createOpeningDraft` / `openingNode` 喂合法、越界纪年、未来出生年与错型 YAML；<br>2. 构造 15–30 项对抗记账回复（非法映射键、自创势力、自定义装备移交 NPC、遗漏移除、修改 `角色.<ID>.所在`、提前结束事件串、非法 JSON 等），用 `host.pushResponse` 跑 `runKeeperLoop` / `repairRecord`；<br>3. 拉入 6–10 名高权重角色同场调用 `route` | **通过**：开局前端对非法输入不抛未捕获异常、不产生非法派生值（如负年龄）；自定义装备/技能移交后路由与下轮记账提示词一致；记账对抗 100% 符合协议契约；多人拥挤在场时路由按预算分级退化且不崩溃。<br>**失败**：与具体作品无关的提示词缺项、校验漏拦截或前端异常标 C 类问题单；卡自身声明缺失标 A 类 | 记账模型故意输出的非法命令被协议校验器正确拒绝并写入 `失败` 列表属于**预期通过**，不是缺陷 |

## 2. `mount-card.mjs` 离线试玩脚本调用范式

将以下最小可运行模板放到 `<临时目录>` 或过程目录运行，全程只读不改写卡文件与世界书：

```js
import assert from 'node:assert/strict';
import path from 'node:path';
import {mountCard, snapshotHashes, probeCard} from './scripts/mount-card.mjs';

const projectDir = process.env.PLAYTEST_PROJECT_DIR; // 仅通过环境变量传入，不在报告打印宿主机绝对路径
const cardPath = process.env.PLAYTEST_CARD_PATH;

// 1. 起手防篡改哈希快照
const beforeSnap = await snapshotHashes([path.join(projectDir, '世界书'), cardPath]);

// 2. 挂载真实打包卡（自动适配 hook / legacy-export）
const {api, mode, cardMeta, host, cleanup} = await mountCard(cardPath);
try {
  // 3. 结构探针（D1 默认档案清单 + D4 停用影响）
  const probe = probeCard(api, {disableGroups: ['<核心主角组ID>']});
  console.log('挂载模式:', mode, '卡哈希:', cardMeta.sha256.slice(0, 12), '默认档案数:', probe.defaultProfiles.length);

  // 4. D5：真实开局前端草稿与 DOM 桩测试
  const draft = api.createOpeningDraft({
    protocol: api.protocol,
    catalog: api.catalog,
    decl: api.decl,
    defaults: api.bundle.opening,
    commands: api.bundle.openingCommands,
  });
  const ui = api.openingNode(draft, {compact: false});
  const submitBtn = host.findNode(ui.node ?? ui, n => n.tag === 'button');
  assert.ok(ui);

  // 5. 封卷 + 场景切换 + 路由（D1 / D2 / D3 / D5）
  let state = api.seal(api.protocol, api.bundle.opening);
  const routed = api.route(api.quietRouter, state, ['第一轮玩家输入']);
  const promptText = api.renderContext(routed.context);
  assert.ok(promptText.length > 0);

  // 6. D5：记账对抗（离线注入模拟模型 JSON 输出）
  host.pushResponse(JSON.stringify({
    时间: {方式: '不变', 日期: '', 事件ID: ''},
    地点: {地标: '', 场景: ''},
    在场: [],
    发生的事件: [],
    新情况: [],
  }));
  const loop = await api.runKeeperLoop({
    keeper: api.keeper,
    base: state,
    input: '推进剧情',
    narration: '众人稍作休整，暂无状态变化。',
    config: {应答格式: '提示词'},
    attempts: 2,
    call: api.callKeeper,
    isCurrent: () => true,
  });
  assert.equal(loop.stale, false);
  assert.ok(loop.best && loop.best.outcome.失败.length === 0);
  assert.ok(host.calls.length >= 1);
} finally {
  cleanup();
}

// 7. 收尾防篡改核对（断言 100% 只读零落盘）
const afterSnap = await snapshotHashes([path.join(projectDir, '世界书'), cardPath]);
assert.equal(afterSnap.fileCount, beforeSnap.fileCount);
assert.equal(afterSnap.rootSha256, beforeSnap.rootSha256);
```

## 3. 问题级别 × 归属三分法裁决指南

每条试玩发现必须同时给出**严重级别**与**归属分类**，防止为迎合极端魔改把原作主干改碎：

### 严重级别

- **P0（崩溃 / 硬穿帮）**：未捕获异常、协议封卷/路由崩溃、默认期严重泄漏终局剧透或直接写死未来身份。
- **P1（显著体验损毁）**：高危单分支转折点在玩家提前截胡后跨年静默覆盖战果、关键角色默认期错期、核心功能记账提示词漏列导致高频记错。
- **P2（边界优化）**：非核心角色轻度措辞提示、预算边界微调、极端自由度下的边角体验优化。

### 归属三分法与典型判例

| 归属 | 定义 | 作品无关典型判例 | 处置出口 |
|---|---|---|---|
| **A. 卡侧值得立刻修** | 在合理游玩与常见反原作介入下即可触发的本卡内容/结构缺陷 | ① 某反派或盟友的 `默认: true` 档案写入了中后期战败、归顺或死亡后的关系；<br>② 默认档案误标在中后期时期而非开局时期；<br>③ 局部个人决斗类「自动确认」转折点只有单分支，玩家提前救人或打断后跨年仍强行写入原作死亡结果 | 移交 `世界树·修订` 按改动级别最小精准修复 → 重跑 `ygg check` 与 `ygg pack` → 复验确认消除 |
| **B. 原作卡合理边界（记录不硬修）** | 作品固有结构或路由预算设计的合理边界，强改反而破坏正史体验 | ① 单主角正史长篇卡在玩家手动停用第一主角组后，80%+ 围绕主角的剧情事件停摆；<br>② 纯静态地点词条无法预知玩家在沙盒中自建新王国或炸毁城池；<br>③ 连续沙盒推演多年并写入数十条事件后，早期非核心事件在字符预算满额时按优先级被正常淘汰 | 写入卡片发布说明的「已知边界」，或记入后续独立平行世界线规划；**严禁为极端魔改阉割正史主干** |
| **C. 引擎/协议/提示词侧改进** | 与具体作品内容无关的框架、开局前端、路由或记账提示词缺陷 | ① 开局前端遇到错型 YAML 抛出未捕获 `TypeError`；<br>② 记账提示词漏列某个可写字段或未展示合法引用 ID 列表；<br>③ 自定义装备移交 NPC 后下轮记账提示词未体现当前持有归属 | 抽离为作品无关的最小复现用例，单列上游问题单反馈给引擎维护线 |

## 4. 可选：跨模型家族双盲分轨协议

标杆卡或大版本发布前，若具备多模型执行环境，可将五维拆为两轨并行只读执行，减少单一模型的审阅盲点；单模型环境顺序执行一遍即可，不作硬前置：

- **叙事与设定轨**：侧重 **D1**（逐份精读默认期防剧透）、**D2**（剧情转折合理性与分支记忆隔离）、**D3**（长线沙盒叙事体验与静态地点张力）、**D4**（文本级「幽灵主角」引用审计）。
- **系统与对抗轨**：侧重 **D5**（真实 `createOpeningDraft`/`openingNode` 边界输入 + 15–30 项记账对抗与修补 + 拥挤在场预算）、**D3**（逐年淘汰临界曲线精确测算）、**D4**（事件树图论级直接/级联依赖统计）。

两轨各自输出脱敏报告后，统一按「级别 × 归属三分法」合并去重，交作者拍板 A 类修复范围。
