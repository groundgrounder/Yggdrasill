# 世界树·文本

本 skill 只改已有文本：档案正文、事件的概要与叙事条件、分支条件与分支结果、角色位置、条目与说明文件、世界概况、扮演准则与 `设定/文本规范.yaml`。结构字段、声明与检查器不在本 skill 内改；新写档案正文用“建角色”。文本写法见 [`docs/写作规范.md`“文本”](../../docs/写作规范.md#文本)，越界与公共检查见 [`../shared/编辑分级.md`](../shared/编辑分级.md)。

## 1. 锁定文本字段与归属

1. 写明要改的文件、字段与当前文本。
2. 判断字段类型：普通文本，或条件文本。条件文本是叙事条件、分支条件、介入条件、触发情境与触发限制；分支结果是普通文本。
3. 结构字段（门槛、变化、默认分支、适用版本、初始能力等）停下，交给“事件”“角色”或“设定”；新档案正文交给“建角色”。

完成标准：文件、字段与当前文本已写明；普通文本与条件文本已区分；结构字段与新写正文已排除。

## 2. 改前基线与适用范围

1. 在临时副本上工作，记录输入哈希；按 shared 跑 `check --static-only --json` 与 `format --check --json`，保存基线与有差异文件集合。
2. 按 shared 保存 `if --json` 基线：默认路径，加上本次相关的方案、排除、分支或停用角色组。
3. 条件文本写下五槽适用范围：对象、地点、时间、分支、触发情形。
4. 记录被改文件的哈希，改后用逐行 `diff` 证明变动只在文本字段。

完成标准：输入哈希、检查基线、`format` 差异文件集合与 `if --json` 已保存；条件文本五槽已写成可对照的条目；被改文件哈希已记录。

## 3. 改文本

1. 只改文本字段；保持行为方式与当期视角。
2. 条件文本的措辞改动不得改变五槽；分支结果按所属分支写实际结果。
3. 改 `设定/文本规范.yaml` 时，第五层只收紧或补充第四层已有约束；不放宽禁用词、ID 命名、字段形式或长度预算，`check` 的 `设定.文本规范` 按错误处理。
4. 不改结构、声明、测试或检查器；需要统一 YAML 风格时按 shared 运行 `format`，只写确有差异的文件。

完成标准：逐行 `diff` 的变动都落在已锁定的文本字段；结构字段与 `.yaml` 没有变化；第五层约束没有放宽。

## 4. 核对条件文本

1. 逐条对照五槽：对象、地点、时间、分支、触发情形。五槽只由人工核对，`check` 与 `if` 不判语义。
2. 任一槽变化的，退回原文，或把改动拆出来交给结构级 skill。
3. 条件文本涉及事实放错位置时，清理越界断言，保留行为方式，把缺口交给结构级 skill。

完成标准：五槽逐条对照后与第 2 步一致；越界断言已清理；需要结构改动的地方已交接。

## 5. 检查与比较

1. 按 shared 跑 `check`，与基线比较；只把本次新增错误与提示列为问题。
2. 重跑 `format --check --json`：本次改动文件不得新进入差异集；差异总数只按新建、删除或既有差异解释。
3. 重跑 `if --json`；两次 JSON 删除 `输入.世界书` 后比较。纯文本改动应为空差异；触及条件所引结构时应只有预期路径变化。
4. 对照被改文件哈希与逐行 `diff`：`.yaml` 与结构字段没有变化，变动只在文本字段。

完成标准：检查无新增问题；`format` 与 `if` 的比较符合上述条件；结构哈希与逐行 `diff` 证明只有文本变化。

## 6. 报告

写明文件与字段、改动前后、普通文本或条件文本、五槽适用范围对照、人工复核记录、检查与比较结果，以及未解决项。

完成标准：报告能按字段复核文本改动；未解决项写明位置与是否影响本次范围。
