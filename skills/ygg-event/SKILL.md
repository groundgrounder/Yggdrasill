# 世界树·事件

本 skill 处理结构级的事件与其连接：事件、分支、门槛、变化、事件串、开局选项与开局方案。修改已有事件时，结构归本 skill，概要、叙事条件、分支条件与分支结果归“文本”；新建事件或分支时，本 skill 一并写必填文本首稿，归属见 [`../shared/编辑分级.md`](../shared/编辑分级.md) 的“首稿归属”。字段与条件见 [`docs/参考/事件.md`](../../docs/参考/事件.md)，规则见 [`docs/03-事件.md`](../../docs/03-事件.md)。

## 1. 锁定对象与归属

1. 写明要改的是事件、分支、门槛、变化、事件串、开局选项还是开局方案；分支、门槛与变化的对象键是所属事件。
2. 区分新建与修改：新建事件或分支时本 skill 写结构与必填文本首稿；修改已有对象时只改结构，文本字段交“文本”。
3. 记下对象键、所属文件与预期路径变化。

完成标准：对象键、字段与预期路径已写明；新建与修改已区分；文本字段的归属已写明。

## 2. 改前基线与引用

1. 在临时副本上工作，记录输入哈希；按 shared 跑 `check --static-only --json` 与 `format --check --json`，保存基线。
2. 按 shared 保存 `if --json` 基线：默认路径，加上本次相关的方案、排除、分支或停用角色组。
3. 用 `trace` 查询待改对象：事件查 `事件:<ID>`，事件串查 `事件串:<ID>`；开局选项或方案没有独立对象键时，查询它涉及的事件与角色组。
4. 把“引用它”的每个来源对象、文件与字段逐项列出；这些位置在改动后都要同步。

完成标准：基线、`if --json` 与引用清单已保存；每个待同步位置都有文件与字段。

## 3. 建或改结构

1. 新建事件时写 `历史/事件/<事件ID>/事件.txt` 与 `历史/事件/<事件ID>/角色/<角色组ID>.txt`；事件ID 等于目录名；必填字段按参考。
2. 新建分支时写 `分支ID`、门槛、`分支条件`、`分支结果` 与变化；事件与分支的必填文本首稿一并写出，越界按 shared。
3. 新建事件串写 `历史/事件串/<事件串ID>.yaml`；开局选项写 `历史/开局选项.yaml`；开局方案写 `历史/开局方案/<方案ID>.yaml`。新事件要接串时，同步事件串的成员与结局；要进入开局时，同步相关选项与方案。
4. 门槛只写真正的因果；状态变化只写进变化表；分支条件要能相互区分；自动确认的事件有带门槛的分支时保留兜底分支。
5. 开局选项只用开局前事件与可选分支；开局方案的历史选择须在选项内，且不晚于开局时间。
6. 事件串只命名过程与结局，结局须属于本串且可达。
7. 本节结束前跑 `check --static-only --json`，只把相对基线的本次新增错误列为问题。

完成标准：静态检查无新增错误；每个改动都有明确的事件、分支或方案位置；新建对象文件齐全，文本首稿完整。

## 4. 路径核对

1. 按 shared 重跑 `if --json`：默认路径与本次相关的方案、排除、分支或停用角色组。
2. 对比四类差异：没发生、新发生、分支不同、停住的事件串；影响面与异常单独看。
3. 两次 JSON 比较前删除 `输入.世界书`；差异逐项对应改动清单，非预期差异回到第 3 步。
4. 影响面逐项记录下游事件数、涉及的事件串与引用位置；数量或跨事件串的缺口在报告里说明，不设虚构阈值。

完成标准：`if` 输出已保存；预期路径出现或消失的事件能逐个解释；每个影响面项都有数量与说明；没有非预期差异。

## 5. 全量检查

按 shared 跑全量 `check`，需要时运行 `format` 检查。只对本次新增的错误负责，改动前已有的问题单列。

完成标准：全量检查无新增错误；抽样通过；改动前已有的错误与提示已分开列出。

## 6. 报告

写明对象键、改动前后、`trace` 引用清单、`if` 路径对比、静态检查与全量检查结果，以及未解决项。

完成标准：报告能按对象键复核每一处引用同步；未解决项写明位置与是否影响本次范围。
