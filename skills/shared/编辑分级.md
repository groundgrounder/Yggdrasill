# 编辑分级与公共检查

六个作者 skill 共用本页。改动级别按所改字段属于哪一层判断，不按文件判断；规范原文见 [`docs/写作规范.md`“编辑”](../../docs/写作规范.md#编辑)。本页是分级、工具、改前改后、首稿归属与边界的唯一公共页，各 skill 只写自己的步骤。

## 分级

| 级 | 所改字段 | 改前 | 改后 |
|---|---|---|---|
| 设定级 | 第二层：`设定/` 中的声明 | 记基线；用反向清单列出仍使用旧声明的第三层字段与文本提及 | 全量检查；清单逐项迁移，经作者同意；不再合法的内容没有残留 |
| 结构级 | 第三层：事件、分支、门槛、变化、事件串、开局、角色组、档案元数据、条目 ID 与引用 | 记基线；用 `trace` 列出引用；触及事件门槛、变化、事件串或开局时另存 `if --json` | 同步全部引用；静态检查与抽样；比较 `if` 的前后差异 |
| 文本级 | 第四、五层：文本字段、条件文本与分支结果 | 记基线、`format` 差异文件集合与 `if --json`；写下条件文本的五槽适用范围 | 格式与措辞检查；`format` 与 `if` 两次运行比较；五槽人工复核 |

混合改动取最高级，并叠加各级检查。

## 越界

越界指把本局状态写进文本：关系、婚姻、家系、职位、资产、持有物、伤势、当前穿着、能力的取得与丧失，以及当前所在。这些只由事件变化或写场景写入；换个字段名承载同样越界。越界清单只在本节维护，各 skill 用“越界”指回本节。

`check` 不判定语义上的越界：文本里的状态断言可以零错误通过。文本中的越界由作者逐条人工核对。

## 首稿归属

| 动作 | 结构与骨架 | 文本首稿 |
|---|---|---|
| 新建单个事件或分支 | 事件 skill | 事件 skill 一并写 `事件概要`、各分支的 `分支条件` 与 `分支结果`；有叙事条件时也写 |
| 修改已有事件 | 事件 skill | 概要、叙事条件、分支条件与分支结果归文本 skill |
| 新建角色组或版本 | 角色 skill | 两份档案正文交建角色 skill |
| 建立整套世界书 | 建立 skill 按篇编排 | 事件与档案首稿随建立步骤写出，规则与检查仍按对应 skill |

## 工具

以下命令都在世界树代码仓库根执行，`<世界书目录>` 与对象键按项目替换。用法以 [`cli/ygg.mjs`](../../cli/ygg.mjs) 的实际输出为准。

| 用途 | 调用 | 说明 |
|---|---|---|
| 全量检查 | `node cli/ygg.mjs check <世界书目录> [--json]` | 静态检查通过后执行抽样；有错误时退出非零 |
| 静态检查 | `node cli/ygg.mjs check <世界书目录> --static-only [--json]` | 只核对目录、声明、字段、引用与文本，不封卷 |
| 溯源 | `node cli/ygg.mjs trace <世界书目录> <对象键> [--json]` | 列出引用它、它引用、出处与异常；结构级改前必跑 |
| 如果视图 | `node cli/ygg.mjs if <世界书目录> [--方案 <方案ID>] [--排除 <事件ID>]... [--分支 <事件ID>:<分支ID>]... [--停用角色组 <角色组ID>]... [--json]` | 对比默认路径与 if 路径；输出四类差异、影响面与异常 |
| 初始化预览 | `node cli/ygg.mjs preview <世界书目录> <角色组ID> [--开局 <纪年>] [--方案 <方案ID>] [--本局 <本局JSON>] [--json]` | 只读封卷后输出首次登场将写入的档案、能力与装备；`--本局` 读取已封卷本局 |
| 排版 | `node cli/ygg.mjs format <世界书目录> [--check] [--write] [--json]` | 缺省只检查；需要统一 YAML 风格时才用 `--write` |
| 作者视图 | `node cli/ygg.mjs view --worldbook <世界书目录> [--storage <审阅存储目录>] [--port <端口>]` | 本地图形作者工具；预览为静态检查，只有界面显式保存才写单个事件；参数与边界见[作者视图](../../view/README.md) |

命令的行为、输出与错误码见[作者指南“工具”](../../docs/作者指南.md#4-六个工具)与[检查规则“命令”](../../docs/参考/检查规则.md#命令)。`trace` 只认六类对象键；等级、能力、条目库与词表声明没有对象键，用下面的反向清单。

## 改前

1. 在临时副本上工作，真实世界书与 `作者资料/` 只读；记录输入的哈希。
2. 跑 `check --static-only --json`，把已有的错误与提示记作基线；需要抽样时另跑一次全量 `check`。
3. 结构级改动跑 `trace`，把每个待改对象与它的引用位置逐项列出。触及事件门槛、变化、事件串或开局时，另存默认路径与相关方案、排除、分支、停用角色组的 `if --json` 作为路径基线。
4. 设定级改动建立反向清单：有对象键的声明用 `trace` 与文本搜索；没有对象键的声明在一次性副本上删去或改名待改取值，跑 `check --static-only --json`，把报出的文件、规则与说明逐条记下，再还原副本。
5. 文本级改动跑 `format --check --json`，保存 `项目.差异` 与有差异文件集合；条件文本另写下改前的五槽适用范围：对象、地点、时间、分支、触发情形。记录被改文件的哈希。

## 改后

1. 用同一命令重跑，分开报告“改动前已有”与“本次新增”的错误、提示。
2. 结构级改动跑静态检查与抽样；触及事件、分支、事件串或开局时再跑 `if --json`。两次 JSON 比较前删除 `输入.世界书`，否则路径不同会产生伪差异；结构改动只应出现预期路径变化。
3. 文本级改动比较 `format`：本次改动文件不得新进入差异集；差异总数只按新建文件、删除文件或既有差异解释。纯文本改动重跑 `if` 应为空差异。
4. 文本级改动对照改前哈希与逐行 `diff`：结构字段与 `.yaml` 没有变化，变动只落在已锁定的文本字段。
5. 人工复核只做工具做不到的部分：越界断言逐条交作者确认；条件文本五槽逐条对照；修改 `设定/文本规范.yaml` 时确认第五层只收紧或补充第四层，`check` 的 `设定.文本规范` 报告放宽。
6. 没跑的检查不说通过；不为让检查通过而改测试、检查器、声明或真实世界书。计数或快照因改动合理变化时，先报告具体断言。

## 边界

- 只调用现有 `ygg` 工具与现有协议接口，不另造条件解析、引用索引、封卷、初始化解析、格式化或检查命令。
- 作者视图的预览是 `check --static-only` 的等价静态检查，保存后才是完整检查；批注/布局只写审阅状态，不改事件正文。存储默认值必须在实现仓库与世界书之外。
- `check` 与 `if` 不判定语义：状态断言、条件文本的适用范围、越界与否都由人工复核。`check` 通过不等于这些语义没有变化。
- `trace` 只列路径与条件引用，不列变化中的取值；取值级引用以反向清单与文本搜索为准。
- 世界书的规范正本在 `docs/`；作者资料只写设计理由、进度、出处与候选，不复述声明或规范条文。
