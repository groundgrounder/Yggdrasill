# 卡面与打包核对

## 卡面字段契约

| 字段 | 必填 | 约束 |
|---|---|---|
| `卡ID` | 是 | 非空文本；跨版本稳定，不得随 `名称` 改变 |
| `卡版本` | 是 | 非空文本，供人识别版本 |
| `名称` | 是 | 非空文本，同时决定产物文件名 `<名称>.json` |
| `描述` | 是 | 非空文本；写叙述者职责，不写命令语法或随运行模式冲突的长期指令 |
| `开场白` | 是 | 非空纯正文；严禁包含 `<命令>` 或 `</命令>`。静态预设卡写默认场景正文；自由开局/多世界线卡可直接写封面说明占位 |
| `开局` | 是 | 映射（可含 `世界线`、`开局时间`、`方案`、`角色组`、`玩家`、`历史选择`；自建玩家可附 `初始能力` 与 `初始装备`），供开局前端作默认初值 |
| `开场命令` | 否 | 单键命令映射的列表（如 `确认初始化`、`写场景`）；仅在「预设精修」开场白模式下执行，打包时会在内存中预执行一次 |
| `可选在场` | 否 | 无重复角色组ID列表，不能含 `玩家`；与 `必需角色组` 不得重叠；未写为 `[]` |
| `必需角色组` | 否 | 无重复角色组ID列表，不能含 `玩家`；未启用时预设精修开局预演与提交均被拒绝；未写为 `[]` |
| `按方案` | 否 | 映射；键须存在于 `历史/开局方案/`，子项只允许 `开场白`、`开场命令`、`可选在场`、`必需角色组`；未写字段继承顶层 |

不得写入上述字段之外的未授权字段。方案内开场白同样不得包含 `<命令>`；方案开场命令须与顶层同形，仍是单键命令映射的列表。

多方案/多世界线卡打包时，顶层默认开局与 `按方案` 中声明的每个方案都会按各自所属 `世界线` 分别封卷并试跑开场命令，任一方案失败即拒绝打包。方案开场白按世界书方案顺序导出到角色卡 `data.alternate_greetings`，与主开场白完全相同或重复的不写入；`first_mes` 始终是顶层 `开场白`。游玩开局时，除「预设精修」外，玩家还可直接选择「AI 自动生成」「提示扩写」或「玩家手写」生成第 0 楼正文并记账落盘。不写 `按方案` 的单方案卡行为不变。

## 打包命令与路径解析

- 统一入口：`ygg pack [项目目录] [--face <卡面文件>] [--prepare-only] [--compatible <64位指纹>]...`
  - 未链接 `ygg` 到 `PATH` 时用 `node <世界树仓库>/cli/ygg.mjs pack ...`。
  - `[项目目录]` 相对当前工作目录解析，省略时取当前工作目录。
  - `--face` 相对当前工作目录解析，省略时取 `<项目目录>/卡面.yaml`。
- 兼容保留的旧脚本：`node <世界树仓库>/adapter/build.mjs [项目目录] [--face <卡面文件>]`（注意该旧脚本中 `[项目目录]` 相对仓库根解析且缺省为内部夹具、`--face` 相对 `adapter/` 解析）。日常建卡优先用 `ygg pack`。

## 打包后四项核对

1. **开场命令**：构建日志确认顶层与 `按方案` 各方案的 `开场命令` 均执行成功，无失败输出。
2. **构建清单**：打印的 `卡ID`、`卡版本`、`世界书哈希` 与 `程序指纹`（以及显式传入的 `--compatible` 旧指纹）与角色卡 JSON 内嵌脚本一致。
3. **资料隔离**：产物 JSON 不含 `/作者资料/` 与私有本地路径。
4. **多方案导出**：角色卡 JSON 的 `first_mes` 是顶层 `开场白`，`alternate_greetings` 是去重后的方案开场白；`bundle.planOpenings` 中每个方案的四个字段都已按继承规则补全。

打包机制与兼容升级细节见本地 Yggdrasill 仓库 `docs/06-酒馆适配.md`。
