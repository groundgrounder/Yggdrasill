# 卡面与打包核对

本参考页供 `世界树·打包` 独立自包含查阅，涵盖 `卡面.yaml` 完整字段契约、`开局.玩家` 8 项双模式定制字段、`开场命令` 运行边界、打包后四项核对与发版旧存档 A/B/C 兼容升级规范。

## 1. 卡面字段契约（`卡面.yaml`，仅允许以下 10 键）

| 字段 | 必填 | 约束 |
|---|---|---|
| `卡ID` | 是 | 非空文本；**跨版本必须稳定不变**，不得随 `名称` 改变（旧存档兼容判定的首要锚点） |
| `卡版本` | 是 | 非空文本，供人识别版本（不代替指纹哈希） |
| `名称` | 是 | 非空文本，同时决定产物文件名 `<名称>.json` |
| `描述` | 是 | 非空文本；写叙述者职责，不写命令语法或随运行模式冲突的长期指令 |
| `开场白` | 是 | 非空纯正文；严禁包含 `<命令>` 或 `</命令>`。静态预设卡写默认场景正文；自由开局/多世界线卡可直接写封面说明占位 |
| `开局` | 是 | 映射（可含 `世界线`、`开局时间`、`方案`、`角色组`、`玩家`、`历史选择`），供开局前端作默认初值 |
| `开场命令` | 否 | 单键命令映射的列表（如 `确认初始化`、`写场景`）；仅在「预设精修」开场白模式下执行，打包时会在内存中预执行一次 |
| `可选在场` | 否 | 无重复角色组ID列表，不能含 `玩家`；与 `必需角色组` 不得重叠；未写为 `[]` |
| `必需角色组` | 否 | 无重复角色组ID列表，不能含 `玩家`；未启用时预设精修开局预演与提交均被拒绝；未写为 `[]` |
| `按方案` | 否 | 映射；键须存在于 `历史/开局方案/`，子项只允许 `开场白`、`开场命令`、`可选在场`、`必需角色组`；未写字段继承顶层 |

- **严禁未授权字段**：不得写入上表 10 键之外的任何字段（例如 **`头像` 不是 `卡面.yaml` 的合法键**，写入即报未授权字段错误）；方案内开场白同样不得包含 `<命令>`，方案开场命令仍是单键命令映射的列表。

## 2. `开局.玩家` 完整定制字段（双模式共 8 项新版定制）

`开局.玩家` 支持 `模式: 自建`（可附 `档案`、`初始能力`、`初始装备`）与 `模式: 扮演`（必填 `扮演角色组`），并开放以下 **8 项玩家定制字段**（封卷末尾对玩家持有的 `唯一: true` 装备自动执行全本局强制唯一归属清理）：

| 字段 | 适用模式 | 写法与校验约束 |
|---|---|---|
| `自定义装备` | 自建、扮演通用 | 非空列表，每项只含 `{名称, 说明, 状态, 位置}`；`名称` 须合法、不含 `.`、不与装备库重名且列表内不重复；`状态` 取 `词表.装备状态` |
| `自定义技能` | 自建、扮演通用 | 非空列表，每项只含 `{名称, 说明, [限制]}`；`名称` 不重复 |
| `额外技能` | 自建、扮演通用 | 非空无重复技能ID列表（须声明技能库），不得与 `移除技能` 重叠 |
| `移除技能` | 自建、扮演通用 | 非空无重复技能ID列表（须声明技能库），不得与 `额外技能` 重叠 |
| `能力覆写` | 扮演增量 | 非空映射：维度名 → 覆写值（等级映射逐键覆写，单值等级与集合整体覆写，集合允许 `[]`） |
| `移除能力` | 扮演增量 | 非空无重复相对字段路径列表（如 `武艺.剑术`、`勇力`），不得与 `能力覆写` 覆盖同一路径冲突 |
| `额外装备` | 扮演增量 | 非空列表 `[{装备ID, 状态, 位置}]`，写法同 `初始装备`，不得与 `移除装备` 重叠 |
| `移除装备` | 扮演增量 | 非空无重复装备ID列表，不得与 `额外装备` 重叠 |

## 3. `开场命令` 与多方案干跑边界

- **`显式确认` 角色先初始化再入场**：对于 `初始化方式` 为 `显式确认`（缺省）且从未出场的角色组，`开场命令` 中必须先执行 `{确认初始化: {角色组ID: ...}}` 再执行 `{写场景: {在场: {...}}}`，否则协议报 `协议.场景` 导致打包失败。
- **扮演角色组自动裁剪**：当前地点写入后扮演角色组自动在场，适配层会自动从 `写场景` 的 `在场`/`所在` 中裁剪扮演角色组（但保留其 `确认初始化` 以免丢失初始能力与装备）。
- **`可选在场` vs 非可选关停行为**：
  - 列入 `可选在场` 的角色被玩家关停时，适配层**静默裁剪**其 `确认初始化` 与 `写场景` 中的 `在场`/`所在`；
  - **未列入 `可选在场`** 的开场命令角色或 `必需角色组` 若被关停，绝不裁剪，开局预演与提交**直接拒绝**。
- **`按方案` 逐方案干跑与导出**：打包时顶层默认开局与 `按方案` 的每个方案分别封卷（以方案字段覆盖顶层 `开局`）并试跑对应 `开场命令`，任一失败即拒绝打包。`first_mes` 始终是顶层 `开场白`；`data.alternate_greetings` 按世界书方案顺序导出并去重（与主开场白相同的跳过）。

## 4. 打包前置校准与命令口径

- **打包前校准**：先跑全量 `ygg check <世界书目录>` 0 错误，并用 `ygg context <世界书目录> --方案 <方案ID> --地点 <地标ID> --在场 <角色组ID>...` 复核上下文规模与 `yggdrasill.yaml` 预算。
- **统一入口**：`ygg pack [项目目录] [--face <卡面文件>] [--prepare-only] [--compatible <64位指纹>]...`
  - 未链接 `ygg` 到 `PATH` 时用 `node <世界树仓库>/cli/ygg.mjs pack ...`；
  - `[项目目录]` 与 `--face` 均相对当前工作目录（`cwd`）解析；省略时默认取当前目录与 `<项目目录>/卡面.yaml`。

## 5. 打包后四项核对

1. **开场命令**：构建日志确认顶层与 `按方案` 各方案的 `开场命令` 均执行成功，无失败输出。
2. **构建清单**：打印的 `卡ID`、`卡版本`、`世界书哈希` 与 `程序指纹`（以及显式传入的 `--compatible` 旧指纹）与角色卡 JSON 内嵌脚本一致。
3. **资料隔离**：产物 JSON 不含 `/作者资料/` 与私有本地路径。
4. **多方案导出**：角色卡 JSON 的 `first_mes` 是顶层 `开场白`，`alternate_greetings` 是去重后的方案开场白；`bundle.planOpenings` 中每个方案的四个字段都已按继承规则补全。

## 6. 发版与旧存档 A/B/C 三级兼容升级

更新已发布的卡时，**必须保持 `卡ID` 不变**。若世界树引擎/模板程序指纹发生变化且确认与旧版兼容，打包时显式传入 `--compatible <64位旧程序指纹>`（可重复传多个）。载入旧聊天且 `世界书哈希` 变化时，适配层自动在内存中只读试重放全聊并判定兼容等级：

| 级别 | 触发条件 | 常见改动例子 | 运行时行为 |
|---|---|---|---|
| **A 级（自动兼容）** | 全聊重放 0 失败、`已写入` 与 `本局` 快照完全一致 | 仅修改档案/事件/条目纯文本、世界概况、扮演准则、追加未到期未来事件，或仅修改 `<项目目录>/外观/`（不改变世界书哈希） | 直接放行、零改写旧楼，新楼沿用新清单 |
| **B 级（纯增补待升级）** | 全聊重放 0 失败、`已写入` 一致，差异严格仅在 `开局.角色组` 或 `世界.剧情标记` 新增默认键 | 新增新角色组、新增新剧情标记 | 进入待升级阻断态，展示新增明细并由玩家一键确认无损升级 |
| **C 级（破坏性冲突）** | 重放报错、命令失败、`已写入` 变化，或出现白名单外字段增删改 | 改 ID、删除角色组/剧情标记、新增早于开局时间的过去事件改变历史 | 严格只读保护，展示逐楼精准差异，需新建聊天 |

打包机制与兼容升级细节见本地 Yggdrasill 仓库 `docs/06-酒馆适配.md`。
