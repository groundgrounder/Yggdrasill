# 世界树·打包

本 skill 是建卡第 5 层：卡面定稿与酒馆打包。卡面完整契约、`开局.玩家` 8 项双模式定制字段、`开场命令` 边界、打包后四项核对与 A/B/C 兼容升级指引见 [`./references/卡面与打包核对.md`](./references/卡面与打包核对.md)。

## 卡面（`卡面.yaml`）

- 必填：`卡ID`（跨版本稳定，不随名称改变）、`卡版本`、`名称`、`描述`（写叙述者职责，不写命令语法）、`开场白`（纯正文，禁止包含 `<命令>` 块；支持自由开局的长篇卡可直接作封面占位）、`开局`（默认开局映射，可含 `世界线`、`开局时间`、`方案`、`角色组`、`玩家`、`历史选择`；`玩家` 支持自建/扮演双模式共 8 项定制字段，见参考页）。
- 可选：`开场命令`（单键命令映射的列表；未出场 `显式确认` 角色须先 `确认初始化` 再 `写场景.在场`）、`可选在场`、`必需角色组`、`按方案`（按方案ID覆盖 `开场白`、`开场命令`、`可选在场`、`必需角色组`）。
- **严禁写未授权字段**：`卡面.yaml` 只允许上述 10 个顶层键，**不得写入 `头像` 等未授权字段**；出现未授权字段报错时按报错清单删改，不绕过校验。
- 开局前端支持按「世界线 → 预设开局（含无预设自由开局）→ 时间与地点 → 玩家（扮演/自建表单）→ 开场白（预设精修 / AI 自动生成 / 提示扩写 / 玩家手写）」开局；长篇多世界线卡不必为每个时间点穷举手写开场白与开场命令，保留 1–2 个精修预设或直接用封面占位即可。
- 若项目由 `世界树·迁移` 导入，优先对照 `作者资料/迁移/原卡开场白.yaml` 复核 `开场白` 与 `按方案` 配置。
- 参考示例：本地 Yggdrasill 仓库中的 `examples/三国演义/卡面.yaml` 或 `test/fixtures/雾港/卡面.yaml`。

## 构建与四项核对

优先使用 `ygg pack`（未链接 `ygg` 到 `PATH` 时改用 `node <世界树仓库>/cli/ygg.mjs pack`）：

1. **打包前置**：确认全量 `ygg check <世界书目录>` 0 错误，并已通过 `ygg context <世界书目录>` 完成上下文与 `yggdrasill.yaml` 预算校准；如需卡专属前端外观，先经 `世界树·前端` 落盘 `<项目目录>/外观/` 并通过 `theme-tool.mjs validate`。
2. 执行打包：
   `ygg pack [项目目录] [--face <卡面文件>] [--prepare-only] [--compatible <64位指纹>]...`
   - `[项目目录]` 与 `--face` 均相对当前工作目录（`cwd`）解析；省略项目目录时默认取当前目录，`--face` 缺省为 `<项目目录>/卡面.yaml`。
   - 若项目根存在可选 `<项目目录>/外观/` 目录，`ygg pack` 会自动按声明式安全规则校验并写入 `bundle.themes`（不进入 `世界书哈希`，更新外观不影响旧存档兼容）。
   - 预检查只生成清单与包数据而不调用 `esbuild` 时加 `--prepare-only`；更新发版且确认兼容旧引擎程序时，保持 `卡ID` 不变并重复传入 `--compatible <64位旧程序指纹>`（A/B/C 三级旧存档兼容判定见参考页）。
3. **核对构建输出四项**（与参考页「打包后四项核对」严格同口径）：
   1. **开场命令**：顶层与 `按方案` 各方案的 `开场命令` 干跑全部成功；
   2. **构建清单**：`卡ID`、`卡版本`、`程序指纹`、`世界书哈希`（及 `--compatible`）与卡内一致；
   3. **资料隔离**：卡内无 `/作者资料/` 与私有路径泄露；
   4. **多方案导出**：`first_mes`、`alternate_greetings`（去重）与 `bundle.planOpenings` 继承补全准确。
4. 构建失败并指明字段时，修卡面或回对应层修世界书，不在本层绕过检查。

## 交付酒馆

- 导入构建出的角色卡 JSON（位于 `<世界树仓库>/adapter/dist/<名称>.json`），导入并打开聊天时允许启用卡内世界树脚本（若在「世界树：设置」中关闭独立记账回到旧版正文 `<命令>` 模式，还需允许并启用卡内局部正则）。
- **预设说明（可选开箱预设）**：仓库提供 `presets/yggdrasill.json` 作为**可选开箱预设**；作者或玩家若已有常用的酒馆预设可直接沿用，无需替换，只需确保主提示词不要求模型在正文输出 `<命令>` 或状态块即可。
- **大型卡发布前验收**：大型多卷/多世界线卡在正式发布前，建议先走 `世界树·验收` 跑一轮打包卡离线五维试玩验收。

出口门禁：构建成功且**四项核对**全过。呈报：产出摘要（卡文件路径、世界书哈希、程序指纹）+ 四项核对结果 + 导入指引 + 待拍板项。
