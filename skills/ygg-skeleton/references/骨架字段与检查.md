# 骨架字段与检查

## 角色组与档案项（`角色/{角色组ID}/角色组.yaml`）

- **角色组字段**（按序）：`显示名`、`别名`（两字及以上）、`角色包`、`分类`、`默认启用`、`默认版本`（写了版本时必填）、`初始化方式`（`显式确认` / `出场自动`）、`初始所在`、`版本`（含 `版本ID`、`显示名`、`别名`、`简介`）、`档案`。
- **档案项**：`档案ID`（等于 `档案/` 下子目录名）、`适用版本`（写了版本时必填）、`默认`（每个版本至多一份）、`前置档案`、`生效条件`（非默认档案必填，须含正向引用的 `事件确认` 或正向引用的 `世界线`，不得含封卷不可求值的条件）、`初始能力`、`初始装备`（含 `装备ID`、`状态`、`位置`）。
- 每份档案目录下必须且只能有 `基本信息.txt` 与 `角色印象.txt` 两份文件。

## 事件、分支与确认策略（`历史/事件/{事件ID}/事件.txt`）

- **必填字段**：`事件ID`（等于目录名）、`事件概要`、`主类型`、`标签`、`事件结果`、`触发时间`（`{最早, 最晚}`）、`确认策略`（`自动确认` / `条件确认` / `仅作候选`）、`核心参与者`（不含“玩家”）、`默认分支`、`分支`。
- **可选字段**：`事件标题`、`影响范围`、`地点`、`门槛`、`关联事件`、`叙事条件`、`公开信息`、`隐秘信息`。
- **分支**：`分支ID`、`门槛`（可选；`自动确认` 事件只要有分支带门槛，须有不带门槛的兜底分支）、`分支条件`、`分支结果`、`变化`（`{路径, 操作, 值}`）。
- **确认策略与封卷**：`自动确认` 与 `条件确认` 在开局封卷前可求值，不得在门槛中引用 `当前场景` 或 `在场实力人数`；`仅作候选` 不参与开局历史与 `开局选项.yaml`。

## 事件树五条红线

建事件树时须逐条守住以下五条语义结构红线（`ygg check` 0 错误不代表结构健康）：

1. **事件原子化与命名禁令（禁「A与B」拼盘）**：一个事件只承载一件可独立判定发生/未发生的因果节点；禁止为凑章节数或配额把毫不相干的甲乙两事用「与 / 及 / 暨」硬捆成拼盘事件（如把晋升与成婚、学艺与宴会硬拼）。二者皆重要则拆为两个原子事件，其一为日常琐事则降格进角色档案或舍弃。
2. **准入门槛（禁前史与零变化日常硬升事件）**：仅发生在角色出场前、用于交代身世的固定前史写进角色默认档案，不建历史事件；建事件前须过「三问至少中其一」：① 会触发 `变化` 或档案切期？② 是下游重要事件/分支的真实因果前提？③ 是玩家可能亲历或介入改写的标志性高光事件？三者皆无的纯日常章回流水账不入事件树。
3. **真因果铁律（严分因果门槛与时间先后）**：时间先后只靠 `触发时间` 表达，绝不靠伪 `事件确认` 硬串；`世界` / `势力` 级事件禁止把主角个人日常小事当作硬门槛，使玩家停用核心角色或远离主线时，宏观大事仍能自然运转。
4. **善用 `确认策略` 三分法（禁全员盲写 `自动确认`）**：
   | 确认策略 | 开局封卷行为 | 游玩期行为 | 典型适用场景 |
   |---|---|---|---|
   | `自动确认` | 按门槛自动补齐历史 | 窗口到期即使玩家不在场也自动确认 | 世界大事、政局变动、幕后暗线与关键历史锚点 |
   | `条件确认` | 按门槛自动补齐历史 | 须由叙事模型实际演到才确认，窗口结束未演到即自然排除 | 长篇卡大量采用：个人战斗、感情、拜师、社交、可被玩家绕开或截胡的遭遇事件 |
   | `仅作候选` | 不参与开局历史补齐 | 仅在游玩中特定场景/条件下触发 | 可选支线、特定场景触发与彩蛋 |
5. **`主类型` 准确归类与真实纪年精度**：`主类型` 按事件实际影响层归类，不把主角个人成长或家庭琐事误标为 `势力`；原作未交代具体月日的事件，结构纪年一律只写到年，严禁为凑先后顺序编造 `01月01日`。

## 12 类条件类型与组合词

- 组合词：`all`、`any`、`none`（值为非空条件列表）。奇数层 `none` 内对 `事件确认` 的引用计为排斥，偶数层计为正向。
- 封卷可求值条件：`角色启用(角色组ID)`、`角色版本(角色组ID, 版本ID)`、`事件确认(事件ID, [分支ID])`、`事件串状态(事件串ID, 状态)`、`当前时间(比较: 小于|大于等于, 值)`、`剧情标记(标记ID, 比较: 等于|不等于, 值)`、`角色状态(角色组ID, 字段, 属于)`、`同处(角色组ID列表)`、`角色已出场(角色组ID)`、`世界线(世界线ID)`。
- 封卷不可求值条件：`当前场景(地标, 场景)`、`在场实力人数(最低实力, 最少人数, [排除角色组])`。
- **状态驱动轻引导**：自由游玩中的预设外经历以动态事件（附 `实际参与者` 与 `摘要`）及角色知识作软记忆即可；对幕后 `自动确认` 易穿帮的关键节点（空间分流、核心人物重大状态、主线转折前提），门槛优先读取 `所在`、`同处`、`角色状态`、`剧情标记`、`事件串状态`，让动态事件改写的状态或提前结束的事件串自然接上事件树。

## 事件串、世界线、开局与出处

- `事件串/{事件串ID}.yaml`：`概述`、`事件`（每个事件至多属一个串）、`结局`（`{事件ID}` 或 `{事件ID, 分支ID}`）。
- `历史/世界线/{世界线ID}.yaml`（可选）：`概述`（必填）、`默认`（可选布尔，全局至多一条为 `true`）、`角色组`（可选覆写）；可选在 `世界概况/世界线/{世界线ID}/*.txt` 放该世界线专属概况。
- `开局选项.yaml`：`自由组合`（布尔）、`选项`（列表，每项含 `事件ID`、`选项`，可选 `问题`；省略 `问题` 时界面回退事件标题/ID）。写法保持克制简练、客观自然，例如：
  ```yaml
  - 事件ID: 三张决意取天下
    选项:
      乘势取天下: 乘势举事取天下
      温和传教: 止于传教，不举兵
      未发生: 三张未起事
  ```
- `开局方案/{方案ID}.yaml`：`世界线`（多世界线卡必填）、`概述`、`开局时间`、`开局地点`（可选地点库 ID）、`角色组`、`历史选择`。
- `作者资料/出处/*.yaml` 事件级记录：每项只含 `事件ID`、`来源`。

## 第 3 层出口命令

- 全量检查：`ygg check <世界书目录> [--json]`
- 分支推演：`ygg if <世界书目录> [--世界线 <世界线ID>] [--方案 <方案ID>] [--排除 <事件ID>]... [--分支 <事件ID>:<分支ID>]... [--停用角色组 <角色组ID>]... [--json]`
- 首次登场与状态预览：`ygg preview <世界书目录> <角色组ID> [--世界线 <世界线ID>] [--开局 <纪年>] [--方案 <方案ID>] [--状态] [--json]`
- 本地作者视图：`ygg view <世界书目录> [--storage <审阅存储目录>] [--port 0]`
- 完整参考表见本地 Yggdrasill 仓库 `docs/参考/角色.md` 与 `docs/参考/事件.md`。
