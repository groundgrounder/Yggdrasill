# 骨架字段与检查

本参考页供 `世界树·骨架` 独立自包含查阅，覆盖核心参与者五重硬机制、完整变化表操作矩阵、`none` 终身排斥、触发时间起点陷阱、三值求值与 if 线四原则、事件树五条红线与 4 条机械拆分测试、角色组/档案解析/初始化硬规则及事件串/世界线/开局校验。

---

## 1. 核心参与者五重硬机制（严禁乱填）

`核心参与者` 不是“出场人员名单”或“旁观者列表”，而是直接绑定五重运行时硬机制的开关：

1. **事件发生硬前提（最高优先级排除）**：任一核心参与者在本局未启用 → 整个事件直接判为 `已排除`（优先级高于时间窗口与门槛，在封卷、历史求解、待登记与游玩均生效）。因此只列**缺之事件即不成立**的角色组；**世界事件通常保持 `核心参与者: []`**，绝不塞入旁观者或路人导致关掉一个配角连坐整条主线瘫痪。
2. **候选路由准入与排序**：游玩期候选事件仅在「有核心参与者在场」「事件 `地点` 与地点链有交集」「`核心参与者` 为空 `[]`」三者之一成立时进入上下文；同级排序中，**在场核心参与者人数越多越靠前**。
3. **封卷 / 待登记 `实际参与者` 来源**：封卷补入与待登记自动确认的事件，其 `实际参与者` 直接取 `核心参与者`（游玩中由正文确认时为 `核心参与者` 与命令另列参与者的并集）。`实际参与者` 决定谁被计为 `角色已出场`、谁触发 `出场自动` 初始化，以及该事件后续作为谁的「共同经历 / 在场者经历」被路由召回。
4. **变化表角色启用担保**：任一分支 `变化` 路径或映射键写到的角色组，必须要么在 `核心参与者` 中，要么由「事件门槛 + 本分支门槛」以正极性保证其已启用（仅 `角色启用`、`角色版本`、`角色已出场`、`角色状态`、`同处` 5 种条件可提供担保），否则静态检查直接报错误 `变化.角色未保证启用`。
5. **开局前端必选锁定**：被选入开局 `历史选择`（值非 `未发生`）的事件，其全部 `核心参与者` 会被开局前端强制锁定为必选启用角色组，玩家无法关闭。

## 2. 角色组、档案解析与初始化硬规则（`角色/{角色组ID}/角色组.yaml`）

### 角色组与档案项字段

- **角色组字段**（按序）：`显示名`（省略取角色组ID）、`别名`（两字及以上，**禁用单字别名**；同组含各版本内不得重复，跨组重复报提示）、`角色包`、`分类`（须取 `设定/角色分类.yaml`）、`默认启用`（布尔）、`默认版本`、`初始化方式`（`显式确认` / `出场自动`）、`初始所在`（地点ID）、`版本`（列表，每项含 `版本ID`、`显示名`、`别名`、`简介`）、`档案`（非空列表，与 `档案/` 下子目录一一对应）。
- **单版本 vs 多版本硬规则**：
  - 未写 `版本` 的单版本角色组：**严禁写 `默认版本` 与档案项 `适用版本`**（版本ID自动等于角色组ID）；
  - 只要写了 `版本`（即使列表只有 1 项）：`默认版本` 与每份档案项的 `适用版本` **均必填**。
- **档案项字段**：`档案ID`（等于 `档案/` 下子目录名）、`适用版本`、`默认`（布尔，每版本至多 1 份默认档案；默认档案**不得写 `生效条件`**）、`前置档案`、`生效条件`（非默认档案必填，须含正向引用的 `事件确认` 或正向引用的 `世界线` 至少其一，不得含封卷不可求值条件，**不得引用该档案自身赋予的状态**）、`初始能力`、`初始装备`（非空列表，每项只含 `{装备ID, 状态, 位置}`，装备ID不重复，状态取 `词表.装备状态`）。
- 每份档案目录下**必须且只能有** `基本信息.txt` 与 `角色印象.txt` 两份文件。

### 初始化方式与生命周期

- **`初始化方式` 缺省为 `显式确认`**：未写 `出场自动` 时，首次在 `写场景` 中把从未出场的角色组写为 `在场: true` 会触发协议错误 `协议.场景`（必须先执行 `确认初始化`）；长篇群像卡对非关键配角推荐按需显式声明 `初始化方式: 出场自动`。
- **终生只初始化一次，切期不再初始化**：首次登场初始化写入 `初次登场·{角色组ID}`（分支 `初始化`）并置 `已初始化: true`（空起点同样置真）；之后切期绝不再初始化。
- **只补缺失、不覆写、不强抢**：等级维度只填无值键、集合维度只在本局无该字段时写入、装备只在本局未持有时加入；已在 `能力移除记录` 中的字段**不补回**；`唯一: true` 且已被他人持有的装备**跳过不强抢**。

### 档案解析与冲突边界

- **`前置档案` 只表示先后取代，不表示优先级**：解析时仅沿适用于本版本的档案追溯前置链（遇不适用档案即停止），成立的档案若是另一成立档案前置链上的祖先则被取代；前置链不得成环且须与本档案适用版本有交集。
- **平行切期互斥**：同一版本下多份互不为前置关系的非默认档案若能同时成立，检查器报错误 `抽样.档案冲突`；运行时发生档案冲突或无成立档案（解析异常）时，**整份档案不进入上下文**（只输出角色组ID与显示名）。
- **4096 组合上限**：抽样检查档案互斥时，同版本所有档案生效条件引用的事件状态组合超过 **4096 种**，报提示 `抽样.组合过多` 并跳过该版本，宜精简同一角色组跨期条件所引事件数。

## 3. 事件、分支与确认策略（`历史/事件/{事件ID}/事件.txt`）

- **必填字段**：`事件ID`（等于目录名）、`事件概要`、`主类型`、`标签`、`事件结果`、`触发时间`（`{最早, 最晚}`）、`确认策略`（`自动确认` / `条件确认` / `仅作候选`）、`核心参与者`（不含 `玩家`）、`默认分支`、`分支`。
- **可选字段**：`事件标题`、`影响范围`、`地点`（**不是门槛**，仅用于路由挑选相关经历与候选事件）、`门槛`、`关联事件`（仅作者查阅，不能自引用）、`叙事条件`、`公开信息`、`隐秘信息`。
- **分支字段**：
  - 必填：`分支ID`（事件内唯一）、`分支条件`（条件文本，各分支须可区分）、`分支结果`；
  - 可选结构：`门槛`（`自动确认` 事件只要有分支带门槛，就**必须有不带门槛的兜底分支**，否则报 `分支.缺兜底`）、`变化`（`{路径, 操作, 值}` 列表）；
  - **分支专属四文本字段（可选）**：`事件概要`、`影响范围`、`公开信息`、`隐秘信息`。组装**已确认经历与待登记**时，所走分支声明的字段**直接覆盖**事件顶层同名字段（不拼接），未声明才回退顶层；**候选阶段绝不输出**任何分支专属字段（防剧透未走分支）。
- **分支选择与不适用**：事件门槛成立但没有任何分支门槛成立时，事件为 `不适用`（封卷排除）；封卷与待登记选分支时，**仅当 `默认分支` 门槛成立才优先选它**，否则按书写顺序取首个门槛成立的分支，都不成立则选不出分支。

## 4. `触发时间` 完整语义与起点比较陷阱

- **精度与窗口**：支持写到年（`{前缀}{年}年`）或写到日（`{前缀}{年}年{MM}月{DD}日`），**严禁写到月**；`最早` 与 `最晚` 均必填且窗口非空（`最早` 起点 < `最晚` 终点）。事件本身无持续时间，持续过程用 `事件串`。
- **纪元前写法**：`{前缀}前{年}年` 或 `{前缀}前{年}年{MM}月{DD}日`（连续负整数轴，`前001年` 紧邻 `000年`），**严禁 `前000年`**。
- **年精度按首日起点比较陷阱**：检查器校验 `事件树.前置超出窗口`（所有路径前置 `最早` 起点 > 本事件 `最晚` 起点）与 `事件树.前置倒流`（所有路径前置 `最晚` 起点 > 本事件 `最晚` 起点）时，**写到年的时间一律按该年首日（`01月01日`）计起点**。
  - 若同一年内前置事件精确到日（如 `中平001年04月01日`），后续事件若缺月日只写到年（`中平001年`），其起点 `01月01日` 早于前置 `04月01日`，检查器将报错！
  - **正确边界**：原作未交代具体月日时绝不为凑顺序编造 `01月01日`；但同一年内若存在精确到日的前置事件而须把后续事件窗口放宽至该年末，后续事件 `最晚` 须写到**年末日**（如 `12月30日`）或与前置保持同精度。
- **历史求解顺序与倒流**：封卷与待登记按 `触发时间.最晚` 的**起点升序**（同刻按事件ID码点序）求解；若较晚事件写入的变化才使较早事件门槛成立，封卷报错误 `封卷.时间顺序冲突`（游玩待登记则跳过排除）。

## 5. 12 类条件、三值求值与 `none` 终身排斥铁律

- **组合词**：`all`（全部成立）、`any`（任一成立）、`none`（全部不成立），值须为非空条件列表；条件不能为 `null`。偶数层 `none` 内 `事件确认` 为正向引用，奇数层 `none` 内为排斥。
- **全部 12 类条件**：
  | 条件类型 | 参数 | 封卷可求值 | 关键边界 |
  |---|---|---|---|
  | `角色启用` | `角色组ID` | 是 | 可作变化启用担保 |
  | `角色版本` | `角色组ID`、`版本ID` | 是 | 启用且选定该版本；可作变化启用担保 |
  | `事件确认` | `事件ID`、可选 `分支ID` | 是 | 有效本局状态为 1（含待登记）；`none` 下为终身排斥 |
  | `事件串状态` | `事件串ID`、`状态`（`未开始`/`进行中`/`已结束`） | 是 | 表达“某过程之前/进行中”优先用它而非 `none` |
  | `当前时间` | `比较`（`小于`/`大于等于`）、`值`（纪年） | 是 | 表达“在某时点之前”用它而非 `none` |
  | `剧情标记` | `标记ID`、`比较`（`等于`/`不等于`）、`值` | 是 | 标记缺失为未知 |
  | `角色状态` | `角色组ID`、`字段`、`属于`（列表） | 是 | **仅支持 `所在`（支持下级地点向上包含匹配）与二层带取值表的角色字段**（映射写到键，未写过默认取值表首项）；**严禁读数值（如好感度）、集合（身份/知识）、自由文本或能力维度**；可作变化启用担保 |
  | `同处` | `角色组ID`（至少 2 个） | 是 | 任一未启用为不成立，任一所在未知为未知；依赖地点库；可作变化启用担保 |
  | `角色已出场` | `角色组ID` | 是 | 视为在场、已初始化或已确认事件实际参与者；可作变化启用担保 |
  | `世界线` | `世界线ID` | 是 | 本局选定该世界线；须已声明世界线 |
  | `当前场景` | `地标`、`场景` | **否** | 仅可用于 `仅作候选` 事件；不得用于 `自动确认`/`条件确认` 或档案生效条件 |
  | `在场实力人数` | `最低实力`、`最少人数`、可选 `排除角色组` | **否** | 同上；须在 `能力.yaml` 声明 `综合实力: true` |

- **三值逻辑（成立 / 不成立 / 未知）**：
  - 封卷前一律为未知；变量缺失（如角色组无本局 `所在` 且未设 `初始所在`）或无当前地点时为未知；
  - `all` 有不成立→不成立，否则有未知→未知；`any` 有成立→成立，否则有未知→未知；**`none(未知)` 仍为未知**；
  - 门槛、分支门槛与档案生效条件遇**未知一律按不成立处理**。因此依赖 `所在` / `同处` 分流的事件，必须为相关角色组配置 `初始所在`！
- **`none` 终身排斥铁律**：
  - `none` 下的 `事件确认` 是**终身不可逆排斥**——事件甲确认后，协议每次提交都会重跑排斥检查，若被排斥事件乙后来确认导致甲门槛变不成立，将直接触发 `协议.排斥冲突`（封卷触发 `封卷.配置冲突`）；
  - **只想表达“在乙发生之前”时，严禁用 `none`，必须改用 `当前时间` 或 `事件串状态`！**

## 6. 完整 `变化` 表语法与操作矩阵

每条变化为 `{路径, 操作, 值}`（部分移除操作禁带 `值`）。路径有 3 种根：`世界.剧情标记.{标记ID}`、`世界.{二层世界字段}`、`角色.{角色组ID}.{字段}`（含 `所在`、`装备.{装备ID}`、能力维度），一律写到要改的那一格：

| 目标字段种类 | 路径写法 | 允许操作 | `值` 要求与运行语义 |
|---|---|---|---|
| 剧情标记 | `世界.剧情标记.{标记ID}` | `设定` | 必填；须在声明取值中 |
| 单值（取值/引用/文本/`所在`） | 写到该字段 | `设定` | 必填；`所在` 须为地点ID |
| 集合（身份/知识/集合能力维度） | 写到集合字段 | `新增`、`移除` | **均必填成员 `值`**（集合 `移除` **必须带 `值`**）；**严禁 `设定`** 整体覆盖 |
| 映射（关系/职位/自定义映射） | 写到键，如 `关系.{角色组ID}` | `设定`、`新增`、`移除` | `新增` 仅键不存在时写入；**映射 `移除` 严禁带 `值`** |
| 数值与数值映射（如好感度） | 写到字段或键 | `增加`、`减少` | **仅允许 `增加`/`减少`，严禁 `设定`**；值为正整数且 ≤ `单次增减上限`（缺省 100），无值从 0 起算并截断在上下限内 |
| 等级维度（单值等级 / 等级映射） | 单值写到维度；映射写到键 | `提升`、`设定`、`移除` | `提升` 只升不降（防重放降级，清除移除记录）；`设定` 明确降级；**`移除` 严禁带 `值`** 并记入 `能力移除记录` |
| 装备 | `角色.{角色组ID}.装备.{装备ID}` | `新增`、`设定`、`移除` | `新增`/`设定` 值为 `{状态, 位置}`（`状态` 取 `词表.装备状态`）；**`移除` 严禁带 `值`** |

- **`唯一: true` 装备预设行为**：在预设事件中，若全本局任一角色已持有该唯一装备，`新增` 操作**跳过不强抢**；需要强制易主（夺宝/继承/移交）时，必须用 `设定`（写入时自动从原持有者移除）或先显式 `移除` 原主。
- **禁区与双向支撑**：
  - 严禁写协议维护字段 `能力移除记录` 与 `已初始化`（报 `变化.协议字段`）；
  - 预设事件路径、映射键与引用角色组的值**严禁出现保留字 `玩家`**（报 `变化.玩家`）；
  - 变化表字段与 `事件结果` 受双向支撑提示（`事件.结果缺支撑` / `事件.结果遗漏`），保留支撑名 `档案切期` 表示本事件分支被某档案 `生效条件` 正向引用。

## 7. if 线四原则与状态驱动轻引导

1. **只写真因果**：门槛只写“没有它这件事就不成立”，绝不把原作章节先后硬写成 `事件确认` 链；
2. **核心参与者最小化**：只列缺之事件不成立的角色组，**世界事件保持 `核心参与者: []`**；
3. **世界事件与个人后果分离设计法**：世界事件到时间就发生，无核心参与者，只写世界层面变化（如剧情标记、世界字段）；它对不同人物的影响另拆为各自的**个人后果**事件，门槛是世界事件已确认，各分支门槛读取当时的 `所在`、`同处`、`关系` 或能力并配不带门槛的**兜底分支**；
4. **关键节点多分支**：核心转折点提供多条可区分的分支，下游事件按实际所走的分支 ID 设门槛。
- **状态驱动轻引导**：自由游玩中的预设外经历以动态事件与角色知识作软记忆即可；对幕后 `自动确认` 易穿帮的关键节点（空间分流、核心人物重大状态、主线转折前提），门槛优先读取 `所在`、`同处`、`角色状态`、`剧情标记`、`事件串状态`，让动态事件改写的状态或提前结束的事件串自然接上事件树。

## 8. 事件树五条红线与 4 条机械拆分测试

建树须逐条守住五条语义结构红线（`ygg check` 0 错误不代表结构健康）：

1. **事件原子化（禁「A与B」拼盘）+ 4 条一票否决机械拆分测试**：一个事件只承载一件可独立判定发生/未发生的因果节点，禁把无关甲乙两事用「与/及/暨/并/兼」等硬捆成拼盘（如晋升与成婚、学艺与宴会），也不把新增无关剧情顺手塞进既有事件分支。遇拿不准的节点，逐条过 **4 条机械拆分测试**（命中任一条即必须拆为独立原子事件，或将琐事降格进档案/舍弃）：
   - **① 反事实独立成败测试**：A 发生而 B 不发生（或 B 走另一分支）在世界内是否成立？成立必拆；
   - **② 核心参与者正交测试**：拆成两件后，能否减少任一方的 `核心参与者` 人数？能少人必拆；
   - **③ 跨日/跨地拆分铁律**：发生在不同日期或不同地点的两件事严禁合写为一个事件，持续过程改用 `事件串`；
   - **④ 单焦点分支测试**：概要或分支结果出现“先……随后……/同时完成另一事”且两段可独立分岔的必拆。
   仅不可分割的单一互动专名（如双人同盟定约本身）可豁免拆分。
2. **准入门槛（禁前史与零变化日常硬升事件）**：出场前固定前史写进角色默认档案，不建历史事件；建事件前须过「三问至少中其一」：① 会触发 `变化` 或档案切期？② 是下游重要事件/分支的真实因果前提？③ 是玩家可能亲历或介入改写的标志性高光事件？三者皆无的纯日常章回流水账不入树。
3. **真因果铁律（严分因果门槛与时间先后）**：时间先后只靠 `触发时间` 表达，绝不靠伪 `事件确认` 硬串；`世界`/`势力` 级事件禁止把主角个人日常小事当作硬门槛，使玩家停用核心角色或远离主线时宏观大事仍可运转。
4. **善用 `确认策略` 三分法（禁全员盲写 `自动确认`）**：
   | 确认策略 | 开局封卷行为 | 游玩期行为 | 典型适用场景 |
   |---|---|---|---|
   | `自动确认` | 按门槛自动补齐历史 | 窗口到期即使玩家不在场也自动确认（待登记） | 世界大事、政局变动、幕后暗线与关键历史锚点 |
   | `条件确认` | 按门槛自动补齐历史 | 须由叙事模型实际演到才确认，窗口结束未演到即自然排除 | 长篇卡大量采用：个人战斗、感情、拜师、社交、可被玩家绕开或截胡的遭遇事件 |
   | `仅作候选` | 不参与开局历史补齐 | 仅在游玩中特定场景/条件下触发（唯一允许用封卷不可求值条件） | 可选支线、特定场景触发与彩蛋 |
5. **`主类型` 归类与真实纪年精度**：`主类型` 按实际影响层归类，不把个人成长或家庭琐事误标 `势力`；原作未交代具体月日时只写到年，严禁为凑先后顺序编造 `01月01日`（同一年内存在精确到日前置时按第 4 节年末日/同精度边界处理）。

## 9. 事件串、世界线、开局与通用措辞/ID 禁区

- **`历史/事件串/{事件串ID}.yaml`**：含 `概述`、`事件`（顺序不表示先后，**每个事件至多属于 1 个串**）、`结局`（`{事件ID}` 或 `{事件ID, 分支ID}`）。**起点由工具推出（不手写，每串至少 1 个起点）**；进行中事件串不受经历预算限制，每轮常驻上下文，因此 **`概述` 严禁剧透结局**。
- **`历史/世界线/{世界线ID}.yaml`**（可选）：`概述`（必填）、`默认`（可选布尔，全局至多一条 `true`）、`角色组`（可选覆写）；可另配 `世界概况/世界线/{世界线ID}/*.txt`。
- **`历史/开局选项.yaml`**：`自由组合`（布尔，**缺省 `false`**）、`选项`（列表，每项 `{事件ID, [问题], 选项}`，不得引用 `仅作候选` 事件；省略 `问题` 回退事件标题/ID）。写法克制简练：
  ```yaml
  - 事件ID: 三张决意取天下
    选项:
      乘势取天下: 乘势举事取天下
      温和传教: 止于传教，不举兵
      未发生: 三张未起事
  ```
- **`历史/开局方案/{方案ID}.yaml`**：`概述`（必填）、`世界线`（**多世界线卡必填，单世界线世界书严禁填写**）、`开局时间`、`开局地点`（地点ID）、`角色组`、`历史选择`（**只能用 `开局选项.yaml` 已声明的事件与选项**，且所选事件 `触发时间.最晚` 终点 ≤ 方案 `开局时间` 起点）。角色组覆写优先级：`角色组.yaml < 世界线 < 方案 < 输入`。
- **`作者资料/出处/*.yaml` 事件级记录**：每项只含 `事件ID`、`来源`。
- **通用命名与 `.yaml` 措辞硬禁**：
  - ID 一层字符安全：非空、首尾无空白、不含 `.` `/` `\`、不用保留字（`玩家`、`__proto__`、`constructor`、`prototype`）；
  - `.yaml` 中面向模型或玩家的字段（角色组/版本 `显示名`、`别名`、`简介`；事件串 `概述`；世界线 `概述`；开局选项 `问题` 与选项文字；开局方案 `概述`）**同样受 25 个禁用词与 U+2014/U+2015 破折号检查**！

## 10. 第 3 层出口命令

- 全量检查：`ygg check <世界书目录> [--json]`（重点复核 `事件.疑似拼盘` 与 `事件.世界事件含核心参与者` 提示）
- 分支推演：`ygg if <世界书目录> [--世界线 <世界线ID>] [--方案 <方案ID>] [--排除 <事件ID>]... [--分支 <事件ID>:<分支ID>]... [--停用角色组 <角色组ID>]... [--json]`
- 首次登场与状态预览：`ygg preview <世界书目录> <角色组ID> [--世界线 <世界线ID>] [--开局 <纪年>] [--方案 <方案ID>] [--状态] [--json]`
- 本地作者视图：`ygg view <世界书目录> [--storage <审阅存储目录>] [--port 0]`
- 完整参考表见本地 Yggdrasill 仓库 `docs/参考/角色.md` 与 `docs/参考/事件.md`。
