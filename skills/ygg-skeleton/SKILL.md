# 世界树·骨架

本 skill 是建卡第 3 层：先搭可运行的逻辑骨架，正文字段只写足以过检与表意的短句，修饰与长段描写留给第 4 层。读取 `作者资料/通读/人物总名单与分期方案.yaml`、`作者资料/通读/全书年表与因果事件表.yaml` 与 `作者资料/通读/if分岔与开局提案.yaml`。核心参与者五重机制、完整变化表操作矩阵、`none` 终身排斥、触发时间起点陷阱、三值求值与 if 线四原则、4 条机械拆分测试及档案/开局硬规则见 [`./references/骨架字段与检查.md`](./references/骨架字段与检查.md)。

## 步骤

1. **全名单角色组**：按总账名单建 `角色/{角色组ID}/角色组.yaml`：版本、档案分期与生效条件、初始能力/装备/所在、别名（两字及以上可辨识称呼，**禁用单字别名**，同组含版本内不得重复）。
   - 单版本角色组**严禁写 `默认版本` 与档案项 `适用版本`**；只要写了 `版本`（即使仅 1 项）则两者必填。
   - **`初始化方式` 缺省为 `显式确认`**（首次把未出场角色写为在场前须先 `确认初始化`，否则报 `协议.场景`）；长篇群像推荐按需显式声明 `出场自动`。
   - 依赖 `所在`/`同处` 分流的事件，须确保相关角色组已设 `初始所在`。
   - 每份档案建最小合法壳（必须且只能有 `基本信息.txt` 与 `角色印象.txt`），切期档案生效条件指向实际达成结果的分支且不引用自身赋予的状态；平行切期须互斥防 `抽样.档案冲突`。
2. **全书事件树**：逐事件原子建 `历史/事件/{事件ID}/事件.txt`：触发时间、地点（非门槛，仅用于路由挑选）、`核心参与者`、只写因果的门槛、分支（含可选分支专属四字段 `事件概要`/`影响范围`/`公开信息`/`隐秘信息`）、变化表、确认策略；把发现所需的取值同步补进 `设定/剧情标记.yaml`。建树须严守：
   - **核心参与者最小化**：`核心参与者` 绑定事件排除、候选路由、封卷实际参与者、变化担保与开局必选锁定五重硬机制——只列**缺之事件即不成立**的角色组，**世界事件通常为空 `[]`**，个人后果另拆事件，绝不塞入旁观者或路人；
   - **事件树五条红线 + 4 条机械拆分测试**（细则见 `./references/骨架字段与检查.md`）：① **事件原子化与 4 条机械一票否决测试**（反事实独立成败 / 核心参与者正交 / 跨日跨地必拆 / 单焦点分支），严禁把无关甲乙两事用「与/及/暨/并/兼」等硬捆成拼盘，也不把无关剧情顺手塞进既有分支；② **准入门槛**，出场前固定前史归默认档案，建事件须过三问至少中其一（触发 `变化` 或切期 / 下游真实因果前提 / 玩家可亲历改写高光），纯日常流水账不入树；③ **真因果铁律**，时间先后只靠 `触发时间`，严禁滥用 `none` 表达“在它之前”（`none` 是终身排斥），`世界`/`势力` 级事件不硬绑主角个人日常；④ **`确认策略` 三分法**，禁全员盲写 `自动确认`，长篇卡应大量用 `条件确认` 承接游玩期个人遭遇/战斗/感情/拜师/社交事件，`自动确认` 只留幕后必发大事与历史锚点，`仅作候选` 留给可选支线与彩蛋；⑤ **`主类型` 归类与真实纪年精度**，不把个人成长或家庭琐事误标 `势力`，缺月日只写到年严禁编造 `01月01日`（同一年内前置精确到日时，后续放宽到年末须写年末日或保持同精度，避免年精度首日起点比较报错）。
   - **状态驱动轻引导**：自由游玩中的预设外经历以动态事件与角色知识作软记忆即可；对幕后自动确认易穿帮的关键节点（空间分流、核心人物重大状态、主线转折前提），门槛优先读取状态条件（`所在`、`同处`、`角色状态`、`剧情标记`、`事件串状态`），使动态事件改写的状态或提前结束的事件串自然接上事件树。
3. **过程与开局**：建 `历史/事件串/{事件串ID}.yaml` 与结局（起点由工具推出、不手写，每事件至多属 1 串，`概述` **严禁剧透结局**）；多世界线卡先建 `历史/世界线/{世界线ID}.yaml`（按需附 `世界概况/世界线/{世界线ID}/*.txt`），再建 `历史/开局选项.yaml` 与 `历史/开局方案/{方案ID}.yaml`（单世界线卡严禁在方案写 `世界线`；方案 `历史选择` 仅用开局选项声明项且所选事件最晚终点 ≤ 开局时间起点）。`开局选项.yaml` 保持克制简练、客观自然：分岔处直接写事件名（或省略 `问题` 回退事件标题/ID），选项直接写简明分支名。
4. **事件级出处**：每条 `作者资料/出处/` 记录写明来源（只含 `事件ID`、`来源` 两键；写原作卷章或作者原创）。`.yaml` 中的显示名/别名/版本简介/事件串概述/世界线概述/开局选项与方案文字同样受禁用词与破折号检查。

步骤完成标准：拍板名单中每个角色组与年表中每个保留事件全部落盘且可被静态检查接受；占位正文保持短句。

## 出口门禁（逻辑跑通再填肉）

优先使用 `ygg <命令>`（未链接 `ygg` 到 `PATH` 时改用 `node <世界树仓库>/cli/ygg.mjs <命令>`）：

- 全量 `ygg check <世界书目录>` 0 错误（含抽样）；逐条排查并处置 `事件.疑似拼盘` 与 `事件.世界事件含核心参与者` 提示（确属不可分割单一互动专名或缺人即不成立的特例可保留并在复核清单单列说明）；反映真实因果的跨级过渡提示（如 `事件.世界依赖个人`）允许保留并在复核清单说明，不为凑“零提示”改写门槛。
- 事件树五条红线、4 条机械拆分测试与 `确认策略` 三分法核验：复核无「A与B」拼盘事件、无核心参与者臃肿或世界事件误塞参与者、无前史/零变化日常流水账硬升事件、无把时间先后写成伪因果门槛、未全员盲写 `自动确认`（个人遭遇类已合理使用 `条件确认`）、`主类型` 与真实纪年精度（无编造 `01月01日`）准确。
- `ygg if <世界书目录>`：默认路径、各 if 线与开局方案符合预期，影响面无意外。
- `ygg preview <世界书目录> <关键角色组>`：首次登场初始化符合预期。
- 骨架拍板收口：引导模式引导作者用 `ygg view <世界书目录> --port 0` 审树，拍板后才进入第 4 层；自动模式按统筹传入口径取保守方案，记入待复核清单。

门禁通过后呈报：产出摘要（角色组/事件/事件串/开局数量）+ 检查（含提示处置记录）与 `if`/`preview` 结果 + 待拍板项 + 下一步建议（并行进入 `世界树·档案` 与 `世界树·填景`）。
