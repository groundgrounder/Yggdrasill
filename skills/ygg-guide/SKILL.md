# 世界树·统筹

本 skill 只读诊断项目现状并编排分层建卡，不代写各层产物；各层写法归对应阶段 skill。

## 调用口径

- 命令行优先使用 `ygg <命令>`；若未把 `ygg` 链接到 `PATH`，则改用 `node <世界树仓库>/cli/ygg.mjs <命令>`。
- 诊断项目与各层检查时，`<世界书目录>` 或 `<项目目录>` 按当前创作项目所在工作目录传入。

## 诊断（只读）

先跑 `ygg status <项目目录> --json` 取得第 0–5 层只读盘点（含静态检查与台词统计），再按序人工核对项目根，判定当前层并列出缺口与推荐下一步：

1. `来源资料/`、`作者资料/迁移/` 与 `作者资料/通读/`：若作者提供现有酒馆角色卡（PNG/JSON）或独立世界书待转换，先确认是否已完成 `世界树·迁移` 拆包与映射；核对分卷账本（或拆包映射）与 5 份全局总账是否齐全、坐标是否可查。
2. `世界书/设定/`、`世界书/世界概况/`、`世界书/扮演准则/` 与项目根 `yggdrasill.yaml`：第二层声明、全局文风与运行参数预算配置。
3. 条目库目录（对照 `设定/条目库.yaml`）：公共条目与引用 ID 是否就绪。
4. `世界书/角色/` 与 `世界书/历史/`：角色组、事件树、事件串、世界线与开局。
5. 事件正文、角色位置与 `作者资料/出处/`：实写程度、出处完整性与上下文校准（`ygg context`）状态。
6. `<项目目录>/外观/`：是否已定制声明式卡专属主题（`主题.yaml` + 可选 CSS），若存在确认是否已跑 `theme-tool.mjs validate` 与离线预览。
7. 卡面（`卡面.yaml`）与打包产物：是否已有可导入的角色卡，大型卡是否已走第 5.5 层试玩验收。

完成标准：能向作者说出“当前第 N 层、缺什么、下一步做哪件事”。

## 运行模式（开工时与作者确认，二选一）

- **引导模式（默认）**：执行并跑通当前层出口门禁后停下，按三段呈报——产出摘要、工具检查结果、待拍板清单与下一步建议；作者拍板后才进入下层。
- **自动模式**：作者要求自动推进或指定目标层时，按 `0→1→2→3→4a/4b→(上下文校准 / 可选前端)→5→(大型卡自动衔接 5.5 验收)` 连续推进至目标层：
  - 第 4 层完成后，按需跑 `ygg context` 校准典型开局与多人拥挤场景的上下文体量并调优项目根 `yggdrasill.yaml`；
  - 若作者明确要求定制专属前端或项目根已存在 `<项目目录>/外观/`（或原卡迁移已摘录视觉复现需求），在打包前衔接 `世界树·前端`；
  - 打包完成后，凡满足大型卡门槛（世界书文件数 ≥ 200、角色组 ≥ 15、事件数 ≥ 50、含多世界线/长跨度时间轴或公开发布标杆卡），自动衔接第 5.5 层 `世界树·验收`；
  - 只在硬阻塞停下问作者：改编范围未定、核心设定冲突、缺少来源原文。非阻塞细节取保守方案记入待复核清单，推进完成或到达目标层后一并汇总呈报。

## 分层分工与分流

| 阶段 | 负责 skill | 出口检查 |
|---|---|---|
| 第 0 层 通读 | `世界树·通读` | 覆盖范围完整、坐标与词表全量回查通过、事件表红线与拼盘豁免通过、待拍板收口 |
| 第 0 层 迁移 | `世界树·迁移` | 拆包完整、映射表 100% 覆盖原卡字段与条目、总账坐标回查通过、待拍板收口 |
| 第 1 层 地基 | `世界树·地基` | `ygg check <世界书> --static-only` 0 错误 |
| 第 2 层 条目 | `世界树·条目` | `ygg check <世界书> --static-only` 0 错误 |
| 第 3 层 骨架 | `世界树·骨架` | 全量 `ygg check`（排查拼盘与世界事件核心参与者提示）+ `ygg if` + `ygg preview`（另用 `ygg view <世界书> --port 0` 审树） |
| 第 4a 层 档案 | `世界树·档案` | 全量 `ygg check` + `ygg format <世界书> --check` |
| 第 4b 层 填景 | `世界树·填景` | 全量 `ygg check` + `ygg format <世界书> --check` + `ygg tree --stats-only` + `ygg context` 上下文校准 |
| 可选 前端（第 4 层后/打包前） | `世界树·前端` | `theme-tool.mjs validate` 0 错误 + 暗/亮/移动端离线预览无溢出 |
| 第 5 层 打包 | `世界树·打包` | `ygg pack <项目目录>` 成功 + 产物**四项核对**（开场命令、构建清单、资料隔离、多方案导出） |
| 第 5.5 层 验收（大型卡推荐） | `世界树·验收` | 打包卡离线挂载 + 五维反原作剧本试玩 + 只读哈希核对 + 问题三分法裁决 |
| 建成后 修订 | `世界树·修订` | 按外观级（分流前端）/ 设定级 / 结构级 / 文本级跑最小必要检查 |

- 各层执行：若作者提供现有酒馆角色卡（PNG/JSON）或独立世界书待转换，先分流至 `世界树·迁移` 完成拆包与同构总账映射，再衔接第 1–5 层；其余按阶段点名对应 skill（`世界树·通读` / `世界树·地基` / `世界树·条目` / `世界树·骨架` / `世界树·档案` / `世界树·填景` / `世界树·打包`）。若作者希望为本卡定制专属前端主题与正文排版，可在第 4 层后、打包前调用可选的 `世界树·前端`（写入 `<项目目录>/外观/`，不改动世界书）；大型多卷/多世界线卡在打包完成后、交付酒馆前推荐加走 `世界树·验收`（小/微型单幕卡可跳过），传递诊断结论与作者拍板口径。当前代理环境支持隔离子代理时，每层（长篇可分批）派发独立子代理，交接包固定 4 项：项目根目录路径、当前层 skill 名称或路径、上游总账与已拍板口径、运行模式与硬阻塞回报规则；不支持时在本会话按层收口。
- 建成卡（或返工）后的局部改动与跨层小修：交由 `世界树·修订` 处理（纯 `<项目目录>/外观/` 修订直接分流 `世界树·前端`）。
