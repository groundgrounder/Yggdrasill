# 世界树·角色

本 skill 处理结构级的角色内容：角色组、版本、档案项元数据、别名、初始能力与初始所在。新建角色组或版本时写结构与档案骨架，两份档案正文交“建角色”，归属见 [`../shared/编辑分级.md`](../shared/编辑分级.md) 的“首稿归属”。字段见 [`docs/参考/角色.md`](../../docs/参考/角色.md)，规则见 [`docs/02-角色.md`](../../docs/02-角色.md)。

## 1. 锁定对象与归属

1. 写明要改或新建的角色组、版本或档案项；档案正文的措辞不在本 skill 内改。
2. 判断改动是否影响版本与档案的适用关系、初始化、别名或引用键。
3. 记下对象键：`角色组:<ID>` 或 `档案:<角色组ID>:<档案ID>`；新建对象另写预期目录。

完成标准：角色组、版本与档案项已写明；新建与修改已区分；文本字段已排除。

## 2. 改前基线与引用

1. 在临时副本上工作，记录输入哈希；按 shared 跑 `check --static-only --json` 与 `format --check --json`，保存基线。
2. 用 `trace` 查询角色组与受影响的档案项，记下“引用它”的事件、条件、档案项与出处。
3. 检查版本与档案的对应：每个版本至少一份适用档案；默认档案不写生效条件；非默认档案有正向事件确认。

完成标准：基线、输入哈希与引用清单已保存；版本与档案的对应关系已核对。

## 3. 新建或改元数据

1. 新建角色组写 `角色/<角色组ID>/角色组.yaml` 与 `档案/<档案ID>/基本信息.txt`、`角色印象.txt`；字段与档案项按参考；骨架写足以通过静态检查的必填字段，正文交“建角色”。
2. 新建版本写 `版本ID`、显示名与各档案的适用版本；同步至少一份适用档案，漏补由 `档案项.无适用档案` 检出。
3. 档案项：默认、前置档案、生效条件、初始能力、初始装备按声明校验；生效条件只引用实际达成结果的分支。
4. 别名：组内不得重复；跨组同名只提示，不自行合并。
5. 初始所在取地点库中的地点；初始能力按能力维度与等级声明书写。
6. 本节结束前跑 `check --static-only --json`，只把相对基线的本次新增错误列为问题。

完成标准：静态检查无新增错误；每个版本都有适用档案；新建骨架的档案项与 `档案/` 目录一一对应。

## 4. 初始化与互斥

1. 按 shared 用 `preview` 核对首次登场预览：`node cli/ygg.mjs preview <世界书目录> <角色组ID> [--开局 <纪年>] [--方案 <方案ID>] [--json]`。要核对非默认版本时，用选择该版本的方案。
2. 需要核对本局已有值时，保存一份已封卷本局，用 `--本局 <文件>` 重跑；已初始化的角色组应得到 `预览: null` 与原因“已初始化”。
3. 按 shared 跑全量 `check`；抽样会枚举档案生效条件所引事件的状态，核对每个版本至多一份当前档案。
4. 需要反向证明抽样有效时，只在临时副本上制造一份冲突档案，确认检查报出档案冲突，然后丢弃该副本。

完成标准：`preview` 的档案、能力与装备符合预期；全量检查无新增错误；档案互斥由抽样覆盖；临时反例没有留在输入中。

## 5. 引用复核

1. 再次用 `trace` 查询角色组与档案项，确认每个引用仍能解析。
2. 改动 ID 前确认没有需要兼容的存档，或建立旧 ID 到新 ID 的迁移表。
3. 需要统一 YAML 风格时按 shared 运行 `format`。

完成标准：引用清单没有悬空项；ID 迁移有表或确认无需兼容；检查结果相对基线无新增错误。

## 6. 报告

写明角色组、版本与档案项、改动前后、`preview` 输出、档案互斥抽样、引用复核与检查结果，以及未解决项。

完成标准：报告能按角色组与档案项复核改动；未解决项写明位置与是否影响本次范围。
