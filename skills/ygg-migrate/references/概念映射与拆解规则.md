# 概念映射与拆解规则

本参考页供 `世界树·迁移` 独立自包含查阅，覆盖五层概念映射、弃用清单与视觉复现衔接、三类原卡处置策略、事件树防拼盘与核心参与者最小化原则、以及完整禁用词与宏清洗红线。

## 一、五层概念映射表

| 原卡元素 | 目标世界树归属 | 拆解与清洗规则 |
|---|---|---|
| `description` / `personality` | `角色/<角色组ID>/档案/<档案ID>/基本信息.txt` + `角色印象.txt`；动态部分拆入 `初始能力` / `初始装备` / `初始所在` / 事件变化 / 开局方案 | 剥离一切当前状态（当前关系、好感、伤势、穿着、持有物、所在位置），只留稳定事实与行为规律。 |
| `scenario` | `世界概况/` + 默认 `开局方案`（`历史/开局方案/`） | 长期背景入 `世界概况/`；开局时刻与场景入默认 `开局方案` 概述与开局时间。 |
| `mes_example` | `角色印象.txt` 的 `表达规律`（自称、句式、语气、口头特征）与参考情境台词 | **明确标注来源为 `原卡 mes_example`**，不得标为原作逐字原台词，也不写入原作台词出处。 |
| `system_prompt` / `post_history_instructions` | `扮演准则/`（仅有效文风与叙事约束） | 只保留人称、文风、对白比例等有效约束；彻底剥离越狱、思维链（CoT）、格式控制与旧变量更新指令。 |
| `first_mes` / `alternate_greetings` | `作者资料/迁移/原卡开场白.yaml` → 第 5 层 `卡面.yaml` 的 `开场白` 与 `按方案` | 去除 HTML 状态栏、`<UpdateVariable>`、旧变量标签与脚本块，保留纯叙事正文与原索引；多条开场白在拍板后决定是否对应多个开局方案。 |
| `character_book`（`constant: true`） | `世界概况/`、`扮演准则/` 或常驻世界通则 | 区分长期背景与系统指令；后者按弃用清单处理。 |
| `character_book`（关键词触发） | 原子公共条目（`地点/`、`势力/`、`技能/`、`装备/` 含可选 `唯一: true`、自定义库）、`角色/`、`历史/事件/` | 按一地/一势力/一技/一物拆为单件原子条目；同类通则抽入目录同名说明文件（≤ 300 字）；停用条目（`enabled: false` / `disable: true`）照常入映射表并标注弃用或待拍板。 |
| EJS 条件（`<% if (...) %>` / `getvar` / `getwi`） | 档案 `生效条件`、事件 `门槛` / `分支` 或 `历史/世界线/` | 将按日期/变量硬切的条件转为因果事件或世界线/开局方案条件，不把 EJS 语法带入世界书。 |
| MVU 变量表（`[InitVar]` / `stat_data` / `_.set`） | `设定/本局变量.yaml`（数值/词表/映射/集合）、`设定/能力.yaml`（等级映射/单值等级/集合与 `技能可用`）、`设定/剧情标记.yaml` 与玩家开局自定义能力/装备 | 从 `scripts/extensions.json` 与世界书初始化条目完整提取变量名、初值、上下限与枚举，保留核心玩法数值体系。 |

## 二、明确弃用清单（由世界树原生接管）

以下内容在 `作者资料/迁移/原卡盘点与方案.md` 与 `迁移映射表.yaml` 中显式标记为“弃用（世界树原生接管）”，不迁入 `世界书/`：

1. **HTML / CSS 状态栏与前端面板**：`<style>`、`<div`、`<table>`、`<details>` 及旧状态卡片渲染壳（世界树由适配层独立呈现状态）。**视觉需求接力**：弃用旧 HTML/CSS 壳的同时，若原卡具备有价值的配色方案、字体气质、边框纹样或排版风格需求，将其整理写入盘点报告的「外观复现建议」，交后续可选层 **`世界树·前端`（`ygg-theme`）** 以声明式 `<项目目录>/外观/`（零 JS、不污染世界书哈希）无损复现；
2. **MVU 记账与变量更新提示词**：`<UpdateVariable>`、`_.set(...)`、正文末尾 JSON/YAML 补丁输出格式指令（世界树由独立记账与协议模板接管）；
3. **纯界面美化正则**：`placement` 仅含显示层（`2` / `markdownOnly`）的排版与折叠正则；
4. **TavernHelper / STScript 旧面板与宏脚本**：改写提示词或操控前端 DOM 的旧脚本；
5. **越狱与思维链指令**：通用破限词、`<thinking>` 输出规范与与世界观无关的系统控制段落。

若某条正则脚本或扩展中夹杂了**世界观规则或数值公式**（例如属性换算、好感阶段阈值），须先将规则/阈值提取进总账的 `世界体系汇总.yaml`，再弃用脚本壳本身。

## 三、三类原卡处置策略

### 1. 轻量单角 / 小群像卡

- **判定特征**：单主角或少数配角，世界书条目少（或无世界书），无复杂时间线与动态脚本。
- **处置策略**：采用最小合规骨架，不硬造伪长篇事件树。
  - 纪年使用贴合原卡背景的简单纪年（缺失时默认 `纪年前缀: 序`，年位数 3，月数 12，每月天数 30，记入拍板清单）；
  - 人物优先使用单份默认档案承载稳定设定，仅在原卡明确存在人生阶段切换时才切多份档案；
  - 原卡中提及的潜在剧情或互动钩子优先建为 `仅作候选` 事件，不虚构未在原卡出现的长篇因果链。

### 2. 长篇 / 多期 / EJS 阶段卡

- **判定特征**：含多时期人物设定、大量世界书条目或 `<% if (...) %>` 阶段切换逻辑。
- **处置策略**：
  - 按人物经历的实质转折切分时期档案，将“按年份/变量硬切”改写为“绑定关键事件确认”；
  - 将合并在一条世界书里的多件物品、多处地点或多名人物拆回原子条目与独立角色组；
  - 将原卡的多条分支/剧情线梳理为因果事件树与 `历史/世界线/`，并严格执行下方「事件树五条红线 + 4 条机械拆分测试 + 核心参与者最小化」。

### 3. MVU 强系统数值卡

- **判定特征**：`hasMvu: true`，含 `[InitVar]`、`stat_data`、`_.set` 或大段变量表与数值系统。
- **处置策略**：
  - 完整清点全部变量并逐项归类：数值/好感/资产/词表入 `设定/本局变量.yaml`，等级/技能/属性维度入 `设定/能力.yaml`，全局开关与阶段标志入 `设定/剧情标记.yaml`；
  - 保留玩家开局自定义能力/装备的玩法自由度，确保核心数值体验不缩水；
  - 彻底剥离原卡内联记账规则与 HTML 面板，由世界树原生记账接管。

## 四、事件树五条红线、4 条机械拆分测试与核心参与者最小化

长篇/多期/EJS 原卡在产出 `全书年表与因果事件表.yaml` 时，与第 0 层通读同口径守住以下结构护栏：

1. **事件原子化 + 4 条一票否决机械拆分测试（禁「A与B」拼盘）**：一个事件只承载一件可独立判定发生/未发生的因果节点，禁把无关两事用「与/及/暨/并/兼」等硬捆。命中以下任一条必拆：
   - ① **反事实独立成败测试**：A 发生而 B 不发生/走另一分支是否成立？成立必拆；
   - ② **核心参与者正交测试**：拆开能否减少任一方 `核心参与者` 人数？能少人必拆；
   - ③ **跨日/跨地拆分铁律**：不同日或不同地的两事禁合写，过程改用 `事件串`；
   - ④ **单焦点分支测试**：概要/结果含“先……随后……/同时完成另一事”且可独立分岔的必拆。
2. **准入门槛（前史归档案 + 三问准入）**：出场前固定前史入默认档案；拟入事件须过三问至少中其一（触发 `变化` 或切期 / 下游真实因果前提 / 玩家可亲历改写高光），纯日常流水账不入树。
3. **真因果铁律**：时间先后只靠 `触发时间`，不靠伪 `事件确认` 硬串；`世界`/`势力` 级事件不硬绑主角个人日常。
4. **`确认策略` 三分法**：`自动确认` 只留幕后必发大事与历史锚点；可被玩家绕开/截胡的个人战斗、感情、拜师、社交用 `条件确认`；可选支线与彩蛋用 `仅作候选`。
5. **`主类型` 归类与真实纪年精度**：按实际影响层归类 `主类型`，缺月日只写到年严禁编造 `01月01日`。
6. **`核心参与者` 五重机制最小化原则**：`核心参与者` 绑定①任一未启用即排除整件事件、②候选路由准入与排序、③封卷/待登记 `实际参与者` 来源、④变化表角色启用担保、⑤开局前端必选锁定——因此只列缺之事件即不成立的角色组，**世界事件通常保持 `核心参与者: []`**，个人后果另拆事件，绝不塞入旁观者或路人。

## 五、忠实原卡、宏替换与完整措辞清洗红线

1. **严格忠实原卡、零脑补扩写**：原卡未写明的背景、时间线、地点上下级或人物过往一律不擅自补充；世界树必填结构缺失时取最小合法默认，并在 `待作者拍板清单.md` 中列出供作者决定是否补写。
2. **彻底清除酒馆语法与宏残片（含 `{{user}}` 红线）**：
   - 待迁设定正文与开场白不得残留 `<%`、`%>`、`getvar(`、`setvar(`、`_.set`、`<UpdateVariable>`、`<div`、`<style` 等脚本或标签；
   - `{{char}}` 替换为角色自然称谓；`{{user}}` 在叙述正文按语境替换为世界内自然称谓（如“旅人”“来访者”或视语境说明），**严禁把保留字 `玩家` 写入任何 ID、核心参与者、预设事件变化路径/映射键/引用值或条件门槛**（否则静态检查与协议直接报错）。
3. **清理真实检查器 25 禁用词、破折号与包裹标签**：
   - **越界清单**：关系、婚姻、家系、职位、资产、持有物、伤势、当前穿着、能力的取得与丧失、当前所在等本局状态一律不写进角色静态档案正文；
   - **全部 25 个 `文本.禁用词`（出现即报错，清洗时须逐项排查替换）**：
     `stat_data`、`变量`、`schema`、`索引`、`路由`、`ID`、`状态0`、`状态1`、`状态2`、`状态0/1/2`、`候选事件`、`额外模型`、`冲突队列`、`条目`、`注册`、`挂载`、`加载`、`目录`、`记录规则`、`目录规则`、`统一格式`、`登记规则`、`引用边界`、`记录边界`、`维护`；
   - **破折号与包裹标签**：非原台词正文彻底清除 U+2014（`—`）/ U+2015（`―`）破折号与单独成行的 `<...>` 包裹标签（如 `<世界书>`、`<状态栏>`）。
4. **坐标与去向可回查**：所有总账记录统一使用 `原卡拆包/<相对路径>:L起-L止` 坐标；`迁移映射表.yaml` 必须覆盖 100% 的原卡核心字段与世界书条目，确保零静默丢弃。
