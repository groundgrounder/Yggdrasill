# 路由与上下文

> 状态：2026-10-22 已确认；2026-10-23 按术语收词的决定修订用语。酒馆适配（打包、EJS 或脚本路由、MVU schema、开局前端、命令的解析与执行时机）另写设计文档，在第一个里程碑之后进行。

## 路由（第一层）

路由每轮只读计算，不写任何变量。输入是本局变量、最近的消息与运行参数；输出是模型上下文，以及只给作者看的审计信息。上下文先组装为结构化数据，再由渲染函数生成文本。

- 读取都经协议（spec/15），在有效本局上进行：待登记事件视为已发生，它写入的状态都看得到。
- 最近的消息是一组文本，从旧到新；只看最后“提及窗口”条。

## 输出的组成与顺序

| 序 | 部分 | 预算 |
|---|---|---|
| 1 | 协议文本 | 不限 |
| 2 | 世界概况 | 不限 |
| 3 | 世界当前状态 | 不限 |
| 4 | 在场角色 | 不限 |
| 5 | 被提及角色 | 不限 |
| 6 | 相关条目正文 | 每个库各有字符预算 |
| 7 | 事件：已确认经历、待登记、候选、待初始化 | 经历、候选各有条数与字符预算；待登记、待初始化不限 |

预算不是整个提示词的上限。没有内容的部分省略。

### 1. 协议文本

由模板生成（spec/10），打包时算一次，每轮原样输出。依次是变量更新规则、角色通用约束、扮演准则（架构部分在前，本卡 `扮演准则/` 的原文由占位符填入），以空行分隔。

### 2. 世界概况

`世界概况/` 下各文件的内容，按文件名码点顺序。

### 3. 世界当前状态

- 当前时间、当前地点、剧情标记、二层世界字段（有值的）。
- 进行中的事件串：每串给概述，以及本串状态为 1 的事件，每项为“事件标题：分支结果”，按实际时间先后。事件串按ID码点顺序。
- 待定项：原样输出。

### 4. 在场角色

**在场者**为视为在场的已启用角色组（spec/15），按角色组ID码点顺序；自建模式的“玩家”排在最后。每个角色组输出：

| 项 | 内容 |
|---|---|
| 角色组ID、显示名 | 显示名取所选版本的显示名，其次角色组的显示名，其次角色组ID |
| 年龄 | 当前时间的年份减出生年；没有出生年或当前时间时省略 |
| 档案 | 当前档案的基本信息与角色印象，剥离机器字段；技能补充只留可用技能的项 |
| 当前能力、可用技能 | spec/15 |
| 本局状态 | 角色变量中的二层字段与装备；不含在场、所在、能力维度、能力移除记录、已初始化 |
| 玩家扮演 | 扮演角色组标为是，叙事模型不替他决定言行 |

- 档案冲突或异常的角色组只给角色组ID与显示名，原因进审计。
- 自建玩家输出角色组ID“玩家”、显示名（档案的姓名，没有时为“玩家”）、年龄、`开局.玩家.档案`、当前能力、可用技能、本局状态。

### 5. 被提及角色

已启用而不在场的角色组，在提及窗口内被提及时，只给角色组ID、显示名与别名，不给档案。按首次出现的位置排序。

### 6. 相关条目正文

条目按以下来源依次选入，同一条目只选一次，以先选入的来源为准：

1. **本局状态引用**：在场者的本局状态与集合能力中，按声明引用了条目库的值与映射键，例如持有的装备、职位所属的势力、天赋中的技能。按在场者顺序、字段声明顺序、值的顺序。
2. **地点链**：当前地点的地标，以及它的各级上级，从地标往上。
3. **提及**：提及窗口内出现条目ID或名称的条目，按首次出现的位置。

技能另须是某个在场者的可用技能；不可用的不展开，记入审计。

- 输出的单位是一个条目的条目正文。按种类分的库，条目前面附上它所在各级目录的同名说明（库的根说明在前），每份说明只输出一次；按上下级分的库，只附根说明。说明与条目一起计入预算。
- 每个库有自己的字符预算。按选入顺序放入，放不下的整条略过，接着试下一条，不截断。
- 输出按条目库声明的顺序分组，组内按选入顺序。

### 7. 事件

**已确认经历**：候选池是有效本局中状态为 1 的预设事件与动态事件，不含初次登场记录，也不含待登记事件（它们在“待登记”中完整输出）。满足下列任一理由才入选，按最高的理由排优先级：

| 优先 | 理由 | 条件 |
|---|---|---|
| 1 | 点名 | 提及窗口内出现事件ID或事件标题 |
| 2 | 候选前置 | 被选入的某个候选事件的门槛中，在成立的路径上正向引用了它 |
| 3 | 当前地点 | 事件的地点与地点链有交集 |
| 4 | 共同经历 | 实际参与者中至少两个是在场者 |
| 5 | 在场者经历 | 实际参与者中至少一个是在场者 |

- 同级时：点名按首次出现的位置；其余按在场的实际参与者人数从多到少，实际时间从近到远，事件ID码点顺序。
- “成立的路径”：从门槛根向下，只进入求值为成立的节点；只认其上的正向引用（spec/06），处于否定之下的引用不算。分支门槛同样计入（只看门槛成立的分支）。
- 每项输出：事件ID、事件标题、事件概要、实际时间、所走分支的分支结果、公开信息、隐秘信息（含义由角色通用约束说明：属实，只有知情者知道）、在场者的角色位置（按所走分支合并；只留角色概要、角色定位、角色知情、主观记忆）。动态事件只有事件ID、摘要、实际时间。
- 按优先级放入：超出条数上限的略过；超出字符预算时先去掉角色位置，仍放不下就整条略过。入选的按实际时间先后输出，同时刻按事件ID码点顺序。

**待登记**：全部输出，按求解顺序。每项同已确认经历的完整形式，另标“已经发生”。

**候选**：候选池是有效状态为候选的预设事件。满足任一即入选：有核心参与者在场；地点与地点链有交集；没有核心参与者。

- 排序：属于进行中事件串的在前；其次地点相关的在前；其次在场的核心参与者人数从多到少；其次触发时间最晚从早到晚；最后事件ID码点顺序。
- 每项输出：事件ID、事件标题、事件概要、叙事条件、公开信息、触发时间最晚、门槛成立的各分支（分支ID、分支条件、分支结果），以及在场者的角色位置（只留角色定位、介入条件、事件触发语料；角色位置的适用分支与这些分支有交集才取）。不输出隐秘信息、角色知情、主观记忆。
- 超出条数上限或字符预算的整条略过。

**待初始化**：在场者中初始化方式为显式确认、有待初始化预览的角色组，输出角色组ID、档案ID与预览。出场自动的不列，它们在下一次写入时自动初始化。

### 审计

审计不进模型。逐部分记录：选入与略过的项及理由（经历的理由、去掉角色位置、超出条数、超出字符；不可用的技能；未启用的提及），各部分的字符用量与预算，以及异常（档案冲突或异常、当前地点不在地点库中）。

## 预算

- 每项的字符数是该项 JSON 序列化后的 Unicode 码点数；一部分的用量是入选各项之和。不是 token 数。
- 只有经历、候选、条目受预算约束。

## 呈现

- 默认渲染：每一部分用类型名作包裹标签，例如 `<协议>`、`<世界状态>`、`<在场角色>`、`<条目>`、`<事件>`；协议文本、世界概况原样放入，其余部分以 YAML 写出。部分内部的每一项写出自己的名称或ID。
- 标签名集中在一张表里，适配层可以替换。
- 机器字段在组装时剥离（spec/06）。

## 运行参数

运行参数不属于任何一层，写在项目根（世界书目录的上级）的 `yggdrasill.yaml`；不写时取默认值。未知键或取值不是非负整数时报错。

```yaml
运行参数:
  经历: {条数: 6, 字符: 3000}
  候选: {条数: 4, 字符: 4000}
  条目字符:
    默认: 1500
  提及窗口: 2
```

`条目字符` 可以按库单独设置，例如 `技能: 2000`。
