# 路由与上下文

> 状态：2026-10-20 已确认。酒馆适配（打包、EJS 或脚本路由、MVU schema、开局前端、变化表写入钩子）另写设计文档，在第一个里程碑之后进行。

## 路由（第一层）

路由每轮只读计算，不写任何变量。输入是本局变量与最近的消息；输出是模型上下文，以及只给作者看的审计信息。

## 输出的组成与顺序

1. **协议文本**：变量更新规则、角色通用约束、扮演准则（由模板生成的架构部分加上第五层），见 spec/10。
2. **世界概况**。
3. **世界当前状态**：当前时间、当前地点、剧情标记；进行中的事件串（概述与本串已确认的事件）。
4. **在场角色**：当前档案（技能补充按可用技能过滤）、当前能力、可用技能ID、本局状态中二层声明的字段。
5. **被提及角色**：只给显示名与别名，不加载档案。
6. **相关条目正文**。
7. **事件**：已确认经历（受预算约束）、待登记事件（完整输出，不受预算约束）、候选事件（门槛成立的分支，以及在场角色的角色定位与触发语料；受预算约束）、待初始化。

筛选理由、略过清单、预算用量与解析异常只进审计，不进模型。

## 在场与被提及

- **在场**：本局变量中在场为真的角色组；扮演模式下的玩家角色组每轮视为在场；自建玩家以保留ID“玩家”输出。
- **被提及**：最近 N 条消息中出现角色组的显示名、别名，或当前所选版本的版本级别名。N 是运行参数。

## 条目进入上下文

条目在以下任一情况下进入：

- 在场角色的本局状态引用了它，例如持有的装备、道具，职位所属的势力；
- 它在当前地点的地点链上；
- 最近 N 条消息中出现它的名称或 ID。

技能另须是在场角色的可用技能；不可用的技能不展开。

每个库有自己的字符预算。选入顺序为本局状态引用、地点链、提及（按出现先后）；超出预算的条目整条略过，不截断正文。

## 预算

- 字符按 JSON 序列化后的 Unicode 码点计数，不是 token 数。
- 只有可选内容受预算约束：已确认经历、候选事件、条目正文。协议文本、世界概况、当前状态、在场角色的档案与状态、待登记事件另计。
- 预算不是整个提示词的上限。

## 呈现

- 每一部分用类型名作包裹标签，例如 `<世界状态>`、`<角色>`、`<事件>`、`<技能>`；部分内部的每一项写出自己的名称或 ID。
- 机器字段与作者字段在呈现前剥离。
- 标签名的完整清单在酒馆适配设计中确定。

## 运行参数

运行参数不属于任何一层，写在项目根的 `yggdrasill.yaml`；不写时取默认值。

```yaml
运行参数:
  经历: {条数: 6, 字符: 3000}
  候选: {条数: 4, 字符: 4000}
  条目字符:
    默认: 1500
  提及窗口: 2
```

`条目字符` 可以按库单独设置，例如 `技能: 2000`。
