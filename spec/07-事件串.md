# 事件串

> 状态：2026-10-20 已确认。事件串取代剧情线。

全部事件由门槛与分支门槛连成一棵**事件树**：每个事件可以有多个分支，某个分支通向后面的事件，几条路径可以在某处汇合（门槛用 any）。原著走向、作者改编、if 线在结构上没有区别，都是这棵树里的路径；默认分支只表示封卷时没有其它因素决定时走哪一边。

**事件串**是事件树中被命名的一段，表达一个有开头、有结局的过程，例如一次政变、一次救援、一段师从。事件串不规定结构，结构仍只由门槛给出；它只负责命名与声明结局，由此推出“进行中”。“正在进行”不是事件的字段，而是事件串的状态：开了头、还没到结局，就是进行中。

## 文件

每个事件串一个文件：`历史/事件串/{事件串ID}.yaml`，只给工具读。

| 字段 | 必填 | 写法 | 层 |
|---|---|---|---|
| 概述 | 是 | 一句话；进行中时随当前状态发给模型 | 四 |
| 事件 | 是 | 本串的事件ID列表 | 三 |
| 结局 | 是 | 列表，每项为事件ID，可附分支ID；该事件（或该分支）确认即走到结局 | 三 |

```yaml
# 历史/事件串/爱丽儿争夺王位.yaml
概述: 爱丽儿回到阿斯拉，联络支持者并发动政变。
事件: [返回阿斯拉, 争取北方贵族支持, 王宫政变]
结局:
  - {事件ID: 王宫政变}
```

## 规则

- 每个事件最多属于一个事件串。不属于任何串的事件是孤立事件，不必为它建串。
- 列表顺序不表示先后。串内的先后与分岔全部由事件门槛、分支门槛给出：后面的事件声明“我需要什么”，前面的事件不声明“我之后接什么”。“之后能走向哪些事件”由世界树反查画出。
- 起点不写：门槛不依赖本串其它事件的事件就是起点。每个串至少有一个起点。
- 结局由作者声明。检查器提示不可达的结局，以及与本串其它事件既无依赖也不被依赖的成员。
- 串的边界由作者划定，不按门槛自动推算。
- 跨串的依赖写在事件门槛里，不另设引用列表。
- 世界树可以在图上编辑事件树：作者从某个分支连线到后面的事件，工具替后面的事件写入门槛。数据仍只有门槛这一处来源。

## 状态（第一层）

由已确认事件推出，不存入变量：

| 状态 | 含义 |
|---|---|
| 未开始 | 还没有起点被确认 |
| 进行中 | 有起点已确认，还没有结局被确认 |
| 已结束 | 有一个结局已确认，或有动态事件声明本串结束 |

- 没有预设的结局（例如中途辞职）由叙事模型登记一个动态事件，并在事件记录中写“结束事件串: {事件串ID}”。
- 门槛可以用条件类型“事件串状态”判断某串处于未开始、进行中或已结束。

## 上下文与封卷

- 进行中的事件串作为当前状态输出：概述与本串已确认的事件，不受经历预算限制。本串的候选事件优先选入候选。
- 封卷照旧按默认分支（及分支门槛的选择规则）确认开局前的事件。起点已确认、结局尚未确认的串，开局时就是进行中。
