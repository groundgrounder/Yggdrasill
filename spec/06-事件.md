# 事件

> 状态：2026-10-20 已确认。事件串见 spec/07。

历史由统一事件构成。每个事件在 `历史/事件/{事件ID}/` 下有一个模型可见的 `事件.txt`，角色位置在同目录的 `角色/` 下。

## 字段

| 字段 | 必填 | 写法 | 层 |
|---|---|---|---|
| 事件ID | 是 | 等于目录名；世界内中性的短语，不带“原著·”这类来源前缀 | 三 |
| 事件标题 | 否 | 文本；省略时等于事件ID | 四 |
| 事件概要 | 是 | 一句话点明事件内容 | 四 |
| 主类型 | 是 | 单选，取二层事件分类 | 三 |
| 标签 | 是 | 多选，至少一项，取二层事件分类 | 三 |
| 事件结果 | 是 | 多选，至少一项，取二层事件分类 | 三 |
| 影响范围 | 否 | 文本 | 四 |
| 触发时间 | 是 | 最早、最晚，见“时间” | 三 |
| 地点 | 否 | 地点ID列表 | 三 |
| 确认策略 | 是 | 自动确认 / 条件确认 / 仅作候选 | 三 |
| 核心参与者 | 是 | 角色组ID列表，可为空 | 三 |
| 门槛 | 否 | 条件，见 4b | 三 |
| 关联事件 | 否 | 事件ID列表，只供作者查阅 | 三 |
| 叙事条件 | 否 | 条件文本 | 四 |
| 公开信息 | 否 | 文本列表 | 四 |
| 隐秘信息 | 否 | 文本列表 | 四 |
| 默认分支 | 是 | 分支ID | 三 |
| 分支 | 是 | 见 4b | 三 |

- 门槛、确认策略、默认分支、变化、适用分支、关联事件等机器字段在注入模型前剥离。
- 地点只写地点ID，程序据此挑选与当前地点相关的经历；更细的场景写进事件概要或叙事条件。
- 事件的出处（原著或作者改编、章节）写进 `作者资料/出处/` 的事件级记录（spec/11）；来源摘要、核定依据写进核定日志。事件文件里只放属于五层的字段。
- 事件标题与概要用世界内中性的名称，描述公共行动、转折或结果，不以单一角色的视角命名。
- 不在静态正文里写本局确认状态。
- 每个事件最多属于一个事件串，见 spec/07。
- 门槛只写真正的因果；核心参与者只列缺了就不成立的人。世界事件与个人后果分开写，见 spec/12。
- 身份转变（成为护卫、成为家庭教师等）是事件分支的结果，写进变化表，不单独构成事件，也不写进事件ID。事件按发生的行动命名。

## 时间

- 时间按二层纪年书写，写到年或写到日，不写到月。只写年表示那一整年，从首月首日到末月末日。
- 触发时间的最早与最晚都含端点，最晚不可省略。
- 前置事件的触发时间最晚不晚于后续事件。较晚事件的变化不能倒流解锁较早事件。
- 触发时间是事件可以发生的窗口：早于最早为未到；到最晚仍未发生即排除（自动确认事件门槛成立时为待登记）。事件本身没有持续时间；持续的过程由事件串表达。

## 分类

- 主类型描述事件主要改变的对象；标签描述事件的形式或主题；事件结果描述分支实际写入的长期结果。三者只用于检索和作者审阅，不参与门控，不推导能力或结果。
- 事件结果取所有分支实际写入的结果的并集。
- 二层 `事件分类.yaml` 为每项事件结果声明支撑它的本局变量字段（见 spec/02）。检查器双向提示：
  - 变化表写了某个字段，事件结果里没有它对应的一项；
  - 事件结果写了某一项，变化表里没有支撑它的变化。
- 只有出现在某项事件结果支撑列表里的字段才参加双向检查；例如“在场”不在任何支撑列表里，写了它也不提示。
- “档案切期”是一种特殊的支撑：本事件的某个分支被某份档案的生效条件引用。
- 没有声明支撑字段的事件结果不检查，由作者判断。

## 分支

| 字段 | 必填 | 写法 | 层 |
|---|---|---|---|
| 分支ID | 是 | 事件内唯一 | 三 |
| 门槛 | 否 | 条件；省略表示恒成立 | 三 |
| 分支条件 | 是 | 条件文本，各分支之间必须能区分 | 四 |
| 分支结果 | 是 | 文本 | 四 |
| 变化 | 否 | 见 4b | 三 |

- 事件门槛决定事件能不能发生，分支门槛决定这个分支能不能走。分支门槛在注入模型前剥离。
- 游玩时，叙事模型只能在门槛成立的分支中选择；确认时协议校验所选分支的门槛。门槛为未知的分支不能选。
- 候选事件只附上当前门槛成立的分支。事件门槛成立而没有一个分支门槛成立时，事件不适用。
- 封卷时：默认分支的门槛成立就走默认分支；否则按书写顺序取第一个门槛成立的分支；都不成立则事件排除。分支门槛与事件门槛在同一时间语境下求值。
- 自动确认事件过期待登记时，按同样规则选出分支登记。
- 自动确认事件只要有一个分支带门槛，就必须有一个不带门槛的兜底分支；否则所有分支门槛都不成立时，事件被排除，后果凭空消失。缺少兜底分支时报错。
- 检查器对每个分支单独做前置的时间顺序与可达性检查；分支门槛不可能成立时提示。

## 变化

每条变化有路径、操作、值。路径根有三种：`世界.剧情标记.{标记ID}`；`世界.{二层世界字段}`（spec/09，例如天气）；`角色.{角色组ID}.{字段}…`。路径一律写到要改的那一格：

| 字段类型 | 路径 | 操作 |
|---|---|---|
| 集合（知识、固有技能等） | 写到集合，值是成员 | 新增、移除 |
| 映射（关系、职位、装备、道具等） | 写到键，如 `关系.秦守` | 设定；新增（键不存在时才写入）；移除（不带值） |
| 数值（好感度、道具数量等） | 写到键 | 增加、减少 |
| 等级 | 写到键 | 提升、设定、移除，见 spec/03 |
| 单值（所在、剧情标记、二层的取值或文本字段） | 写到该字段 | 设定 |

- 集合不能用设定整体覆盖。
- 增加、减少的值是正整数，单次不超过二层声明的上限；结果按二层声明的范围截断。
- 取值按二层声明校验：词表取值、等级、装备状态。映射的键按二层声明解析：关系、好感度、亲密度的键是角色组ID，职位的键是势力ID，装备的键是装备ID，道具的键是道具ID。
- 写到的角色必须保证已启用：某个分支的变化中，路径里的角色组ID与映射键里的角色组ID，须为核心参与者，或由“事件门槛且分支门槛”保证已启用。检查器这样判断：把该角色组视为未启用，凡涉及它的条件（角色启用、角色版本、角色已出场、角色状态、同处）记为不成立，其余条件记为未知；求值后门槛仍不是“不成立”就报错。
- 预设事件不写保留ID“玩家”：路径、映射键、引用角色组的值都不能是“玩家”。玩家是谁要到开局才定（自建或扮演某个角色组），预设内容无从写起；“玩家”的状态只由游玩中的动态事件写入（spec/15）。门槛同样不能引用“玩家”。
- 能力移除记录、已初始化由协议维护，变化表不能写。
- 同一事件的变化只写一次；事件记录已有该事件ID时不再写入。

## 门槛与条件

条件是单键映射，键为条件类型或组合词。组合词 all（全部成立）、any（任一成立）、none（全部不成立），列表不能为空。

求值为三值：成立、不成立、未知。变量缺失或封卷前读取为未知；未知只能使条件不成立，不能经 none 取反成立。

| 条件类型 | 参数 | 成立 | 封卷可求值 |
|---|---|---|---|
| 角色启用 | 角色组ID | 本局启用了该角色组 | 是 |
| 角色版本 | 角色组ID、版本ID | 启用且选了该版本 | 是 |
| 事件确认 | 事件ID、分支ID（可选） | 事件已确认或待登记；指定分支时分支一致 | 是 |
| 事件串状态 | 事件串ID、状态（未开始 / 进行中 / 已结束） | 事件串处于该状态，见 spec/07 | 是 |
| 当前时间 | 比较（小于 / 大于等于）、值 | 按纪年比较 | 是 |
| 剧情标记 | 标记ID、比较（等于 / 不等于）、值 | 标记的本局值满足比较 | 是 |
| 角色状态 | 角色组ID、字段、属于 | 该字段的本局值在“属于”列表中 | 是 |
| 同处 | 角色组ID列表（至少两个） | 所列角色组的所在是同一个地点；任一角色组未启用为不成立，任一所在未知为未知 | 是 |
| 角色已出场 | 角色组ID | 在场、已初始化，或任一已确认事件的实际参与者含该角色组；启用、提及、候选与排除不算 | 是 |
| 当前场景 | 地标（地点ID）、场景 | 当前地点的地标与场景都精确一致；地点缺失为未知 | 否 |
| 在场实力人数 | 最低实力、最少人数、排除角色组（可选） | 在场且综合实力不低于最低实力的人数达到最少人数；人数不足且有在场者综合实力缺失时为未知 | 否 |

- 依赖条目库或能力维度的条件，在卡没有声明所依赖项时不可用（见 spec/02）。
- none 表示排斥，不是前置，不参加前置的时间顺序检查。排斥是终身的：用 none 排斥了某事件的事件一旦确认，那个事件就不能再确认（spec/15“排斥检查”）。只想表达“在它之前”时，用当前时间或事件串状态。
- 剧情标记在封卷时写入开局值（二层声明中的第一个取值）。
- 事件的“地点”字段只用于挑选相关经历，不是门槛。

### 封卷求不出值的条件

封卷在幕后补出开局前的历史，没有当前场景，也没有在场者。“当前场景”“在场实力人数”在封卷时求不出值，用在会被封卷判断的事件上，晚期开局会把事件及其后续悄悄排除。

- 确认策略不是“仅作候选”的事件，其门槛和各分支门槛（包括 none 之内）不得含封卷不可求值的条件，违反时报错。
- 改法二选一：改为“仅作候选”，只在游玩中发生；或把地点与在场要求写进叙事条件交给模型判断，门槛只留可求值的条件。
- 档案的生效条件同样不得含这两种条件。

### 角色状态

让门槛读本局状态，使动态事件写出的结果也能接上预设事件。例如出师考核的“通过”分支要求学徒与秦守是师徒；师徒关系可以由“拜师”写入，也可以由游玩中的动态事件写入：

```yaml
门槛:
  角色状态: {角色组ID: 灯塔学徒, 字段: 关系.秦守, 属于: [师徒]}
```

- 字段只能是二层声明了取值表的字段（例如关系阶段、身体状态的健康），或“所在”；数值与自由文本字段不能用。“属于”中的值须在取值表里。
- 字段为“所在”时，“属于”列地点ID，所在为其中某个地点或其下级地点即成立。
- 封卷前为未知；角色组未启用为不成立；字段从未写过时取二层取值表的第一个值（关系阶段为第一个值，例如“陌生”）。
- 封卷按时间顺序边确认边写入，后面的事件读到前面事件写入后的状态；较晚事件的变化让较早事件成立时报时间顺序冲突。
- 只认由事件写入的取值，不认会自然涨落的数值。没有预设事件会写出门槛所要求的值时，检查器只提示，因为动态事件也可能写出。

## 角色位置

角色位置记录某个角色在这个事件中的个人视角、知情、记忆与台词，位于 `历史/事件/{事件ID}/角色/{角色组ID}.txt`，模型可见。它不复制事件正文与变化表；状态变化只写在变化表里。

| 字段 | 必填 | 写法 | 层 |
|---|---|---|---|
| 事件ID | 是 | 等于目录名 | 三 |
| 角色组ID | 是 | 等于文件名 | 三 |
| 角色概要 | 是 | 一句话 | 四 |
| 角色定位 | 是 | 短语列表 | 四 |
| 适用分支 | 否 | 分支ID列表；省略表示适用于全部分支。注入前剥离 | 三 |
| 介入条件 | 否 | 条件文本 | 四 |
| 角色知情 | 否 | 文本列表 | 四 |
| 主观记忆 | 否 | 文本列表 | 四 |
| 按分支 | 否 | 见下 | 三、四 |
| 事件触发语料 | 否 | 列表，见下 | 四 |

- 每个角色在一个事件中只有一份角色位置。
- 角色知情、主观记忆必须与所适用的分支一致，不把成功的记忆写进失败分支。角色知道、猜测、希望或记得某事，不等于世界事实已经成立。

### 按分支

各分支的知情与记忆不同时，共用的部分写在外层，分支专属的写在“按分支”下；加载时把外层与本局所走分支的内容合并：

```yaml
主观记忆:
  - 记得大雾压到灯塔窗口时，灯芯突然暗了下去。
按分支:
  重燃灯塔:
    主观记忆:
      - 记得秦守按住风门，自己把火引回灯芯。
  独自守灯:
    主观记忆:
      - 记得自己一个人摸黑下楼取油，在楼梯上摔了一跤。
```

“按分支”的键是分支ID，须在适用分支之内；值只能含角色知情、主观记忆。分支ID在注入前剥离。

### 事件触发语料

子字段都属第四层。

| 子字段 | 必填 | 写法 |
|---|---|---|
| 触发情境 | 是 | 条件文本 |
| 候选台词 | 是 | 文本列表 |
| 表达目的 | 否 | 文本 |
| 情绪或语气 | 否 | 文本 |
| 触发限制 | 否 | 条件文本列表 |

- 候选台词只收本角色自己说的话。别人对他说的话写进他的知情或主观记忆。
- 原著中该角色在本事件或同类情境下的原台词逐字收录，排在作者撰写的台词之前；原著已有适用台词时，不另写同义台词。
- 只有原著没有适用台词时（本局新增分支、原著未覆盖的情境、扩展角色）才由作者撰写，且须符合当期档案的表达规律。
- 原台词的出处写进 `作者资料/出处/` 的结构化记录（spec/11），正文不标注。检查器在世界书旁找到 `作者资料/出处/` 时，有台词记录的候选台词视为原台词。
- 台词不能单独确认事实；台词涉及的事实须已在事件正文或已确认的结果中。

### 加载与检查

- 事件已确认、角色在场时，按本局所走分支加载适用的角色位置（外层与该分支内容合并），计入经历预算；超预算时整条退为摘要。
- 候选事件带上在场角色的角色定位与事件触发语料，只取适用于门槛成立的分支（或不限分支）的语料，计入候选预算。角色知情、主观记忆在事件确认前不加载，以免模型把未发生的事当作已发生。
- 检查器校验：文件名与角色组ID、目录名与事件ID一致；适用分支与按分支中的分支ID存在，且按分支的键在适用分支之内。
- 原台词的说话人须与角色位置所属角色一致。这依赖作品的章节资料格式，由作者工具的台词统计检查（第二个里程碑）。
