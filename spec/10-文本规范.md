# 文本规范

> 状态：2026-10-20 已确认。本文取代 tavern-cards 的 `rules.md`、`rules-check.md` 中适用于世界书正文的部分；tavern-cards 改为引用本文。

本文规定第四层通用文本规范、第五层的声明方式，以及发给模型的协议文本如何生成。适用对象是所有模型可见的文本字段（见 spec/00 的“按字段分层”）。

## 协议文本由模板生成

发给模型的协议文本中，由第一层机制推出、对所有卡都相同的部分，不作为源文件维护，打包时由世界树模板生成：

| 生成的文本 | 内容 |
|---|---|
| 变量更新规则 | 事件确认、动态事件、首次登场初始化、写入方式、待定项、只读字段（spec/09） |
| 角色通用约束 | 知识边界、能力边界、事件与关系、表达、表现一致性 |
| 扮演准则的架构部分 | 登场规则（启用不等于登场，只有已启用角色会登场，出身里提到的人物只作背景）；静态介绍是常态、当前状况以剧情为准；只描写当前视角能感知的内容 |

- 模板中的二层取值（等级、取值表等）由声明自动填入。
- 扮演准则的源文件只写第五层内容：叙述人称、对白比例、文风偏好、本卡的写入约束。

### 模板与占位符（第一层）

模板是世界树仓库 `templates/` 下的三份文本：`变量更新规则.txt`、`角色通用约束.txt`、`扮演准则.txt`。占位符写作 `{{名字}}`，只有下表几种；模板中出现其它占位符时报错。

| 占位符 | 生成 |
|---|---|
| `{{纪年格式}}` | 纪年的写法与每月天数，例如“潮历YYY年或潮历YYY年MM月DD日（年份 3 位，每年 4 个月，各月 91、91、91、92 天）”；各月天数相同时写“每月 N 天” |
| `{{单次增减上限}}` | 二层声明的单次增减上限 |
| `{{可写字段}}` | 动态事件可写的字段，一行一条，见下 |
| `{{地点列表}}` | 地点库的全部地点ID，按上下级缩进（每级两个空格，同级按ID码点顺序），每行“地点ID（类型）”；没有地点库时为“无” |
| `{{本卡扮演准则}}` | `扮演准则/` 下各文件的原文，按文件名码点顺序，以空行分隔；没有时为“无” |

`{{可写字段}}` 按以下顺序列出：剧情标记（声明顺序）、二层世界字段、二层角色字段、能力维度、装备。每行写“路径：操作；取值”：

- 路径中的映射键：引用写成 `<库名ID>` 或 `<角色组ID>`，其它写成 `<键>`；等级映射的键写成 `<键>`。角色路径写成 `角色.<角色组ID>.字段`；子字段逐个展开成单独的行。
- 操作按字段类型：取值、文本、引用、单值等级为“设定”；集合为“新增、移除”；映射的值为“设定、新增、移除”；数值为“增加、减少”；等级为“提升、设定、移除”；装备为“新增、设定、移除”。
- 取值：取值表写成“甲 / 乙 / 丙”；数值写成“下限 至 上限 的整数”；文本写“文本”；引用写 `<库名ID>`；等级写该维度所用的等级；等级映射另列可用的键。集合写成员的取值；成员取自条目库时写 `<库名ID>`，有成员条件时后接“（字段为 值）”。
- 不列在场、所在（由写场景负责），不列能力移除记录、已初始化。

例如雾港的几行：

```
世界.剧情标记.灯塔状态：设定；运转 / 熄灭 / 重燃
角色.<角色组ID>.好感度.<角色组ID>：增加、减少；-100 至 100 的整数
角色.<角色组ID>.技艺.<键>：提升、设定、移除；学徒 / 熟手 / 匠人 / 名匠；键为 灯语 / 航海 / 修船 / 雾中视
角色.<角色组ID>.装备.<装备ID>：新增、设定、移除；值为 {状态: 完好 / 破损 / 报废, 位置: 文本}
```

## 第四层：模型可见文本

扫描范围是模型可见文件中剥离机器字段与作者字段之后的值，以及由作者撰写的键：情境列表的键（情境）、文本容器与条目说明中的键。字段表规定的字段名不扫描。

### 禁用词

- 运行实现术语与作者维护用语：stat_data、变量、schema、索引、路由、ID、状态0/1/2、候选事件、额外模型、冲突队列、条目、注册、挂载、加载、目录、记录规则、目录规则、统一格式、登记规则、引用边界、记录边界、维护。违反时报错。
- 同名说明文件另外不用系统视角措辞：模块、读取、登记、记录、资料、写入、本文件、运行状态、定义、依据、入口。违反时报错。具体条目中的同类词可能是世界内用语（如“公会登记”），不在此列。
- 第五层声明的禁用词（例如来源用语）同样报错。

### 来源与版本

- 用世界内的直接叙述介绍事物，不以外部作品、作者判断或未启用的版本说明静态事实。本卡具体禁用哪些来源用语（例如“原作中”），由第五层声明。
- 版本差异只在角色组、档案与事件门槛中体现，其它正文不描述未启用的版本或版本对照。

### 条目正文

- 说明文件与具体条目只介绍对象本身：身份、作用、稳定特征、自然边界和必要的动态范围。
- 会随时间、经历、地点或关系变化的内容，写成“会随……变化”这类世界内表达，不写当前状况。
- 边界只写在它适用的最高一层；下层不重复上层或协议文本（角色通用约束、扮演准则）已有的边界。条目的边界只写本领域特有、模型容易犯错的部分，例如“灯号须双方约定同一套”“船级不等于船长的技艺”。
- 边界类字段建议各库统一叫“边界”（字段名属二层声明）。
- 不在正文里断言本局状态（spec/00）。

### ID 与长度

- 模型可见的 ID 是世界内有意义的短语，不用编码样式；超过 12 个字时提示。
- 长度预算按正文字数（去空白）提示，不判失败：同名说明 300，基本信息 500，角色印象 600，事件 800。第五层只能收紧。

## 第四层：写作质量

### 格式

- 全文简体中文，不用繁体字或日文汉字。
- 不用“某城市”“某组织”这类占位说法；关键名称写明。不确定时问作者，不编造。
- 用列表和键值，不写成段落散文。
- 每条独立可读：不写“详见某条”“与某条配套”这类引用；需要的关键句写进本条。
- 同一信息只在职责最贴切的一处写，换种说法复述也算重复。

### 压缩

每句话过四问：删了这句模型会出错吗；是信息还是装饰；能改成列表吗；不看原文能读懂吗。只写会让模型出错的差异信息，不写模型已知的常识和主观评价。

### 具体性

用行为与画面代替标签。

| 不写 | 写 |
|---|---|
| 性格温柔善良 | 遇到受伤的小动物会带回家照顾 |
| 他们关系很好 | 有记忆起就在一起 |
| 她很独立 | 搬进新宿舍那晚，她没让任何人帮忙搬箱子 |

一句一意：写完一个判断就停，不补述同一件事。

### 禁用的写法

| 类型 | 例子 | 改法 |
|---|---|---|
| 主观评价、堆砌形容词 | 非常善良；精美绝伦的门 | 删，或保留必要特征（雕花木门） |
| 模糊词 | 似乎、几乎、仿佛、如同、宛如 | 纯虚指删除；不确定的认知改为行为呈现 |
| 陈旧比喻 | 心湖泛起涟漪、像小兽、投石入湖 | 删比喻，直陈事实 |
| 八股微表情与语气描写 | 嘴角微微上扬、眼中闪过一丝、带着……的口吻 | 删，或改为简洁动作；让对白本身承担语气 |
| 极端情绪词 | 陷入极大的恐惧、万念俱灰 | 改为具体行为或状态 |
| 否定转折 | 她不是冷漠，只是不善表达 | 直接写表现：她话少，常被当成冷淡 |
| 空洞数字 | 目光停留 1.5 秒 | 删 |
| 假性主体 | 一个念头在她心里成形；一股烦躁涌了上来 | 命名实际行为者，或改为行为 |
| 远距离叙事 | 她感到一阵悲伤；她并不知道这个决定将改变一切 | 改为行为或对白；删去预告 |
| 翻译腔 | 她是拘谨的；对这件事，她始终是回避的 | 她表现得拘谨；她一直回避这件事 |
| 元叙事 | 写作要点、戏剧用途、本卡独家 | 删 |

- 破折号（——，含 U+2014、U+2015）一律不用：删去后半段仍成句就删；否则改为逗号、冒号或省略号。原著原台词中的破折号按原文保留，只提示；哪些候选台词是原台词，以 `作者资料/出处/` 中的台词记录为准（spec/06“事件触发语料”）。
- 正常使用“笑了”“皱眉”“攥拳”等常见动作词不算违规，不要矫正过度。

检查器对禁用词与破折号报错；对“禁用的写法”中可以按词识别的部分提示；其余由作者与审阅判断。

## 第五层：本卡文本规范

第五层只能在第四层之上收紧或补充，不能放宽。分两处写：

- 能机器检查的部分写在 `设定/文本规范.yaml`。
- 不能机器检查的文风要求写进扮演准则正文。

```yaml
禁用词: [原作中, 设定上]
ID命名:
  全部: {只用中文: true}
  技能ID: {前缀字段: 门类}          # 技能ID写作“{门类}·名称”
档案追加字段:                       # 只能追加可选字段，写法同 spec/08
  基本信息:
    惯用手: {形态: 文本}
长度预算:
  基本信息: 400
```

下表的键都属第五层。

| 键 | 内容 |
|---|---|
| 禁用词 | 追加的禁用词，报错 |
| ID命名 | 按命名空间（或“全部”）的命名规则：只用中文（不含拉丁字母）、前缀字段（ID 以该字段的值加“·”开头）；违反时报错 |
| 档案追加字段 | 基本信息、角色印象中追加的可选字段，写法同 spec/08 |
| 长度预算 | 收紧的长度预算 |
