# 本局变量

> 状态：2026-10-20 已确认。

本局变量是一局游戏的全部存储状态，由封卷、已确认事件与叙事模型（只限场景状态）写入，随 MVU 楼层快照回档。当前档案、有效能力、事件有效状态、事件串状态都由路由每轮计算，不写回变量。

本局变量分两部分：一层骨架由本规范规定，所有卡相同；二层字段由每张卡在 `设定/本局变量.yaml` 声明。

## 一层骨架

```yaml
世界:
  当前时间: 按纪年书写
  当前地点: {地标: 地点ID, 场景: 文本}
  剧情标记: {标记ID: 取值}        # 封卷时写入开局值
开局:                            # 封卷写入，之后只读
  开局时间: 按纪年书写
  已封卷: 布尔
  历史选择: {事件ID: 分支ID 或 未发生}   # 开局选项，见 spec/12
  方案: 方案ID                  # 可选
  角色组: {角色组ID: {启用: 布尔, 版本ID: 版本ID}}
  玩家:
    模式: 扮演 / 自建
    扮演角色组: 角色组ID          # 扮演模式必填，须已启用
    档案: 基本信息字段的子集      # 自建模式，见 spec/05
角色:
  角色组ID:                      # 首次登场或首次被事件写入时创建；自建玩家用保留ID“玩家”
    在场: 布尔
    所在: 地点ID                  # 卡声明了地点库时才有；见“场景状态”
    能力各维度: 见 spec/03
    装备: {装备ID: {状态: 词表.装备状态, 位置: 文本}}
    能力移除记录: 由协议维护，不能由变化表写入，不注入模型
    已初始化: 由协议维护，见 spec/04
事件:
  事件ID:
    状态: 0 未选 / 1 确认 / 2 排除
    分支: 分支ID
    实际时间: 按纪年书写
    实际参与者: 角色组ID列表
    摘要: 文本                    # 动态事件必填
    结束事件串: 事件串ID          # 可选，动态事件声明某串到此结束
待定项:
  - {字段路径, 候选值, 事件ID, 说明}
```

- 角色变量在首次登场或首次被事件写入时创建，不为全部已启用角色预建。
- 叙事模型不确定某字段该取何值时不覆盖原值，写入一条待定项；剧情明确后写入结果并移除待定项。
- 场景状态以外的持久字段只由事件写入，都能在事件记录中找到写入它的事件；运行变量本身不逐字段记录来源。

## 场景状态

当前时间、当前地点、在场、所在统称场景状态。角色在剧情中走动、时间推进时，叙事模型直接写场景状态，不必登记事件：

- 角色的首次实际登场必须登记事件（以便首次登场初始化与出场记录），之后的离场与返场可以直接写在场。
- 在场的角色，所在视为当前地点的地标；离场时写下所在，之后按存储值读取。
- 所在从未写过时取 `角色组.yaml` 的初始所在；也没有初始所在时为未知。
- 事件也可以在变化表里写所在，例如“罗亚赴任”写入所在为罗亚。封卷时只有事件写入，开局前的所在由已确认事件推出。

## 二层声明：`设定/本局变量.yaml`

下表的键都属第二层。

| 键 | 内容 |
|---|---|
| 词表 | 命名的取值表；第一个值是默认值。其它声明以 `词表.{名字}` 引用 |
| 角色 | 角色下的二层字段 |
| 世界 | 可选；世界下的二层字段，例如天气、季节 |
| 单次增减上限 | 可选，正整数，缺省 100；数值字段单次增加或减少的上限（spec/06） |

字段按 spec/08 的写法声明，本局变量可以另用“数值”“集合”两种写法。字段名不得与一层骨架重名，角色字段也不得与能力维度重名。`词表.装备状态` 必须声明，因为一层骨架的装备状态引用它。

```yaml
词表:
  关系阶段: [陌生, 相识, 试探, 友好, 信任, 亲密, 恋人, 配偶, 疏远, 敌对, 决裂]
  健康: [未初始化, 正常, 轻伤, 重伤, 濒危, 死亡]
  魔力: [未初始化, 充足, 一般, 不足, 枯竭, 不可用]
  装备状态: [完好, 破损, 报废]
角色:
  关系: {映射: {键: {引用: 角色组}, 值: {取值: 词表.关系阶段}}}
  好感度: {映射: {键: {引用: 角色组}, 值: {数值: [-100, 100]}}}
  亲密度: {映射: {键: {引用: 角色组}, 值: {数值: [0, 100]}}}
  职位: {映射: {键: {引用: 势力}, 值: {形态: 文本}}}
  身份: {集合: {形态: 文本}}
  身体状态: {子字段: {健康: {取值: 词表.健康}, 魔力: {取值: 词表.魔力}}}
  身体形态: {形态: 文本}
  知识: {集合: {形态: 文本}}
  道具: {映射: {键: {引用: 道具}, 值: {数值: [0, 9999]}}}
  资产: {映射: {键: {形态: 文本}, 值: {子字段: {标签: {集合: {形态: 文本}}, 属性: {形态: 文本}, 状态: {形态: 文本}}}}}
```

## 身份、职位与知识

- **职位**只放与势力挂钩的职位。**身份**放与势力无关的社会身份，例如“洛琪希的学生”“冒险者”“流亡者”。身份转变由事件写入，不单独成事件（spec/06）。
- **知识**每轮都发给模型、不受经历预算限制，只收会影响以后行为的长期事实，例如“洛琪希是魔族”“菲兹就是希露菲”。其余内容放到：

| 内容 | 放到 |
|---|---|
| 身份、职位 | 身份 / 职位 |
| 剧情条件 | 剧情标记 |
| 经历与记忆 | 角色位置的主观记忆 |
| 只与这一次事件有关的细节 | 角色位置的角色知情 |

- 已写进知识的事实，角色位置的角色知情不再重复。

## 变量更新规则

发给模型的变量更新规则不作为源文件维护，打包时生成：

- 世界树提供一层协议的模板：事件确认、动态事件、首次登场初始化、写入方式、待定项、只读字段。
- 二层的等级、取值表等由声明自动填入模板。
- 本卡另加的写入约束属于第五层，写进扮演准则，例如“只有双方明确表白后才写恋人”。
