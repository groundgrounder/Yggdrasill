# 角色组

> 状态：2026-10-20 已确认；2026-10-23 按术语收词的决定修订用语，并定非默认档案的生效条件须含正向的事件确认。

角色组是本局变量、事件参与者与关系引用的唯一主体。每个角色组在 `角色/{角色组ID}/` 下有一个 `角色组.yaml`，是工具数据：其中角色组与版本的显示名、别名进入上下文，版本的简介展示给玩家，其余字段只给工具读（spec/01）。角色组ID取自目录名，文件内不重复写。

## 字段

| 字段 | 必填 | 写法 | 层 |
|---|---|---|---|
| 显示名 | 否 | 文本；省略时等于角色组ID | 四 |
| 别名 | 否 | 文本列表；所有版本共用的称呼 | 三 |
| 角色包 | 是 | 取值来自 `设定/角色分类.yaml` | 三 |
| 分类 | 是 | 取值来自 `设定/角色分类.yaml` | 三 |
| 默认启用 | 是 | 布尔 | 三 |
| 默认版本 | 多版本时必填 | 版本ID | 三 |
| 初始化方式 | 否 | 显式确认 / 出场自动；缺省为显式确认 | 三 |
| 初始所在 | 否 | 地点ID；本局从未写过“所在”时取此值，见 spec/09 | 三 |
| 版本 | 多版本时必填 | 列表，见下 | 三 |
| 档案 | 是 | 列表，见下 | 三 |

键按上表顺序书写。可选字段没有内容时整键省略。

别名用于识别本轮被提及的角色。别名在本组内（含版本级别名）不得重复；不同角色组之间出现相同别名时，检查器提示，不判失败。

### 版本

| 字段 | 必填 | 写法 | 层 |
|---|---|---|---|
| 版本ID | 是 | 文本 | 三 |
| 显示名 | 否 | 文本 | 四 |
| 别名 | 否 | 文本列表；只在本局选了这个版本时算数 | 三 |
| 简介 | 否 | 文本；开局选择版本时给玩家看 | 四 |

单版本的角色组可以不写“版本”，此时视为只有一个版本，版本ID等于角色组ID，“默认版本”和各档案的“适用版本”都省略。写了“版本”（哪怕只有一项）时，“默认版本”和每份档案的“适用版本”都必须写。

### 档案

| 字段 | 必填 | 写法 | 层 |
|---|---|---|---|
| 档案ID | 是 | 等于 `档案/` 下的目录名 | 三 |
| 适用版本 | 多版本时必填 | 非空的版本ID列表；只适用一个版本时写一项 | 三 |
| 默认 | 否 | 布尔 | 三 |
| 前置档案 | 否 | 档案ID | 三 |
| 生效条件 | 非默认档案必填 | 条件 | 三 |
| 初始能力 | 否 | 以维度名为键，写法同变化表的“提升”与“新增”，见 spec/03 | 三 |
| 初始装备 | 否 | 列表，每项为装备ID、状态、位置 | 三 |

键按上表顺序书写。档案列表必须与 `档案/` 下的子目录一一对应。

初始能力以维度名为键：等级映射写 `{键: 等级}`，单值等级写一个等级，集合写成员列表；写入方式见“首次登场初始化”。

```yaml
  - 档案ID: 林澜·守塔期
    适用版本: [林澜]
    前置档案: 林澜·学徒期
    生效条件:
      事件确认: {事件ID: 出师考核, 分支ID: 通过}
    初始能力:
      技艺: {灯语: 匠人, 修船: 熟手}
      习惯: [交班前逐项复述灯具状况]
    初始装备:
      - {装备ID: 灯具·风暴灯, 状态: 完好, 位置: 随身}
```

一个组的“版本 × 档案”解析表集中在本文件，便于核对互斥。

## 档案解析（第一层）

由协议在读取时计算，不存入变量（spec/15）：

1. 取本局该角色组所选的版本，只考虑适用版本包含该版本的档案。
2. 默认档案恒成立；其余档案在生效条件为真时成立。
3. 成立的档案若是另一成立档案前置链上的祖先，则被取代。
4. 剩一份为当前档案；剩多份是档案冲突，一份也没有是解析异常，两种情况下档案都不进入上下文。

## 首次登场初始化（第一层）

开局时间晚于部分事件时，角色组在本局首次实际出场之前已有的能力与装备，由当前档案的初始能力、初始装备一次写入：

- 通过首次登场初始化事件 `初次登场·{角色组ID}` 写入，只写一次，空起点也封存为已初始化；切换时期不再初始化。
- 只填本局尚未记载的部分：等级维度只填还没有值的键；集合维度在本局还没有这个字段时才写入，已有集合（含空集合）优先；装备只在本局未持有时加入。能力移除记录中的字段不补回。
- 初始化方式为“出场自动”的角色组，在确认其实际出场的事件时，于同一次提交中完成初始化；“显式确认”的角色组由上下文输出待初始化，叙事模型确认初始化事件。启用、提及、候选和只读组装都不触发。

## 规则

- 每个版本至少有一份适用的档案，至多一个默认档案。默认档案不写生效条件，非默认档案必须写。
- 前置链不成环；前置档案与当前档案的适用版本必须有交集。前置只表示同一版本内的先后，不表示优先级。
- 非默认档案的生效条件必须含正向引用（spec/06）的“事件确认”，不能只写时间等其它条件：档案的改变是身份的改变，身份由事件确立。代表授职、受雇、取得身份或成婚的档案，只引用实际达成结果的分支；拒绝或暂缓的分支不能冒充身份取得。
- 生效条件不引用该档案自身将赋予的等级、技能或状态。
- 初始能力的维度、键与取值按能力声明校验；初始装备的装备ID须在装备库中，状态取二层声明的装备状态。
- 任意开局时间与事件组合下，每个版本至多一份当前档案。检查器按抽样时间与事件状态组合检查（spec/15）。
- 玩家是保留的角色组ID，任何角色组不得使用。
