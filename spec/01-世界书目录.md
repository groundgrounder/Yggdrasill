# 世界书目录

> 状态：2026-10-20 已确认。

## 根目录

世界书根下只有三类目录：

| 类 | 目录 | 层 | 要求 |
|---|---|---|---|
| 固定根 | 角色、历史、设定 | 一 | 必须存在；本局变量的结构见 spec/09 |
| 条目库 | 例如技能、装备、地点、道具、势力、生物、货币 | 二 | 由本卡背景设定声明；未声明的目录不应出现 |
| 文本容器 | 扮演准则、世界概况 | 四、五 | 只放给模型读的正文 |

全部条目库平铺在根下，不再用“战斗”“经济”“地理”这类分组目录。

## 条目库

条目库是同一种公共条目的集合。

### 一层规定的通用机制

- 每个库是一个 ID 命名空间，库内 ID 唯一。
- 实例文件名等于其 ID。
- 分类即子目录（见下节）。
- 别处对条目的引用按命名空间解析。

### 一层规定名称与必需字段的库

以下三个库由运行协议读取，名称和下列字段固定。卡用不到时可以不声明。

| 库 | 运行协议读取的字段 | 用途 |
|---|---|---|
| 技能 | 技能ID，以及能力声明中“技能可用”规则引用的字段（见 spec/03）；展开时输出条目正文 | 计算可用技能、展开技能正文、校验技能补充与固有技能 |
| 装备 | 装备ID | 本局装备的键；档案初始装备与事件取得装备的引用 |
| 地点 | 地点ID、上级（由目录推出）；地点链输出条目正文 | 当前场景条件，上下文的地点链与地点相关性 |

技能库与能力维度的对应见 spec/03。

### 二层声明的内容

- 本卡有哪些条目库。
- 每个库的分类层级与字段。
- 本局变量字段引用哪个库，例如“道具的键是道具ID”“职位的键是势力ID”。检查器据此校验引用。

## 条目库的子目录

分目录方式有两种：

- **按种类**：目录名等于二层声明的种类名，分几级由二层声明。例如技能先按类别、再按体系。
- **按上下级**：目录即实例，深度不限。二层可以声明实例类型和允许的上下级搭配；不声明时只要求上级存在。

地点库固定按上下级。其它库用哪种分法由二层声明，例如势力可以按上下级，让政治派系挂在政治实体下。

哪些文件是实例：
- 按种类：文件名等于所在目录名的 `.txt` 是说明文件；其余 `.txt` 是实例，所在目录的层级与名称必须对应“分级”。
- 按上下级：库根下的 `{库名}.txt` 是库的说明文件；其余 `.txt` 都是实例。文件名等于所在目录名时，它是该目录这个实例的条目，上级是再上一级目录的实例；否则上级是所在目录的实例。库根下的实例没有上级。

## 文本容器

- **扮演准则**：五层，本卡的叙述人称、文风与写入约束。由架构推出的扮演规则不写在这里，由模板生成（spec/10）。
- **世界概况**：跨条目库、整个可游玩时期都成立的世界内容，例如战力格局、经济格局、纪年与远古历史。文件按主题划分，写法在文本规范议题中规定。

文本容器的名称固定，工具据名称识别。

## 扩展名

| 扩展名 | 读者 |
|---|---|
| `.txt` | 模型会读到（可能先剥离机器字段） |
| `.yaml` | 只给工具读 |

两种文件的内容都按 YAML 书写。扩展名只表示读者，不表示语法。

## 索引

“索引”只指可以从目录推导的清单，不作为源文件维护：工具直接读目录，打包时按需生成。

现有四个特殊“索引”按实际内容改名或撤掉：

| 现有 | 改为 | 理由 |
|---|---|---|
| `角色/{角色组ID}/{角色组ID}索引.txt` | `角色/{角色组ID}/角色组.yaml` | 内容是角色组的定义：版本、档案、生效条件。格式见 spec/04 |
| `历史/剧情线索引.txt` | 撤掉，由 `历史/事件串/{事件串ID}.yaml` 取代 | 剧情线改为事件串，见 spec/07 |
| `历史/事件/事件索引.txt` | 撤掉 | 事件ID和路径都能从目录推出 |
| `角色/角色索引.txt` | 撤掉；角色包、分类并入各自的 `角色组.yaml` | 入口能从目录推出 |

## 包裹标签

源文件不写包裹标签，由组装或打包阶段按文件种类统一添加：外层用类型名，内层每项写自身名称或 ID（spec/14）。检查器拒绝源文件中单独成行的包裹标签。

## 说明文件

- 条目库的根目录和分类目录可以有一个同名说明文件 `{目录名}.txt`，写这一库或这一类特有的世界内容。它是四、五层约束的文本。
- 写得出本层特有的内容才写，写不出就不写，不留空壳。一个分类层写不出任何特有内容时，应考虑并入上级。
- 说明文件不复述二层声明的种类与取值清单（例如装备种类、等级档）；模型需要看到的清单由组装或打包阶段从声明生成（spec/02）。
- 按上下级分的库，目录的同名文件就是该实例自身的条目，兼作说明。
- 跨库的格局写进世界概况，不写进某个库的说明。
- 固定根不放说明文件。

## 书写风格

源文件不进模型，YAML 的书写风格（列表块状或行内、缩进、引号）不属于任何一层。键顺序按各文件规范的字段表。`ygg 格式化` 统一书写风格与键顺序；检查器只报内容问题，不为书写风格报错。

## 命名

- ID 的字符（第一层，所有 ID）：不含 `.`、`/`、`\`；首尾不留空白；不为空；不用保留字（`玩家`、`__proto__`、`constructor`、`prototype`）。违反时报错。
- ID 的可读性（第四层）：ID 是世界内有意义的短语，不用“E042”“skill_water_01”这类编码；ID 宜短，因为模型写变量时要原样写回。检查器对编码样式和过长的 ID 只提示，阈值见 spec/10。
- 本卡命名规则（第五层）：例如“ID 只用中文”“技能ID写作体系·名称”。在 `设定/文本规范.yaml` 声明，检查器按声明报错。
- 实例文件名等于其 ID，即 `{ID}.txt`。目录型实例（角色组、档案、事件、按上下级分的条目）的目录名等于其 ID。
- 只给工具读的文件不重复写自身 ID，由目录名或文件名给出。模型可见的文件保留 ID 字段，因为模型写变量时要用到；检查器校验它与文件名或目录名一致。
- 以 `.` 开头的文件和目录不读取。
