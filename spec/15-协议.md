# 协议

> 状态：2026-10-22 已确认。本文规定第一层的运行协议：读取本局（事件有效状态、事件串状态、档案、能力）与写入本局（确认、动态事件、初始化、场景、封卷），以及检查器如何用协议抽样。路由组装见 spec/14。

协议只读本局变量与世界书，不调用模型。写入不修改传入的本局变量：成功时返回新的本局变量，失败时报错，什么也不写。

## 有效本局

把本局变量中的待登记事件（见“待登记”）按求解顺序写到一份草稿上，得到**有效本局**。封卷前没有待登记事件，有效本局就是本局变量。

- 读取（事件有效状态、事件串状态、档案、能力、条件）都按有效本局计算；待登记事件本身仍报告为待登记。
- 每次写入都先把待登记事件按顺序登记，再执行本次写入，两者在同一次提交中。
- 因此待登记事件在其它条件中视为已确认，它写入的状态后面的读取都看得到。

## 条件求值

封卷前一律为未知。组合词按 spec/06 的三值逻辑；叶子在 none 之内时按取反后的极性求值，未知取反仍为未知。封卷后：

| 条件类型 | 求值 |
|---|---|
| 角色启用 | 开局选择中启用了该角色组 |
| 角色版本 | 启用且版本一致 |
| 事件确认 | 有效本局有该事件状态为 1 的记录；指定分支时分支一致 |
| 事件串状态 | 见“事件串状态” |
| 当前时间 | 当前时间缺失为未知。小于：当前时间的终点不晚于值的起点；大于等于：当前时间的起点不早于值的起点 |
| 剧情标记 | 本局值满足比较；标记缺失为未知 |
| 角色状态 | 角色组未启用为不成立；否则按“字段的读取”取值，判断是否在“属于”中 |
| 同处 | 任一角色组未启用为不成立；任一所在未知为未知；否则所在全部相同为成立 |
| 角色已出场 | 视为在场、已初始化，或任一状态为 1 的记录的实际参与者含该角色组，为成立；否则不成立 |
| 当前场景 | 当前地点缺失为未知；地标与场景都相同为成立 |
| 在场实力人数 | 见下 |

- **视为在场**：本局在场为真的角色组；当前地点已写入时，扮演模式的扮演角色组与自建模式的“玩家”也视为在场。
- **所在的读取**：视为在场且当前地点已写入的，取当前地点的地标；否则取本局存储的所在；没有存储时取初始所在；都没有为未知。
- **字段的读取**（角色状态）：字段为所在时按“所在的读取”，属于所列地点或其下级地点即成立；其它字段取本局值，从未写过时取二层取值表的第一个值。
- **在场实力人数**：当前地点缺失为未知。否则对视为在场者（已启用的角色组；自建模式的“玩家”），除去排除角色组，读综合实力维度。不低于最低实力的人数达到最少人数为成立；否则有人综合实力缺失为未知；否则不成立。

## 分支的选择

封卷与待登记按同一规则为事件选出一个分支：

1. 指定了分支时（封卷的历史选择），只考虑该分支。
2. 否则默认分支的门槛成立就选默认分支；否则按书写顺序取第一个门槛成立的分支。
3. 门槛未知视为不成立。都不成立则选不出分支。

候选事件不选分支，附带门槛成立的全部分支，由叙事模型从中选择。

## 事件有效状态

每次读取时计算，不写回变量。按顺序取第一个符合的：

| 状态 | 条件 |
|---|---|
| 已确认 | 本局变量有该事件状态为 1 的记录 |
| 已排除 | 本局变量有该事件状态为 2 的记录 |
| 待登记 | 在待登记列表中 |
| 未到 | 未封卷，或当前时间缺失 |
| 已排除 | 任一核心参与者未启用 |
| 未到 | 当前时间的终点不晚于触发时间最早的起点 |
| 已排除 | 当前时间的起点不早于触发时间最晚的终点 |
| 候选 | 事件门槛成立，且至少一个分支门槛成立 |
| 不适用 | 其余情况 |

候选与不适用的门槛按有效本局求值，时间语境为当前时间。

## 历史求解

封卷与待登记用同一个求解过程补出一组事件：

1. 参加求解的事件按触发时间最晚的起点排序，同时刻按事件ID的码点顺序。
2. 每一轮按此顺序找第一个满足以下条件的事件：尚未写入；核心参与者都已启用；以触发时间最晚为当前时间，事件门槛成立且选得出分支。
3. 找到后写入记录：状态 1、所选分支、实际时间为触发时间最晚、实际参与者为核心参与者；按分支变化写入状态。然后回到第 2 步，从头找。
4. 找不到时结束。
5. **倒流**：找到的事件，触发时间最晚的起点早于上一个写入事件的实际时间起点，说明较晚事件的变化让较早事件成立。封卷时报时间顺序冲突；待登记时该事件不写入（窗口已过，状态为已排除），求解继续。

求解中“事件确认”只认已写入的记录；其余条件读草稿上的当前状态。

## 待登记

- 参加求解的事件：本局变量中没有记录，确认策略为自动确认，当前时间的起点不早于触发时间最晚的终点。
- “上一个写入事件的实际时间”的初值，取本局变量中状态为 1 的记录里最晚的实际时间。
- 求解写出的事件依次成为待登记列表，各带所选分支。
- 分支按读取时的本局状态选出。场景状态经协议写入时，时间推进后先登记待登记事件，再处理走动（见“写场景”）；绕过协议直接改场景状态，可能使分支与窗口结束时的状态不一致。

## 事件串状态

在有效本局上按 spec/07：

- 已结束：有一个结局状态为 1（指定分支时分支一致），或有状态为 1 的记录写了“结束事件串: 本串”。
- 进行中：未结束，且有起点状态为 1。
- 未开始：其余情况。

## 档案解析

按 spec/04“档案解析”，在有效本局上求值。没有“版本”的角色组，版本清单为 `[角色组ID]`，全部档案适用。前置链只沿适用于本版本的档案追溯，遇到不适用的档案即停止。生效条件未知视为不成立。结果为：成立（档案ID）、冲突（成立的档案ID列表）、异常、未启用。

## 当前能力与可用技能

- 当前能力只读有效本局（spec/03）：等级映射输出有值的键，没有键的维度省略；单值等级有值才输出；集合没有值时输出空集合。本局值不在维度所用的等级或成员范围内时报错。
- 可用技能：技能库的每个条目，按它适用的那条技能可用规则判断。等级门槛：键字段所指的键在本局有值，且不低于技能的等级字段；集合持有：技能ID在该集合维度中。按技能库的读取顺序输出。
- 未启用的角色组没有当前能力。自建玩家读 `角色.玩家`。

## 写入变化

每条变化先按 spec/06、spec/03 校验（与检查器同一套校验），再写入：

- 等级维度：提升在本局无值或新值更高时写入，设定直接写入，两者写入时清除该字段的能力移除记录；移除删去值，记入能力移除记录。
- 集合：新增、移除，不产生重复；移除不存在的成员不报错。映射：设定写键；新增在键不存在时才写；移除删去键。
- 数值：增加、减少，本局无值时从 0 起算，结果按二层范围截断。单值：设定。
- 路径中与映射键中的角色组须已启用。“玩家”（作为路径中的角色组、映射键或引用值）只在自建模式可写，扮演模式下报错；预设事件不写“玩家”（spec/06），所以只有动态事件会写到它。角色变量在首次写入时创建。
- 能力移除记录写在 `角色.{角色组ID}.能力移除记录`，是相对字段路径的列表，例如 `技艺.灯语`、`名望`。

## 首次登场初始化

- **填写规则**（spec/04）：等级映射的键、单值等级，在本局无值且不在能力移除记录中时写入；集合在本局没有这个字段（空集合也算有）且不在能力移除记录中时写入；装备在本局未持有时加入。
- **待初始化预览**：角色组已启用、未初始化、当前档案成立时，按填写规则算出将写入的能力与装备；否则没有预览。路由在角色组视为在场时输出待初始化。
- **写入**：记录 `初次登场·{角色组ID}`，状态 1、分支“初始化”、实际时间为当前时间、实际参与者为该角色组；按填写规则写入；已初始化写为真。写入初始化不会再触发初始化。
- **显式确认**：叙事模型调用“确认初始化”。须已封卷，角色组已启用、当前档案成立；已初始化时不写入，返回“未写入”。
- **出场自动**：每次提交前，凡已启用、未初始化、初始化方式为出场自动的角色组，若是本次写入的事件（含随之登记的待登记事件）的实际参与者，或写入后视为在场，就在同一次提交中初始化。当前档案不成立时跳过，由路由在审计中报告。
- 封卷不初始化任何角色组。

## 确认事件

输入：事件ID、分支ID、实际参与者（可选）。

1. 须已封卷；事件须是预设事件，分支须属于该事件。
2. 本局变量已有该事件的记录时不写入，返回“未写入”。
3. 该事件为待登记时，所选分支须与待登记的分支一致，随待登记一并登记，返回“已写入”；分支不一致时报错，待登记事件不能改分支。
4. 否则该事件在有效本局上须为候选，所选分支的门槛须成立。
5. 实际参与者为核心参与者与传入参与者的并集，须都已启用；“玩家”只在自建模式可用。
6. 写入记录：状态 1、分支、实际时间为当前时间、实际参与者；按分支变化写入状态。
7. 出场自动初始化，排斥检查，提交。

## 动态事件

输入：事件ID、摘要、实际参与者（可选）、变化、结束事件串（可选）。

- 事件ID 须是非空文本，不与预设事件重复，不以“初次登场·”开头，不含“.”。本局变量已有该记录时不写入，返回“未写入”。
- 摘要必填。变化可以为空列表；每条按“写入变化”校验与写入。
- 实际参与者须都已启用；“玩家”只在自建模式可用。
- 结束事件串须是存在且在有效本局上进行中的事件串。
- 记录：状态 1、分支“完成”、实际时间为当前时间、实际参与者、摘要、结束事件串（有时）。然后出场自动初始化，排斥检查，提交。

## 写场景

输入：当前时间、当前地点、在场、所在，各项可选，按以下顺序处理：

1. **当前时间**：合法纪年，起点不早于原值的起点。写入后，把因此新到期的待登记事件登记；后面几步读到的是走动之前的状态。
2. **当前地点**：地标须是地点ID，场景为文本。
3. **在场**：键须是已启用的角色组；扮演角色组不能写（“玩家”不是角色组，也不能写）。从未出场的角色组写为真时，初始化方式为显式确认的报错，须先确认初始化；出场自动的在本次提交中初始化。由真变假而本次没有给它写所在时，把写入前的当前地点地标存为它的所在。
4. **所在**：键须是已启用的角色组，值须是地点ID；写入后视为在场的角色组不能写。
5. 出场自动初始化，排斥检查，提交。

在场的角色随当前地点移动；要让某人留在原地，同一次写入把他的在场写为假。

## 待定项

输入：操作（新增 / 移除）、字段路径；新增另需候选值、事件ID、说明。

- 字段路径按 spec/06“变化”的路径写法，须写到一个已声明的字段格；规则同变化（含“玩家”只在自建模式）。在场、所在不能作为待定项。
- 新增：候选值是非空列表；事件ID须是本局状态为 1 的记录；说明为文本。同一字段路径已有待定项时替换它。
- 移除：删去该字段路径的待定项；没有时不报错。
- 待定项不产生事件记录。写入前照常登记待登记事件。

## 命令

叙事模型只通过命令写本局，不直接改变量。每条命令对应一个写入：

| 命令 | 参数 | 写入 |
|---|---|---|
| 确认事件 | 事件ID、分支ID、实际参与者（可选） | 确认事件 |
| 动态事件 | 事件ID、摘要、实际参与者（可选）、变化、结束事件串（可选） | 动态事件 |
| 确认初始化 | 角色组ID | 确认初始化 |
| 写场景 | 当前时间、当前地点、在场、所在（各项可选） | 写场景 |
| 待定项 | 操作、字段路径、候选值、事件ID、说明 | 待定项 |

- 一轮的命令按顺序逐条执行，每条是独立的一次写入：失败的那条不写入，记下失败原因，接着执行后面的。
- 模板（spec/10）中的写法是：回复末尾一个 `<命令>` 标签，内为 YAML 列表，每项是以命令名为键的单键映射。适配层可以换成别的语法，并决定失败如何反馈给作者或模型。

## 封卷

输入：开局时间、方案、角色组、玩家、历史选择，各项可选；没有方案时开局时间必填。

1. **合并**：有方案时以方案为底，直接传入的项覆盖方案；角色组按角色组ID合并，历史选择按事件ID合并。
2. **角色组**：未写的取默认启用与默认版本（单版本的组，版本ID为角色组ID）；版本ID须属于该组。`开局.角色组` 写全部角色组。
3. **玩家**：缺省为自建、档案为空；扮演模式的扮演角色组须已启用。
4. **骨架**：当前时间为开局时间；剧情标记写开局值（声明中的第一个取值）；`开局` 写开局时间、已封卷为真、历史选择、方案（有时）、角色组、玩家；角色、事件为空，待定项为空列表。之后的求值都按封卷后进行。
5. **开局前事件**：触发时间最晚的终点不晚于开局时间的起点，且确认策略不是仅作候选。
6. **历史选择**：每项的事件须是开局前事件，值须是该事件的分支ID或“未发生”。“未发生”的事件写状态 2，不参加求解。
7. **求解**：对其余开局前事件做历史求解；指定了分支的只能走该分支。
8. 指定了分支却没有写入的事件，报历史选择错误，不退回默认分支。其余没有写入的开局前事件写状态 2。
9. 排斥检查；违反时报配置冲突。

- 封卷不写当前地点与在场，不初始化角色组。开局前事件的实际参与者使“角色已出场”成立。
- “历史选择只能用开局选项中声明的事件与选项”由检查器与开局前端把关，协议只按第 6 步校验。

## 排斥检查

none 表示排斥（spec/06）：门槛用 none 排斥了某事件的事件，一旦确认，那个事件就不能再确认，不只是“在它之前”。只想表达先后时，用当前时间或事件串状态。

每次提交前检查：对有效本局中写入前已为状态 1 的预设事件（含待登记事件；封卷时为全部写入的预设事件），以写入后的记录重新求值它的事件门槛与所走分支的门槛，“事件确认”按记录求值，其余条件记为未知。结果为不成立即排斥冲突，本次写入被拒绝。

## 检查器的抽样

静态检查没有错误时才抽样，否则提示未执行抽样。

- **抽样年份**：全部事件触发时间最早、最晚所在的年份，各取该年与下一年；另加最早年份的前一年（不小于 0）。去重后升序；抽样时的开局时间写到年。
- **档案互斥**：对每个角色组的每个版本，收集该版本档案生效条件中引用的事件；在每个抽样年份，枚举这些事件的全部状态组合（无记录、状态 2、各分支的状态 1），在只含这些记录的封卷后本局（默认开局，该组启用并取该版本，开局时间为抽样年份）上直接解析档案，不登记待登记事件。冲突时报错。组合数超过 4096 时提示并跳过该版本。
- **运行抽样**：每个抽样年份封卷：默认开局一次；全部角色组启用、各取第 i 个版本（版本不足的取默认版本）各一次。封卷须成功，每个启用的角色组档案解析不得冲突；解析异常提示。
- **开局方案**：每个方案封卷一次，开局时间取方案的；方案没写时取所选事件中触发时间最晚的年份的下一年，没有所选事件时取最后一个抽样年份。须成功。
- **开局选项**：每个选项的每个分支（含“未发生”），在该事件触发时间最晚的年份的下一年，以默认开局加这一项历史选择封卷。历史选择错误只提示（默认历史下不可选，前端不会给出）；其它失败报错。
