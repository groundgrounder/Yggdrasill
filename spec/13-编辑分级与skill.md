# 编辑分级与 skill

> 状态：2026-10-20 已确认；2026-10-23 按术语收词的决定修订用语。skill 的改写与迁入在第二个里程碑进行。本文取代 tavern-cards 的 `period-profile/edit-levels.md` 与 `build-order.md`。

## 编辑分级

先按字段所属的层判断改动的级别，再决定由哪个 skill 处理、跑什么检查。级别按字段判断，不按文件判断（spec/00）。

| 级 | 层 | 范围 | 检查 |
|---|---|---|---|
| 设定级 | 二 | `设定/` 中第二层的声明：能力维度、等级、事件分类、条目库、本局变量、剧情标记、角色分类 | 全量检查；不再合法的三层内容逐项列出，经作者同意后迁移，不静默丢弃 |
| 结构级 | 三 | 程序读取的字段：事件的时间、门槛、分支、变化，事件串，开局选项与方案，角色组的全部字段（含别名、初始能力、初始所在），档案的生效条件，条目的 ID、取值与引用字段 | 改前溯源（列出指向该对象的全部引用）并逐项同步；结构检查与抽样；涉及事件时重看“如果”视图的影响面 |
| 文本级 | 四、五 | 文本字段：档案正文、事件概要与叙事条件、角色位置、条目说明、世界概况、扮演准则、`设定/文本规范.yaml` | 格式与措辞检查（spec/05、spec/10）；条件文本另核对适用范围不变 |

第一层是本规范本身，角色卡的 skill 不改它；只能通过修订规范改变。

### 文本级的边界

- 不授予本局状态：不把“已成婚”“持有某物”“已任职”“已掌握某招”写进文本，也不换个字段名承载。
- 不借改字改变条件文本的适用范围。
- 不顺带改结构、设定、测试或检查器。
- 发现事实放错位置时，清理越界的断言，保留行为方式；指出缺口，交给结构级的 skill，不在文本修改中自行补事件。

### 通用检查规则

1. 设定级与结构级改动前先跑检查与测试，记下已有的失败。
2. 改动后再跑同样的检查，只对新增失败负责；交付时分开列出“新增失败”和“改动前已有的失败”。
3. 不为让检查通过而改测试或检查器。计数或快照因本次改动合理变化时，向作者报告具体断言，征得同意再改。
4. 事件ID、档案ID等是存档里的引用键。改 ID 前确认没有需要兼容的存档，或建立旧 ID 到新 ID 的迁移表。
5. 没跑的检查不说通过。交付时说明改了什么、在哪一级、跑了哪些检查及结果。

## 建立顺序

从原作或资料建立整套世界书时：

```
定名单 → 预建名单内全部角色组（按首次出场分批审阅）
└── 按篇循环，一篇审阅通过再进入下一篇：
    核对角色组 → 建事件 → 命名事件串 → 接档案 → 审阅
```

- **定名单**：原作中有名有台词的人物原则上都进名单，无名说话人不进；名单由作者确认，记在作者资料中。
- **预建角色组**：只写首次出场那一期的档案，写初始能力、初始所在与别名。后期档案等切期事件建成后再写。
- **核对角色组**：本篇名单内的说话人都应已预建；有遗漏就先停下补建，不在建事件时边建边补。
- **建事件**：逐章抽取。门槛只写因果；能力取得、所在变化直接写进变化表。名单内人物的原台词逐字收入其角色位置，并写出处记录；名单外说话人的台词不收录，只在核定日志记台词数。
- **命名事件串**：为本篇中有开头、有结局的过程建事件串并声明结局。
- **接档案**：本篇的切期事件建好后，写下一期档案或从暂存接回；尚无切期事件的档案放进暂存并登记接回条件。
- **审阅**：台词收录与出处；事件分类；档案与事件不矛盾；门槛是否只写因果；“如果”视图的影响面；事件串的结局可达。

中途增补名单时，新角色组只写当前篇起的档案；此前各篇的台词从核定日志的名单外说话人记录中找回，用“世界树·事件”补入。后面的篇发现前面的事件需要调整时，单独修改，不在建立新事件时顺带改。
