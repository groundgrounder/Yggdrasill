# 背景设定声明

> 状态：2026-10-20 已确认。能力格式见 spec/03，条目库格式见 spec/08，本局变量格式见 spec/09。

每张卡的第二层（背景设定）只在一处声明：世界书根下的固定根 `设定/`。

## 位置与文件

`设定/` 是固定根，只放 `.yaml`，只给工具读。它放第二层的全部声明，以及第五层中能机器检查的声明。按节分文件：

| 文件 | 内容 | 格式 |
|---|---|---|
| `纪年.yaml` | 时间写法 | 本文 |
| `等级.yaml` | 各套等级 | 本文 |
| `能力.yaml` | 能力维度及其取值、技能可用规则 | spec/03 |
| `事件分类.yaml` | 主类型、标签、事件结果 | 本文 |
| `条目库.yaml` | 有哪些条目库，各自的分法、分级与字段 | spec/08 |
| `本局变量.yaml` | 取值表、二层的本局变量字段及值域 | spec/09 |
| `剧情标记.yaml` | 剧情标记及取值 | 本文 |
| `角色分类.yaml` | 角色包与分类 | 本文 |
| `文本规范.yaml` | 第五层：禁用词、ID 命名、档案追加字段、长度预算 | spec/10 |

纪年、事件分类、本局变量三个文件必须有。其余文件在用到时才需要：例如有技能库就要有能力，有剧情标记就要有剧情标记文件。

本局变量中一层的骨架（在场、能力移除记录、已初始化、开局、事件记录等）写在规范里，所有卡相同；卡只声明二层的字段。

## 单一来源

- 二层的每项种类与取值只在 `设定/` 声明一次。
- 模型需要看到的清单（例如关系阶段有哪些值、等级的高低顺序），由组装或打包阶段从声明生成。正文、说明文件和协议文本不再手写复述。
- 创作规划等作者资料不抄写种类与取值，只写设计理由，需要时引用声明。

## 字段声明

条目库和本局变量的字段声明同时标出字段所属的层：

- 写“取值”“引用”的字段属第三层，检查器校验取值与引用。
- 写“形态”的字段是文本，受四、五层约束。

```yaml
装备:
  分法: 按种类
  分级: [标签]
  字段:
    标签: {必填: true, 取值: [剑, 刀, 枪, 斧, 锤, 弓, 弩, 杖, 盾, 魔道具]}
    装备等级: {必填: true, 取值: 等级.七档}
    简介: {必填: true, 形态: 文本}
    效果: {必填: true, 形态: 文本列表}
    边界: {形态: 文本列表}
```

完整写法见 spec/08。

## 条件类型

条件类型全部属于第一层。依赖某个条目库或能力维度的条件，在卡没有声明所依赖项时不可用：

| 条件 | 依赖 |
|---|---|
| 当前场景 | 地点库 |
| 在场实力人数 | 能力中的综合实力维度 |

## 不属于二层的

上下文预算等运行参数不是种类或取值，写在项目的 `yggdrasill.yaml`，见 spec/14。检查器的抽样起始年由事件时间推出，不需要声明。

## 各文件格式

每一项的机制属于第一层，所有卡相同，在对应议题的规范中规定；本节只写第二层的取值。例如“事件有主类型、标签、事件结果，只用于检索，不参与门控”是第一层，“有哪些标签”是第二层。

### 纪年

```yaml
前缀: 甲龙历
年位数: 4
月数: 12
每月天数: 30        # 整数，或长度等于月数的逐月列表
```

四个键都必须写。写法为 `{前缀}{年}年` 或 `{前缀}{年}年{MM}月{DD}日`，年补足到年位数，月日两位。纪年换算等世界内容写进世界概况。

### 等级

```yaml
七档: [初级, 中级, 上级, 圣级, 王级, 帝级, 神级]
```

每个键是一套等级的名字，值从低到高排列。字段以 `等级.{名字}` 引用。

### 事件分类

```yaml
主类型: [世界, 关系, 个人]
标签: [战斗, 政治, 灾难, 成长, 家庭, 教育, 迁移, 知识, 身份, 伤势, 生育, 死亡, 谈判, 救援]
事件结果:            # 每项结果声明支撑它的本局变量字段；空列表表示不检查
  关系变化: [关系, 好感度, 亲密度]
  能力变化: [修习阶段, 实力定位, 固有技能, 施法方式, 装备]
  身份变化: [身份, 职位, 身体形态, 档案切期]
  知识变化: [知识]
  职位变化: [职位]
  身体状态变化: [身体状态, 身体形态]
  资产变化: [资产, 装备, 道具]
  地缘变化: [剧情标记]
  剧情条件变化: [剧情标记]
```

三项的取值都由本卡声明，规范可以附一份默认清单作模板，新卡复制进自己的 `设定/`。每个事件怎样填写这三项、如何据支撑字段检查，见 spec/06。“档案切期”是保留的支撑名，不是变量字段。

### 剧情标记

```yaml
阿斯拉王权: [未定, 爱丽儿·阿涅摩伊·阿斯拉]
菲托亚领状态: [完好, 已毁, 重建中]
王宫战况: [平静, 混战, 结束]
```

键是标记ID，值是该标记的全部取值，第一个取值是开局值，封卷时写入。事件门槛与变化表只能使用已声明的标记和取值。门槛比较等于或不等于、变化表设定取值，这些属于第一层。

### 角色分类

```yaml
角色包: [原著, Fate]
分类: [格雷拉特家, 阿斯拉王室, 龙族, 剑士, 魔术师, 跨界者]
```

两张平铺的清单，`角色组.yaml` 的角色包与分类只能取其中的值。分类不挂在角色包下面：同一分类可以跨包使用，例如“跨界者”。每个角色组属于一个角色包、一个分类，只用于开局选择时的列表，不作整包开关，这些属于第一层。
