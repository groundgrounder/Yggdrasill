# 背景设定声明

> 状态：2026-10-20 已确认；2026-10-23 按术语收词的决定补纪年的区间、事件分类的世界事件与默认声明。能力格式见 spec/03，条目库格式见 spec/08，本局变量格式见 spec/09。

每张卡的第二层（背景设定）只在一处声明：世界书根下的固定根 `设定/`。

## 位置与文件

`设定/` 是固定根，只放 `.yaml`，只给工具读。它放第二层的全部声明，以及第五层中能机器检查的声明。按节分文件：

| 文件 | 内容 | 格式 |
|---|---|---|
| `纪年.yaml` | 时间写法 | 本文 |
| `等级.yaml` | 各套等级 | 本文 |
| `能力.yaml` | 能力维度及其取值、技能可用规则 | spec/03 |
| `事件分类.yaml` | 主类型、标签、事件结果 | 本文 |
| `条目库.yaml` | 有哪些条目库，各自的分法、分级与字段 | spec/08 |
| `本局变量.yaml` | 取值表、二层的本局变量字段及值域 | spec/09 |
| `剧情标记.yaml` | 剧情标记及取值 | 本文 |
| `角色分类.yaml` | 角色包与分类 | 本文 |
| `文本规范.yaml` | 第五层：禁用词、ID 命名、档案追加字段、长度预算 | spec/10 |

纪年、事件分类、本局变量三个文件必须有。其余文件在用到时才需要：例如有技能库就要有能力，有剧情标记就要有剧情标记文件。

本局变量中一层的骨架（在场、能力移除记录、已初始化、开局、事件记录等）写在规范里，所有卡相同；卡只声明二层的字段。

## 单一来源

- 二层的每项种类与取值只在 `设定/` 声明一次。
- 模型需要看到的清单（例如关系阶段有哪些值、等级的高低顺序），在打包时从声明生成。正文、说明文件和协议文本不手写复述。
- 创作规划等作者资料不抄写种类与取值，只写设计理由，需要时引用声明。

## 字段声明

条目库和本局变量的字段声明同时标出字段所属的层：

- 写“取值”“引用”的字段属第三层，检查器校验取值与引用。
- 写“形态”的字段是文本，受四、五层约束。

```yaml
装备:
  分法: 按种类
  分级: [标签]
  字段:
    标签: {必填: true, 取值: [灯具, 工具, 航具]}
    装备等级: {必填: true, 取值: 等级.技艺}
    简介: {必填: true, 形态: 文本}
    效果: {必填: true, 形态: 文本列表}
```

完整写法见 spec/08。

## 条件类型

条件类型全部属于第一层。依赖某个条目库或能力维度的条件，在卡没有声明所依赖项时不可用：

| 条件 | 依赖 |
|---|---|
| 当前场景 | 地点库 |
| 在场实力人数 | 能力中的综合实力维度 |

## 不属于二层的

上下文预算等运行参数不是种类或取值，写在项目的 `yggdrasill.yaml`，见 spec/14。检查器的抽样起始年由事件时间推出，不需要声明。

## 各文件格式

每一项的机制属于第一层，所有卡相同，在对应议题的规范中规定；本节只写第二层的取值。例如“事件有主类型、标签、事件结果，只用于检索，不参与门控”是第一层，“有哪些标签”是第二层。

### 纪年

```yaml
前缀: 潮历
年位数: 3
月数: 4
每月天数: [91, 91, 91, 92]   # 整数，或长度等于月数的逐月列表
```

四个键都必须写。写法为 `{前缀}{年}年` 或 `{前缀}{年}年{MM}月{DD}日`，年补足到年位数，月日两位。纪年换算等世界内容写进世界概况。

时间都表示区间：写到日的是当日，写到年的是整年，即首月首日至末月末日。区间含起点、不含终点；日的终点是次日的起点，年的终点是次年首日的起点。前者的终点不晚于后者的起点，称前者早于后者；前者的起点不早于后者的终点，称前者已过后者。事件是否未到、是否已过、是否属于开局之前，都按这两种关系判断（spec/06、15）。

### 等级

```yaml
技艺: [学徒, 熟手, 匠人, 名匠]
船级: [小舟, 渔船, 帆船, 大帆船]
```

每个键是一个等级序列的名字，值从低到高排列；序列中的每个值称等级。字段以 `等级.{名字}` 引用。卡可以声明几个等级序列，例如技艺用一个、船级用另一个。

### 事件分类

```yaml
主类型: [世界, 关系, 个人]
世界事件: 世界        # 可选：哪个主类型表示世界事件，须是上面的主类型之一
标签: [天灾, 修习, 航行, 商事, 家庭]
事件结果:            # 每项结果声明支撑它的本局变量字段；空列表表示不检查
  关系变化: [关系, 好感度]
  能力变化: [技艺, 名望, 天赋, 习惯, 装备]
  身份变化: [身份, 职位, 档案切期]
  知识变化: [知识]
  剧情条件变化: [剧情标记]
```

三项的取值都由本卡声明。每个事件怎样填写这三项、如何据支撑字段检查，见 spec/06。“档案切期”是保留的支撑名，不是变量字段。

“世界事件”可选，写一个主类型，表示到时间就发生、只写世界层面变化的事件（spec/12）。声明了它，检查器在这类事件的门槛正向引用其它主类型的事件时提示；不声明则不作这项检查。

### 剧情标记

```yaml
灯塔状态: [运转, 熄灭, 重燃]
雾季: [未至, 已至, 已过]
```

键是标记ID，值是该标记的全部取值，第一个取值是开局值，封卷时写入。事件门槛与变化表只能使用已声明的标记和取值。门槛比较等于或不等于、变化表设定取值，这些属于第一层。

### 角色分类

```yaml
角色包: [雾港]
分类: [灯塔, 商会, 港务]
```

两张平铺的清单，`角色组.yaml` 的角色包与分类只能取其中的值。分类不挂在角色包下面：同一分类可以跨包使用。每个角色组属于一个角色包、一个分类，只用于开局选择时的列表，不作整包开关，这些属于第一层。

## 默认声明

世界树附带一套默认声明，供新卡复制进自己的 `设定/` 后修改；复制以后即为本卡的声明，与世界树不再关联。默认声明包括事件分类的默认清单，以及推荐的本局变量字段：身份、职位、知识（用法见 spec/09）。默认声明属于第二层，内核不特别对待其中的任何字段。
