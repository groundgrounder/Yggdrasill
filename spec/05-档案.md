# 档案

> 状态：2026-10-20 已确认。本文取代 tavern-cards 的 `period-profile/field-norms.md`。

时期档案写某个版本在一段时期内稳定的事实与行为方式。每份档案在 `角色/{角色组ID}/档案/{档案ID}/` 下有两个模型可见的文件：`基本信息.txt` 与 `角色印象.txt`。档案的版本、默认、前置与生效条件写在 `角色组.yaml`，见 spec/04。

## 字段表归属

- 两个文件的字段表属第四层，所有卡相同。
- 第五层可以追加可选字段，不能删除或改名已有字段，也不能改变已有字段的形态。追加字段在 `设定/文本规范.yaml` 声明，见 spec/10。
- 程序读取的部分属第一层与第三层：能力特征的结构，技能补充的技能ID（三层，须为已登记技能），出生年（三层，格式由二层纪年规定）。

## 形态

| 形态 | 含义 |
|---|---|
| 文本 | 非空的一句话 |
| 文本列表 | 每项一句话 |
| 短语列表 | 每项一个短语，不以句号结尾 |
| 情境列表 | 每项是单键映射 `- 情境: 内容`，键写条件，值写表现 |
| 禁区列表 | 每项以“不”开头 |

可选字段没有内容时整键省略。能力特征的两个数组例外，没有内容写空列表。

由固定子字段组成的字段（稳定体貌、能力特征、表达规律）按 spec/08 的“子字段”写法，至少写一个子字段；出生年按 spec/08 的“取值: 纪年”。子字段与其所属字段同层。

## 基本信息

| 字段 | 必填 | 形态 | 层 | 写什么 |
|---|---|---|---|---|
| 姓名 | 是 | 文本 | 四 | 本版本的全名 |
| 称号 | 否 | 短语列表 | 四 | 本时期对外使用的称号或名号。没有就省略，不写“无”。职位由事件写入，不在此确认 |
| 性别 | 是 | 文本 | 四 | 本版本的性别 |
| 出生年 | 否 | 取值：纪年 | 三 | 资料只有范围时省略，不编造 |
| 种族 | 是 | 文本 | 四 | 短语，补充放括号 |
| 出身 | 是 | 文本 | 四 | 一句话只写出身，补充放括号；身份与经历交给事件 |
| 稳定体貌 | 是 | 子字段 | 四 | 遮住名字也能认出的特征 |
| 穿着习惯 | 否 | 文本列表 | 四 | 偏好、场合与功能取舍 |
| 能力特征 | 是 | 子字段 | 一、三、四 | 个人差异与限制 |

性别、种族是版本身份的一部分，改动等于换了一个人，但程序不读取它们，按第四层文本处理。以后路由读取它们时再升级。

档案不写年龄。一份档案往往跨好几年，写死的年龄很快就不对；当前年龄由路由按出生年与当前时间计算。

### 稳定体貌

| 子字段 | 形态 | 写什么 |
|---|---|---|
| 发色发型 | 文本 | 如“亚麻色微卷短发，后脑留细小鼠尾辫” |
| 瞳色 | 文本 | 如“墨黑色”“金色三白眼” |
| 体型 | 文本 | 只写显著特点，普通身材不写 |
| 特征 | 短语列表 | 角、尖耳、泪痣、鳞纹这类标志 |

只写偏离该种族与年龄默认印象的特征，不写“精致”“白皙”这类放在谁身上都成立的词。时期之间的体貌变化写进各自的档案。

### 穿着习惯

写“在什么场合偏好穿什么、为什么”。偏好不等于当前穿着。涉及专属装备时写成“持有并使用风暴灯时……”，偏好某件装备不等于持有它。

### 能力特征

```yaml
能力特征:
  特征:
    - 能在低照度下辨清远处灯号的间隔。
  技能补充:
    - 技能ID: 雾中视·辨影
      个体表现:
        - 辨别交错岸灯时先数明暗间隔。
      个体限制:
        - 强光直照后需要闭眼歇息。
```

- 特征（文本列表，四层）：天赋、体质、当期施法限制，一句一项。
- 技能补充：某个公共技能在这个人身上的表现与限制。技能ID属三层；个体表现、个体限制属四层，至少写一项，都写成文本列表。
- 不写当前能力、已学技能名单、综合实力或公共技能正文。写了技能补充不代表已掌握该技能，运行时只在本局可用时发送。

## 角色印象

全部字段属第四层。

| 字段 | 必填 | 形态 | 建议条数 | 写什么 |
|---|---|---|---|---|
| 核心身份 | 是 | 短语列表 | 1–3 | “形容词＋身份”，如“讲规矩的老灯塔守” |
| 行为准则 | 是 | 文本列表 | 2–4 | 处事方式：在什么情况下先做什么、再做什么 |
| 价值优先 | 是 | 短语列表 | 2–4 | 从高到低排序 |
| 表达规律 | 是 | 子字段 | — | 说话方式 |
| 通用反应 | 是 | 情境列表 | 2–5 | 跨事件反复出现的具体反应 |
| 关系表现 | 否 | 情境列表 | 1–5 | 对各类对象的表现 |
| 表现禁区 | 是 | 禁区列表 | 1–4 | 本角色最容易被写歪的方向 |

建议条数只提示，不判失败。

- 核心身份每轮定调，只放这个时期最稳定的身份感，不放亲密倾向和一次性处境。
- 行为准则写可执行的处事顺序，不写“善良”“冷静”这类评价。
- 价值优先是排序，前面的在冲突时胜出，写成名词短语。

### 表达规律

只写和常规叙述口吻不同的部分，按以下子字段归位，资料没有的省略：

| 子字段 | 形态 | 写什么 |
|---|---|---|
| 自称与称呼 | 文本 | 自称；对不同对象的称呼及其变化条件 |
| 句式 | 文本列表 | 句子长短、组织顺序、敬语或命令的习惯 |
| 语气变化 | 情境列表 | 慌张、被戳穿、愤怒、示好时说法怎么变 |
| 场合差异 | 情境列表 | 公开与私下、正式与日常的差别 |
| 内外差 | 文本列表 | 心里想的和说出口的有什么落差 |
| 口头特征 | 短语列表 | 固定用词、语气词、口癖，每项不超过 8 个字 |

判断标准：拿到一句台词，读者能根据每一条判断它像不像这个角色。“温柔”“冷淡”“礼貌”不能单独成条，必须落到具体说法。自称与称呼、句式最能区分角色，资料里没有时在核定日志列为待补，不编造。

完整台词只放在事件角色位置的候选台词中；档案里写死的台词每轮都会发送，模型会反复套用。通用反应写“做什么”，语气变化只写“怎么说”。

### 通用反应与关系表现

- 通用反应的键写具体情境，值写具体做法。只属于某一次事件的反应写进该事件的角色位置。
- 关系表现的键写对象类别或条件。针对具名角色或亲密关系时，键写关系阶段与场合，关系阶段取二层声明的值；不用亲密度这类数值作条件。键只描述条件，不声明双方现在是什么关系。
- 同一对象的行为与说话方式写在同一条，其它字段不重复。
- 值写具体的触发与收起情境，不写“偶尔”“有时”这类频率词。
- 亲密场景写主动性、态度与节奏，保留成年与自愿前提。

### 表现禁区

每条以“不”开头，写模型最容易写歪的具体方向。适用于所有角色的规则写进角色通用约束，不在每份档案重复。

## 档案写什么、不写什么

- 档案写“这个人会怎么做”；“现在是什么状态”只由事件确认。
- 关系、婚姻、家系、职位、资产、持有物、伤势、当前地点、当前穿着、能力的取得与丧失，只来自事件变化表。把这些状态改写成句子、换个字段名放进档案，同样属于越界。
- 档案只写本时期及以前已经确立的事实，不提及之后才出现的人物、身份或事件。

## 何时另开时期档案

- 核心身份、行为准则、价值优先或稳定体貌明显改变时另开，例如流亡前后、婚后、身份公开前后。
- 单纯的能力成长或装备变化不另开，由事件变化表写入本局。
- 每个版本通常 1–4 份档案；更多时在核定日志说明理由。

## 共享与镜像

- 共享档案（适用版本含多个版本）只改一处。
- 镜像档案是不同版本同一时期的两份独立档案。修改一份时比对另一份的同一字段：原本相同就提醒是否同步；原本不同是版本差异，不动。

## 自建玩家

自建模式下，玩家的身份写在本局变量 `开局.玩家.档案`，字段取基本信息字段表的子集：姓名、称号、性别、出生年、种族、出身、稳定体貌、穿着习惯。没有能力特征与角色印象：玩家的行为由玩家决定，能力全部来自本局变量。
